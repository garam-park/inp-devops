## 1. 오브젝트 스토리지

### 1.1 버킷과 키

환경마다 버킷 하나(`subsidence-dev`, `subsidence-stage`, `subsidence-prd`). 접두사로 성격을 나눈다.

```text
raw/{upload_id}/manifest.json                 올린 원본의 목록(파일명·크기·sha256·역할)
raw/{upload_id}/{원본 파일 그대로}              zip 은 풀어서 저장. 경로는 zip 안 경로
raw/{upload_id}/geocode-cache.json            (있으면) 지오코딩 캐시

datasets/{version}/manifest.json              번들 목록 (§2)
datasets/{version}/model.json
datasets/{version}/layers/regions.json
datasets/{version}/layers/risk_areas.geojson
datasets/{version}/layers/area_scores.json    신규: 기간 조합별 점수 (§4)
datasets/{version}/layers/risk_grid.geojson
datasets/{version}/layers/insar_cells.json
datasets/{version}/layers/{coast,geology,sinkholes,hazard,excavation}.geojson
datasets/{version}/layers/excavation_items.json
datasets/{version}/insar10m/index.json, {bx}_{by}.json
datasets/{version}/pipes/index.json, {읍면동}.geojson
datasets/{version}/logs/build.jsonl

exports/{yyyy}/{mm}/{export_id}.{geojson|csv|xlsx|pdf|zip|tif}
incidents/uploads/{upload_id}.xlsx
backups/postgres/{yyyy-mm-dd}.dump
```

| 접두사 | 쓰는 쪽 | 읽는 쪽 | 불변 | 수명 |
|---|---|---|---|---|
| `raw/` | api(업로드) | pipeline | 예 | 보관. 삭제는 관리자 명시 (빌드 재현을 위해) |
| `datasets/` | pipeline | api(중계·importer) | 예 | 보관. 활성·직전 N개 외는 관리자가 삭제 |
| `exports/` | api, pipeline | api(다운로드) | 예 | `EXPORT_TTL_DAYS`(기본 30) 뒤 lifecycle 규칙으로 삭제. DB 행은 남긴다(감사) |
| `incidents/uploads/` | api | (감사 시) | 예 | 보관 |
| `backups/` | CronJob | 운영자 | 예 | 30일 |

"불변"은 같은 키에 다시 쓰지 않는다는 뜻이다. 그래서 `datasets/{version}/...` 응답에 `Cache-Control: public, max-age=31536000, immutable` 을 붙일 수 있고(§10), 캐시 무효화 문제가 없다.

### 1.2 접근 방식

| 방식 | 기본안 | 언제 바꾸나 |
|---|---|---|
| 다운로드 | **api 중계** (`GET /api/datasets/{v}/files/{path}`, `GET /api/exports/{id}/download`). api 가 권한을 검사하고 S3 `GetObject` 스트림을 그대로 흘린다 | api 파드가 대역폭 병목이면 presigned GET(짧은 만료, 레이어 단위 발급)으로. 그래도 권한 검사는 발급 시점에 한다 |
| 업로드 | **api 중계** (스트리밍, `lib-storage` 멀티파트). 수 GB 원본도 메모리에 올리지 않는다 | 브라우저 → 스토리지 직접 PUT 은 스토리지 엔드포인트를 Ingress 에 내야 한다. 운영 환경 승인이 되면 |
| pipeline | S3 API 직접 (`boto3`), 전용 자격 증명(읽기 `raw/`, 쓰기 `datasets/`·`exports/`) | — |

자격 증명은 역할별로 셋이다. api(전부), pipeline(위 범위), 백업(쓰기 `backups/`). MinIO 정책 또는 IAM 정책으로 접두사를 제한한다.

### 1.3 로컬 개발

`docker-compose.yml` 의 MinIO 가 같은 버킷·접두사를 쓴다. `pipeline cli build` 는 폴더 → 폴더로도 돌고 `--upload` 를 주면 MinIO 로 올린다. web 은 Vite 프록시로 `/api` 를 api 에 넘긴다.

## 2. 데이터셋 번들 규약

번들 = pipeline 이 한 번 실행해 만든 파일 전체 + manifest. **화면이 보는 자료의 단위**이자 **감사가 가리키는 단위**다.

```json
{
  "schemaVersion": 1,
  "version": "01JAB3C4D5E6F7G8H9JKMNPQRS",
  "generatedAt": "2026-10-17T09:12:33+09:00",
  "pipeline": { "image": "ghcr.io/innopam/subsidence-pipeline@sha256:…", "git": "abc1234" },
  "model": "model.json",
  "inputs": { "uploadId": "01JAB…", "files": [{ "path": "1. 지질 평면도 및 분포도/수치지질도_25만_제주.shp", "sha256": "…", "bytes": 123 }] },
  "options": { "excavationMode": "point", "geocodeUpdated": false },
  "summary": { "cells": 104973, "areas": 754, "grades": { "E": 12, "D": 80, "C": 300, "B": 362 }, "insarCells": 98637 },
  "files": [
    { "path": "layers/risk_areas.geojson", "bytes": 2300000, "sha256": "…", "layer": "risk", "sensitive": false, "contentType": "application/geo+json" },
    { "path": "pipes/건입동.geojson", "bytes": 1368519, "sha256": "…", "layer": "pipes", "sensitive": true, "contentType": "application/geo+json" },
    { "path": "insar10m/65_40.json", "bytes": 700000, "sha256": "…", "layer": "insar", "sensitive": false, "contentType": "application/json" }
  ]
}
```

- `files[].layer` 가 권한의 열쇠다. api 파일 중계는 요청 경로를 manifest 에서 찾아 `layer` 를 얻고, 역할의 허용 레이어에 없으면 403 이다. manifest 에 없는 경로는 404. **web 이 어떤 경로를 요청하든 이 표 밖은 나가지 않는다.**
- `sensitive: true` 는 지금 `SENSITIVE_LAYERS`(`pipes`, `excavation`)다. 권한 화면의 ＊ 표시와 감사 기록의 "민감 자료 열람" 플래그에 쓴다.
- `model.json` 은 지금 것에 `years`, `factorShortLabels`, `schemaVersion` 을 더한다. 번들 안에 있으므로 화면은 "자기 버전의 model" 만 본다 → 01 §7-1 의 드리프트가 구조적으로 사라진다.
- 번들 스키마(`contracts`)가 바뀌면 `schemaVersion` 을 올리고 importer 가 구버전을 거부하거나 변환한다.

### 파일 중계의 응답 헤더

```text
GET /api/datasets/01JAB…/files/pipes/건입동.geojson
→ 200, Content-Type: application/geo+json, Content-Length, ETag: "<sha256>",
  Cache-Control: public, max-age=31536000, immutable, Content-Encoding: gzip(수용 시)
```

`GET /api/datasets/active` 만 `Cache-Control: no-store` 다. 브라우저는 버전이 바뀔 때만 새 파일을 받는다.

## 3. 동적 파이프라인 — 작업 표와 워커

### 3.1 `jobs` 표

```sql
jobs(
  id            text primary key,          -- ULID. dataset_build 면 곧 version
  type          text not null,             -- dataset_build | export_shp | export_geotiff | geocode
  status        text not null,             -- queued | running | built | ready | done | failed | cancelled
  payload       jsonb not null,            -- {uploadId} 또는 {exportId, params}
  progress      jsonb,                     -- {step: "scoring", pct: 42, message: "격자 54,330셀 채점"}
  result        jsonb,                     -- {version, summary} 또는 {key, bytes}
  error         text,
  attempts      int not null default 0,
  locked_by     text, locked_at timestamptz,
  created_by    text not null references users(id),
  created_at    timestamptz not null default now(),
  started_at    timestamptz, finished_at timestamptz
)
```

### 3.2 워커 루프

```text
매 5초:
  BEGIN;
  SELECT * FROM jobs WHERE status='queued' AND type = ANY($types)
    ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED;
  UPDATE … SET status='running', locked_by=$host, locked_at=now(), attempts=attempts+1;
  COMMIT;
  작업 실행 (진행률은 별도 커넥션으로 UPDATE)
  성공: status = built(dataset_build) | done(export_*), result 기록
  실패: status='failed', error 기록, 올린 부분 접두사 삭제
```

- `locked_at` 이 오래된(예: 2시간) `running` 은 api 의 정리 루틴이 `failed` 로 돌린다(워커가 죽은 경우).
- 재시도는 자동으로 하지 않는다. 빌드 실패는 보통 입력 문제라 사람이 봐야 한다. 관리자 화면에 "다시 실행" 버튼.
- 동시성 1. `dataset_build` 는 메모리를 많이 쓰고 연 몇 번이라 병렬이 필요 없다. 내보내기 변환은 같은 워커가 사이사이에 처리한다. 늘려야 하면 워커 replicas 만 올리면 된다(`SKIP LOCKED` 가 분배).

### 3.3 상태 전이 (dataset_build)

```text
queued → running → built → ready → (activate) active
                 ↘ failed                      ↘ (다른 버전 활성화) archived
```

- `built`: 번들이 스토리지에 다 올라갔다. pipeline 의 책임은 여기까지.
- `ready`: api importer 가 `risk_areas`·`area_scores`(2단계: `risk_cells`·`pipes`)를 DB 에 적재했다. 미리보기 가능.
- `active`: `dataset_versions.is_active` 하나만 true. 활성화·보관 전환은 트랜잭션 하나.

### 3.4 입력 묶음

원본 자료는 폴더 구조가 제공처마다 다르다(`1. 지질 평면도 및 분포도/…`, `20260811_상하수도시설물…/1_가공자료/…`). pipeline 이 폴더를 뒤지는 대신, 업로드 때 **역할 매핑**을 받는다.

```json
{ "roles": {
    "geology_shp": "1. 지질 평면도 및 분포도/수치지질도_25만_제주.shp",
    "hazard_shp": "5. 자연재해저감 종합계획/자연재해저감 종합계획.shp",
    "sinkhole_xlsx": "제주_지반침하_과거이력.xlsx",
    "sinkhole_gpkg": "jeju_subsidence_points_epsg5186.gpkg",
    "survey_route_shp": "4. 지반침하 발생지/지하안전정보시스템_지반침하탐사노선.shp",
    "pipe_grid_gpkg": "…/pipe_grid_100m_5186.gpkg",
    "water_pipes_gpkg": "…/water_pipes_5186.gpkg",
    "sewer_pipes_gpkg": "…/sewer_pipes_5186.gpkg",
    "insar_gpkg": "jeju_ps_sbas_integrated_grid10m.gpkg",
    "excavation_xlsx": ["3. 지하공사 좌표 및 굴착 이력/*.xlsx"],
    "geocode_cache": "geocode-cache.json"
} }
```

업로드 화면이 zip 안 파일 목록을 보여 주고 역할을 고르게 한다(확장자로 추정해 미리 채움). 빠진 필수 역할이 있으면 빌드를 시작하지 않는다.
지금 `gislib.py` 상단의 경로 상수 5개와 `build_data.py` 안의 경로 조립이 전부 이 매핑으로 바뀐다.

### 3.5 지오코딩

- 캐시(`geocode-cache.json`, 지금 `tools/.cache/excavation_geocoded.json`)를 원본 묶음의 일부로 올린다. 캐시만으로 좌표가 다 나오면 외부 호출이 없다.
- 캐시에 없는 지번이 있고 `GEOCODE_ENABLED=true` 이면 pipeline 이 브이월드를 부르고, 갱신된 캐시를 번들 `inputs/` 에 함께 저장한다. 다음 업로드에 쓰라고 관리자 화면에서 내려받게 한다.
- 꺼져 있으면 지금처럼 동 단위로 물러나고 manifest `excavationMode: "dong"` 으로 적는다. 화면·보고서의 "동 단위 집계" 문구는 이 값을 본다.

## 4. 기간별 채점 — 사전 계산을 추천

지금 화면은 기간을 바꾸면 `scoring.js` 가 후보마다 굴착 인자를 다시 더해 CSI·등급·판단근거를 재계산한다. 같은 공식이 Python 에도 있다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 사전 계산 (추천)** | pipeline 이 후보 × 기간 조합(2015–2021 → 시작≤끝 28개)별로 `csi, grade, rawScore, evidence[], permits` 를 미리 계산해 `area_scores.json` 에 담는다. api 는 조회만 한다 | 채점 공식이 **Python 한 벌**. 결과가 번들에 고정돼 보고서가 재현된다(공공 보고서에 중요). api·web 에 산정 로직이 없다 | 기간 단위가 월로 바뀌면 조합이 늘어난다(84개월 → 3,570조합 × 754 = 270만 행. 그래도 PostgreSQL 에서 작다). 가중치 변경은 재빌드 |
| B. api 재채점 | `scoring.js` 를 TS 로 옮겨 api 가 요청마다 계산 | 조합 폭발 없음 | 공식 두 벌 유지. Python 결과와 TS 결과가 같음을 골든 테스트로 묶어야 한다(지금은 사람이 맞춘다) |

A 를 택하면 `lib/scoring.js` 와 `GRADE_CUTS` 복제가 사라지고, 지금 `README.md` "기간 설정이 하는 일" 절이 그대로 성립한다(굴착 인자만 기간에 반응). 지역 안 순위·상위 5%·등급 집계는 조회 시 SQL 윈도 함수로 한다(공식이 아니라 정렬이다).

`area_scores.json` 한 행:

```json
{ "areaId": "RA0001", "fromYear": 2015, "toYear": 2021, "csi": 99, "grade": "E", "rawScore": 72,
  "evidence": [{ "key": "insar", "score": 51, "ratio": 1.0 }, { "key": "geology", "score": 10, "ratio": 0.571 }],
  "permits": 0 }
```

(`label` 은 `model.json` `factorLabels` 에서 붙이므로 행마다 적지 않는다.)

## 5. DB 스키마 초안

```text
users(id, login, name, dept, role, password_hash?, oidc_sub?, disabled, created_at)
roles(key)  -- admin | service | user
role_permissions(role, kind, key)            -- kind: layer | export. 시드는 domain/rbac DEFAULT_PERMS
sessions(id, user_id, csrf, expires_at)

dataset_versions(id, status, is_active, generated_at, manifest jsonb, model jsonb, summary jsonb, built_by, activated_at, activated_by)
jobs(…)                                      -- §3.1
risk_areas(version_id, id, geom geometry(MultiPolygon,4326), props jsonb, city, dong, bbox)   -- props = 지금 properties 그대로
area_scores(version_id, area_id, from_year, to_year, csi, grade, raw_score, evidence jsonb, permits,
            primary key(version_id, area_id, from_year, to_year))
-- 2단계
risk_cells(version_id, col, row, geom geometry(Polygon,4326), csi, grade, conf_g, dong, vel)
pipes(version_id, id, kind, year, dia, depth, len, dong, geom geometry(LineString,4326))

incidents(id, sago_no unique, source, date, sigungu, dong_addr, addr, lon, lat, geom, width, extend, depth, grd_kind, cause,
          death, injury, vehicle, tr_status, tr_fn_date, tr_method, detail, created_by, updated_by, updated_at, deleted_at)
incident_revisions(id, incident_id, at, by, action, before jsonb, after jsonb, upload_id?)
incident_uploads(id, file_key, filename, bytes, sha256, by, at, applied, unchanged, invalid jsonb)

exports(id, user_id, kind, params jsonb, version_id, rows, file_key, bytes, sha256, status, job_id?, created_at, expires_at)

audit_events(id, at, user_id, user_name, dept, role, action, target, detail, result, ip, request_id)
```

- `audit_events` 는 앱 DB 역할에 `INSERT`·`SELECT` 만 준다. `UPDATE`·`DELETE` 권한이 없어 코드 버그로도 못 지운다. 보존·삭제는 DBA 절차.
- 데이터 표(`risk_areas`, `area_scores`, `risk_cells`, `pipes`)는 `version_id` 를 앞에 둔 복합 키다. 버전 삭제는 `DELETE … WHERE version_id=` 하나.
- `incidents.source` 는 `ledger`(원본 대장, 읽기 전용) | `user`. 대장은 **번들에서 importer 가 적재**한다(`sinkholes.geojson` 의 `kind='사고'`). 지금 `mergeIncidents` 의 "같은 번호를 담당자가 쓰면 그 기록이 이긴다" 규칙은 `source='user'` 행이 있으면 그것을 보여 주는 뷰로 옮긴다.
- PostGIS 가 운영 DB 에서 허용되지 않을 수 있다(02 §4.2). 1단계 표(`risk_areas`, `area_scores`)는 `geom` 없이도 돌아간다(`props` 와 `bbox` 숫자만으로 지역·범위 필터). PostGIS 는 2단계 표에서만 필수다.

## 6. 공간 질의로 바꾸는 레이어 (2단계)

| 레이어 | 1단계 | 2단계 | 효과 |
|---|---|---|---|
| `risk_grid` 26MB | 파일 중계 (시작 시 전부) | `GET /api/layers/grid?v&bbox&zoom` — 배율 13 이상에서만, 화면 범위 셀 | 초기 로딩 26MB → 0. 화면당 수백 KB |
| `pipes` 39MB | 파일 중계 (읍면동 3개) | `GET /api/layers/pipes?v&bbox` | 읍면동 경계 가장자리에서 끊기는 문제 해소. 화면 쪽 "가까운 동 고르기" 코드 삭제 |
| `insar10m` 241MB | 파일 중계 (블록) | 그대로. 또는 `ST_AsMVT` 벡터 타일 | 블록 방식이 이미 "화면에 든 것만"이다. 바꿀 이유가 약하다 |
| `insar_cells` 3.4MB | 파일 | 그대로 | 작다 |

벡터 타일(MVT)로 가면 Leaflet 에 `Leaflet.VectorGrid` 를 더하거나 MapLibre 로 바꿔야 한다. 격자 수치 라벨(배율 15 이상에서 셀마다 숫자) 같은 지금 기능이 타일에서는 다른 방식이 필요하다. 2단계 착수 때 결정 (05 §4-3).

## 7. 내보내기

| 종류 | 생성 | 어디서 | 저장 | 비고 |
|---|---|---|---|---|
| GeoJSON, CSV | 동기 (<1초) | api `generators/geojson.ts`, `csv.ts` | `exports/…` | 지금 속성 한글 열 이름 그대로. 메타데이터(`exportMeta`) 포함 |
| XLSX | 동기 | api `exceljs` | | 데이터 시트 + 메타데이터 시트 (지금과 같음) |
| PDF | 동기 (수 초) | api jsPDF + autotable, 서버 TTF | | 도넛·표·자료 한계 쪽 그대로 이식. 상위 60건 제한 유지 |
| SHP (zip) | **비동기** | pipeline `convert.py` (`pyshp`) | | 지금 "준비 중" 해제. dbf 는 한글 필드명 10자 제한이 있어 영문 약어 매핑표 필요 |
| GeoTIFF (변위 격자) | 비동기 | pipeline `rasterio` | | 입력은 번들의 `insar_cells` 또는 원본 래스터(`raw/`). 화면 범위·지역 자르기 |
| 사고 이력 XLSX, 감사 기록 XLSX | 동기 | api | | 내보내기 표로 통일 → 모두 감사 대상 |

- 요청 본문은 조회 조건(`version, from, to, city, dong, grades, sort, quick, bbox?, scope: all|one, areaId?`)이다. 서버가 `areas` 모듈의 **같은 쿼리 함수**로 대상을 뽑는다.
- `exports` 행이 조건·건수·해시를 들고 있으므로 "그 보고서가 어느 자료·조건에서 나왔나"를 나중에 답할 수 있다.
- 권한: 역할의 `export` 권한(`geojson`·`csv`·`report`)을 가드가 검사한다. SHP·GeoTIFF 는 `geojson` 권한에 묶는다(지금 메뉴 구성과 같음).
- 다운로드 URL 은 `GET /api/exports/{id}/download`. 본인 또는 관리자만. 다운로드도 감사에 남긴다(`export.download`).

## 8. 사고 기록·권한·감사·인증

### 사고 기록

- CRUD 는 `service` 이상. 삭제는 `deleted_at`(소프트). 모든 변경이 `incident_revisions` 에 전후 값으로 남는다.
- 엑셀 가져오기는 02 §5.4. 검증 규칙은 `domain/incidents.ts` 한 벌을 web 폼과 api 가 같이 쓴다. 지금 `checkUpload`(5MB·확장자·매직 바이트)와 `validateIncident`(필수·숫자·제주 범위)를 그대로 옮긴다.
- 지도 레이어 `sinkhole` 는 번들 파일(원본 대장 + 탐사노선)과 `GET /api/incidents?geo=1`(담당자 기록)을 합쳐 그린다. 지금 `App.jsx` 의 `sinkholes` useMemo 가 하던 일이다.

### 권한 (RBAC)

- 표는 `role_permissions`. 시드는 `DEFAULT_PERMS`. `admin` 행은 UI 에서 잠그고 api 도 거부한다(지금 "고정" 태그와 같음).
- 집행 지점: 파일 중계(레이어), 2단계 공간 질의(레이어), 내보내기(형식), 관리자 라우트(역할), 사고 기록 변경(역할).
- web 은 `GET /api/me` 의 `permissions` 로 **숨기기만** 한다. 서버가 막는다.

### 감사

- 액션 키는 지금 `AUDIT_ACTIONS` 에 `dataset.upload`, `dataset.build`, `dataset.activate`, `export.download`, `auth.login`, `auth.logout`, `perms.save` 등을 더한다.
- `GET /api/audit?kind&from&to&user&page` 는 관리자. 엑셀은 내보내기 표로.
- 보존 기간은 정책값. 기본 3년 제안(공공 감사 관행 기준이며 확인 필요).

### 인증

- 1차: 자체 계정. `POST /api/auth/login` → 세션 쿠키(`httpOnly; Secure; SameSite=Lax`) + CSRF 토큰(응답 본문 → `X-CSRF-Token` 헤더). 비밀번호 Argon2id. 로그인 실패 제한(IP·계정).
- 2차: OIDC. `GET /api/auth/oidc/start|callback`. `users.oidc_sub` 로 매핑, 역할은 SSO 클레임 또는 로컬 표 중 **하나**를 출처로 정한다(05 §4-4).
- `GET /api/me` 응답: `{ id, name, dept, role, permissions: { layers: [...], exports: [...] } }`. 지금 `USER` 상수와 `perms[role]` 을 합친 모양이다.

## 10. 캐시·성능

| 응답 | 캐시 | 이유 |
|---|---|---|
| `/datasets/{v}/files/*` | `immutable`, 1년, ETag=sha256 | 불변 번들 |
| `/datasets/active`, `/me`, `/areas*` | `no-store` | 바뀐다 |
| `/exports/{id}/download` | `private, no-store` + `Content-Disposition` | 개인 파일 |
| 2단계 `/layers/*` | `private, max-age=60` | 버전이 바뀌면 `v` 가 바뀐다 |

- 번들 파일은 gzip 으로 저장하고(`Content-Encoding: gzip` 메타데이터) 중계 때 재압축하지 않는다. GeoJSON 은 5–10배 줄어든다(312MB → 약 43MB, 지금 git 압축 크기와 같은 비율).
- api 파일 중계는 `stream.pipeline` 으로 백프레셔를 지킨다. 파드 메모리에 파일을 올리지 않는다.
- 1단계의 초기 로딩은 지금과 같다(약 33MB, gzip 뒤 약 5MB). 2단계에서 `risk_grid` 를 빼면 약 7MB(gzip 1MB 안팎).

## 11. 보안 체크리스트

- [ ] 모든 `/api` 라우트가 `auth` 훅을 지난다. 예외는 `/auth/login`, `/health`, `/ready` 뿐.
- [ ] 파일 경로는 manifest 조회로만 해석한다. 경로 문자열로 S3 키를 만들지 않는다(경로 탐색 차단).
- [ ] 업로드: 크기 상한(원본 묶음 `UPLOAD_MAX_BYTES`, 엑셀 5MB), 매직 바이트, zip 안 경로의 `..`·절대 경로 거부, 압축 폭탄 상한(풀린 크기).
- [ ] 엑셀 파서는 수식·외부 링크 해석을 끈다(지금 `cellFormula:false` 와 같은 의도).
- [ ] 브이월드 중계는 레이어·좌표 형식을 정규식으로 검증한 뒤 **고정 호스트**로만 나간다(SSRF).
- [ ] 세션 쿠키 `httpOnly; Secure; SameSite=Lax`, CSRF 토큰 검증(상태 변경 요청 전부).
- [ ] 감사 표는 추가 전용 DB 권한. 실패도 기록.
- [ ] 비밀값은 Secret 으로만. 번들·이미지·로그에 키가 없다(지금 `VITE_VWORLD_KEY` 제거).
- [ ] 이미지: 비루트, `readOnlyRootFilesystem`(api·web), `drop: [ALL]`, PSA restricted 통과. pipeline 은 `/work` 만 쓰기.
- [ ] 외부 네트워크 의존 0 으로 빌드 가능(npm 레지스트리·pip 인덱스 미러 전제, 글꼴 저장소 내장).
- [ ] 개인정보: 굴착 허가 신청인 미수집 유지. 사고 기록에 개인 식별 정보가 들어올 수 있으므로(주소·피해) 접근 권한과 감사로 통제.
