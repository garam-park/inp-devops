# 05. 전환 단계, 리스크, 열린 결정

- 앞: [04. 데이터·스토리지·API](04.data-and-storage.md) · 처음: [README](README.md)

## 1. 원칙

1. **매 단계 끝에 동작하는 제품이 있다.** 반쯤 옮긴 상태로 멈추지 않는다.
2. **자료부터, 사용자 상태 다음, 계산은 마지막.** 가장 큰 문제(코드·자료 드리프트, 권한 미집행)를 먼저 푼다.
3. **되돌릴 수 있게.** 각 단계는 기능 플래그나 이전 경로를 한 단계 동안 남긴다.
4. **알고리즘은 건드리지 않는다.** 채점·군집 코드는 옮기기만 한다. 결과가 같음을 골든 테스트로 묶은 뒤에만 개선한다.

## 2. 단계

### 0단계 — 뼈대

- 목표: 모노레포 레이아웃, 로컬 한 벌(compose), TS 전환 시작. 동작은 지금과 같다.
- 작업
  - `app/` → `apps/web/`, `tools/` → `apps/pipeline/`(패키지화, 경로 상수 → 인자). `packages/contracts`, `packages/domain` 빈 패키지.
  - `docker-compose.yml`: postgres/postgis, minio, api(빈 Fastify, `/health`), web(vite).
  - `mise.toml`, lefthook, markdownlint, ESLint·Prettier, vitest 뼈대. `pipeline` 에 pytest + 작은 원본 샘플.
  - **골든 테스트**: 지금 `build_data.py` 로 샘플 원본에서 만든 번들을 기준으로 저장. 이후 모든 pipeline 변경이 이 결과를 유지해야 한다.
- 완료 조건: `docker compose up` 으로 web 이 뜨고(아직 정적 데이터), `pipeline cli build 샘플 → 폴더` 가 골든과 같다.
- 되돌리기: 폴더 이동뿐이라 git revert.

### 1단계 — 데이터셋 번들과 파일 중계 (드리프트·권한 해소)

- 목표: 자료가 git 을 떠나 스토리지로. 화면은 api 를 통해서만 자료를 받는다.
- 작업
  - pipeline: `bundle`(manifest·업로드), `model.yaml`, `confG` 일관 출력, 10m 블록 스트리밍. `cli build --upload`.
  - api: `datasets`(active·list·files 중계·권한), `me`(임시 고정 사용자 — 아직 로그인 없음), `rbac` 시드.
  - web: `getJSON('data/…')` → `useLayerFile(name)`(manifest 기반). `model.json` 은 `useActiveDataset` 에서. `app/public/data/` 삭제.
  - 운영: dev0 에 MinIO·Postgres·api·web 배포(chart 초안). 첫 번들은 개발자가 `cli build --upload` 로 올리고 `activate` 는 SQL 로.
- 완료 조건: 저장소에 데이터가 없다. 역할 `user` 로 관로 파일을 요청하면 403. 두 버전을 올려 활성 전환하면 화면의 `model.json` 과 레이어가 함께 바뀐다.
- 되돌리기: web 의 자료 출처를 env 로 `static|api` 전환 가능하게 한 단계 동안 둔다.

### 2단계 — 사용자 상태의 서버화 (사고 기록·권한·감사·로그인)

- 목표: localStorage 4종 삭제. 누가 무엇을 했는지 서버에 남는다.
- 작업
  - api: `auth`(자체 계정·세션·CSRF), `rbac` 라우트, `incidents`(CRUD·엑셀 가져오기·내보내기), `audit`.
  - importer: `sinkholes.geojson` 의 사고 → `incidents(source=ledger)`.
  - web: 로그인 화면, `useMe`, 관리자 화면 3종을 API 로. `lib/{audit,perms,incidents,runHistory}.js` 삭제. "직전 조회 대비"는 이 단계에서 **숨긴다**(4단계에서 버전 차이로 복귀).
- 완료 조건: 두 브라우저에서 같은 사고 기록이 보인다. 권한 변경·반출·사고 변경이 `audit_events` 에 있고 UI 로 지울 수 없다.
- 되돌리기: 1단계 이미지로 롤백. DB 는 남겨 둔다.

### 3단계 — 내보내기 서버화

- 목표: 모든 파일 생성이 서버에서, 결과가 스토리지에, 감사와 연결.
- 작업
  - api: `exports`(4종 동기), 글꼴 파일 포함, `exceljs` 전환. `pdfFont.js` 삭제.
  - pipeline: `convert.py`(SHP·GeoTIFF), 작업 종류 추가.
  - web: `ExportActions` → API, 내 내보내기 목록·진행 표시. SHP·GeoTIFF 메뉴 해제.
- 완료 조건: PDF 가 서버에서 나오고 한글이 깨지지 않는다. SHP zip 을 QGIS 로 열 수 있다. 내보내기 행과 감사 기록이 파일을 가리킨다.
- 되돌리기: web 에 브라우저 생성 경로를 플래그로 한 단계 남긴다.

### 4단계 — 파이프라인 동적 실행과 사전 계산

- 목표: 관리자가 화면에서 자료를 갱신한다. 채점 공식이 한 벌이 된다.
- 작업
  - api: `uploads`, `datasets.builds`, `jobs`, importer 자동화(`built → ready`), `activate` 라우트, `areas`(기간·지역 조회, 순위, 상위 5%, 버전 차이).
  - pipeline: `worker`, `inputs`(역할 매핑), `periods`(28조합), 진행률.
  - web: DatasetsPage(올리기·역할 지정·빌드·진행·검토·활성화), 조회를 `useAreas` 로, `scoring.js` 삭제, 알림을 서버 플래그로, "직전 자료 대비" 복귀.
- 완료 조건: 개발자 PC 없이 새 원본으로 새 버전을 만들고 활성화한다. 기간을 바꾸면 결과가 지금과 같다(골든 비교). `lib/scoring.js` 가 없다.
- 되돌리기: `cli build --upload` 수동 경로는 계속 남는다(워커가 죽어도 자료 갱신 가능).

### 5단계 — 공간 질의 (성능)

- 목표: 초기 로딩에서 26MB 를 빼고, 관로를 화면 범위로 받는다.
- 작업: importer 가 `risk_cells`·`pipes` 적재(PostGIS). `layers` 모듈. web 훅 두 개의 자료 출처 교체. (선택) MVT.
- 완료 조건: 첫 화면 전송량 1/4 이하. 관로가 읍면동 경계에서 끊기지 않는다.
- 되돌리기: 훅의 출처를 플래그로.

### 6단계 — 제품화 마무리

- SSO(OIDC) 연동, 운영 환경 values, 백업 CronJob, 보존 정책(내보내기·감사), 모니터링(요청 로그·작업 실패 알림), 부하 시험(동시 사용자 수는 발주처 확인), 보안 점검(04 §11), 운영 문서.

## 3. 리스크

| 리스크 | 영향 | 완화 |
|---|---|---|
| pipeline 메모리가 dev0 쿼터를 넘는다 (01 §7-8, 미측정) | 빌드가 OOM 으로 죽는다 | 0단계에서 실제 원본으로 **측정**. 10m 블록 스트리밍을 1단계에 넣는다. 넘치면 pipeline 을 별도 네임스페이스 또는 k8s Job 으로 |
| 원본 InSAR GeoPackage 크기(수 GB 추정)가 업로드·디스크 한도를 넘는다 | 업로드 실패 | 멀티파트 스트리밍, emptyDir 20Gi, Ingress 본문 크기 상한 해제(`/api/uploads` 만) |
| 운영 DB 에 PostGIS 가 없다 | 5단계 불가 | 1–4단계는 PostGIS 없이 설계됨. 5단계 전에 확인 |
| SSO 프로토콜이 OIDC 가 아니다 | 6단계 지연 | 자체 계정으로 운영 가능하게 유지. SAML 이면 Keycloak 브로커 |
| 사전 계산을 택했는데 기간 단위가 월로 바뀐다 | 조합 수 증가 | 270만 행도 PostgreSQL 에서 문제없음. 그래도 B 안(재채점)으로 바꿀 수 있게 `evidence` 계산을 Python 함수 하나에 모아 둔다 |
| TS 전환과 구조 분해를 한꺼번에 하다 화면이 깨진다 | 회귀 | 파일 단위 전환. Playwright 로 주요 흐름(조회·상세·내보내기·관리자) 스모크를 0단계에 만든다 |
| `exceljs` 로 바꾸면서 엑셀 열 이름·날짜 처리가 달라진다 | 가져오기 실패 | 지금 내려받은 엑셀 파일을 픽스처로 왕복 테스트 |
| 보고서 수치가 프로토타입과 달라 보인다 | 신뢰 | 골든 테스트 + 4단계 완료 조건의 "기간 바꿔도 같음" |
| 폐쇄망 빌드 | 이미지 못 만듦 | 외부 의존 목록화(npm·pip·글꼴·베이스 이미지), 미러 전제. 6단계 전 리허설 |

## 4. 열린 결정

결정이 필요한 순서대로 적었다. 각 항목에 추천을 달았다.

### 4-1. "직전 조회 대비 신규·상향·해소"의 기준

- A. 지금처럼 **같은 사람의 직전 조회**(브라우저) — 사람마다 답이 다르고 서버에서 재현 불가.
- B. **직전 데이터셋 버전 대비** (추천) — "자료가 갱신되며 무엇이 새로 올라왔나"가 되어 모두에게 같다. 사업수행계획서의 "리스크 변동 트리거"에도 이 뜻이 더 맞는다. 화면 문구는 "직전 자료 대비".
- C. 둘 다 — 복잡도만 는다.

### 4-2. 기간별 채점

- A. **사전 계산** (추천, 04 §4) — 공식 한 벌, 재현성.
- B. api 재채점 — 기간 단위가 월·일로 바뀔 것이 확실하면.

### 4-3. 격자·관로 전달 방식 (5단계)

- A. **PostGIS bbox GeoJSON** (추천) — Leaflet 그대로, 코드 변화 최소.
- B. 벡터 타일(MVT) + MapLibre — 성능 최상, 지도 라이브러리 교체와 라벨 기능 재구현 필요.
- C. 파일 중계 유지 — 초기 26MB 를 감수.

### 4-4. 인증과 역할의 출처

- 자체 계정 기간을 얼마나 둘지, SSO 가 OIDC 인지 SAML 인지, 역할을 SSO 클레임에서 받을지 시스템 안 표에서 관리할지. 발주처 확인 필요.
- 추천: 역할은 **시스템 안 표**에서 관리(SSO 는 신원만). 지금 권한 화면이 그 전제다.

### 4-5. 운영 환경의 오브젝트 스토리지

- 지자체 제공 스토리지가 S3 호환인지, MinIO 를 자체 운영할지. 백업·용량(번들 버전당 약 45MB gzip + 원본 수 GB)과 함께 확인.

### 4-6. 지오코딩 외부 호출

- 운영에서 브이월드 호출이 허용되는지. 안 되면 캐시 전용 + 동 단위 fallback 으로 고정하고 화면 문구를 그에 맞춘다.

### 4-7. Python 유지 vs TS 포팅

- 추천은 **유지** (02 §6). 포팅하려면 1,900줄 재작성 + 수치 동일성 검증 + GeoPackage·Shapefile·엑셀 파서 대체가 필요하고, 얻는 것은 언어 하나 줄이기다. 단, pipeline 이 별도 컨테이너·별도 CI 라는 운영 비용은 받아들여야 한다.

### 4-8. 저장소

- 추천은 **모노레포** (03 §1). 분리한다면 `apps/pipeline` 부터.

### 4-9. 내보내기·감사 보존 기간

- 내보내기 30일, 감사 3년을 기본값으로 적었다. 발주처 보안 정책에 맞춘다.
