# 제주 AI 제품·dev0의 개발 배포 준비와 결정 채팅 인계

- 날짜: 2026-11-05
- 요청: 11/2~11/6 개발 일정의 결정 없는 일을 새 워크트리에서 마무리하고, 결정 목록과 이어갈 새 채팅 생성.

## 배경

최신 FE·BE에 로그인·권한·DB 적재가 구현돼 있으나 dev0는 S3만 주입하는 API 설정을 유지하고
DB·CNPG가 없었다. 서로 다른 저장소의 제품 코드와 클러스터 설정을 함께 준비해야 했다.

## 변경 내용

- `projects/jeju-ai`의 별도 worktree: 이 저장소 T141 작업·현황·결정 인계와 검증 기록 추가.
- `jeju-ai-saas-be`의 별도 worktree: DB·공간 확장·주요 테이블·S3를 읽기 전용 점검하는 CLI,
  전용 Compose 리허설·HTTP 검사 추가. PostGIS SQL 스크립트 패키지도 라이브러리와 같은
  `3.6.4+dfsg-2.pgdg13+1`로 고정해 새 이미지의 공간 확장 초기화 실패 수정.
- `ops/dev0`의 별도 worktree: 기존 앱과 분리한 DB·인증 준비용 Kustomize overlay,
  초기 계정·권한·전환·복귀 절차와 자체 history 추가.
- 별도 결정 채팅 생성: `제주 AI 개발 배포 결정 — DB·백업·초기 계정`,
  ID `01a1a8f2-02e4-7720-9393-fdc653299b54`.

## 결정과 이유

원래 체크아웃을 보존하고 각 저장소의 `codex/t141-dev-deploy-ready` 브랜치·worktree에서 작업했다.
제품 관련 세 경로는 T141 작업 본문에, 이 우산 기록은
`.ai-workflow/.worktrees/inp/codex-t141-dev-deploy-ready/`에 있다.
DB 3복제 + local-path 방침은 유지하되 실제 배치·쿼터·백업·계정 대상 결정을 새 채팅으로 넘겼다.

## 검증

제품 작업 T141의 현황·history와 dev0 history에 상세 결과를 기록한다.
읽기 전용 실측에서 API·FE·S3 Ready 1/1, Argo CD Synced·Healthy를 확인했다.
현재 배포·실제 DB·계정·Secret·PVC는 변경하지 않았다. 커밋·push·PR·서브모듈 포인터 갱신은 하지 않았다.

## 되돌리는 방법

각 worktree의 이번 미커밋 변경만 제거한다. 원래 체크아웃·배포 자원은 그대로다.
worktree 제거 여부는 별도로 정한다. 검증에서 만든 임시 컨테이너·볼륨은 해당 실행에서 정리한다.

## 남은 일

별도 채팅에서 결정 후 DB·Secret 준비와 GitOps 배포, 실제 HTTPS 로그인과 백업 복구 확인을 이어간다.
