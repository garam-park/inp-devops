# 프로젝트 커밋과 서브모듈 포인터를 원격과 정리

- 날짜: 2026-11-05
- 요청: 전반적인 프로젝트 커밋 관리 및 하위 저장소부터 상위 저장소까지 push 승인.

## 배경

상위 develop에 미전송 커밋 1개, 업무 기록 3개, 프로젝트 포인터 변경 3개가 있었다. 포트홀 develop은 원격보다 4개 앞섰다.

## 변경 내용

- 포트홀: 기존 커밋 f1e25de, f35453d, f5cec97, ba14e0d를 origin/develop에 push했다.
- 상위 업무 기록 3개를 d22fe6a로 커밋했다.
- projects/goyang-uam: 6319e6a → 34ac1cc.
- projects/jeju-ai: b50f36d → ee68832.
- projects/porthole: 52642ed → ba14e0d. 기존 스테이징 a2f700a 대신 현재 최신 커밋을 고정했다.
- 원격 상위 f097403을 병합해 .gitmodules 브랜치 변경과 홈페이지 포인터 57c3f0d를 보존했다. 홈페이지 작업 트리도 해당 커밋에 맞췄다.

## 결정과 이유

기존 이력을 재작성하지 않고 병합했다. 포트홀 충돌은 원격 포인터 461d83d가 ba14e0d의 조상임을 확인해 최신 포인터로 해결했다. 홈페이지는 원격이 지정한 포인터를 보존했다.

## 검증

- 포트홀 기존 기록의 훅 및 XLSX 검증 결과를 확인했다. 이번에는 산출물을 수정하거나 재생성하지 않았다.
- 업무 기록 커밋의 markdownlint 훅 통과. 고양·제주 현재 커밋은 원격 브랜치에 포함됨을 확인했다.
- 초기 fetch는 샌드박스 Git 메타데이터 접근 및 네트워크 제한으로 실패했고 추가 권한으로 성공했다.
- 첫 병합은 로컬 commit-graph 오류로 실패해 core.commitGraph=false로 우회했다. 이어 발생한 포트홀 포인터 충돌은 조상 관계 확인 후 해결했다.

## 되돌리는 방법

필요한 상위 커밋을 revert하고 하위 체크아웃을 해당 포인터에 맞춘다. 공유 이력을 강제로 되돌리지 않는다.

## 남은 일

commit-graph 캐시 복구는 이번 범위에 포함하지 않았다. 제품 실행 테스트는 수행하지 않았다.
