# 개발 배포 준비 커밋을 로컬 develop으로 통합하고 고정 커밋 연결

- 날짜: 2026-11-05
- 요청: 준비한 변경을 커밋하고 develop에 머지. 원격 작업 없이 로컬에서 진행.
- 이전 기록: [개발 배포 준비](02.jeju-ai-deploy-readiness.md)

## 배경

T141의 검증한 BE·제품 문서·dev0 준비용 설정은 별도 worktree에 미커밋 상태였다.
사용자가 로컬 커밋과 develop 통합까지 진행하도록 후속 요청했다.

## 변경 내용

| 저장소 | 작업 커밋 | 로컬 develop 머지 |
| --- | --- | --- |
| jeju-ai-saas-be | `cd8c6bc` | `f903dc2` |
| dev0 | `e9a9f38` | `8fd1842` |
| ws-jeju-ai | `722e43a` | `d35f5d8` |

- 제품의 BE gitlink: `4a4cc3d` → `f903dc2`.
- 이 우산 저장소 `projects/jeju-ai`: `ee68832` → `d35f5d8`.
- 이 우산 저장소 `ops/dev0`: `6b51920` → `8fd1842`.
- 우산 작업 브랜치에 앞 준비 기록과 이 후속 기록·두 gitlink를 커밋하고 기존 develop에 머지한다.
- 제품은 기존 origin/develop이 main의 조상이라 그 기준에서 develop을 만들고 현재 작업을 통합했다.
- dev0는 develop이 없어 알려진 origin/main `26414ba`에서 로컬 develop을 만들었다.
- 각 저장소의 기존 main·원격 브랜치·배포는 변경하지 않는다.

## 결정과 이유

사용자가 지정한 develop을 로컬 통합 대상으로 삼았다. 원격 push를 하지 않으므로
BE·dev0·제품의 아직 게시하지 않은 커밋을 상위 gitlink로 로컬에서 연결한다.
나중에 push할 때는 BE·dev0 → 제품 작업 공간 → 이 우산 저장소 순서로 게시해야 한다.
서브모듈을 원격에서 갱신할 기준인 `.gitmodules`의 기존 branch 설정은 바꾸지 않는다.

## 검증

- BE 커밋 훅: 비밀값·ESLint·서식·Markdown·Dockerfile 검사 통과.
- dev0 커밋 훅: 비밀값·YAML·Markdown·Kustomize 전체 렌더 스키마 46개 모두 통과.
- 제품 커밋 훅: 비밀값·Markdown 통과. 새 작업·history 상대 링크 0건 오류.
- 각 develop 머지 트리는 검증한 작업 브랜치의 트리와 일치하며 로컬 작업 폴더가 clean이다.
- 우산 커밋 훅을 실행하고 머지 후 두 gitlink와 실제 서브모듈 HEAD 일치를 확인한다.
- 실제 클러스터·계정·DB·Secret·PVC는 변경하지 않았다. 원격 push·PR·배포·CI 실행은 하지 않았다.

## 되돌리는 방법

각 저장소에서 이번 develop 머지 커밋을 revert하고 상위 gitlink를 이전 값으로 되돌린다.
main·원격·클러스터에는 이번 로컬 통합으로 인한 변경이 없다. worktree는 보존한다.
