# pm6f 사내 서비스 Pool 운영 계획 문서화

- 날짜: 2026-11-10
- 요청: 회사 Proxmox를 `ops/pm6f`로 관리하고 `internal-services` Pool을 따로 운영하도록 문서를 만든다. 순서대로 한 단계씩 진행한다.

## 배경

`ops/pm6f`는 비어 있으며 `.gitmodules`에 등록되어 있지 않았다.
대화 중 브라우저에서 확인한 `proxmox10` VE 8.4.0은 `ops/dev0`와 별도 환경이다.
관련 기존 기록은 `pm6f`, `pm.6f`, `internal-services` 검색에서 찾지 못했다.

## 변경 내용

- `ops/pm6f/README.md`: 없음 → 환경 식별·관리 범위·Proxmox 층과 Pool별 경로·저장소 준비 상태 설명
- `ops/pm6f/proxmox/pools/internal-services/README.md`: 없음 → 현황 조사부터 실제 서비스 편입까지 5단계 계획, 완료 조건·권한 경계·복구 원칙
- `README.md`: 준비 중인 `ops/pm6f` 진입 링크 추가

## 결정과 이유

Pool별 관리 경로는 `proxmox/pools/internal-services/`로 두어 최상위 층 규칙을 따른다.
독립 저장소 등록 전 준비 문서라 현재 우산 저장소에 기록한다.
관찰한 목록과 미확인 설정을 구분하고 첫 실행 단계는 읽기 전용 현황 조사로 정했다.

## 검증

기존 `.gitmodules`·디렉터리·운영 규칙을 확인했다.
변경 문서 4개의 Markdown 린트와 상대 링크 존재 검증을 통과했다.
Proxmox 설정·Pool·계정·토큰은 변경하지 않았으며 실제 구성과 API 권한 검증은 미실시다.

## 되돌리는 방법

이번에 추가한 문서 2개와 이 기록을 제거하고 루트 README의 준비 중 항목만 되돌린다.

## 남은 일

1단계 현황 조사, 별도 저장소·서브모듈 등록, 권한 설계와 시험 환경 검증.
