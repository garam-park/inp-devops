# 보류했던 pm6f 첫 커밋과 우산 안내를 기록

- 날짜: 2026-11-12
- 요청: 의미별 커밋의 범위 확인 질문에 사용자가 pm6f 내부 첫 커밋도 생성하도록 선택했다. 우산 서브모듈 등록은 별도로 남긴다.
- 이전 기록: [앞선 의미별 커밋 정리](01.semantic-commits.md)

## 배경

앞선 작업에서 총 12개 커밋을 만들고 pm6f 관련 항목은 사용자 응답을 기다리며 보존했다.
응답 이후 상태를 다시 확인했으며 pm6f는 여전히 `main` 브랜치의 첫 커밋·원격이 없는 독립 저장소였다.

## 변경 내용

- `ops/pm6f`: 커밋 없음 → `b66d4ee` (`docs: internal-services 운영 계획 초기 기록`).
  README·internal-services 도입 계획·초기화 기록·이번 작업 기록의 Markdown 4개를 첫 커밋에 포함했다.
- pm6f `README.md`: 첫 커밋 전 상태 → 운영 계획 문서 첫 커밋 완료 상태.
- 루트 `README.md`: 미커밋이던 pm6f 준비 안내 링크를 우산에서 추적한다.
- `docs/history/2026/11/10/01.pm6f-internal-services-plan.md`: 기존 계획 기록을 추적하고 이 후속 기록으로 이어지는 대체 안내를 추가했다.
- `docs/history/2026/11/12/01.semantic-commits.md`: 본문은 보존하고 pm6f 보류 항목을 처리한 이 기록으로 이어지는 안내만 추가했다.
- 이 기록과 우산 안내·기존 기록을 하나의 `docs(pm6f)` 커밋으로 묶는다. 앞선 12개에 2개를 더해 총 14개 커밋이다.

## 결정과 이유

pm6f 내부 변경은 운영 문서의 최초 기준을 기록하는 한 가지 의미여서 한 커밋으로 묶었다.
우산의 안내와 여러 저장소에 걸친 정리 결과는 우산에 별도로 기록했다.
임베디드 저장소를 우산의 gitlink로 추가하지 않고, 원격 연결·push·서브모듈 등록은 후속으로 남겼다.

## 검증

- pm6f 문서 4개는 우산의 Markdown 규칙을 임시 설정으로 적용해 통과했다. 우산의 서브모듈 경로 제외를 해제해 실제 파일을 검사했다.
- pm6f 스테이징 내용은 gitleaks 8.30.1에서 비밀값 검출이 없었고 `git diff --cached --check`를 통과했다.
- pm6f의 로컬 문서 링크 3개 대상이 존재함을 확인했다.
- 기존 internal-services 도입 계획의 SHA-256이 같고, 초기화 기록 본문은 대체 안내 외에 같음을 확인했다.
- pm6f 첫 커밋 이후 작업 트리가 깨끗하고 커밋 수가 1개임을 확인했다.
- 우산의 관련 문서 4개는 기존 Markdown 검사를 통과했다. 우산 커밋 검사는 기존 lefthook을 사용한다.
- Proxmox 접근·구성 변경·실제 서비스 검증은 수행하지 않았다.
- 내부 상세 기록: [pm6f 첫 커밋 기록](../../../../../ops/pm6f/docs/history/2026/11/12/01.initial-commit.md).

## 되돌리는 방법

우산 안내를 되돌려야 하면 이번 우산 커밋을 `git revert`한다.
pm6f의 문서 상태는 후속 커밋으로 수정하며 최초 커밋이나 `.git/`을 삭제하지 않는다.

## 남은 일

- pm6f 원격 연결·push와 우산 서브모듈 등록. 등록 전까지 우산의 `ops/pm6f/` 미추적 표시는 유지된다.
- 앞서 제외한 `projects/porthole/docs/deliverable/outs/정리.md` 인력 배치 메모의 보관 위치 결정.
- internal-services 1단계 현황 조사. 이번 작업은 로컬 커밋까지 수행했다.
