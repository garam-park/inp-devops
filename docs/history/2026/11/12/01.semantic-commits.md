- 요청: semantic-commits로 현재 작업 공간의 미커밋 변경을 의미별로 나누어 커밋한다.
- 이전 기록: [앞선 제주 의미별 커밋 정리](../../10/30/01.jeju-ai-semantic-commits.md)

## 배경

우산 `develop`의 `2031731`에서 README, 서브모듈 5개, 주간 작업·UI 배포 기록이 변경되어 있었다.
`projects/jeju-ai`의 `7f68e5f` 기준은 이미 스테이징되어 있었으며 실제 체크아웃은 `a584b37`이었다.
포트홀 내부에는 체크리스트·개발환경 조사·인증 문의 초안·임시 파일 제외 규칙이 섞여 있었다.
`ops/pm6f`는 원격과 첫 커밋이 없는 별도 Git 저장소였다.

## 결정과 이유

기존 한국어 Conventional Commits 형식을 따랐다. 포트홀의 작업 목록 한 헝크에 있던 T169·T171 행은
인덱스 패치로 분리했다. 제주 고정 값은 기존 스테이징 기준과 이후 UI 통합 기준을 두 단계로 기록했다.
포트홀 내부 커밋을 먼저 만들고 우산이 그 최종 커밋을 가리키도록 했다.

아래 변경은 보존하고 커밋에서 제외했다.

- `ops/pm6f/`의 문서 3개: 첫 커밋이 없는 독립 저장소의 포함 범위를 사용자에게 질문한 상태다.
- 루트 `README.md`의 pm6f 안내와 `docs/history/2026/11/10/01.pm6f-internal-services-plan.md`:
  pm6f 범위 결정에 맞춰 함께 처리할 항목이라 보류했다. 임베디드 Git 저장소를 우산에 gitlink로 추가하지 않았다.
- `projects/porthole/docs/deliverable/outs/정리.md`: 여러 프로젝트 인력 배치 메모여서 포트홀 문서 작업에서 제외했다.

## 검증

- 각 커밋은 저장소의 정상 lefthook을 사용했다. Markdown을 포함한 커밋의 markdownlint와 포트홀 커밋의 gitleaks가 통과했다.
- 사전 검사에서 포트홀 조사 wiki의 미정의 참조 오류 6개를 발견해 S1~S6 링크 정의와 구분 표기를 보완했다.
- 우산 122개, 포트홀 2,342개, pm6f 3개의 최초 추적·신규 항목을 SHA-256·파일 모드로 대조했다.
  포트홀 wiki의 링크 문법 수정 외에는 원본 내용이 같았다. 이번 작업 기록 2개는 별도로 추가했다.
- 변경한 서브모듈 5개의 최종 고정 값이 실제 체크아웃 HEAD와 같고 재귀 서브모듈 14개의 고정 값이 일치함을 확인했다.
- 커밋별 파일 통계, 남은 변경과 빈 스테이징 영역, `git diff --check`를 확인했다.
- 최초 포트홀 인덱스 초기화는 보호된 Git 메타데이터 쓰기 권한 때문에 실패했고 권한 확장 후 성공했다.
- 11월 10일 배포 기록은 dev0의 `3b870cb`까지 설명하지만 현재 dev0 체크아웃은 `76bfc9f`다.
  이번에는 원래 미커밋 상태의 고정 값만 기록했으며 원격 최신 조회나 체크아웃 변경은 하지 않았다.
- 서비스 빌드·통합 테스트·실제 배포 검증은 이번 커밋 정리에서 수행하지 않았다.

## 되돌리는 방법

필요한 의미 단위 커밋을 의존성 역순으로 `git revert`한다.
우산의 gitlink를 되돌린 뒤 서브모듈을 갱신할 경우, 먼저 남겨 둔 미추적 메모와 독립 저장소를 보존한다.
기존 커밋 이력이나 미커밋 파일을 삭제하지 않는다.

## 남은 일

- pm6f 내부 첫 커밋의 포함 범위 확인, 원격·서브모듈 등록 및 관련 우산 문서 처리.
- 제외한 인력 배치 메모의 보관 위치 결정, T169·T171 초안 내용 검토.
- 원격 push는 요청되지 않아 수행하지 않았다. 나중에 포트홀을 먼저 push한 뒤 우산을 push한다.
- dev0를 실제 최신 배포 기록의 기준까지 동기화할지는 별도 작업이다.
