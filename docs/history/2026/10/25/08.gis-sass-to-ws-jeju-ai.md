# gis-sass 폐기하고 projects/jeju-ai 를 ws-jeju-ai 서브모듈로 전환

- 날짜: 2026-10-25
- 요청: `projects/jeju-ai/repos/gis-sass` 이제 없애고 설계 개념만 옮긴다. `projects/jeju-ai` 로 옮기고 gis-sass 는 폐기 처분한다.

## 배경

ws 저장소가 `projects/jeju-ai` 아래에 코드 저장소 4개(gis-sass · jeju-subsidence-ai · jeju-ai-saas-be ·
jeju-ai-saas-fe)와 문서·작업 폴더를 직접 추적하고 있었다. 같은 날짜에 만들어진 porthole 와 goyang-uam 은
각각 자체 저장소(`innopam/ws-jeju-porthole` · `innopam/ws-goyang-uam`)로 분리되어 ws 에 서브모듈로 붙어 있다.
jeju-ai 도 같은 모양으로 정리하고, gis-sass 의 제품 코드는 폐기하되 업무·설계·문서와 커밋 이력은 살린다.

## 변경 내용

- `innopam/ws-jeju-ai` 저장소를 만들고 gis-sass 이력을 이어받았다
  - gis-sass `develop` (`85a96ba`) 637커밋이 `main` 의 조상이 됐다. 병합 커밋 `ee7acae` 로 2026-10-22 에 만든 기존 커밋 `4f6ab83` 을 이력에 연결했다.
  - `docs/20261021/t077-gov-measurements` 브랜치(`4514bff`)도 합쳤다. 로컬에만 있던 2커밋(주간보고 3주차 · WBS 스냅샷 · 한글 보고서 생성 스크립트)이 여기 있었다.
- ws 의 `projects/jeju-ai` 를 서브모듈로 전환했다
  - `.gitmodules`: `projects/jeju-ai` → `innopam/ws-jeju-ai`(main) 추가. `gis-sass` · `jeju-subsidence-ai` · `jeju-ai-saas-be` · `jeju-ai-saas-fe` 항목 제거
  - `projects/jeju-ai/apps/` 아래 코드 저장소 3개는 ws-jeju-ai 의 서브모듈이 됐다. 고정 커밋은 ws 가 가리키던 것과 같다(`jeju-ai-saas-be` `ddf5b573` · `jeju-ai-saas-fe` `d44c5b54` · `jeju-subsidence-ai` `24d48ce9`)
- ws 에서 옮겨간 자료를 지웠다
  - `.ai-workflow/work/tasks/` 의 `현장방문대비`(215) · `CSAP-인증준비`(153) · `jeju-ai-고도화`(2)
  - `.ai-workflow/docs/jeju-ai-auth-integration.md`, `projects/jeju-ai/docs/`(252), `projects/jeju-ai/tasks/`(5), `docs/design/jeju-subsidence-ai/`(23)
- ws 문서를 새 구조에 맞게 고쳤다
  - `README.md`: 서브모듈 목록 — gis-sass 4줄을 `projects/jeju-ai` 한 줄로. ops/gov-ncloud · projects/porthole · projects/goyang-uam 항목도 함께 정리했다
  - `AGENTS.md`: `projects/<제품>` 절을 "제품 작업 공간"으로 고치고, 코드 저장소는 그 저장소의 `.gitmodules` 로 관리한다고 적었다
  - `.ai-workflow/work/index.md`: 옮겨간 작업 폴더 링크를 `projects/jeju-ai/.ai-workspace/work/tasks/` 로, 작업목록 xlsx 링크를 `docs/sources/outsides/전달자료/` 로 고쳤다
  - `scripts/check-jeju-ai-parity.sh` · `scripts/jeju-ai-parity/expected/README.md`: 프로토타입 경로를 `apps/jeju-subsidence-ai` 로 고쳤다

## 결정과 이유

- 저장소 이름은 `ws-jeju-ai` 로 통일했다. porthole(`ws-jeju-porthole`) · goyang-uam(`ws-goyang-uam`) 과 같은 패턴이다.
- 이력 이관은 force push 없이 갔다. `git merge -s ours --allow-unrelated-histories` 로 두 이력을 잇고 fast-forward 로 push 했다.
- `deploy/charts/gis/` 는 ws-jeju-ai 에 남겼다. 제품 Helm chart 가 아직 없고 CSAP 증적 문서가 "gis-sass chart 구조 준용"을 근거로 인용한다.
- gis-sass 원격 저장소(`innopam/gis-sass`)는 지우지 않았다. 이력이 ws-jeju-ai 에도 있으므로 archive 처리는 사용자 판단으로 남겼다.

## 되돌린 것 — 서브모듈 전환으로 지워진 로컬 작업물

ws 의 `projects/jeju-ai` 디렉터리를 통째로 지우면서 git 이 추적하지 않던 로컬 파일이 함께 사라졌다.

| 대상 | 상태 | 조치 |
| --- | --- | --- |
| `jeju-ai-saas-be/data/` (스토리지 사본 495개 · 323M) | 사라짐 | dev0 스토리지에서 되찾았다. `kubectl -n dev port-forward svc/jeju-ai-saas-storage 18333:8333` → `npm --prefix api run storage -- pull data` |
| `jeju-ai-saas-be/.env` (S3 자격 증명 · VWORLD 키) | 사라짐 | dev0 의 Secret `jeju-ai-saas-s3` 에서 같은 값으로 다시 만들었다. `VWORLD_KEY` 는 빈 값(파이프라인 지오코딩은 비워도 된다) |
| `jeju-ai-saas-fe/.env` · `.env.local` (브이월드 키) | 사라짐 | `.env.example` 기반으로 다시 만들었다. `VITE_VWORLD_KEY` 는 **비었다** — GitHub 저장소 시크릿 `VWORLD_KEY` 는 값을 읽을 수 없어 되찾을 수 없다. vworld.kr 에서 발급받은 키를 사용자가 채워야 한다. 배포는 GitHub 시크릿을 쓰므로 배포에는 영향이 없다 |

`data/` 와 `.env` 는 둘 다 git 이 추적하지 않는 파일이라 이 커밋에 실리지 않는다. 이관 전 상태는
ws 저장소의 이전 커밋에서 `git show` 로 파일 목록만 볼 수 있고, 내용(특히 비밀값)은 남지 않는다.

## 검증

- ws-jeju-ai: `python3 scripts/check-doc-links.py` → 깨진 링크 2건. 둘 다 규칙 문서의 자리표시자다.
- `git submodule status` → `projects/jeju-ai` 가 `7cc2cc7` 로 고정돼 있다.
- 현장방문대비 `10 원천데이터/참고/`(1.0G, git 밖)는 `projects/jeju-ai/docs/sources/outsides/현장방문/참고/` 로 옮기고 ws-jeju-ai 의 `.gitignore` 에 추가했다.
- `bash scripts/check-jeju-ai-parity.sh` → 통과. 새 서브모듈 경로(`apps/jeju-subsidence-ai` · `apps/jeju-ai-saas-be`)에서 레이어 자료와 파이썬 도구가 이전과 같음을 확인했다.
- `git submodule status` → ws 의 `projects/jeju-ai` 는 `01d92a7`, 그 안의 앱 서브모듈 3개는 `ddf5b573` · `d44c5b54` · `24d48ce9` 로 고정돼 있다.

## 되돌리는 방법

- ws 의 `docs/history/` 에 이관 전 파일이 남아 있다. `git show <커밋>:<경로>` 로 되찾을 수 있다.
- 서브모듈 전환은 `git rm --cached projects/jeju-ai` 후 `.gitmodules` 에서 항목을 되돌리면 된다.
