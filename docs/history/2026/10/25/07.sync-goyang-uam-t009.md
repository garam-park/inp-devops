# 고양 UAM 저장소의 T009 완료 커밋을 우산 저장소 포인터에 반영

- 날짜: 2026-10-25
- 요청: T009(simulation2 실행 패널 여백 개선)의 지적 반영 · 구현 · PR 병합 · 기록 · 아카이브까지 진행한 뒤, 우산 저장소가 새 프로젝트 커밋을 가리키게 한다.
- 이전 기록: [T008 완료 커밋 포인터 반영](06.sync-goyang-uam-t008.md)

## 배경

고양 UAM 프로젝트 저장소에서 T009(simulation2 "운항 실행" 패널의 여백 개선)를 마쳤다. T008 로 패널을 5구획으로 나눴지만 구획 안쪽 여백은 그대로여서 "여백을 개선하자 좁아 보여" 라는 지적이 붙었다.

`ux-ui-review` 스킬로 NN/g 휴리스틱 기준 Before/After 리포트를 만들고, 리포트의 모든 수치를 브라우저 `getComputedStyle` + `getBoundingClientRect()` 로 실측했다. "좁다"는 감각이 아니라 4px · 6px · 90px 라는 숫자였다.

구현은 프론트 PR #241 로 `develop` 에 병합했고, 기록 · 아카이브 커밋을 만들어 `origin/develop` 에 push 했다(`0acd1ab8` → `3b9fd44`).

우산 저장소의 `projects/goyang-uam` gitlink 는 T008 완료 커밋 시점인 `0acd1ab8` 에 고정돼 있었다.

## 변경 내용

- `projects/goyang-uam`: `0acd1ab8` → `3b9fd44` 로 gitlink를 갱신한다.
- `docs/history/2026/10/25/07.sync-goyang-uam-t009.md`: 이 기록.
- 우산 저장소의 현재 사용자 변경인 `AGENTS.md`, `ops/dev0`, `ops/gov-ncloud`, 기존 감리 기록(10-24/01·03, 10-25/02·03·05)과 `ops/inbox/` 는 이 작업에 포함하지 않는다.

## 결정과 이유

- 프로젝트 저장소 커밋이 원격에 먼저 올라간 것을 확인한 뒤 우산 저장소 포인터를 갱신한다. clone 시 존재하지 않는 커밋을 가리키지 않게 하기 위해서다.
- 기록 파일 순번은 이 저장소 `docs/history/2026/10/25/` 폴더의 마지막 번호에 1을 더해 `07` 을 쓴다. 같은 날 폴더에 `01`~`06` 이 이미 있으므로 겹치지 않게 `07` 다. 프로젝트 저장소 쪽 기록은 별도 폴더라 그쪽 `docs/history/2026/10/25/04` 를 썼다.
- 앱 저장소 변경은 프론트 하나뿐이다(병합 커밋 `10aee8f`). 백엔드 저장소는 이 작업에서 건드리지 않았다.
