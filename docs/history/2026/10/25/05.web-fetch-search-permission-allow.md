# web_fetch · web_search 권한을 도구 단위 무조건 허용으로 바꾸고, 죽은 권한 규칙 정리

- 날짜: 2026-10-25
- 요청: permission 에서 web_fetch, web_search 가 승인되도록 바꾼다. → 이어서 "이것 하면서 의미 없어진 것들이 있을 것 같은데 그거 찾아서 정리해야해".

## 배경

MiniMax Code 의 전역 권한 파일 `/Users/garam/.minimax/permission.json` 에 web_fetch 규칙이 **도메인 단위로 하나씩** 쌓여 있었다(그때 122건). web_fetch 는 호출 URL 의 host 로 정규화해서 매칭하므로, 새 사이트를 읽을 때마다 "Allow once" 를 눌러야 규칙이 하나씩 추가됐다. web_search 는 대응되는 규칙이 아예 없어 매번 승인이 필요했다.

앱 번들(`app.asar`) 의 권한 매칭 로직을 확인한 결과, 저장 형식은 v2 (`{ tool_name, matcher }`) 이고 `matcher.kind` 는 `tool` · `command` · `path` 세 종류였다. `structuredMatcherMatches()` 에서 `matcher.kind === 'tool'` 이면 인자·URL 과 무관하게 즉시 true 를 돌려준다. 도메인 단위 `command` 규칙으로는 "이 도구 전체를 허용" 을 표현할 수 없다.

blanket allow 을 넣고 나니 기존 도메인 규칙들이 전부 죽은 규칙이 됐다. 그래서 죽은 규칙을 전수 조사해서 정리했다.

### 남긴 것 (의도적으로 지우지 않음)

- `bash` 의 `kind: "path"` 규칙 중 **명령 문자열**로 저장된 것 (`/bin/mv "$BASE/..."`, Chrome headless 실행 명령 등). 앱이 bash 명령을 경로처럼 저장한 형태인데, bash 체커가 `ruleContent` + `parseShellRule` 로 정확히 매칭해서 실제로 동작한다.
- `bash` 의 `kind: "path"` 규칙 중 `actions` 가 `read` / `write` 로 갈린 vworld 규칙 2건. 같은 패턴이지만 액션이 달라 중복이 아니다.
- OneDrive 제주 지반 변위 주간보고 경로, `~/.minimax/**`, `grep /Users/garam/**`, `session-hub/apps/api/**` 등 대상이 살아있는 규칙.

## 결정과 이유

- web_fetch 는 URL 의 host 기준으로 정규화되고, web_search 는 매칭 대상이 입력 전체 JSON 이라 패턴 규칙으로 잡을 수 없다. 두 도구 모두 `kind: "tool"` 이 유일하게 확실한 방법이다.
- 규칙 승자는 deny > ask > allow 이라 allow 규칙끼리는 순서가 무관하다. blanket 규칙 하나가 도메인 규칙 121개를 완전히 대체하므로 도메인 규칙은 더 이상 어떤 결과도 바꾸지 못한다.
- 삭제 방향은 항상 안전 쪽이다. allow 규칙을 지워서 나빠지는 일은 "프롬프트가 한 번 더 뜬다" 뿐이고, 권한이 더 넓어지지 않는다.
- `bash` `kind: "path"` 규칙을 "경로가 없으니 죽었다" 하고 지우면 안 된다. 앱이 bash 명령을 경로 형식으로 저장하는 것이라 경로 존재 여부로 판정하면 오판한다. 실제로는 명령 문자열 exact/prefix 매칭으로 동작한다.
- `web_search` 는 blanket allow 인에도 실패했다. 원인은 Matrix 툴 서버 전송 오류(`MATRIX_TOOL_REQUEST_FAILED`) 로, 권한 게이트 문제가 아니었다. 정리 전 백업(350 규칙)으로 되돌려 같은 오류가 재현되는 것을 확인해 원본 부재(unit test) 다짐.

## 검증

- `JSON.parse` 성공. `version: 2` 유지, allow 178건, `deny` · `ask` 0건, web 규칙은 `web_fetch` · `web_search` blanket 2건만 남음.
- 살아있는 경로 규칙 재검사 → 남은 `read`·`fs` 규칙의 대상 경로는 모두 존재.
- 라이브 확인
  - `web_fetch` · `https://example.com` (기존 allow 목록에 없던 도메인) → 승인 프롬프트 없이 정상 응답
  - `web_fetch` · `https://ko.wikipedia.org/wiki/최소코드` → 정상 응답
  - `web_search` → `MATRIX_TOOL_REQUEST_FAILED`. 정리 전 백업으로 되돌려도 동일 → **권칙 변경과 무관한 Matrix 툴 서버 쪽 문제**
- 앱 재시작 없이 반영됐다 (권칙 저장소가 호출 시 디스크에서 다시 읽는다).

## 되돌리는 방법

- 정리 전 상태: `cp /Users/garam/.minimax/permission.json.bak-2026-10-25 /Users/garam/.minimax/permission.json`
- blanket 규칙만 되돌리려면 `allow` 배열 맨 앞의 `web_fetch` / `web_search` + `kind: "tool"` 블록 2건을 삭제한다.
- deny · ask 는 건드리지 않았다.
