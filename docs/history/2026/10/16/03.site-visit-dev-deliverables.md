## 결정과 이유

- 21종만 작성했다. 23종에서 JSA-CM-CT-003(보안 요구사항 반영 결과)은 CSAP 과업(M011, WBS ID 33)에서 작성하므로 뺐고, JSA-PF-OP-002 는 기획 담당이라 옮겼다.
- 승인된 설계(ADR-2026-08-26.01 모듈러 모놀리식 + 선택적 분해)와 `dev0` 구성은 사실로 적었다. 프로토타입과의 결합은 "검토 중·미결정"으로 적고 결정이 필요한 항목을 각 문서의 열린 질문에 모았다.
- 근거가 없는 칸은 채우지 않고 "확인 필요"·"미정"·"미실시"로 표시했다. 작성자는 저장소 산출물의 관행대로 "개발팀", 승인자는 "확인 필요"로 했다.
- 통제항목 갭 분석은 증거가 있는 만큼만 판정했다. 증적이 없는 항목은 충족으로 적지 않아 충족 0건이 되었다(부분 17, 미충족 11, 해당없음 2). T078 은 KISA 최신판 확보 뒤에 시작하므로 이 표는 확정 판정이 아니다.
- QA 테스트케이스의 판정은 smoke 3종, CI 실행(`gh run view`), Task 검증 기록에서 인용했다. 다시 돌리지 않았다. 기록이 없거나 수행할 수 없는 항목은 Block 으로 두거나 판정을 비우고 사유를 적었다.
- Word·Excel 은 python-docx·openpyxl·LibreOffice 가 설치되어 있지 않고 새로 내려받지 않기 위해 파이썬 표준 라이브러리로 양식 XML 을 직접 채웠다. 양식의 표지·이력·머리글·서식은 그대로 두고 작성 안내와 예시 행만 지웠다.
- 비밀값·내부 IP·개인 연락처는 넣지 않았다. 외부 소스 인증키 암호화 키의 기본값도 적지 않았다.

## 검증

- Word 5종, Excel 2종: XML 구조 검사(`xmllint`)와 ISO/IEC 29500 스키마 검증을 통과했다. 자리표시자 `{{…}}`, 작성 안내, 예시 행(`예)`)이 남아 있지 않다. Excel 은 판정 목록의 검증 범위를 예시 행이 있던 2행부터 적용하도록 늘렸다(`E2:E200`, `I2:I200`).
- 서식은 macOS Quick Look 미리보기로 확인했다. 표지·제목·표·글머리표, 본문 시트의 줄바꿈과 열 너비, "확인 필요" 칸의 노란 강조가 보였다.
- 사실 대조: 설계서 9장, Task 기록, 주간보고, 해설서 정리본, CI 실행 기록을 다시 열어 수치와 판정을 맞췄다. 이 과정에서 두 가지를 바로잡았다. dev·prod values 의 NetworkPolicy 는 꺼져 있지 않고 켜져 있으며 대상 정보가 비어 렌더가 실패하도록 막혀 있다(T105 기록의 `false` 는 CI 렌더 검증용 인자였다). 인용한 완료 날짜도 T099·T101 은 2026-10-14 로 바로잡았다.
- Markdown: 저장소 루트 규칙으로 `mise exec -- markdownlint-cli2` 를 돌렸다. `30 관리 산출물/개발/*.md` 15개와 이 기록, 모두 16개 파일에서 0건이다. 처음에는 JSA-PF-ST-002 표의 브랜치 이름(`refactor/*` 등)이 강조 표시로 읽혀 MD037 3건이 나와, 이름을 백틱으로 감쌌다.
- 미검증: Microsoft Office·한컴 오피스로 직접 열어 보지 않았다. 테스트·배포·클러스터 동작은 재수행하지 않았다. 외부 소스 인증키 암호화 키가 chart 로 주입되지 않는다는 것은 저장소 점검 결과이고 클러스터에서 실측하지 않았다.
