# 서브모듈을 제외한 ws 자체 파일에 lefthook + markdownlint 커밋 훅 적용

- 날짜: 2026-10-16
- 요청: 서브모듈을 제외하고 이 저장소에 lint 를 적용한다. 도구는 lefthook.
- 이전 기록: [ws 우산 저장소 정리](../14/01.workspace-setup.md)

## 배경
- ws 가 추적하는 파일은 Markdown(AGENTS.md, README.md, docs/history/, .ai-workflow/)과 .gitignore, .gitmodules 뿐이다.
  그래서 린터는 markdownlint 하나로 충분하다.
- ops/dev0 에 이미 mise + lefthook + markdownlint-cli2 틀이 있다
  (dev0 기록 2026-10-10 `15.secret-scan-commit-hook.md`, `22.markdownlint-lint.md`). 같은 틀, 같은 버전을 쓴다.
- dev0 의 17개 규칙으로 현재 ws 파일 4개를 검사하면 0건이다. 기본 규칙 전체로는 26건인데 전부 줄 길이·빈 줄 같은
  모양 규칙이고, 그중 22건이 지난 기록(10/14)에 있다.

## 변경 내용
- `mise.toml`: 새로 만듦. `lefthook = "2.2.1"`, `node = "24"`, `"npm:markdownlint-cli2" = "0.23.3"`.
  task `lint` → `lint:md`(`git ls-files -z '*.md' | xargs -0 markdownlint-cli2`).
- `lefthook.yml`: 새로 만듦. pre-commit 에 markdownlint 하나(`glob: "*.md"`, `mise exec -- markdownlint-cli2 {staged_files}`).
- `.markdownlint-cli2.jsonc`: 새로 만듦. dev0 와 같은 17개 규칙(`default: false`). `ignores: ["ops/**", "projects/**"]`.
- `README.md`: 받기 절에 훅 설치 명령(`mise trust && mise install && mise exec -- lefthook install`) 추가.
- `.git/hooks/pre-commit`: `lefthook install` 이 생성(저장소에 올라가지 않는다).
- mise: ws 를 `mise trust` 했다. 도구 세 개는 dev0 작업 때 이미 설치돼 있어 새로 받은 것은 없다.
- 커밋하지 않았다. 사용자가 요청하면 커밋한다.

## 결정과 이유
- 서브모듈 제외는 세 겹이다.
  1. 훅의 `{staged_files}`: 우산 저장소의 인덱스에는 서브모듈이 커밋 포인터(`ops/dev0` 한 경로)로만 잡히고
     안의 파일은 올 수 없다(`git add ops/dev0/x.md` 는 git 이 거부한다). 포인터 경로는 `*.md` 에 안 걸린다.
  2. `mise run lint` 의 `git ls-files`: `--recurse-submodules` 를 주지 않으면 서브모듈 안으로 내려가지 않는다.
  3. `.markdownlint-cli2.jsonc` 의 `ignores`: 누가 `markdownlint-cli2 '**/*.md'` 처럼 글롭으로 돌리거나 편집기 확장이
     ws 를 루트로 돌릴 때를 막는다. 서브모듈 경로를 하나씩 적지 않고 `ops/**`, `projects/**` 로 했다.
     AGENTS.md 구조상 그 아래는 전부 서브모듈이라 서브모듈을 추가할 때 손댈 필요가 없다.
     대신 ops/ 나 projects/ 바로 아래에 우산 저장소 자체의 .md 를 두면 검사에서 빠진다.
- 린터는 markdownlint 하나만 넣었다. ws 가 추적하는 파일 중 다른 종류가 없다.
  yamllint(대상이 lefthook.yml 하나)와 gitleaks 는 넣지 않았다. 필요해지면 dev0 의 lefthook.yml 에서 그대로 가져온다.
- 규칙은 dev0 와 같은 17개다. 모양 규칙을 켜면 기존 기록이 걸리고 docs/history 양식(긴 줄, 제목 바로 아래 목록)과
  부딪힌다. 같은 사람이 두 저장소에 같은 양식으로 기록을 쓰므로 규칙을 맞춘다.
- 버전을 dev0 와 같게 고정했다. mise 는 상위 디렉터리의 mise.toml 도 읽어 합치므로, 버전이 다르면 서브모듈 안에서
  어느 쪽이 이기는지 신경 써야 한다. 같으면 문제가 없다.
- `node = "24"` 를 ws 에 넣은 영향: mise.toml 이 없는 projects/Jeju-subsidence-AI 안에서도 node 24, lefthook,
  markdownlint-cli2 가 PATH 에 보이게 된다. gis-sass 는 자기 mise.toml(node 24)이 있고 package.json engines 도
  `>=24 <25` 라 영향이 없다. dev0 도 자기 mise.toml 이 있다.

## 검증
- `mise run lint`: 0건(exit 0). `git ls-files '*.md'` 는 ws 파일 4개만 보여주고 서브모듈 경로는 없다.
- `mise exec -- lefthook run pre-commit` 을 임시 파일 `docs/_lefthook-test.md` 로 실행(지웠다):
  - 깨진 앵커 + 언어 없는 코드 블록 + 칸 수 다른 표: 차단(exit 1, MD051·MD040·MD056).
  - 긴 줄, 빈 줄 여러 개, 제목·목록 앞뒤 빈 줄 없음: 통과(exit 0).
  - .md 없이 mise.toml 만 스테이징: "no files for inspection" 으로 건너뜀(exit 0).
- 실제 `git commit` 에 언어 없는 코드 블록이 든 .md: 차단(exit 1), HEAD 변화 없음.
- `mise ls --current`: ws 루트, projects/gis-sass, ops/dev0, projects/Jeju-subsidence-AI 모두 node 24.20.0,
  lefthook 2.2.1, markdownlint-cli2 0.23.3. gis-sass 와 dev0 는 자기 mise.toml 에서 온 값이다.
- 미검증: VS Code markdownlint 확장이 ws 를 루트로 열었을 때 `ignores` 때문에 서브모듈 파일을 편집기에서 검사하지
  않을 수 있다. VS Code 소스 제어 화면에서 커밋할 때 훅이 도는지(셸 PATH 가 다를 수 있다).

## 되돌리는 방법
`mise exec -- lefthook uninstall` 로 `.git/hooks/pre-commit` 을 지우고 `mise.toml`, `lefthook.yml`,
`.markdownlint-cli2.jsonc` 를 삭제한다. README.md 는 커밋 전이라 `git checkout -- README.md` 로 돌아간다.

## 남은 일
- ws 커밋(사용자 요청 시).
- 새로 clone 하면 `mise trust && mise install && mise exec -- lefthook install` 을 한 번 실행해야 훅이 걸린다.
- ops/dev0 는 이 ws 안에서 새로 받은 서브모듈이라 훅이 안 걸려 있다(`.git/modules/ops/dev0/hooks/` 에 lefthook 훅 없음).
  dev0 에서 커밋하려면 `cd ops/dev0 && mise trust && mise install && mise exec -- lefthook install`.
- 로컬 훅은 `git commit --no-verify` 나 `LEFTHOOK=0` 으로 건너뛸 수 있다. 서버 쪽 검사(Actions)는 없다.
