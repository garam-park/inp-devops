# official-website 저장소를 projects/official-website 서브모듈로 추가

- 날짜: 2026-10-16
- 요청: `git@github.com:innopam/official-website.git` 를 서브모듈로 만든다.
- 이전 기록: [ws 우산 저장소 정리](../14/01.workspace-setup.md)

## 배경

- innopam/official-website 는 회사 홈페이지(Next.js) 저장소다. AGENTS.md 구조상 제품 저장소는 `projects/<제품>` 에 둔다.
- 원격 기본 브랜치는 `release` 다. `develop` 도 있지만 2026-06-01 이후 멈춰 있고, 그 뒤 26커밋(SEO PR #2 머지, MapLibre 전환,
  7월 소개 페이지 수정)은 모두 `release` 에 직접 올라갔다. `develop` 은 `release` 에 완전히 포함된다.

## 변경 내용

- `.gitmodules`: `[submodule "projects/official-website"]` 추가.
  `path = projects/official-website`, `url = git@github.com:innopam/official-website.git`, `branch = release`
- `projects/official-website`: 새 서브모듈. 고정 커밋 `5a94be7`(origin/release 최신, 2026-07-29)
- `README.md`: 서브모듈 목록에 `projects/official-website` 한 줄 추가
- 커밋하지 않았다. 인덱스에만 올라가 있다. 사용자가 요청하면 커밋한다.

## 결정과 이유

- 따라가는 브랜치를 `release` 로 했다. gis-sass 는 `develop` 을 따라가지만, 이 저장소는 `develop` 이 멈춰 있고 실제 작업이
  `release` 에 쌓이기 때문이다. `develop` 을 따라가면 `git submodule update --remote` 가 4개월 전 커밋으로 되돌린다.
- README 의 서브모듈 목록에 `projects/Jeju-subsidence-AI` 가 원래 빠져 있는데, 이 작업 범위 밖이라 손대지 않았다.

## 검증

- `git submodule status` 에 `5a94be7 projects/official-website (1.0.0-RC0-26-g5a94be7)` 로 보임. 태그 `1.0.0-RC0` 뒤 26커밋이라는 뜻이다.
- `git -C projects/official-website branch --show-current` → `release`
- `git config -f .gitmodules --get submodule.projects/official-website.branch` → `release`
- `mise exec -- markdownlint-cli2` 로 README.md 와 이 기록 검사 0건
- 미검증: 서브모듈 안에서 `npm ci`, `npm run build` 는 돌리지 않았다.

## 되돌리는 방법

- 커밋 전이다.
  `git rm --cached projects/official-website && rm -rf projects/official-website .git/modules/projects/official-website && git restore --staged --worktree .gitmodules README.md`
  뒤에 이 기록 파일을 지운다.

## 남은 일

- ws 커밋과 push
- README 에 `projects/Jeju-subsidence-AI` 줄 추가 여부
