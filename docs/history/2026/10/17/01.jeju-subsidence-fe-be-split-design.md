# Jeju-subsidence-AI 프로토타입 → 제품 전환(FE/BE 분리) 설계 문서 작성

- 날짜: 2026-10-17
- 요청: `projects/Jeju-subsidence-AI` 를 분석해 FE 와 BE 를 실제로 분리하고, 파일 쓰기는 S3 같은 오브젝트 스토리지로 동적으로 처리하는 제품 구조를 모듈화 관점에서 설계한다. C4 도식 포함.

## 배경

- 서브모듈 `projects/Jeju-subsidence-AI`(커밋 `129d660`)는 백엔드 없는 정적 SPA 다. Python 배치(`tools/build_data.py`)가 개발자 PC 에서 312MB 레이어 파일을 만들어 git 에 넣고,
  Vite+React 앱이 그대로 받는다. 권한·감사·사고 기록·조회 이력은 localStorage 에만 있고, 채점 공식은 Python 과 JS 두 벌이다.
- 읽는 중 발견한 사실: 저장소의 `risk_areas.geojson` 에는 코드가 더 이상 내보내지 않는 `conf`·`lowConf` 필드가 있고(`confG` 로 바뀜), `model.json` 의 격자 수(104,973)와 README 의 수(54,330)가 다르다.
  `build_risk_grid()` 는 주석("C등급 이상")과 조건(`D`·`E` 건너뜀)이 어긋난다(추정: 등급 문자 방향 반전 뒤 미수정). 설계 문서 01 §7-1 에 적었다.
- 작업 전 `/align-intent` 로 세 가지를 확정했다. (1) 스토리지로 옮길 파일 쓰기 범위 = 전부(산출 데이터 + 사용자 업로드 + 내보내기 결과), (2) BE = Node.js/TypeScript, (3) 문서 위치 = ws 루트 `docs/` 아래 새 폴더.
- `grep -ril "subsidence" docs/history` 결과 관련 설계 기록은 없었다(10/16 두 기록은 서브모듈 추가·린트 언급뿐).

## 결정과 이유

- **문서를 서브모듈이 아니라 ws `docs/design/` 에 둔다.** 사용자 결정. 서브모듈 쪽에는 아직 제품 구조가 없고, 설계가 dev0 배포와 gis-sass 관례를 함께 참조하므로 우산 저장소가 맞다.
- **C4 는 Mermaid `flowchart` + C4 표기 관례로 그렸다.** dev0 `docs/architecture/k8s-c4.md` 가 같은 이유(C4 전용 문법은 선 라벨이 겹침)로 정한 표기를 따랐다. 시험 삼아 `C4Container` 로 렌더해 보니 실제로 라벨이 경계와 겹쳤다.
- **Python 파이프라인은 별도 워커 컨테이너로 유지를 추천**, TS 포팅은 열린 결정으로 남겼다. shapely·pyproj·GeoPackage 파싱 1,900줄을 옮기면 수치 동일성 검증까지 비용이 큰데 얻는 것은 언어 하나 줄이기다.
  api 와 pipeline 의 접점은 DB `jobs` 표와 스토리지 번들뿐으로 설계해 어느 쪽 언어도 서로를 모르게 했다.
- **기간별 CSI 는 사전 계산(후보 × 기간 조합 28개) 추천.** `scoring.js` 와 JS 쪽 등급 경계 복제가 사라지고 보고서가 재현된다. 재채점 안은 대안으로 적었다.
- **브라우저는 스토리지와 직접 통신하지 않는다**(업로드·다운로드 모두 api 스트리밍 중계). 망분리·CSAP 환경에서 노출 엔드포인트를 줄이기 위해서다. presigned URL 은 병목 확인 뒤 선택지로.
- 작업 큐는 Redis 없이 **DB 표 폴링**(`FOR UPDATE SKIP LOCKED`). 빌드는 연 몇 번, 내보내기는 수 초라 큐 인프라가 필요 없다.
- 열린 결정 9개(직전 대비 기준, 사전 계산 vs 재채점, PostGIS vs MVT, 인증·역할 출처, 운영 스토리지, 지오코딩 외부 호출, Python 유지, 모노레포, 보존 기간)는 추천만 달고 사용자에게 넘겼다.

## 검증

- `mise exec -- markdownlint-cli2 "docs/design/jeju-subsidence-ai/*.md"`: 처음 3건(MD001 제목 단계 1건, MD056 표 칸 수 2건 — 셀 안의 `|` 문자) → 수정 뒤 **0건**.
- Mermaid 블록 12개를 `@mermaid-js/mermaid-cli@11.4.2` + 설치된 Chrome 으로 PNG 렌더, 12장 모두 생성. Container·api Component·Deployment·자료 갱신 시퀀스·현황 그림을 눈으로 확인했다.
  현황 그림의 선 라벨 "쓰기 (약 10분 추정)" 은 근거 없는 수치라 "쓰기" 로 고치고 다시 그렸다. Container 그림은 api→DB 와 pipeline→스토리지 선 라벨이 일부 겹치지만 읽을 수 있어 두었다.
- 문서 안 수치(파일 크기·건수·줄 수)는 `du`, `wc -l`, 산출 데이터 샘플에서 직접 읽은 값이다. 파이프라인 실행 시간·메모리, 원본 크기, 동시 사용자 수는 **미측정**이며 문서 05 §5 에 그렇게 적었다.
- 미검증: 설계가 전제한 dev0 `dev` 네임스페이스 쿼터(3 CPU·5Gi) 안에 pipeline 빌드가 들어가는지. 운영 환경의 PostGIS·S3 호환 스토리지·SSO 프로토콜.
