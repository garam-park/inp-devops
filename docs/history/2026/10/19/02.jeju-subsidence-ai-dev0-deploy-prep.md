# Jeju-subsidence-AI 를 dev0 에 임시 배포할 준비 (이미지 빌드 파일 + dev 매니페스트)

- 날짜: 2026-10-19
- 요청: 프로토타입 Jeju-subsidence-AI 를 dev0 에 임시로 배포하는 방법을 확인하고 준비한다.
- 이전 기록: [../17/01.jeju-subsidence-fe-be-split-design.md](../17/01.jeju-subsidence-fe-be-split-design.md)

## 배경

저장소 두 개가 함께 바뀐다. 제품 저장소에는 이미지를 만드는 파일이 없었고, dev0 에는 띄울 설정이 없었다.
배포는 AGENTS.md 원칙에 따라 dev0 이 게시된 이미지(GHCR SHA 태그)를 가리킨다.

## 변경 내용

- `projects/Jeju-subsidence-AI` (develop, 커밋 전): `Dockerfile`, `nginx.conf`, `.dockerignore` 추가
  - 빌드 단계는 `node:24-alpine` 에서 `npm ci` 와 `npm run build` 를 하고, json·geojson·js·css·html·svg 를 미리 `gzip -9 -k` 한다.
  - 실행 단계는 `nginxinc/nginx-unprivileged:1.30-alpine`(8080)이다. `gzip_static`, `/assets/` immutable, `/data/` no-cache + `application/geo+json`, SPA fallback 을 둔다.
  - 빌드 인자 `VITE_VWORLD_KEY`. `.dockerignore` 가 `.env*` 를 빼서 env 파일이 이미지에 들어가지 않는다.
- `ops/dev0` (main, 커밋 전): `apps/jeju-subsidence-ai/` 추가, `docs/operations/access.md` 한 줄 추가. 자세한 것은 dev0 의 `docs/history/2026/10/19/01.jeju-subsidence-ai-dev-manifests.md`

## 결정과 이유

- 결정 4개(사용자): 네임스페이스 `dev`, 주소 `jeju-ai.dev.innopam.net`, 접근 제한은 NPM IP 화이트리스트(사용자가 설정), 브이월드 키를 넣는다.
- 요청마다 압축하지 않고 `.gz` 를 미리 만들었다. 데이터가 312MB 이고 가장 큰 파일이 26MB 다. 대신 이미지가 약 560MB 로 커졌다.

## 검증

로컬 arm64 빌드와 읽기 전용 컨테이너 응답을 확인했다(dev0 기록에 자세히). amd64 빌드, push, 클러스터 배포는 미검증이다.

## 되돌리는 방법

두 저장소 모두 커밋 전이다. 새 파일을 지우면 된다.

## 남은 일

- 작업 중 `app/.env.example` 에 실제 브이월드 키가 들어간 커밋 전 수정이 있었다. 사용자가 되돌리고 키를 `app/.env`(gitignore 대상)로 옮겼다. 빌드도 이 `app/.env` 에서 읽는다(사용자 결정, dev0 README). 브라우저에 드러나는 키라 `~/ops/inp/local/` 에 따로 두지 않았다. 키가 git 기록에 올라간 적은 없다(`git log --all -S` 0건).
- 커밋·push 와 이미지 빌드·push, apply 는 dev0 기록의 남은 일을 따른다. 끝나면 ws 의 서브모듈 고정 커밋을 올린다.
