## 결정과 이유

혼합 파일은 인덱스 헝크로 분리했다. BE OpenAPI는 저장소 규칙에 따라 해당 API 변경과 함께
커밋했고 FE 생성 타입은 별도 커밋으로 분리했다. 날짜 회귀 검사가 서버 감사 화면을 사용하므로
FE 서버 연결을 날짜 수정보다 먼저 커밋했다. 기존 제품 코드는 커밋 분리를 위해 수정하지 않았다.

T135를 먼저 등록하고 관련 T134·ADR 링크는 대상 문서가 도입되는 후속 커밋에 연결해
각 프로젝트 문서 커밋에서 깨진 링크가 생기지 않게 했다.

## 검증

- BE 독립 중간 상태: API 184 → 192 → 208개, Python 22 → 22 → 27개 통과.
  각 상태의 타입·OpenAPI 일치·훅 검사 통과.
- FE 독립 중간 상태: 단위 255 → 268 → 283 → 316개 통과, 타입 검사 통과.
  서버 연결·최종 상태의 빌드와 최종 커버리지 게이트 통과.
- 날짜 회귀 45개는 UTC·미국 시간대에서 각각 통과했다.
- 서버 연결 커밋만 분리한 Linux 브라우저 검사: 75개 통과, nginx 전용 14개 제외.
- 각 프로젝트 문서 중간 상태의 링크 오류 0, 최종 프로젝트 전체 린트 통과.
- 커밋 전후 제주 프로젝트·FE·BE의 전체 파일 SHA-256·파일 모드 차이 0.
- 정상 커밋 훅을 사용했으며 기존 이력 수정·push는 하지 않았다.
- 상세 기능 검증은 [제주 프로젝트 결과 기록](../../../../../projects/jeju-ai/docs/history/2026/10/30/04.browser-findings-fixes.md)에 있다.

## 되돌리는 방법

상위 고정 커밋을 별도 revert하면 이전 제주 프로젝트 고정 값으로 돌아간다.
개별 기능은 해당 FE·BE·프로젝트 커밋을 의존성 역순으로 검토해 별도 revert한다.
기존 커밋의 이력을 다시 쓰거나 미커밋 변경을 삭제하지 않는다.

## 남은 일

push·PR·배포는 요청하지 않아 수행하지 않았다. 나중에 push할 때는 BE·FE → 제주 프로젝트 →
상위 ws 순서를 지켜 아직 원격에 없는 커밋을 먼저 가리키지 않게 한다.
GeoTIFF는 이 저장소 T135가 아닌 제주 프로젝트 T135의 후속 작업이다.
