# 전체 서브모듈 초기화와 원격 브랜치 동기화

- 날짜: 2026-10-30
- 요청: 서브모듈들을 동기화한다. 공식 홈페이지는 기존 고정 커밋을 유지하기로 선택했다.

## 배경

작업 시작 시 최상위 서브모듈 6개는 모두 미초기화 상태였고 우산 저장소에 로컬 변경은 없었다.

## 변경 내용

- 최상위 서브모듈 6개와 내부 서브모듈 7개를 초기화했다. URL은 `.gitmodules` 기준으로 동기화했다.
- `projects/porthole`: `52642edb4e4d1772d071d590d61abea56fbb1e7a` → `461d83defe3cfcc1bc057a95d1671711fb4c3694` (`origin/main`).
- `ops/dev0`, `ops/gov-ncloud`, `projects/goyang-uam`, `projects/jeju-ai`: 설정된 원격 브랜치 최신 커밋과 기존 고정 커밋이 같아 유지했다.
- `projects/inp/official-website`: 기존 `220350b0fd4ac308e78650073a9f28d21d399c72` 유지. `.gitmodules`의 `release` 설정도 유지했다.
- 내부 서브모듈은 각 제품 저장소가 고정한 커밋으로 체크아웃했다. 스테이징, 커밋, push는 하지 않았다.

## 결정과 이유

- 원격에 홈페이지 `release` 브랜치가 없어 일괄 원격 갱신이 중단됐다. 사용자 선택에 따라 기존 고정 커밋으로 초기화했다.
- 최초 중단으로 비어 있던 홈페이지·제주·포트홀 작업 디렉터리는 강제 체크아웃으로 복구했다. 작업 전 모두 비어 있어 사용자 변경은 없었다.
- 재귀 초기화가 포트홀을 우산 저장소의 기존 고정 커밋으로 되돌려, 완료 후 이미 받은 `origin/main` 최신 커밋으로 다시 맞췄다.
- 최초 샌드박스 실행은 `.git/config` 쓰기가 거부되어 실패했고, 승인된 권한 확장 실행으로 진행했다.

## 검증

- 최상위 5개 HEAD와 설정된 원격 브랜치의 일치를 확인했다. 홈페이지는 기존 고정 커밋과 일치했다.
- `git submodule status --recursive`: 총 13개 초기화 완료. 포트홀만 우산 저장소 고정 커밋과 차이가 있다.
- 전체 서브모듈의 작업 디렉터리가 깨끗한 것을 확인했다.
- `git diff --check` 통과. 실행 서비스나 제품 기능 테스트는 수행하지 않았다.

## 되돌리는 방법

- `git submodule update --init --recursive`로 우산 저장소가 고정한 커밋으로 복원한다.
- 새로 추가한 이 기록을 제거하면 우산 저장소의 추적 파일 내용은 작업 전과 같아진다. 초기화한 로컬 복제본과 Git 설정은 남는다.

## 남은 일

- 포트홀 고정 커밋 변경과 이 기록은 미커밋 상태다.
- 홈페이지를 향후 원격 최신으로 갱신하려면 추적 브랜치를 별도로 결정해야 한다.
