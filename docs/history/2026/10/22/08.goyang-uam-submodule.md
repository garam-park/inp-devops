# projects/goyang-uam 을 서브모듈로 등록: innopam/ws-goyang-uam(기존 클론)

- 날짜: 2026-10-22
- 요청: ws 안의 일반 폴더 `projects/goyang-uam` 을 서브모듈로 만든다.
- 이전 기록: [06.porthole-submodule.md](06.porthole-submodule.md) (같은 날 porthole 을 서브모듈로 전환한 기록, 방식이 비슷하다)

## 배경

`projects/goyang-uam` 은 ws 에 커밋되지 않은 폴더였다(`git status` 에서 `??`). porthole 과 달리 이미 완성된 git 클론이었다.

- 원격: `origin` = `git@github.com:innopam/ws-goyang-uam.git`. GitHub 기본 브랜치 `develop`, private.
- 체크아웃 브랜치: `chore/split-gygo-database`, HEAD `b38f9248`. 원격의 같은 브랜치와 일치하고(`git ls-remote` 로 확인) `origin/develop`(`a952235`) 바로 위 한 커밋이다. 작업 트리는 깨끗했다.
- `.git` 은 디렉터리(647M). 안에 중첩 서브모듈 3개(`repos/gygo-database`, `repos/gygo-svc3d-back-uamms`, `repos/gygo-svc3d-front-uamms`)와 `.gitmodules` 매핑이 없는 gitlink 1개(`tools/gygo-svc3d-front-microsample`)가 있다. gygo-database 만 `.git` 파일(absorbed)이고 나머지는 `.git` 디렉터리다.
- 예전 경로 `/Users/garam/ws/git-repos/corp/inp/main/ws-goyang-uam/.claude/worktrees/*` 를 가리키는 worktree 17개가 등록돼 있는데 그 경로는 없다(`git worktree list` 에서 전부 `prunable`).

## 변경 내용

- `.gitmodules`: 항목 추가
  - `[submodule "projects/goyang-uam"]`, `path = projects/goyang-uam`, `url = git@github.com:innopam/ws-goyang-uam.git`, `branch = develop`
- ws 인덱스: `projects/goyang-uam` 을 gitlink(`b38f9248`)로 올렸다(`git submodule add -b develop git@github.com:innopam/ws-goyang-uam.git projects/goyang-uam`, 기존 저장소를 그대로 인덱스에 추가). `.gitmodules` 와 함께 스테이지만 했고 ws 커밋은 하지 않았다.
- ws `.git/config`: `submodule.projects/goyang-uam.url` 이 같은 URL 로 들어갔다(`submodule add` 가 자동으로 넣음).
- `projects/goyang-uam` 안은 아무것도 바꾸지 않았다. `.git` 디렉터리, 브랜치, worktree 등록 모두 그대로다.

## 결정과 이유

- `branch = develop`: GitHub 기본 브랜치이고 다른 서브모듈도 기본 브랜치를 추적한다. `git submodule update --remote` 는 develop 끝을 따라간다.
- 고정 커밋 `b38f9248`: 지금 체크아웃된 HEAD 그대로. 원격에 push 된 커밋이라 ws 를 push 해도 없는 커밋을 가리키지 않는다. `develop` 끝(`a952235`)으로 바꾸지 않은 것은 작업 중인 브랜치를 건드리지 않기 위해서다.
- `git submodule absorbgitdirs` 는 하지 않았다(porthole 과 다른 점). 이 명령은 중첩 서브모듈까지 재귀로 옮기는데, `.git` 디렉터리인 중첩 저장소 2개와 매핑 없는 gitlink 1개가 있어 중간에 실패하거나 중첩 저장소 구조까지 바뀔 수 있다. 또 stale worktree 가 등록된 상태에서는 relocate 자체를 거부한다. `.git` 이 디렉터리여도 서브모듈 동작에는 문제가 없다.
- stale worktree 17개는 요청 범위 밖이라 `git worktree prune` 하지 않았다.
- URL 은 SSH 로 적었다. 다른 서브모듈이 모두 `git@github.com:` 형식이다.

## 되돌리는 방법

- ws 커밋 전: `git rm --cached projects/goyang-uam`, `.gitmodules` 의 `projects/goyang-uam` 항목 삭제 후 `git add .gitmodules`, `git config --remove-section submodule.projects/goyang-uam`. 폴더 안은 바뀐 것이 없어 그대로 두면 된다.
