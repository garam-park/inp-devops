# goyang-uam 을 porthole 구조로 바꾸는 계획 작성 (실행 전)

- 날짜: 2026-10-22
- 요청: `projects/goyang-uam` 을 `projects/porthole` 과 비슷한 구조로 바꾸고 싶다. 전체 이동이 목표이지만, 먼저 ws 루트 `.ai-workflow/work/tasks` 에 계획을 세운다.
- 이전 기록: [08.goyang-uam-submodule.md](08.goyang-uam-submodule.md), [06.porthole-submodule.md](06.porthole-submodule.md)

## 배경

porthole(innopam/ws-jeju-porthole)은 오늘 폴더 역할과 규칙을 정했다(`docs/sources · wiki · deliverable · history · ADRs`, `.ai-workspace/docs · work · .worktrees`, `apps/`, 커밋 검사). goyang-uam(innopam/ws-goyang-uam)은 같은 성격의 작업 공간이지만 구조가 다르다(`repos/`, `docs/decisions`, `.ai-workflow/`, `tasks/`, 문서 폴더 18개, 코드 서브모듈 3개, LFS 322개, svn checkout 27 GB).

의도 정렬(`/align-intent`)에서 정한 것: (1) 뼈대만 추가가 아니라 기존 내용을 porthole 폴더로 **전체 이동**, (2) 실행 전에 계획 문서부터, (3) 계획 위치는 ws 루트(goyang-uam 안의 `.ai-workflow/` 는 이번에 이름이 바뀌는 대상이고, 작업이 goyang-uam 과 ws 두 저장소에 걸치기 때문).

## 변경 내용

- `.ai-workflow/work/tasks/goyang-uam-구조변경/index.md`: 새로 만듦. 내용은 지금 모습과 목표 모습, 폴더별 매핑표(코드 · 문서 · AI 작업 문서 · 도구 설정 · 루트 파일), 결정 13개(D1–D13, 추천 포함), 4단계 실행 순서, 깨지는 참조 집계, 검증, 되돌리기, 위험.
- `.ai-workflow/work/index.md`: "다른 작업" 목록에 goyang-uam 구조변경 항목 추가, "그 둘" → "그 셋".
- `projects/goyang-uam`, `projects/porthole`: **읽기만 했다.** 파일 · 브랜치 · 서브모듈 모두 그대로.

## 결정과 이유

- 계획의 뼈대: porthole 폴더 역할을 가져오되 porthole 에 없는 `docs/develop/`(개발 문서), `deploy/` · `tools/` · `local-backend.sh`(개발 환경), `README.md`(사람용 색인)는 goyang 확장으로 인정하는 안을 추천(D2 · D3 · D9). wiki 는 "원자료에서 뽑은 정보" 라 우리가 쓴 명세 · 가이드와 성격이 다르다.
- 산출물의 `drafts/` · `results/` 분류는 후속으로 뺌(D7). 160여 개 바이너리를 파일마다 사람이 봐야 해서 이동 PR 과 섞을 수 없다.
- 과거 ADR 45개는 본문을 고치지 않고 경로만 옮김(D6). 양쪽 규칙 모두 "채택한 ADR 은 안 고친다".
- 작업 브랜치는 PR #161 을 먼저 머지한 뒤 develop 에서 분기하는 안을 추천(D1).
- D1–D13 을 같은 날 사용자와 하나씩 정했다. 결과는 계획 문서 4절에 ✅ 로 표시. 추천과 다르게 정한 것: D2(개발 문서를 `docs/develop/` 확장이 아니라 wiki 분류를 늘려서 담음), D5(microsample gitlink 를 지우지 않고 GitHub `innopam/gygo-svc3d-front-microsample` 을 새로 만들어 등록), D6(ADR 은 MADR 유지). D12 는 조사 결과 `.env.tsk.example` 을 읽는 곳이 없어 삭제로.
- D2 에 따라 계획의 목표 트리 · 매핑표 · 참조 집계를 wiki 분류(api · guides · specs · research · tests 추가) 기준으로 고쳤다.

## 검증

- 매핑표의 파일 수는 `git ls-files` 로, 참조 횟수는 `git ls-files '*.md' '*.sh' '*.json' '*.yml' '*.py' '*.cjs' | xargs grep` 으로 셌다(`repos/` 129 파일 2,530 곳 등). 서브모듈 안은 제외.
- 확인한 사실: `docs/svn/` 은 `.gitignore` 로 git 밖(27 GB 는 디스크만), `.gitattributes` 가 `docs/**` 를 LFS 로 관리(322개), `tools/gygo-svc3d-front-microsample` 은 `.gitmodules` 매핑 없는 gitlink(원격은 사내 GitLab), `.ai-workflow/.workspace/배포` 는 별도 git 저장소, 열린 PR 16개 중 사람 것은 #161 · #140 · #128 · #80, README 와 `.claude/claude.md` 에 이미 깨진 링크 4개.
- 계획 문서의 명령은 아직 실행하지 않았다. `git mv` 로 서브모듈(absorbed 1 + `.git` 디렉터리 2)을 옮기는 동작은 실행 단계에서 확인해야 한다.
