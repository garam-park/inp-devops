## 결정과 이유

- ws push: 처음 고를 때 보여 준 범위보다 커서(새 원격 브랜치, 커밋 80개) 다시 물었다. '그대로 push'(사용자 결정). 다른 선택지는 '로컬에만 두기'였다.
- dev0 스토리지: 1.5Gi(사용자 결정). 로컬 시험에서 1Gi 의 최대 사용량이 914–929MiB 로 여유가 거의 없었다. 다른 선택지와 고르지 않은 이유는 다음과 같았다.
  - 1Gi: 여유가 거의 없다.
  - dev0 실측 먼저: dev 사용자에게 영향을 준다.
  - 그대로 두기: dev 는 동시 사용이 드물다는 이유였다.
- `noUncheckedIndexedAccess`: 별도 이슈로 남긴다(사용자 결정). 다른 선택지는 '지금 켜기'(126건 수정, FE #15 와 같은 파일을 또 건드림)와 '켜지 않음'이었다.
- 인계 문서 위치: 기존 작업 폴더 관례(`.ai-workflow/work/tasks/<작업명>/index.md`)를 따랐다. 결정은 길어서 `결정.md` 로 나눴다.
- 결정 문서의 추천은 근거 문서의 추천을 옮긴 것이다. 사용자가 고른 것과 섞이지 않게 '결정됨'과 '결정 대기'를 나눴다.
- 세션 임시 폴더는 세션이 끝나면 사라진다. 그 안의 내용에 기대지 않게 필요한 사실을 문서로 옮겼다. SDK 우회 GET 시제품 코드는 옮기지 않았고, 사라진다고 적었다.
- 커밋은 경로를 지정해 만들었다(`git commit -- <경로>`). 다른 세션의 porthole 서브모듈 추가(`.gitmodules`, `projects/porthole`)가 stage 돼 있어서, 그대로 커밋하면 섞인다. porthole 의 stage 와 기록 06 은 건드리지 않았다.
