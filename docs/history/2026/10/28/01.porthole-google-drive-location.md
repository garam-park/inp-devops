# 포트홀 저장소에 원자료 위치 규칙을 넣고 고정 커밋을 갱신했다

- 날짜: 2026-10-28
- 요청: "`projects/jeju-ai` 에서 google drive 위치 찾는 걸 `projects/porthole` 에도 적용하고 싶어"
- 이전 기록: [26/05.sync-goyang-uam-t010-table-name-comments.md](../26/05.sync-goyang-uam-t010-table-name-comments.md)

## 배경

`projects/jeju-ai` 는 원자료 위치를 저장소에 고정하지 않고 `.ai-workspace/docs/google-drive.md` + `.ai-workspace/.env` 로 찾는 규칙을 쓰고 있다. `projects/porthole` 에도 같은 방식을 넣으라는 요청이었다.

포트홀 원자료는 클라우드 동기화 폴더 두 곳에 나뉘어 있다. 산출물 작업본은 구글 드라이브 `내 드라이브/02 Projects/포트홀/2026 포트홀`(`00 todo` · `10 doing` · `20 done` · `draft` · `99 사업관리`, 파일 수정 10-27 – 10-28), 계약 원본과 무한 공유 자료는 원드라이브 이노팸 계정 `01.Projects/제주 포트홀/[사업] 포트홀`(10-21 에서 멈춤)이다. 포트홀 저장소 문서에는 이 두 곳을 구분 없이 "OneDrive" 라고 적힌 곳이 많아 위치가 헷갈렸다.

규칙 문서와 결정은 포트홀 저장소 안에서 끝나는 일이라 그 저장소에 남겼다. 이 저장소에는 고정 커밋만 올린다.

## 변경 내용

- `projects/porthole`: gitlink `db797b0` → `de145d1`. 서브모듈 커밋은 "규칙(google-drive): 원자료 위치 찾는 규칙 추가 — 구글 드라이브 · 원드라이브, ADR 0014, 기록 10-28/01" 이다. 원격 `develop` 에 올렸다(`4163f1b..de145d1`).
- `projects/porthole/.ai-workspace/docs/google-drive.md` (신규): 두 드라이브의 역할 · 경로 모양, 찾는 순서(`.env` → macOS 마운트 → 사용자에게 확인), 읽고 쓰는 규칙.
- `projects/porthole/.ai-workspace/.env.example` (신규, 커밋 대상): `PORTHOLE_GOOGLE_DRIVE_ROOT` · `PORTHOLE_ONEDRIVE_ROOT` 템플릿. `.ai-workspace/.env` (장치별 경로, 실제 값)은 git 제외.
- `projects/porthole/.gitignore`: `!.env.example` 추가. `projects/porthole/.gitleaks.toml`: `.env.example` 허용 목록 추가.
- `projects/porthole/AGENTS.md`: `## 외부 위치` 항목, 규칙 문서 표 행 추가.
- `projects/porthole/docs/ADRs/0014-source-location-not-fixed.md` (신규) · `docs/ADRs/index.md`.
- `projects/porthole/docs/history/2026/10/28/01.google-drive-location.md` (신규).
- `projects/porthole/.ai-workspace/work/.archived-tasks/T003-google-drive-location/` (신규) · `.archived-tasks/index.md`: 작업 메모.

## 결정과 이유

- 규칙 문서 · ADR · 기록은 포트홀 저장소에 남겼다. 포트홀 저장소만 받은 사람도 따라갈 수 있어야 하기 때문이다.
- 환경 변수 이름에 `PORTHOLE_` 접두어를 붙였다. `JSAI_` 와 같은 방식이고 두 저장소가 한 워크스페이스에 같이 있을 때 헷갈리지 않는다.
- `.gitignore` 와 `.gitleaks.toml` 둘 다 손봤다. gitleaks `secret-file` 규칙이 `.env.example` 경로도 막아서 허용 목록이 필요했다. 임시 저장소로 확인했다(허용 목록 없으면 1건, 있으면 0건).
- 포트홀 저장소의 기존 "OneDrive `2026 포트홀` " 표기는 고치지 않았다. 같은 파일들에 다른 세션의 미커밋 변경이 있어 건드리면 그 변경까지 같이 커밋된다. 어느 드라이브인지 규칙 문서에 적어 뒀다.

## 검증

- 포트홀 저장소 `mise run lint` 통과(gitleaks 32 커밋 스캔 · 누출 0건, markdownlint-cli2). 커밋 훅도 통과했다.
- `git check-ignore` 로 `.ai-workspace/.env` 는 무시되고 `.ai-workspace/.env.example` 는 무시되지 않음을 확인했다.
- 두 클라우드 경로가 실제로 존재하고 읽힌다. 구글 드라이브 `2026 포트홀/10 doing` 7개 항목, 원드라이브 `20. 설계/10 Doing` 1개 항목, 원드라이브 `04. 개발/00. 무한 공유 자료/` 4개 폴더.
- 포트홀 커밋 `de145d1` 을 원격 `develop` 에 push 했다.
- 이 커밋이 가리키는 서브모듈 커밋이 모두 원격에 있는지 확인했다. `projects/porthole` `de145d1`(이번 커밋), `projects/jeju-ai` `83629d`, `projects/goyang-uam` `a058fd3`, `ops/dev0` `0d25830`(이미 원격 `develop` 에 있던 값), `ops/gov-ncloud` `61019b7`, `projects/inp/official-website` `220350b`.
