# ops/gov-ncloud 폴더 구조를 층으로 정리 — 고정 커밋 갱신, 규칙에 gov-ncloud 층 구조 추가

- 날짜: 2026-10-24
- 요청: "dev0 처럼 ops/gov-ncloud 도 처리해줘"
- 이전 기록: [02.dev0-folder-structure.md](02.dev0-folder-structure.md) (같은 날 같은 요청으로 ops/dev0 를 정리한 것)

## 배경

같은 날 `ops/dev0` 의 최상위 디렉터리가 층(proxmox·talos·k8s)과 역할(apps)이 섞여 있는 걸 찾아 정리하고,
우산 `AGENTS.md` 에 "클러스터 저장소의 최상위는 층이다" 는 규칙을 넣었다(10-24/02).
`ops/gov-ncloud` 은 그 규칙을 아직 따르지 않았다. 최상위에 `tofu/`(도구 이름)와 `scripts/`(역할 이름)가 있어서
층도 역할도 아닌 이름이 앞에 와 있었다.

## 변경 내용

`ops/gov-ncloud`(inp-solution/gov-ncloud):

- `tofu/` → `ncloud/tofu/` — 인프라 코드(VPC·서브넷·NAT·NKS)
- `scripts/tofu.sh` → `ncloud/tofu.sh` — NCP 프로필 주입 래퍼. `scripts/` 폴더는 삭제
- `README.md` 신규, `docs/plans/2026-10-24-folder-structure.md` 신규
- `docs/history/2026/10/24/01.folder-structure.md` 신규
- `mise.toml`·`.gitignore`·`AGENTS.md` 의 경로 참조 갱신
- 상세 내용은 서브모듈의 [기록](../../../../../ops/gov-ncloud/docs/history/2026/10/24/01.folder-structure.md) 를 본다

이 저장소(우산):

- `AGENTS.md` 원칙 절의 층 규칙에 `ops/gov-ncloud` 를 추가했다.
  "`ops/dev0` 는 `proxmox/`·`talos/`·`k8s/`, `ops/gov-ncloud` 는 `ncloud/`(네이버 클라우드)다
  (앞으로 NKS 안의 매니페스트는 `k8s/` 층이 된다)."
- `ops/gov-ncloud` 고정 커밋 갱신

## 결정과 이유

- **`k8s/` 층을 gov-ncloud 에 지금 만들지 않았다.** NKS 안에서 도는 매니페스트가 아직 없다. 빈 폴더를 미리
  세우지 않고 README 에 예정 구조만 적어 두었다. 생기면 dev0 와 같은 역할 구분을 쓴다.
- **제품 경로는 기존 규칙이 그대로 적용된다.** `ops/Y/k8s/apps/X/` 이므로 gov-ncloud 는 `ops/gov-ncloud/k8s/apps/<제품>/` 이 된다.
  규칙 문구를 다시 바꾸지 않았다.
- **state 는 원격이다.** gov-ncloud 의 state 는 공공존 Object Storage 에 있고 backend key 도 절대경로
  (`jeju-ai-prod/terraform.tfstate`)다. 그래서 디렉터리 이동이 state 에 영향하지 않는다. dev0 와 달랐다.

## 검증

- 서브모듈 안에서 `shellcheck`·`tofu fmt -check`·`markdownlint` 통과, md 상대 링크 깨진 링크 0개
- `tofu validate` 은 프로바이더 바이너리 손상으로 실패했다. **이동 때문이 아니다** — 이동 전 경로를 그대로 복사한
  사본에서도 똑같이 실패했다. dev0 에서 같은 증상이 났던 문제(2026-10-24)다.
- 서브모듈을 먼저 push 한 뒤 고정 커밋을 올렸다(우산 `AGENTS.md` 의 서브모듈 작업 순서).

미검증: `tofu plan` 으로 변경 0건 확인, `tofu init` 후 `validate` 통과(검토 서비스 장애로 지연).

## 되돌리는 방법

- 우산: `git revert <이 커밋>` 으로 `AGENTS.md` 와 고정 커밋을 되돌린다.
- 서브모듈: `git revert <커밋>` (파일 이동이므로 git 이 rename 으로 되돌린다).

## 남은 일

- `tofu init` 으로 프로바이더를 다시 받고 `tofu plan` 으로 No changes 확인
- NKS 에 배포할 제품이 생기면 `ops/gov-ncloud/k8s/` 층을 만든다
