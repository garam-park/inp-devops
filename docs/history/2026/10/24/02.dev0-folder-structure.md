## 배경

`ops/dev0`(innopam/dev0) 의 최상위 디렉터리가 **층(layer)**과 **역할(role)**이 섞여 있었다.
`tofu/`·`configs/keepalived/` 는 Proxmox 층, `talos/` 는 Talos OS 층, `k8s/` 는 Kubernetes 층인데
`apps/` 만 Kubernetes 층의 역할인데 최상위 자리에 있었다. `docs/architecture/` 의 두 문서가 이미 이 계층을 구분하고 있었다.

근거 두 가지. `k8s/lint.sh` 가 `k8s` 와 `apps` 를 한 명령·한 루프로 함께 다뤘고(다른 층이었다면 층별로 갈라졌어야 한다),
Argo CD Application(`path: apps/jeju-ai-saas`)이 가리키는 Kubernetes 매니페스트가 `k8s/` 와 `apps/` 두 루트로 갈라져
있었다(imperative 로 관리하는 쪽은 `k8s/` 하나뿐). 즉 GitOps 대상이 두 곳에 흩어져 있었다.

이 우산 저장소의 `AGENTS.md` 도 `ops/Y/apps/X/` 를 규칙으로 적고 있어서, 서브모듈 구조가 바뀌면 규칙도 같이 고쳐야 했다.

## 결정과 이유

- `apps/` 이름은 그대로 뒀다. 규칙 문구("제품 X 를 … 배포한다")와 맞추기 위해서다.
- `secrets/` 는 `k8s/secrets/` 로 옮기지 않았다. gitignore 대상 로컬 디렉터리이고 백업 대상이라 별도 작업으로 남겼다.
- Argo CD Application 의 `path` 변경과 파일 이동을 **같은 커밋**에 넣었다. 경로만 먼저 바뀌면 Argo CD 가 이전 경로를
  못 찾아 `prune: true` 로 기존 리소스를 지울 수 있다. 두 개가 동시에 main 에 도착하면 Argo CD 는 새 경로의
  동일한 리소스를 보고 무변경으로 처리한다.
- 우산 기록을 남긴 이유는 규칙 변경이 있기 때문이다(우산 `AGENTS.md` 의 "여기에 기록하는 것은 두 가지다" 중 (2)).

  새 태그 `5cf978cf…` 가 보존됐음을 확인했다. 리베이스 후 렌더 차이는 그 태그 한 줄뿐이었다.

  바꿔서는 클러스터가 옛 경로를 계속 가리킨다. `k8s/platform/argocd/applications/` 만 적용해 갱신했고,
  100초 대기 뒤 `Synced`·`Healthy` 확인했다. 상세는 서브모듈의 [기록 10-24/02](../../../ops/dev0/docs/history/2026/10/24/02.argocd-application-path-sync.md).

남은 것: `tofu apply` 후 백업을 다시 뜨는 것(gpg 암호는 사람이 넣는다).
