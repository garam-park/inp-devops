### 3. 야간 검사 실패 원인 = 색 대비 (결정 대기 항목 D7)

실패한 잡은 `stack` 하나였고( `trivy` 는 성공 ), 그 안에서 실패한 것은 Lighthouse 이었다.

| 항목 | 값 |
| --- | --- |
| 기준 | 접근성 `minScore: 0.95` (`e2e/lighthouserc.yml`) |
| 첫 화면 `http://web:8080/` | 성능 99 · **접근성 96** · 모범사례 100 → 통과 |
| 관리자 화면 `http://web:8080/?admin` | 성능 99 · **접근성 94** · 모범사례 100 → **미달** |

실패한 접근성 항목은 **단 하나** — `color-contrast`, 대상은 `<span class="util__logout">`(관리자
화면 우측 상단 '로그아웃').

```css
.util__logout {
  background: var(--gray-50);   /* #f8f8f8 */
  color: #979797;               /* 하드코딩 — 토큰이 아니다 */
}
```

`#979797` 은 `src/styles/app.css` 에 하드코딩된 값이다(이 파일의 하드코딩 색 23개 중 하나).
`tokens.css` 에는 대응하는 토큰이 없다(`--gray-400` #a1a1a1 과 `--gray-500` #7e7e7e 사이의 값).

**이것은 이미 알려진 결정 대기 항목이다.** [결정.md](../.ai-workflow/work/tasks/jeju-ai-고도화/결정.md)
의 **D7 | 색 대비(디자인 토큰 색) | FE-039 일부 · FE #5 · FE #8 | 디자인 쪽에 요청(A)** 이다.
`e2e/lighthouserc.yml` 도 "접근성 점수에는 색 대비(이슈 #5, 디자인 토큰 결정 대기)가 들어간다" 고
적어 두었다. **따라서 고치지 않았다** — 어떤 토큰을 쓸지는 디자인 결정이다.

야간 검사 나머지 항목은 모두 통과했다: ZAP(Info 3건) · 보안 응답 헤더 · CSP · k6 부하(p95 1.4–4.7ms,
실패율 0%) · Trivy.

## 결정과 이유

- **색 대비를 고치지 않았다.** D7 이 '디자인 쪽에 요청'으로 열려 있는 결정이다. 하드코딩된
  `#979797` 을 토큰으로 바꾸는 것조차 '어느 토큰인가' 를 정하는 결정이伴는다.
- **D7 의 대상이 `.util__logout` 하나임을 특정해 D7 에 넘긴.** 결정.md 의 D7 항목에는 어떤 요소의
  문제인지가 없었으므로, 무엇을 물어야 하는지(로그아웃 라벨의 색)를 좁혔다.
