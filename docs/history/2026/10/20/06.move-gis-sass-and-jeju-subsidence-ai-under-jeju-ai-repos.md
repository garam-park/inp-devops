# gis-sass · Jeju-subsidence-AI 서브모듈을 projects/jeju-ai/repos/ 아래로 옮김

- 날짜: 2026-10-20
- 요청: `projects/gis-sass` 와 `projects/Jeju-subsidence-AI` 를 `projects/jeju-ai/repos/` 로 옮겨
  `projects/jeju-ai/repos/gis-sass`, `projects/jeju-ai/repos/jeju-subsidence-ai` 로 한다.
- 이전 기록: [02.move-jeju-ai-saas-submodules-under-apps.md](02.move-jeju-ai-saas-submodules-under-apps.md)

## 배경

02 에서 SaaS 앱 저장소 두 개를 `projects/jeju-ai/apps/` 로 모았다. 제주위성AI 관련 나머지 저장소(통합플랫폼 `gis-sass`,
프로토타입 `Jeju-subsidence-AI`)도 `projects/jeju-ai/` 아래 `repos/` 로 모아, 제주 관련 저장소를 한 폴더에서 보게 한다.
`projects/jeju-ai/repos/` 는 작업 전에 이미 빈 폴더로 있었다.

## 변경 내용

- 서브모듈 작업 트리 (`git mv`):
  - `projects/gis-sass` → `projects/jeju-ai/repos/gis-sass`
  - `projects/Jeju-subsidence-AI` → `projects/jeju-ai/repos/jeju-subsidence-ai` (폴더 이름을 소문자로)
- `.gitmodules`:
  - `[submodule "projects/gis-sass"]` `path`: `projects/gis-sass` → `projects/jeju-ai/repos/gis-sass`
  - `[submodule "projects/Jeju-subsidence-AI"]` `path`: `projects/Jeju-subsidence-AI` → `projects/jeju-ai/repos/jeju-subsidence-ai`
- 각 서브모듈 `.git` 파일 `gitdir`: `../../.git/modules/projects/<이름>` → `../../../../.git/modules/projects/<이름>`,
  `.git/modules/projects/<이름>/config` 의 `core.worktree`: `../../../../projects/<이름>` → `../../../../projects/jeju-ai/repos/<새 폴더>` (`git mv` 가 바꿨다)
- `README.md` 서브모듈 목록: `projects/gis-sass` 줄을 지우고 끝에 `projects/jeju-ai/repos/gis-sass`,
  `projects/jeju-ai/repos/jeju-subsidence-ai` 두 줄 추가. 프로토타입 줄은 원래 없었는데
  (10/16 02 기록의 남은 일) 이번에 넣었다.
- `AGENTS.md` 구조 절의 예시: `projects/gis-sass` → `projects/jeju-ai/repos/gis-sass`
- `docs/design/jeju-subsidence-ai/README.md` 상대 링크 두 개:
  `../../../projects/Jeju-subsidence-AI/` → `../../../projects/jeju-ai/repos/jeju-subsidence-ai/`,
  `../../../projects/gis-sass/AGENTS.md` → `../../../projects/jeju-ai/repos/gis-sass/AGENTS.md`

## 결정과 이유

- 02 와 같이 서브모듈 이름(`submodule.projects/gis-sass`, `submodule.projects/Jeju-subsidence-AI`)과
  `.git/modules/projects/{gis-sass,Jeju-subsidence-AI}` 는 그대로 둔다. 이름은 식별자일 뿐이고, 바꾸면 다른 클론에서
  모듈 디렉터리를 다시 받아야 한다. 그래서 `.gitmodules` 섹션 이름은 옛 경로, `path` 만 새 경로다.
- 폴더 이름은 요청대로 `jeju-subsidence-ai`(소문자)로 했다. GitHub 저장소 이름(`innopam/Jeju-subsidence-AI`)과
  `.gitmodules` 의 `url` 은 바꾸지 않았다.
- `AGENTS.md` 의 `projects/<제품>` 규칙 문장은 그대로 두고 예시 경로만 고쳤다. 이제 `projects/jeju-ai/` 아래에
  `apps/`, `repos/`, `docs/`, `tasks/` 가 있어 규칙 문장과 실제 구조가 정확히 맞지는 않는다 (남은 일).
- `docs/history/` 와 `.ai-workflow/` 안의 옛 경로 언급은 그때의 기록이라 고치지 않았다.
  `docs/design/jeju-subsidence-ai/01.current-state.md` 의 `projects/Jeju-subsidence-AI` 는 읽은 시점 기준 표기라 두고,
  같은 폴더 `README.md` 의 깨지는 상대 링크만 고쳤다.
- 커밋하지 않았다. 사용자가 요청하지 않았다.

## 검증

- `git status -s`: `M .gitmodules`, `R projects/gis-sass -> projects/jeju-ai/repos/gis-sass`,
  `R projects/Jeju-subsidence-AI -> projects/jeju-ai/repos/jeju-subsidence-ai` (스테이징됨)
- `git submodule status`: `85a96ba projects/jeju-ai/repos/gis-sass (260918-중간보고-214-g85a96ba)`,
  `f7b9192 projects/jeju-ai/repos/jeju-subsidence-ai (heads/feature/workspace-layers)`. 고정 커밋은 옮기기 전과 같다.
- 새 경로에서 `git -C … status -sb`: gis-sass 는 `develop...origin/develop`, jeju-subsidence-ai 는
  `feature/workspace-layers...origin/feature/workspace-layers`, 둘 다 변경 없음.
- `projects/` 에 `gis-sass`, `Jeju-subsidence-AI` 폴더가 남아 있지 않다.
- 설계 문서 README 의 새 상대 링크 두 개가 실제 파일·폴더를 가리킨다 (`ls` 로 확인).
- 작업 전부터 있던 `projects/jeju-ai/apps/jeju-ai-saas-{be,fe}` 의 변경(`git status` 의 `M` 표시)은 이 작업과 무관하며 건드리지 않았다.

## 되돌리는 방법

`git mv projects/jeju-ai/repos/gis-sass projects/gis-sass`,
`git mv projects/jeju-ai/repos/jeju-subsidence-ai projects/Jeju-subsidence-AI` 후
`git restore --staged --worktree README.md AGENTS.md docs/design/jeju-subsidence-ai/README.md` 로 문서 세 개를 되돌린다.
(`.gitmodules` 는 `git mv` 가 다시 고친다.)

## 남은 일

- ws 에 커밋: `.gitmodules`, 두 서브모듈 경로, `README.md`, `AGENTS.md`, 설계 문서 README, 이 기록
- `AGENTS.md` 구조 절의 `projects/<제품>` 규칙 문장을 `projects/jeju-ai/{apps,repos,docs,tasks}` 구조에 맞게 다시 쓸지 결정
- 다른 클론에서 받을 때: `git pull` 뒤 `git submodule update --init projects/jeju-ai/repos/gis-sass projects/jeju-ai/repos/jeju-subsidence-ai`.
  옛 경로 폴더가 남아 있으면 손으로 지운다.
