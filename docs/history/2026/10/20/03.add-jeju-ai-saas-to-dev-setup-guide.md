# 개발환경 셋업 가이드(JSA-PF-ST-005)에 jeju-ai-saas-be · fe 추가

- 날짜: 2026-10-20
- 요청: `.ai-workflow/work/tasks/현장방문대비/30 관리 산출물/개발/JSA-PF-ST-005_개발환경 셋업 가이드.md` 에 `projects/jeju-ai/apps/jeju-ai-saas-be`, `projects/jeju-ai/apps/jeju-ai-saas-fe` 를 추가한다.
- 이전 기록: [../19/04.site-visit-dev-deliverables-trim-questions.md](../19/04.site-visit-dev-deliverables-trim-questions.md), [02.move-jeju-ai-saas-submodules-under-apps.md](02.move-jeju-ai-saas-submodules-under-apps.md)

## 배경

가이드는 `gis-sass` 와 참조 프로토타입(`Jeju-subsidence-AI`)만 다뤘다. 제주 지반침하 SaaS 서버·화면 저장소가 워크스페이스에 들어왔으므로 같은 가이드에서 셋업 절차를 다룬다.

## 변경 내용

파일: `.ai-workflow/work/tasks/현장방문대비/30 관리 산출물/개발/JSA-PF-ST-005_개발환경 셋업 가이드.md` (116줄 추가, 14줄 삭제)

- 머리말: 범위를 `gis-sass` + SaaS 서버·화면으로 넓히고, 프로토타입 절 번호 `3.2` → `3.4`
- 1절 사전 준비 표: `대상` 열 추가(공통 / `gis-sass` / `jeju-ai-saas-be` / `jeju-ai-saas-fe`). 행 추가: mise, SeaweedFS(`chrislusf/seaweedfs:3.97`), Python 3.12(BE 파이프라인, `mise.toml` 3.12.15 · `.venv`), lefthook 2.2.2, Chromium(Playwright). Node 행은 세 저장소의 고정값(`24` / `24.22.0`)을 적음. Docker 행에 SaaS 저장소가 Docker 를 쓰는 범위를 덧붙임
- 2절: SaaS 저장소 두 개 clone 명령 추가(기본 브랜치 develop)
- 3절: `3.2 지반침하 SaaS 서버`(mise·lefthook 설치, `.env`, `docker compose up -d storage`, `npm --prefix api ci`, `storage -- push`, `npm --prefix api run dev`; 합성 자료 `seed:fixtures`, 파일러·마스터 화면, 파이프라인 순서, 종료)와 `3.3 지반침하 SaaS 화면`(mise·lefthook, `.env.local`, `npm ci`, `npm run dev`, `npx playwright install chromium`; 브이월드 키, `gen:api`, 운영 이미지) 신설. 기존 프로토타입 절은 `3.4` 로 번호만 바뀜
- 4절: 기존 내용을 `4.1 통합플랫폼` 아래로 두고(본문 변경 없음) `4.2`(storage healthy, `/api/catalog`, `/api/openapi.json`, mise 작업 기반 테스트 표 6행)와 `4.3`(화면 5178, 테스트 표 4행) 추가
- 5절 자주 겪는 문제: SaaS 관련 7행 추가(S3 자격 증명 없음, 레이어가 카탈로그에 안 보임, 통합 테스트 버킷 안전장치, 화면이 비어 있음, 5178 포트 충돌, Playwright 브라우저 미설치, 시각 회귀 macOS 건너뜀)
- 6절 근거 자료: BE·FE 저장소 파일 목록 2줄 추가

## 결정과 이유

- 기준 상태: 두 서브모듈의 작업 트리(`chore/quality-gates` 브랜치 + 미커밋 변경)를 기준으로 썼다. ws 고정 커밋(BE `2e81599`, FE `8505ed2`)은 `develop` 끝이지만 `develop` 에는 `mise.toml`·`lefthook.yml` 이 없고 FE E2E 는 puppeteer-core(`node --test`)다. 사용자가 오늘 그 브랜치에서 품질 게이트를 올리는 중이라 병합 뒤 상태를 기준으로 했다. `develop` 기준으로 읽을 때 맞지 않는 항목: mise·lefthook 설치 줄, `mise run …` 명령, Playwright 관련 행(1절·3.3·4.3·5절), BE Python 3.12 행의 `mise.toml`·`pipeline:install`. 실행·자료 올리기·단위 테스트 명령은 두 상태에서 같다.
- 1절 표에 `대상` 열을 추가했다. 저장소가 셋이 되어 행마다 어느 저장소 것인지 없으면 읽기 어렵다.
- 제·개정 이력에 행을 추가하지 않고 V0.1 을 그대로 두었다. 지난 사실 수정(10/17, 10/19)도 이력 행 없이 제자리 수정이었고 문서는 아직 승인 전이다.
- `npx playwright install chromium` 은 저장소 어디에도 적혀 있지 않지만 `@playwright/test` 가 브라우저 없이는 돌지 않으므로 넣었다(5절 오류 문구 `Executable doesn't exist` 도 Playwright 의 것).
- 5178 포트 충돌 행은 프로토타입과 FE 의 `vite.config` 가 같은 포트를 쓰고 `strictPort` 가 없다는 데서 추론했다(Vite 기본 동작은 다음 포트로 옮겨 뜸). 실제로 재현하지는 않았다.
- ws 서브모듈 경로(`projects/jeju-ai/apps/…`)는 문서에 넣지 않았다. ws `AGENTS.md` 원칙대로 서브모듈은 ws 없이 혼자 받을 수 있어야 하고, 제출 문서라 내부 작업 공간 구조를 쓰지 않았다.
