## 결정과 이유

- DevOps 담당자는 사용자 결정으로 박가람(FE·BE 와 별도 인물). 홍길동 겸임이면 한 사람이 두 줄기를 번갈아 하게 돼 작업이 전부 짧아진다.
- 날짜 배치(FE·BE): 담당자별로 작업을 순서대로 이어 붙이는 스크립트(근무일수만 지정). 주말과 공휴일(8/17, 9/24·25·28, 10/5, 10/9, 12/25) 제외, 같은 사람 작업은 겹치지 않음. 기준일(10-20)까지 네 사람 모두 51/51 근무일이 차도록 작업 길이를 맞췄다. 완료는 종료 ≤ 10-20, 진행은 10-20 을 걸침, 예정은 10-21 이후 — 스크립트가 검증한다.
- DevOps 는 사용자 요청으로 가상 배치 대신 dev0 저장소 `docs/history/2026/10/{06,09,10,13,16,19,20}` 의 실제 날짜를 썼다(10/06 시작, 10/09·10/10 은 하루에 작업 7–8개). 같은 날의 기록 여러 건을 작업 하나로 묶고 산출물 열에 기록 번호(예: `10/09/21–24`)를 적었다. 진행은 W65(official-website prd, 10/16 시작) 하나, 예정 8개는 10/21 부터 순서대로.
- BE 5명 배정은 영역별: 김규영 자료(조사·품질·바인딩·빌드 재현성·시계열), 조혜인 격자·지수·벡터 타일, 전재환 지오코딩·행정경계·저장소 CLI·배포 연동·인증·감사 API, 유소운 자료 구조·API 골격·catalog API·DB 설계·전환, 최성민 지수 레이어 격리·샌드박스·품질 검사. 날짜는 사용자 요청이 배정뿐이라 홍길동 때의 한 줄기(의존 순서) 그대로 두었다 — 결과적으로 BE 는 한 번에 한 사람만 일하는 모양이라, 병렬 재배치는 사용자 판단으로 남김.
- ID 는 시트명 + 번호(FE-001, BE-001, DEVOPS-001), 시작일 순.
- 관련 요구사항ID 는 `.ai-workflow/work/tasks/현장방문대비/30 관리 산출물/기획/지반침하스마트관리시스템_요구사항정의서-V1.0.xlsx`(오늘 `39d189c` 로 커밋된 다른 세션 산출물)의 세부요구사항ID(SFR-00n-0m, NFR-00n-0m). 화면ID 는 같은 커밋의 화면정의서 pptx 에서 뽑았다(SCR-001–013).
  - 주의: 화면정의서 22번 슬라이드 "사업수행계획서 대비 구현 현황"은 SFR-001–012 라는 다른 번호 체계(SFR-001 = 10m 격자 멀티소스 융합 …)를 쓴다. 요구사항정의서(SFR-001–008 + 세부 ID)와 맞지 않는다. 엑셀은 요구사항정의서 체계를 따랐다.
- 내용 출처: 프로토타입 README(화면·아직 안 들어간 것), FE·BE 저장소 구조와 품질 검사 기록, GitHub 이슈(FE #1–#7, BE #1–#2), dev0 `.ai-workflow/works/main.md`(W16–W67)와 history 파일명. 추가 기능(로그인, DB 전환, 벡터 타일)은 FE·BE·DevOps 세 시트에 짝을 맞춰 예정으로 넣었다(예: BE 메타데이터 DB 전환 ↔ FE 관리 화면 전환 ↔ DevOps PostgreSQL 운영).
