## 결정과 이유

- 재개 대신 새 워크플로: 캐시는 프롬프트 글자가 같아야 맞고, 공통 머리말에 브랜치명이 있어 고치면 1·2단계도 다시 돈다. 남은 일만 담는 쪽이 어긋날 게 없다.
- 검증 루프가 "러너에서 아직 안 돌았다"와 "ops/dev0 README 가 낡았다"를 매번 major 로 올려 헛돌았다. 중간에 멈추고(13:35) 스크립트에 '알려진 것' 필터를 넣어 이어 돌렸다 — 계속할지 판단에서만 빼고 수정 에이전트에 주는 목록은 그대로 두어 앞선 회차의 프롬프트(캐시 키)를 지켰다.
- 이어 돌릴 때 끝난 에이전트 12개 중 6개(FE 검증 1회차 · BE 검증 2회차)가 재사용되지 않고 다시 돌았다: 결과 재사용이 같은 순서로 불린 앞부분까지만 적용되는데 FE 3단계가 즉시 끝나 호출 순서가 바뀌었다. 약 15분 손실. 다시 돈 BE 2회차는 새 지적(nightly:down 가드 누락, noqa 이유)을 찾아 헛되지는 않았다.
- FE 검증 1회차의 "결정 부합" 검증자는 다른 검증자가 야간 스택을 내려 자기 검사가 깨진 채 결과 없이 끝났다(워크플로는 failed 로 기록, 2회차에서 다시 돌았다). BE 의 compose 잠금이 바로 이 문제의 해법이다.
- FE nightly.yml 은 develop 에 없어 GitHub 이 워크플로를 등록하지 않았고 수동 실행이 404 였다. 에이전트가 브랜치 한정 push 트리거를 임시로 넣어 한 번 돌리고 제거했다(커밋 `b5d07b9` · `1f48d34`). 등록된 뒤에는 브랜치에서 `gh workflow run` 이 된다.
