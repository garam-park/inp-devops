# gis-sass 의 CSAP 해설서·양식을 projects/jeju-ai/docs/CSAP 로 복사

- 날짜: 2026-10-20
- 요청: `projects/jeju-ai/repos/gis-sass` 에서 CSAP 관련된 것만 빼서 `projects/jeju-ai/docs/CSAP` 에 정리해 옮기고 싶다.
  조사 뒤 범위는 "해설서·양식만", 방식은 "이동이 아니라 복사" 로 정했다.
- 이전 기록: [06.move-gis-sass-and-jeju-subsidence-ai-under-jeju-ai-repos.md](06.move-gis-sass-and-jeju-subsidence-ai-under-jeju-ai-repos.md)

## 배경

gis-sass 에서 CSAP 가 이름이나 내용에 들어간 파일은 353개인데, 성격이 갈린다.

| 묶음 | 위치 (gis-sass) | 수량 | 성격 |
| --- | --- | --- | --- |
| 해설서·양식 | `docs/90.관리/산출물/CSAP/` | 249 (해설서 원본 30, 하등급-SaaS 해설 30, 양식 188, 린트 설정 1) | KISA 해설서 정리본과 산출물 양식. 참고 자료 |
| 양식 보조 | `docs/CSAP/양식/` | 2 (비기술 양식 작성 TODO, 작성 팁 html) | 참고 자료 |
| 제출 산출물 자리 | `docs/90.관리/산출물/M011-CSAP-인증/README.md` | 1 | WBS 32–35 제출 문서 목차. planning M011·T079–T081, 산출물 README 표, `.codex/skills` 2개가 가리킴 |
| 중간보고 절 | `docs/90.관리/보고/중간보고/9월-1/32 - CSAP 인증 신청/` | 29 | 중간보고 구조의 한 절. `scripts/render-csap-timeline.sh` 가 경로를 고정 |
| 결정·계획·코드 | ADR 2건, planning 과업·WBS 스냅샷, SecurityConfig·AuditLogger·values.yaml 주석 등 | 나머지 | gis-sass 의 결정과 작업 |

해설서·양식 묶음은 안의 링크가 전부 폴더 안에서만 서로 가리키고(양식에서 해설서, 하등급-SaaS 해설에서 원본),
밖으로 나가는 링크가 없다. 산출물 README 는 "이 폴더는 발주처 제출 문서만" 이라고 정해 두어, 참고 자료인 이 묶음을
빼내는 것이 그 원칙에도 맞는다.

## 변경 내용

- `projects/jeju-ai/docs/CSAP/` 신규 (ws 소유, 아직 git 추적 전). 비어 있던 `projects/jeju-ai/docs/` 에 처음 들어간 내용이다.
  - `해설서/원본/` 30, `해설서/하등급-SaaS/` 30, `양식/하등급-SaaS/` 188, `.markdownlint-cli2.jsonc` 1
    ← gis-sass `docs/90.관리/산출물/CSAP/` (고정 커밋 `85a96ba`, `git archive HEAD` 로 추적 파일만)
  - `양식/비기술 양식 작성 TODO.md`, `양식/양식 작성 팁.html` ← gis-sass `docs/CSAP/양식/`
  - `README.md` 새로 씀: 출처와 복사 시점, 폴더 구조, 상대 링크 주의, 제출 산출물은 gis-sass 에 있다는 안내
- gis-sass: 변경 없음. 파일을 지우거나 링크를 고치지 않았다.

## 결정과 이유

- 범위를 해설서·양식(251개)으로 한정 (사용자 선택). 제출 산출물 자리(M011 README)는 planning 과 스킬이 가리키는 WBS 산출물
  슬롯이고, 중간보고 32 절은 보고서 구조의 일부이며, ADR·planning·코드 주석은 gis-sass 의 것이라 뺐다.
- 이동이 아니라 복사 (사용자 결정). 이동하면 gis-sass 의 ADR 2건(09-26.01, 09-26.02)·T098·T077·주간보고 9월 3주·중간보고
  timeline.md 에서 이 폴더로 가는 링크 15곳 정도가 깨진다. 서브모듈은 ws 없이 돌아가야 하므로 ws 상대 경로로 바꿀 수 없고,
  ws 원격이 개인 저장소(`garam-park/inp-devops`)라 GitHub URL 로 바꿔도 innopam/gis-sass 의 다른 독자는 열지 못한다.
  복사하면 이 문제가 생기지 않는다.
- `docs/CSAP/양식/` 2건을 `양식/` 아래로 합쳤다. gis-sass 에서는 두 경로로 갈라져 있었지만 성격이 같다.
- 작업 트리 `cp` 대신 `git archive HEAD` 를 썼다. 무시 파일(.DS_Store 등)이 섞이지 않고 고정 커밋의 추적 파일만 들어온다.
- 두 복사본 중 어느 쪽이 기준인지는 정하지 않았다. README 에 "아직 정하지 않았다, 고치기 전에 상대 쪽과 대조" 라고 적었다.
- 커밋하지 않았다. 사용자가 요청하지 않았다.

## 검증

- sha256 대조: 복사본 251개 전부 원본(`git archive` 추출본)과 같다. `diff -r` 도 README 와 합친 2건 외 차이 없음.
- 상대 링크: 복사본 안의 `](…)` 상대 링크 380개 전부 실제 파일을 가리킴, 깨진 것 0. gis-sass 원본에서도 380 / 0 으로 같다.
  (검사 스크립트: scratchpad 의 `check_links.py`, URL 디코드 후 파일 존재 확인)
- gis-sass `git status --porcelain`: 0줄. ws `git status`: `?? projects/jeju-ai/docs/` 만 추가됨.
- markdownlint (`mise exec -- markdownlint-cli2 <파일들>`, pre-commit 과 같은 명령): README·TODO 2건 exit 0, 전체 250개 md exit 0.
  단, ws `.markdownlint-cli2.jsonc` 의 `ignores: ["projects/**"]` 가 명시한 파일에도 적용되어 **사실상 검사되지 않는다**.
  MD011 을 일부러 깨뜨린 probe 파일이 `projects/jeju-ai/docs/CSAP/` 아래에서는 exit 0, `docs/` 아래에서는 error 로 나왔다.
  probe 파일은 지웠다.

## 되돌리는 방법

`rm -rf projects/jeju-ai/docs/CSAP`. 아직 추적 전이라 git 작업은 없다. gis-sass 는 건드리지 않았다.

## 남은 일

- ws 커밋 (사용자 요청 시): `projects/jeju-ai/docs/CSAP/` 252개와 이 기록.
- 두 복사본 중 기준 정하기. gis-sass 쪽을 나중에 지울지, ws 쪽을 참고용 스냅샷으로만 둘지.
- ws `.markdownlint-cli2.jsonc` 의 `projects/**` 무시를 서브모듈 경로(`projects/jeju-ai/apps/**`, `projects/jeju-ai/repos/**`, …)로
  좁힐지 결정. 지금은 ws 소유 문서인 `projects/jeju-ai/docs/` 가 훅에서 검사되지 않는다. 좁히면 CSAP 폴더 안의
  `.markdownlint-cli2.jsonc` (MD013·MD041·MD033 끔) 가 ws 규칙 위에 겹쳐 적용된다.
- `AGENTS.md` 구조 절에 `projects/jeju-ai/docs/` 를 설명할지 (06 기록의 남은 일과 같은 건).
