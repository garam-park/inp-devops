# ws 우산 저장소를 정리하고 옛 dev0 clone 의 로컬 상태를 옮겼다

- 날짜: 2026-10-14
- 요청: "손볼 것부터 같이 처리하자". ws 를 ops/ + projects/ 우산 저장소로 쓰기로 한 뒤, 검토에서 나온 정리 항목을 처리했다.

## 배경
- 아침에 innopam/dev0(당시 이름 k8s-1) 안에 projects/gis-sass 서브모듈을 넣었다가, 권한이 다른 저장소를 한 저장소 안에 넣으면 그 저장소만 보는 사람이 초기화에서 막힌다는 이유로 우산 저장소 ws 로 옮기기로 했다.
- 사용자가 ws 에 ops/dev0, projects/gis-sass 서브모듈을 추가(cd4201d)하고 GitHub 저장소 이름을 k8s-1 에서 dev0 로 바꿨다. 옛 이름은 아직 같은 저장소로 연결된다.
- 검토에서 발견한 것: .gitmodules 에 branch 없음, 빈 폴더는 git 에 잡히지 않음, AGENTS.md 와 .gitignore 없음.
  옛 clone ~/ops/inp/dev0 에 git 이 추적하지 않는 tofu 상태·비밀값·talos 출력·10/10 백업이 남아 있었다.
  ~/ops/inp/k8s-1 은 원격 없는 로컬 git 저장소(10/06 초기 설정, kubeconfig, 백업)였다.

## 변경 내용
- `.gitmodules`: ops/dev0 에 `branch = main`, projects/gis-sass 에 `branch = develop` 추가
- `.gitignore`: 새로 생성, `.DS_Store`
- `README.md`: 제목 한 줄 → 구조와 받는 법
- `AGENTS.md`: 새로 생성. 구조, 원칙(기록 위치, 배포 접착 설정 위치), 서브모듈 작업 순서, 작업 기록 양식
- `ops/dev0/` 작업 폴더(git 밖): 옛 clone 에서 복사. tofu/.terraform, tofu/terraform.tfstate 와 .backup, tofu/secrets.auto.tfvars, talos/_out, .backups/dev0-backup-2026-10-10-1826.tar.gz.gpg
- `~/ops/inp/k8s-1` → `~/ops/inp/local/k8s-1` 이동(로컬 git 이력 포함)
- 커밋하지 않았다. 사용자가 요청하면 커밋한다.

## 결정과 이유
- 옛 clone 의 미push 커밋 2개(17d8999 서브모듈 추가, ee2a4f0 그 기록, 브랜치 1develop)는 버린다. 원격 main 에 올라간 적이 없어 revert 가 필요 없다.
- 옛 clone 삭제는 사용자가 세션을 끝낸 뒤 직접 한다. 이 세션의 작업 폴더라서 지금 지우면 이후 명령이 실패할 수 있다.
- k8s-1 은 지우지 않고 local/ 로 옮겼다. 10/06 백업과 kubeconfig 가 있고 로컬 git 이력도 남긴다.
- 비밀값 파일은 저장소 밖 ~/ops/inp/local/ 이 원칙이지만, tofu/talos 도구가 저장소 안 경로를 기대하므로 ops/dev0 안의 무시 경로에 그대로 뒀다.
- .ai-workflow/work/ 틀은 손대지 않았다. dev0 의 .ai-workflow/works/main.md 와 다른 틀이라 의도를 아직 확인하지 못했다.

## 검증
- 복사 뒤 `diff -rq`(tofu/, talos/_out)와 `cmp`(백업 파일)로 옛 clone 과 ws/ops/dev0 가 같음을 확인
- `git -C ws/ops/dev0 status --ignored --short` 에 복사한 파일이 무시 목록으로 보임
- `.gitmodules` 에 branch 두 줄 확인
- 미검증: 새 경로에서 `tofu plan`, `talosctl` 이 실제로 도는지는 돌려 보지 않았다.

## 되돌리는 방법
- ws 변경은 커밋 전이다. `git -C ~/ops/inp/ws checkout -- .gitmodules README.md && rm ~/ops/inp/ws/.gitignore ~/ops/inp/ws/AGENTS.md`
- k8s-1: `mv ~/ops/inp/local/k8s-1 ~/ops/inp/k8s-1`
- 복사한 로컬 상태는 옛 clone 을 지우기 전까지 원본이 남아 있다.

## 남은 일
- 옛 clone 삭제(사용자 직접): `rm -rf ~/ops/inp/dev0`. 다음 세션은 ~/ops/inp/ws 에서 연다.
- .ai-workflow/work/ 틀 결정(새 틀인지, dev0 의 works/main.md 와 맞출지)
- .ai-workflow/work/tasks, projects/jeju-ai 는 파일이 생길 때까지 git 에 잡히지 않는다
- ws 커밋
