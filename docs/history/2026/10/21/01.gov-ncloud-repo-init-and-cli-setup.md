# gov-ncloud 저장소 로컬 생성, Ncloud CLI 조사·설치, API 인증키 발급 방법 정리

- 날짜: 2026-10-21
- 요청: `ops/gov-ncloud` 에 gov-ncloud.com 회사 계정 기반 클라우드 인프라 관리 프로젝트를 만든다. 서브모듈로 쓸 git 저장소를 만들고, gov-ncloud.com 에 CLI 같은 도구가 있는지 확인한다. 이어서 CLI 를 내려받고, 설치와 Access Key 발급 방법을 기록으로 남긴다.

## 배경

NCP 공공기관용(공공존, gov-ncloud.com) 회사 계정의 인프라를 코드와 CLI 로 관리하려 한다. 관리 저장소는 `ops/gov-ncloud` 에 두고, 나중에 이 저장소의 서브모듈로 등록한다.

## 변경 내용

- `ops/gov-ncloud/`: 빈 폴더 → `git init -b main` 으로 로컬 저장소. 커밋 없음, 원격 없음.
  - 상위 저장소에서는 `?? ops/gov-ncloud/` 로 보인다. `.gitmodules` 는 바꾸지 않았다.
- `~/.local/opt/ncloud-cli/` (저장소 밖, 신규)
  - `dl/CLI_1.1.30_20260625.zip`: 공식 배포 파일(281,811,139 바이트, SHA-256 `a07fc3169c8724f53608eaf79fa220e3669776a718103bcd66890ae8fb71bbb4`). 받은 곳: `https://www.ncloud.com/api/support/download/files/cli/CLI_1.1.30_20260625.zip`
  - `CLI_1.1.30_20260625/`: 압축을 푼 것. `cli_linux/lib/ncloud-api-cli-1.1.30-SNAPSHOT-jar-with-dependencies.jar` 를 쓴다.
- `~/.local/bin/ncloud` (신규): 시스템 `java` 로 위 jar 를 실행하는 스크립트. `~/.local/bin` 은 이미 PATH 에 있다.

```bash
#!/bin/bash
# Ncloud CLI 1.1.30. 동봉 jre8 은 Linux x86-64 전용이라 시스템 java 를 쓴다.
exec java -jar "$HOME/.local/opt/ncloud-cli/CLI_1.1.30_20260625/cli_linux/lib/ncloud-api-cli-1.1.30-SNAPSHOT-jar-with-dependencies.jar" "$@"
```

## 조사 결과: 공공존에서 쓸 수 있는 도구

공공존 전용으로 따로 배포하는 CLI 는 찾지 못했다. 민간존 도구의 API 주소를 공공존으로 바꿔 쓴다.

| 도구 | 공공존 | 근거 |
|---|---|---|
| Ncloud CLI 1.1.30 (Java) | 된다(검증 참고) | `ncloud configure` 가 `Ncloud API URL` 을 입력받는다(기본값 `https://ncloud.apigw.ntruss.com`). 공공존 주소 `https://ncloud.apigw.gov-ntruss.com/vserver/v2/getRegionList` 는 인증 없이 호출하면 401 을 돌려준다. 주소는 살아 있다. |
| Terraform provider `NaverCloudPlatform/ncloud` | 공식 지원 | provider 의 `site` 인자가 `public`, `gov`, `fin` 을 받는다. `gov` 는 `www.gov-ncloud.com` 이다. 인증은 `NCLOUD_ACCESS_KEY`, `NCLOUD_SECRET_KEY`, `NCLOUD_REGION` 환경 변수. |
| 공공존 MCP 서버(커뮤니티, glama.ai) | 지원 | `*.apigw.gov-ntruss.com` 을 쓴다. 공식 도구가 아니다. 일부 서비스는 도메인을 단순 치환할 수 없다고 적혀 있다. |

CLI 공식 문서(cli.ncloud-docs.com)는 "Classic/VPC 환경"만 말하고 공공존을 따로 다루지 않는다. `cli.gov-ncloud-docs.com`, `api.gov-ncloud-docs.com`, `guide.gov-ncloud-docs.com` 은 접속되지 않았다.

참고한 문서:
- CLI 다운로드: https://cli.ncloud-docs.com/docs/guide-clichange
- CLI 인증: https://cli.ncloud-docs.com/docs/cli-auth
- API 인증키: https://api.ncloud-docs.com/docs/common-ncpapi
- Terraform provider: https://github.com/NaverCloudPlatform/terraform-provider-ncloud/blob/master/docs/index.md

## 설치 절차 (macOS arm64 기준)

1. zip 을 내려받아 `~/.local/opt/ncloud-cli/` 에 푼다.
2. 동봉된 `cli_linux/jre8/bin/java` 는 Linux x86-64 ELF 라 macOS 에서 실행되지 않는다. 동봉 `ncloud` 스크립트(`./jre8/bin/java -jar ./lib/...`)도 상대 경로라 그 폴더에서만 돈다.
3. 그래서 시스템 `java` 와 절대 경로로 jar 를 부르는 `~/.local/bin/ncloud` 를 만든다(위 변경 내용).
4. 확인: `ncloud` 를 인자 없이 실행해 `ncloud <command> [subcommand] help` 가 나오면 된다.

## API 인증키(Access Key) 발급 절차

민간존 공식 문서 기준이다. 공공존 콘솔 메뉴 이름은 확인하지 못했고 다를 수 있다.

메인 계정 키:
1. gov-ncloud.com 에 회사 계정으로 로그인해 콘솔로 들어간다.
2. 오른쪽 위 **My Account** → **계정 및 보안 관리**.
3. 재로그인 창에서 비밀번호를 다시 입력한다.
4. **보안 관리** → **접근 관리** → **API 인증키 관리** 에서 Access Key ID 와 Secret Key 를 확인한다. 계정 생성 때 1개가 자동으로 생기고, **[신규 API 인증키 생성]** 으로 최대 2개까지 쓸 수 있다.

Sub Account 키(권장):
- 콘솔의 **Sub Account** 서비스에서 이 프로젝트용 사용자를 만든다. 접근 유형은 API 접근, 권한 정책은 필요한 것만 붙인 뒤 그 사용자의 Access Key 를 발급한다.
- 메인 계정 키는 회사 계정 전체 권한이다. Sub Account 는 처음에 조회 권한만 주고 넓힐 수 있고, 새어도 피해가 작고, 행위자를 구분할 수 있다.
- 회사 계정 관리자의 승인이 필요할 수 있다.

CLI 에 등록:

```text
ncloud configure --profile gov
Ncloud Access Key ID []: <발급받은 Access Key>
Ncloud Secret Access Key []: <발급받은 Secret Key>
Ncloud API URL (default:https://ncloud.apigw.ntruss.com) []: https://ncloud.apigw.gov-ntruss.com
```

- 키는 `~/.ncloud/` 의 설정 파일에 저장된다. 저장소와 대화 기록에 넣지 않는다.
- 이후 명령에는 `--profile gov` 를 붙인다.

## 결정과 이유

- GitHub 원격 저장소는 만들지 않고 로컬 `git init` 만 했다. 사용자가 선택했다(옵션 A `innopam/gov-ncloud` 비공개, B 다른 이름, C 로컬만 중 C).
- CLI 는 저장소 밖 `~/.local/opt` 에 설치했다. 281 MB 이고 기기마다 다른 도구라 저장소에 넣을 것이 아니다.
- 동봉 JRE 대신 설치된 OpenJDK 15.0.2 를 쓴다. 공식 문서는 JDK 1.9 이상에서 문제가 생길 수 있다고 경고한다. help 출력까지는 정상이다.

## 검증

- `git -C ops/gov-ncloud status`: `On branch main`, `No commits yet`.
- `ncloud` (인자 없음): `ncloud <command> [subcommand] help` 출력.
- `ncloud help`: 주요 명령어 목록(server, loadbalancer, cdn, autoscaling, vserver, vpc, vnas …) 출력.
- `ncloud vserver help`: 하위 명령 목록 출력.
- `which ncloud`: `/Users/garam/.local/bin/ncloud`.
- 사용자가 공공존 콘솔에서 인증키를 받아 `ncloud configure --profile gov` 로 등록했다(API URL `https://ncloud.apigw.gov-ntruss.com`). 어떤 키(메인 계정·Sub Account)인지는 기록하지 않았다.
- `ncloud vserver getRegionList --profile gov`: `returnCode` `0`, `returnMessage` `success`. 리전 2개 `KR`(KR-CENTRAL), `KRS`(KR-SOUTH). 민간존 CLI 에 API URL 만 바꿔 공공존을 쓸 수 있고, Java 15 로도 API 호출이 된다.

## 되돌리는 방법

- 저장소: `rm -rf ops/gov-ncloud/.git`
- CLI: `rm -rf ~/.local/opt/ncloud-cli ~/.local/bin/ncloud`
- 인증 설정(등록했다면): `~/.ncloud/` 의 `gov` 프로필 항목 삭제.

## 남은 일

- 등록한 키가 메인 계정 키라면 Sub Account 키로 바꾸는 것을 검토한다.
- GitHub 원격 저장소 이름·공개 범위를 정해 만들고, 첫 커밋 push 후 이 저장소에 서브모듈로 등록(`.gitmodules`, 고정 커밋). 그때 새 기록을 쓴다.
- 인프라 코드 도구(Terraform `site = "gov"` 등) 선택.
