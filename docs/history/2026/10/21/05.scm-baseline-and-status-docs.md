## 결정과 이유

사용자 결정:

1. 브랜치 보호: Team 요금제 새 조직으로 옮긴 뒤 적용. 이번에는 규칙만 문서화, 대장은 "적용 예정".
2. 정적분석: SonarQube 없이 기존 semgrep 결과를 리포트로.
3. 대상 저장소: `gis-sass` 가 아니라 `jeju-ai-saas-fe`·`-be`. 기존 산출물 21종(README)의 "통합플랫폼"은 `gis-sass` 라 범위가 다르다.
4. 태그·릴리스: 만들지 않고 규칙만.
5. certifi: PR #6 에 커밋 추가.

내 판단:

- SBOM·라이선스는 이미 고정된 trivy 0.76.0 으로 해 새 도구를 들이지 않았다. 잡 수를 늘리지 않고 checks 잡에 단계만 더함(러너 2대 제약).
- 대상은 운영 의존성만(devDependencies 제외) — 기존 audit·nightly:trivy 와 같은 범위.
- 문서 번호 CF-008·009: 형상·산출물 관리 분류(CF)에서 PF 는 007 만 쓰임. 머리 표는 ST-002 형식, 작성자 박가람·승인자 `-`(10-19 규칙).
- docx 는 `pandoc -f gfm-gfm_auto_identifiers -t docx --reference-doc=md2docx/JSA-PF-ST-002_….docx`. md 원본은 폴더에 두지 않음(세션 스크래치패드에만). PDF 는 스크래치패드의 `bin/report.py` 로 HTML 을 만들고 Chrome headless 로 인쇄.

- 로컬: FE sbom·license·sast 성공, 예외를 빼면 license exit 1(게이트가 잡는지 확인), prettier·markdownlint·actionlint 통과. BE sbom·license·sast·`mise run lint` 통과, certifi 올린 뒤 pip-audit 취약점 0.
