# gov-ncloud 인프라 코드화 도구, state 위치, 기존 리소스 처리 결정

- 날짜: 2026-10-21
- 요청: gov-ncloud 인프라를 어떤 도구로 코드화할지 정한다(Terraform `site = "gov"` 등).
- 이전 기록: [01.gov-ncloud-repo-init-and-cli-setup.md](01.gov-ncloud-repo-init-and-cli-setup.md)

## 배경

공공존 API 가 CLI 로 호출되는 것을 확인했다(이전 기록). 인프라를 코드로 관리할 도구를 정한다.
GitHub 원격 저장소 생성과 서브모듈 등록은 사용자가 다른 세션에서 하기로 했다.

## 확인한 사실

- `ops/dev0` 는 OpenTofu 1.13.1 을 `mise.toml` 로 고정해 쓴다. 커밋 훅에서 `tofu fmt`, `mise run lint:tf` 에서 `validate` 를 돈다. `tofu/*.tfstate` 와 `tofu/secrets.auto.tfvars` 는 gitignore 대상이다. 이 Mac 에도 `/opt/homebrew/bin/tofu` 1.13.1 이 있다.
- ncloud provider(`NaverCloudPlatform/ncloud`)는 OpenTofu 레지스트리에 60개 버전이 있고 최신이 4.0.7 이다. Terraform 레지스트리 최신도 4.0.7(2026-07-27)이다.
- provider 의 `site` 인자는 `public`, `gov`, `fin` 을 받는다. 공공존에서 모든 리소스가 되는지는 확인하지 않았다.
- 공공존 현재 리소스(`ncloud ... --profile gov`, 읽기 전용 조회, 2026-10-21)

| 리전 | 리소스 | 내용 |
|---|---|---|
| KR | VPC | `gis-prod-vpc`(vpcNo 5133886), `10.20.0.0/16`, RUN, 2026-10-13T12:58:15+0900 생성 |
| KR | 서브넷 | `gis-prod-node-sn`(63228, Private, General), `gis-prod-lb-pri-sn`(63229, Private, LB 전용), `gis-prod-lb-pub-sn`(63231, Public, LB 전용). 모두 ACL 33888 |

| KR | 그 밖 | 서버, 블록 스토리지, 공인 IP, LB, NAS, NAT 게이트웨이, 로그인 키 모두 0 |

  - 서브넷 구성(노드 + LB 전용)으로 보아 NKS 클러스터 준비로 보인다. 누가 왜 만들었는지는 `docs`, gis-sass·dev0 문서에서 찾지 못했다.
  - NKS 클러스터와 Object Storage 버킷은 이 CLI 로 조회하지 못해 확인하지 않았다.

## 결정과 이유

1. **도구: OpenTofu 1.13.1 + ncloud provider(`site = "gov"`). OpenTofu 전용 기능은 쓰지 않는다.**
   - dev0 와 도구·버전·린트 방식을 맞춘다. 라이선스가 MPL 2.0 이다.
   - 전용 기능(state 암호화, `.tofu` 파일, 변수로 backend·module source 정하기 같은 early evaluation)을 쓰지 않으면, Terraform 으로 옮길 때 코드는 그대로 두고 `terraform state replace-provider` 로 provider 주소만 바꾸면 된다.
   - ncloud CLI 는 조회와 일회성 운영 작업에 계속 쓴다.
   - 버린 대안: Terraform. 회사 인프라 관리는 BSL 1.1 에서도 허용된다. 하지만 dev0 와 도구가 나뉘고, 라이선스 조건이 더 바뀔 수 있고, 공공 납품 때 오픈소스 목록에서 설명이 필요할 수 있다. CLI 스크립트(bash)는 state 가 없어 drift 확인과 `plan` 미리보기가 안 된다.
2. **state: 로컬 파일(gitignore)로 시작, 나중에 공공존 Object Storage(S3 backend)로 옮긴다.**
   - 옮기는 시점: 운영자가 둘이 되거나 실제 서비스를 올리기 전. `tofu init -migrate-state` 한 번이면 된다.
   - 그 사이 노트북을 잃으면 state 가 사라진다. import 로 복구할 수 있다.
   - 공공존 Object Storage 엔드포인트와 S3 backend 잠금 지원 여부는 아직 확인하지 않았다.
3. **기존 `gis-prod-vpc` 와 서브넷 3개: 지우고 코드로 다시 만든다.**
   - 버린 대안: import 해서 코드로 관리하기(추천했던 안), 그대로 두고 data source 로 읽기.
   - 아직 지우지 않았다. 아래 남은 일 참고.

## 변경 내용

- 파일·클라우드 리소스 변경 없음. 결정과 조회 결과만 기록한다.

## 검증

- 리소스 조회는 `getVpcList`, `getSubnetList`, `getNetworkAclList`, `getRouteTableList`, `getNatGatewayInstanceList`, `getAccessControlGroupList`, `getLoginKeyList`, `getServerInstanceList`, `getBlockStorageInstanceList`, `getPublicIpInstanceList`, `getLoadBalancerInstanceList`, `getNasVolumeInstanceList` 로 했다. 모두 `success`.

## 되돌리는 방법

- 결정만 했으므로 되돌릴 상태 변경이 없다. 결정을 바꾸면 새 기록을 쓰고 이 파일 맨 위에 `> 대체됨:` 을 단다.

## 남은 일

- `gis-prod-vpc` 를 만든 사람과 용도를 확인한 뒤 삭제한다. 다른 작업이 기대고 있으면 결정 3 을 다시 본다.
- 다시 만들 네트워크의 이름과 CIDR 을 정한다(지금 값 `10.20.0.0/16` 을 유지할지 포함).
- `ops/gov-ncloud` 에 OpenTofu 골격을 만든다: `mise.toml`(opentofu 1.13.1), `versions.tf`(ncloud ~> 4.0, `site = "gov"`), gitignore(state, tfvars), 호환 규칙을 저장소 `AGENTS.md` 에 적기.
- 공공존 Object Storage 엔드포인트와 S3 backend 잠금 지원을 확인한다(결정 2 의 이전 준비).
- NKS 클러스터와 Object Storage 버킷이 이미 있는지 콘솔이나 API 로 확인한다.
