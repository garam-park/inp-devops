# ops/gov-ncloud 를 inp-solution/gov-ncloud 서브모듈로 등록

- 날짜: 2026-10-21
- 요청: 사용자가 만든 `https://github.com/inp-solution/gov-ncloud` 에 `ops/gov-ncloud` 를 올리고, ws 저장소에 서브모듈로 등록한다.
- 이전 기록: [01.gov-ncloud-repo-init-and-cli-setup.md](01.gov-ncloud-repo-init-and-cli-setup.md), [02.gov-ncloud-iac-tool-decision.md](02.gov-ncloud-iac-tool-decision.md)

## 배경

`ops/gov-ncloud` 는 오늘 로컬 `git init` 으로 만들었고, 공공존 KR 기본 네트워크를 OpenTofu 로 만든 코드가 들어 있다.
그 작업 기록은 서브모듈 안 `ops/gov-ncloud/docs/history/2026/10/21/01.network-baseline.md` 에 있다.
원격 저장소는 사용자가 `inp-solution` 조직에 비공개로 만들었다. 다른 서브모듈은 `innopam` 조직이다.

## 변경 내용

- `inp-solution/gov-ncloud`: 빈 저장소 → `main` 에 첫 커밋 `2d8ace9`(파일 10개). state·`.terraform/` 은 gitignore 로 빠졌다.
- `.gitmodules`: 항목 추가 — `[submodule "ops/gov-ncloud"]`, `path = ops/gov-ncloud`, `url = git@github.com:inp-solution/gov-ncloud.git`, `branch = main`
- `ops/gov-ncloud`: untracked 폴더 → 서브모듈, 고정 커밋 `2d8ace9`
- `ops/gov-ncloud/.git`: 디렉터리 → `gitdir: ../../.git/modules/ops/gov-ncloud` 파일(`git submodule absorbgitdirs`). 다른 서브모듈과 같은 배치다.

## 결정과 이유

- 서브모듈 이름은 경로와 같은 `ops/gov-ncloud` 로 두었다. `ops/dev0` 와 같은 규칙이다.
- 서브모듈을 먼저 push 하고 ws 에 등록했다(AGENTS.md 서브모듈 작업 순서).

## 검증

- `git ls-remote origin`: `refs/heads/main` = `2d8ace9`.
- `gitleaks protect --staged`: 첫 커밋 전 no leaks found.
- `git submodule status ops/gov-ncloud`: `2d8ace9 ops/gov-ncloud (heads/main)`.
- absorb 뒤에도 `ops/gov-ncloud/tofu/terraform.tfstate` 가 그대로 있고, 서브모듈 `git status` 는 `main...origin/main` 로 깨끗하다.

## 되돌리는 방법

- 등록 취소: `git submodule deinit -f ops/gov-ncloud && git rm -f ops/gov-ncloud && rm -rf .git/modules/ops/gov-ncloud`. 그 전에 `tofu/terraform.tfstate` 를 다른 곳에 복사해 둔다(gitignore 대상이라 원격에 없다).

## 남은 일

- 다른 기기에서 받으면 `ops/gov-ncloud` 에 state 가 없다. state 를 공공존 Object Storage 로 옮기기 전까지는 이 Mac 에서만 `apply` 한다.
- `inp-solution` 조직 접근 권한이 없는 사람은 `git clone --recurse-submodules` 때 이 서브모듈을 건너뛴다.
