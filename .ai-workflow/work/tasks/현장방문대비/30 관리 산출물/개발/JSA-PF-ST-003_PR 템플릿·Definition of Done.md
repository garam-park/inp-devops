## 1. Pull Request 템플릿

**현황: 저장소에 PR 템플릿 파일(`.github/pull_request_template.md`)이 없다**(2026-10-16 확인). 현재 PR 은 아래 규칙을 따라 작성한다.

- 제목은 커밋 메시지와 같은 Conventional Commits 형식이다(`타입(범위): 제목`, 50자 이내 권장).
- 한 PR 은 한 가지 목적만 갖는다. 기계적 변경(이름 변경·포맷팅·이동)은 별도 PR 로 분리하고, 리팩토링과 기능 변경도 섞지 않는다.
- 본문에는 무엇을·왜 바꿨는지를 적는다. 제목에 내부 작업 번호(Task ID, 예: T072)를 함께 적는 경우가 많다.

아래는 양식에 정해 둔 기본 PR 템플릿이다. **저장소에는 아직 적용되지 않았다**(적용 여부 <mark>확인 필요</mark>).

```markdown
## 요약
(무엇을, 왜 바꿨는가)

## 변경 내용
-

## 관련 이슈
closes #

## 테스트
- [ ] 단위 테스트 추가·수정
- [ ] 로컬에서 동작 확인

## 스크린샷(화면 변경 시)
```

## 2. Definition of Done

작업은 아래 조건을 모두 만족할 때 완료로 본다. 각 항목 끝에 적용 상태를 표시했다(현행 = 저장소 규칙 문서에 근거가 있음, 기본안 = 양식 기본 항목이며 규칙 문서에는 명시되어 있지 않음).

- [ ] 작업 문서(Task)에 적은 완료 조건과 검증 방법을 충족한다 — 현행(`AGENTS.md` §5 플래닝·작업 절차)
- [ ] 테스트를 추가·수정했고 CI 가 통과한다 — 현행(`test.md`, `pull-request.md`)
- [ ] 버그를 고쳤다면 그 버그를 재현하는 테스트를 남겼다 — 현행(`test.md`)
- [ ] 셀프 리뷰를 마쳤다(diff 를 처음부터 끝까지 다시 읽었고, 이해하지 못한 줄이 없다) — 현행(`pull-request.md`)
- [ ] 관련 문서(API 문서·ADR·설계서·`docs/TESTING.md`)를 갱신했다 — 기본안(양식 기본 항목 "관련 문서(API 명세·설계 문서) 갱신"을 이 저장소의 문서 이름으로 풀어 쓴 것이며 규칙 문서에는 일반 규정이 없다. 실제로는 동작을 바꾸는 PR 이 API 문서·`docs/TESTING.md` 를 함께 고친 사례가 있다. 예: T101·T106·T107 관련 PR)
- [ ] 완료된 Task 문서를 아카이브로 옮기고 현황판(index)의 상태를 갱신했다 — 현행(`AGENTS.md` §5)
- [ ] 요구사항·이슈의 인수 조건을 만족한다 — 기본안(별도 이슈 인수 조건 양식은 없음)
- [ ] 보안·성능 영향을 확인했다 — 기본안(<mark>확인 필요</mark>)
- [ ] 체인지로그에 반영했다 — 현행(`release.md`: 태그 사이의 커밋 로그가 체인지로그이므로 PR 제목·커밋을 Conventional Commits 형식으로 쓴다. 별도 CHANGELOG 파일은 두지 않고, 릴리스 때 `RELEASE-NOTES.md` 와 GitHub Release 를 쓴다 — `RELEASE-NOTES.md`·T094 결정 D, v0.1.0 에서 실행)

## 3. 리뷰 규칙

- 리뷰어 수: 셀프 리뷰(규칙 문서 기준). 외부 승인자 수는 규정되어 있지 않다. v0.1.0 릴리스 노트에는 "1 approval" 로 보호한다고 적혀 있으나, 이후 조직 플랜 제약으로 branch protection 을 쓸 수 없음이 확인되었다(2026-09-26, T096). 현재 적용 여부 <mark>확인 필요</mark>
- 리뷰 기한: 규정 없음(<mark>확인 필요</mark>). 셀프 리뷰는 작성 직후보다 하루 묵혀서 보는 것을 권장한다.
- 머지 방식: merge commit(`--no-ff`)만 쓴다. squash merge 와 rebase merge 는 쓰지 않는다(저장소 설정 + `lint-git` 사후 검출).
- 머지 조건: CI 통과(문서·API 단위·통합·web·배포물 검증 잡) + 셀프 리뷰. 단, 브랜치 보호를 쓸 수 없어 CI 가 실패해도 머지를 시스템이 막지는 않는다(JSA-PF-ST-002 4절).
- 크기 기준: 줄 수가 아니라 "사람의 리뷰 용량" — 한 번의 셀프 리뷰 세션에서 전부 이해하고 검증할 수 있는 단위.
