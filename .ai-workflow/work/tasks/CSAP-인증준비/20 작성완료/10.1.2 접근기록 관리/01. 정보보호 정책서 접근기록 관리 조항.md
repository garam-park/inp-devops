> [!info] 법령 기준
> 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 같은 법 시행령 제30조제1항제5호(대통령령 제36121호, 2026. 8. 20. 시행), 개인정보의 안전성 확보조치 기준 제2조제3호·제4조·제5조제3항·제8조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

본 문서는 ㈜이노팸 정보보호 정책서 중 접근기록 관리에 해당하는 절이다. 세부 절차는 JAS-10.1.2-02 접근기록 관리 절차(접근통제관리지침의 접근기록 관리 절)에 위임한다.

## 1. 목적

㈜이노팸은 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(이하 "서비스")을 구성하는 시스템에 대한 사용자·관리자의 접속과 접속 후 수행한 행위를 기록·보관하고 그 타당성을 정기적으로 검토하여, 서비스 통제와 보안 모니터링을 가능하게 하고 보안사고 발생 시 책임추적성을 확보하기 위하여 접근기록 관리에 관한 기본 정책을 정한다.

## 2. 적용 범위

- 서비스(하등급 SaaS) 인증 범위 내 다음 시스템과 이들에 접근하는 모든 계정
  - 응용 서비스: web(정적 화면) · api(유일한 진입점, 인증·권한·감사 집행) · pipeline(데이터셋 빌드 워커)
  - 데이터: NCP Cloud DB for PostgreSQL, NCP Object Storage(버킷 `jeju-ai-saas`)
  - 운영 기반: Ncloud Kubernetes Service(NKS) 클러스터 API, NCP Load Balancer·Ingress
  - 클라우드 관리 포털: NCP 콘솔·API(메인 계정, Sub Account)
  - 개발·배포 환경: GitHub 조직 `innopam`(저장소 `jeju-ai-saas-be` · `jeju-ai-saas-fe`, GitHub Actions), self-hosted runner, NCP Container Registry
  - 정보보호시스템: 접근기록 저장소(NCP Cloud Log Analytics 또는 Object Storage 별도 버킷), 웹 방화벽(도입 예정)
- ㈜이노팸의 임직원 전원과 인증 범위 내 시스템에 접근하는 외부인력
- 이용 기관(제주특별자치도 및 산하 공공기관)과 이용자가 서비스에 접근한 기록 중 당사가 생성·보관하는 기록
- 책임공유모델에 따라 NCP(IaaS/PaaS 제공자)가 책임지는 물리 시설, 하이퍼바이저, NKS 컨트롤 플레인 내부, 관리형 DB 내부 관리 계층의 접근기록은 제공자의 인증·계약으로 확인하고, 당사는 당사가 운영·설정하는 계층의 접근기록을 책임진다.
- 사내 개발 클러스터 `dev0`와 로컬 개발 환경은 인증 범위가 아니며 본 조항의 대상이 아니다. 단, 운영 데이터 반입을 금지한다.

## 3. 정책 선언

1. 접근기록을 생성·보관해야 하는 대상 시스템을 서비스와 업무 중요도를 기준으로 정의하고 목록(JAS-10.1.2-03 접근기록 생성 대상 목록)으로 관리한다. 신규 시스템 도입·변경 시 대상 여부를 판단하여 목록을 현행화한다.
2. 접근기록은 시스템에 로그인한 접속 기록과 접속 후 수행한 행위 기록을 모두 포함하며, 접근 주체(계정), 접근 시간, 접근 IP, 수행업무(행위·대상), 처리한 정보주체 정보(해당 시), 결과, 요청 식별자(request_id)를 담아 책임추적성을 보장할 수 있는 형태로 생성한다.
3. 접근기록은 원본 시스템과 분리된 저장소(국내 리전의 관리형 로그 서비스 또는 Object Storage 별도 버킷)에 별도 보관하고, 원본 시스템 관리자를 포함한 누구도 임의로 삭제·변조할 수 없도록 권한 분리, 보존 정책(객체 잠금), 무결성 검증을 적용하며, 별도로 백업한다. 응용 감사 기록(`audit_events`)은 앱 DB 역할에 추가·조회 권한만 주어 응용이 수정·삭제할 수 없게 한다.
4. 접근기록은 법률과 이용 기관의 정책에서 요구하는 기간 중 가장 긴 기간 이상 보관한다. 개인정보처리시스템 접속기록은 1년 이상(5만명 이상 정보주체 또는 고유식별정보·민감정보 처리 시 2년 이상), 접근권한 부여·변경·말소 기록은 3년 이상 보관하며, 당사는 서비스의 접속·감사 기록을 3년, 그 밖의 주요 시스템(클라우드 콘솔·클러스터·로드밸런서 등 인프라) 접근기록을 1년 이상 보관한다.
5. 보관 기간 동안 접근기록을 유지할 수 있는 저장 용량을 산정·확보하고 사용률을 모니터링(70 % 경고, 85 % 조치)하며, 용량 부족으로 접근기록이 보관 기간 전에 삭제되지 않도록 한다.
6. 접근기록 검토의 주기, 대상, 방법, 검토 수행자, 확인자를 포함한 검토 절차를 지침으로 정하고, 위험기반 접근 방식에 따라 월 1회 이상 접근의 타당성을 검토한다. 접근기록 검토는 7.2.2 감사기록 및 모니터링의 점검항목과 함께 수행한다.
7. 개인정보가 포함될 수 있는 자료(사고 기록)와 민감 레이어(관로 `pipes`·굴착 `excavation`)의 내보내기·다운로드는 내부 관리계획에서 정한 기준에 따라 사유와 적정성을 검토하고, 부적정한 다운로드는 사후조치한다.
8. 검토 과정에서 비인가 접근, 오·남용, 침해 의심 행위를 발견하면 즉시 조치하고 침해사고 대응 절차에 따라 보고한다.
9. 모든 대상 시스템의 시각을 표준 시각원(클라우드 제공자 NTP)과 동기화하여 접근기록의 시간 정보를 신뢰할 수 있게 하고, 월 1회 확인한다.
10. 접근기록 자체에 포함된 개인정보와 이용 기관 정보는 검토·조사 목적의 지정된 인원만 열람하며, 심사·조사 목적으로 외부에 제출할 때는 필요 최소한으로 제한한다.
11. 접근기록 저장소와 백업은 국내에 위치하며, 이용 기관(공공기관)이 자기 기관과 관련된 접근기록을 요청하면 정해진 절차에 따라 제공한다.
12. 본 조항과 하위 지침, 대상 목록은 연 1회 이상 적정성을 검토하고 현행화한다.

## 4. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 접근기록 | 대상 시스템에 로그인한 접속 기록과 접속하여 수행한 행위 기록을 통칭한다. 응용 서비스 감사 기록(`audit_events`), DB 접근로그(Cloud DB for PostgreSQL), 클러스터 API 감사 로그(NKS), 클라우드 콘솔·API 감사 로그(NCP), 개발·배포 환경 감사 로그(GitHub)를 포함한다. |
| 접속 기록 | 계정이 시스템에 로그인·로그아웃하거나 세션을 맺은 기록(성공·실패 포함) |
| 행위 기록 | 접속 후 수행한 명령 실행, 조회·입력·변경·삭제·다운로드·출력, 설정 변경, 권한 변경 등의 기록 |
| 접속기록(고시) | 개인정보처리시스템에 접속하는 자가 수행한 업무내역에 대하여 식별자, 접속일시, 접속지 정보, 처리한 정보주체 정보, 수행업무 등을 전자적으로 기록한 것(개인정보의 안전성 확보조치 기준 제2조제3호) |
| 접근기록 저장소 | 원본 시스템에서 생성된 접근기록을 전송받아 별도로 보관·검색하는 중앙 로그 저장소(NCP Cloud Log Analytics 또는 Object Storage 별도 버킷) |
| 개인정보처리시스템 | 데이터베이스시스템 등 개인정보를 처리할 수 있도록 체계적으로 구성한 시스템(개인정보 보호법 시행령 제30조제1항제2호가목). 서비스는 설계상 개인정보를 수집하지 않으나 사고 기록에 주소가 들어올 수 있어, 해당 여부는 발주처 확인 후 확정한다. 확정 전에는 개인정보처리시스템에 준해 관리한다. |
| 검토 수행자 | 접근기록을 실제로 조회·분석하여 이상 여부를 판단하고 기록하는 사람 |
| 확인자 | 검토 수행자의 검토 결과와 조치를 확인·승인하는 사람으로, 검토 수행자와 다른 사람이어야 한다 |

## 5. 역할과 책임

| 역할 | 책임 |
| --- | --- |
| 최고경영자 | 접근기록 관리 정책 승인, 접근기록 저장소·백업에 필요한 자원 지원 |
| 정보보호 최고책임자(CISO) | 접근기록 관리 절차·대상 목록 승인, 검토 결과 보고 접수, 중대한 이상 접근에 대한 조치 결정, 접근기록 삭제·보존 예외 승인 |
| 개인정보 보호책임자(CPO) | 사고 기록 등 개인정보가 포함될 수 있는 자료의 접속기록·다운로드 검토 결과 확인, 내부 관리계획의 접속기록 보관·점검 사항과의 정합성 관리, 내부 관리계획 이행 실태 연 1회 이상 점검 |
| 정보보호 관리자 | 접근기록 관리 절차·대상 목록 관리, 검토 결과 확인(확인자), 이상 접근 조치 지휘, 연간 적정성 검토 |
| 정보보호 담당자(모니터링·사고 대응) | 접근기록 정기 검토 수행(검토 수행자), 검토 기록 작성, 이상 징후 보고, 보관 기간·용량 실측 |
| 접근기록 저장소 관리자 | 저장소·수집 설정 운영, 보존 정책·백업·무결성 검증 설정 유지, 저장소 접근 권한 관리. 운영(인프라) 담당자와 겸하지 않으며, 인력 부족으로 겸하면 검토 수행자는 다른 사람으로 둔다 |
| 시스템 담당자(운영(인프라) 담당자·개발 책임자) | 담당 시스템의 접근기록 생성 설정, 필수 기록 항목 반영, 저장소 전송 설정, 생성 위치 파악과 목록 등재 요청 |
| 개발 책임자 | api 의 감사 기록(`audit_events`)에 수행업무·대상·결과·접속지 IP·request_id 를 남기는 기능 구현·유지 |
| 임직원·외부인력 | 개인 계정 사용, 계정 공유 금지, 검토 과정의 소명 요청에 협조 |
| 이용 기관(이용자) | 이용 기관 계정·권한 관리, 자기 기관 접근기록 요청과 검토, 이상 발견 시 당사 신고 |
| IaaS/PaaS 제공자(NCP) | 물리 시설·하이퍼바이저·NKS 컨트롤 플레인·관리형 DB 내부 관리 계층의 접근기록 생성·보관과 관리형 서비스의 감사 로그 기능 제공(제공자 인증·계약으로 확인) |

## 6. 보관 기간 기준

| 구분 | 대상 | 최소 보관 기간 | 근거 |
| --- | --- | --- | --- |
| 개인정보처리시스템 접속기록 | 개인정보처리시스템에 접속한 자(정보주체 제외)의 접속기록 | 1년 이상 | 개인정보의 안전성 확보조치 기준 제8조제1항 본문 |
| 개인정보처리시스템 접속기록(가중) | 5만명 이상 정보주체의 개인정보를 처리하거나 고유식별정보 또는 민감정보를 처리하는 개인정보처리시스템 | 2년 이상 | 같은 기준 제8조제1항 각 호 |
| 접근권한 기록 | 개인정보처리시스템 접근권한의 부여·변경·말소 내역 | 3년 이상 | 같은 기준 제5조제3항 |
| 서비스 접속·감사 기록 | api 의 로그인·로그아웃·실패, 권한 변경, 데이터셋 업로드·빌드·활성화, 내보내기, 사고 기록 변경, 관리자 설정 변경 기록(`audit_events`)과 그 사본 | 3년 이상 | 당사 기준(개인정보처리시스템 해당 시 법정 요건을 모두 충족하는 값) |
| 주요 시스템 접근기록 | NCP 콘솔·API, NKS 클러스터 API 감사, 로드밸런서, Cloud DB 접근로그, GitHub 조직 감사 로그, 접근기록 저장소 등 JAS-10.1.2-03의 인프라 대상 시스템 | 1년 이상 | 당사 기준(위험평가 결과) |
| 애플리케이션 일반 로그 | web·api·pipeline 의 요청·오류 로그 | 1년 이상 | 당사 기준 |
| 이용 기관 요구 | 이용 기관과의 계약·보안서비스 수준 협약에서 정한 기간 | 계약에서 정한 기간 | 이용 기관 계약, 14.1.1 보안서비스 수준 협약 |
| 사고 관련 기록 | 침해사고·조사 대상 기간의 접근기록 | 사고 종결 후 3년 또는 법적 절차 종료 시까지 | 당사 기준 |

- 하나의 시스템에 여러 기준이 적용되면 가장 긴 기간을 적용한다.
- 정보주체 수가 5만명에 도달하거나 고유식별정보·민감정보를 새로 처리하게 되면 해당 시스템의 보관 기간을 재판단하고 저장 용량을 재산정한다. 당사 기준 3년은 가중 기준 2년보다 길어 추가 상향은 필요하지 않다.

## 9. 위반 시 조치

접근기록을 임의로 삭제·변조하거나 생성을 중단한 경우, 계정을 공유하여 접근 주체를 식별할 수 없게 한 경우, 검토 절차를 이행하지 않거나 검토 결과를 허위로 기록한 경우, 검토 과정의 소명 요청에 정당한 사유 없이 응하지 않은 경우에는 인사 규정과 보안 서약에 따라 조치한다. 외부인력은 계약에 따라 조치한다.

## 10. 검토 및 개정

- 본 조항과 하위 지침·대상 목록은 연 1회 이상 검토하고, 관련 법령·고시 개정, 서비스·시스템 변경, 침해사고 발생, 이용 기관 요구 변경 시 즉시 개정한다.
- 개인정보 보호책임자는 접속기록 보관·점검을 포함한 내부 관리계획 이행 실태를 연 1회 이상 점검한다(개인정보의 안전성 확보조치 기준 제4조제4항).
