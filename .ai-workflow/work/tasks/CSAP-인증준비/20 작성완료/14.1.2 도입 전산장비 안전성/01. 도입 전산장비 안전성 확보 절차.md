> [!info] 법령 기준
> 전자정부법 제56조제3항(법률 제21394호, 2026. 8. 28. 시행): 정보통신망을 이용하여 전자문서를 보관·유통할 때 위조·변조·훼손 또는 유출을 방지하기 위하여 국가정보원장이 안전성을 확인한 보안조치를 하여야 한다. 국가 사이버보안 기본지침 제20조(정보통신제품 도입)와 제5절 보안적합성 검증은 비공개 지침으로 문서명만 인용하며, 세부 요건은 국가정보원이 공지한 보안적합성 검증 정책으로 확인한다. 법령이 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 공공기관에 제공하는 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS, 이하 "JAS")의 시스템을 보호하기 위해 도입하는 보안기능을 가진 정보통신제품이 국가정보원장이 안전성을 확인한 제품이 되도록 도입 요건, 도입 절차, 운영 중 인증 유효성 관리 기준을 정한다.

## 2. 적용 범위

### 2.1 당사 책임 범위

- JAS 인증 범위 내 클라우드 시스템을 보호하기 위해 당사가 직접 선정·도입·운영하는 보안기능을 가진 정보통신제품 전체
  - 정보보호시스템: 당사가 NKS 클러스터에 설치하는 보안 소프트웨어(예: Ingress 컨트롤러의 접근 제한·rate limit 기능, 비밀값 봉인 도구 SealedSecrets, 로그 수집 에이전트), 당사가 별도로 구매·구독하는 백신·EDR, 웹 방화벽, 서버·DB 접근제어, VPN, 자료유출 방지 제품(소프트웨어, 가상 어플라이언스 포함)
  - 당사가 직접 도입·운영하는 네트워크 기능 소프트웨어
  - 보안기능(식별·인증, 접근통제, 암호화, 로깅·감사)을 수행하는 서비스 구성 소프트웨어: web 컨테이너의 nginx, api 컨테이너의 Node.js 런타임(TLS·암호 라이브러리 포함)
- 도입 형태(구매, 구독, 오픈소스 기반 구축)와 무관하게 적용한다.
- 당사가 직접 개발한 응용 프로그램(api 의 인증·권한·감사 기능)은 정보통신제품 도입이 아니므로 본 절차 대상이 아니며, 13.1.2 인증 및 암호화 기능과 13.2.1 구현 및 시험으로 관리한다. 암호 기능의 검증필 암호모듈 적용은 14.3.1 검증필 암호화 기술 제공에서 관리한다.
- 개발 단계 보안 도구(gitleaks, semgrep, trivy, OWASP ZAP, k6)는 운영 시스템에 설치되지 않는 개발·시험 도구이므로 본 절차 대상에서 제외한다. 운영 시스템에 설치하게 되면 본 절차를 적용한다.

### 2.2 IaaS/PaaS 제공자 책임 범위

- 책임공유모델에 따라 IaaS/PaaS 제공자(네이버클라우드, NCP 공공기관용 영역)가 자체 인프라 보호를 위해 도입·운영하는 물리 네트워크 장비, 물리 보안 장비, 하이퍼바이저 보호 수단은 제공자 책임이며, 제공자의 CSAP 인증과 이용 계약으로 확인한다.
- 제공자가 제공하는 관리형 보안 서비스(NCP Load Balancer 의 TLS 종단, 웹 방화벽, SSL VPN, Key Management Service, Cloud DB for PostgreSQL · Object Storage 의 접근통제·암호화 기능 등)는 제공자 인증 범위로 안전성을 확인하되, 보안 정책·규칙 설정은 당사 책임으로 관리한다. 관리형 서비스가 사전 인증 필수 제품군(예: 웹 방화벽, VPN)에 해당하면 제공자에게 해당 서비스의 CC 인증·보안기능 확인서 보유 여부를 확인하고 결과를 기록한다.
- 확인 결과는 양식 02. 보안기능 정보통신제품 목록 3항에 기록한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 보안기능을 가진 정보통신제품 | 식별·인증, 접근통제, 암호화, 로깅·감사 등 보안기능을 수행하는 정보통신제품(전산장비) |
| CC 인증 | 공통평가기준(Common Criteria)에 따른 정보보호제품 평가·인증. 국내 CC 인증과 국제 CC 인증(CCRA)으로 구분한다. |
| 보안기능 확인서 | CC 인증 대상이 아니거나 인증을 받지 않은 제품의 보안기능 안전성을 국가정보원 기준에 따라 확인한 문서 |
| 성능평가서 | 정보보호제품 성능평가 제도에 따라 제품의 보안 성능을 평가한 결과 문서 |
| 보안적합성 검증 | 국가·공공기관에 도입되는 정보통신제품의 안전성을 국가정보원이 검증하고 발견된 취약점을 제거하도록 하는 제도 |
| 검증필 제품 목록 | 국가정보원장이 안전성을 확인한 제품의 목록. IT보안인증사무국(<https://www.itscc.kr>)과 국가사이버안보센터(<https://www.ncsc.go.kr>)에서 확인한다. |
| 형상 변경 | 인증받은 제품의 구성요소(모듈, 버전, 주요 설정 구조)가 인증 당시와 달라지는 변경. 컨테이너 기본 이미지 교체·재빌드로 포함 패키지 버전이 바뀌는 경우를 포함한다. |
| 관리형 보안 서비스 | IaaS/PaaS 제공자가 운영하고 당사는 정책·규칙만 설정하는 보안 기능 서비스 |

## 4. 도입 요건

| 구분 | 요건 | 확인 방법 |
| --- | --- | --- |
| 사전 인증이 필수적인 제품군 | 국가정보원장이 안전성을 확인한 제품(CC 인증 또는 보안기능 확인서 보유)을 도입한다. 관리형 보안 서비스도 같은 요건으로 확인한다. | 검증필 제품 목록 조회, CC인증서·보안기능 확인서 사본(관리형 서비스는 제공자 제출 자료) |
| 성능평가 대상 제품 | 성능평가 결과를 확인하고 성능평가서를 보관한다. | 성능평가서 사본 |
| 검증필 제품 목록에 없는 제품 | 보안적합성 검증 제도를 통해 검증 과정에서 발견된 취약점을 제거한 후에 사용한다. | 보안적합성 검증 결과, 취약점 조치 기록 |
| 공통 | 도입하는 제품의 버전·형상이 인증받은 버전·형상과 일치해야 하며, 인증 유효기간 이내여야 한다. | 인증서의 제품명·버전·유효기간과 도입 제품 대조 |
| 사전 인증 필수 제품군이 아닌 구성 소프트웨어(nginx, Node.js 등) | 인증 요건 대상이 아님을 판단 근거와 함께 기록하고, 공개 취약점 관리(trivy 이미지 검사, 의존성 audit, 기본 이미지 주 1회 재빌드)로 안전성을 유지한다. | 양식 03 검토서 2항 또는 양식 02 비고의 판단 근거, 야간 trivy 결과 |

- 제품군별 인증 요건(필수 인증 대상, 등급, 국제 CC 인증 인정 범위 등)은 국가정보원이 공지한 보안적합성 검증 정책을 따르며, 도입 검토 시점에 최신 공지를 확인한다.
- 요건 충족 여부가 불분명한 제품은 도입 전에 IT보안인증사무국 또는 국가사이버안보센터에 문의하고 확인 내용을 양식 03. 도입 전산장비 안전성 검토서에 기록한다.

## 5. 도입 절차

| 단계 | 담당 | 내용 | 기록 |
| --- | --- | --- | --- |
| 1. 수요 제기 | 수요 부서(개발 책임자 또는 운영(인프라) 담당자) | 도입 목적, 요구 기능, 설치 위치(NKS 네임스페이스·서브넷), 예산을 제기 | 도입 요청 문서(저장소 이슈 또는 메일) |
| 2. 대상 판단 | 정보보호 관리자 | 보안기능 보유 여부와 사전 인증 필수 제품군 해당 여부 판단 | 양식 03. 검토서 2항 |
| 3. 요건 확인 | 정보보호 관리자 | 검증필 제품 목록 조회, CC인증서·보안기능 확인서·성능평가서 확인, 인증 버전·유효기간 확인 | 양식 03. 검토서 3–4항 |
| 4. 검토·승인 | 정보보호 최고책임자 | 검토 결과 승인(적합·조건부 적합·부적합) | 양식 03. 검토서 6항 |
| 5. 계약·구매 | 구매 담당 | 계약서·발주서(관리형 서비스는 이용 신청)에 인증받은 제품명·버전과 인증 요건 유지 조건을 명시 | 계약서 |
| 6. 설치·검수 | 운영(인프라) 담당자 | 설치된 제품의 버전·형상이 인증 내용과 일치하는지 검수. 컨테이너 이미지는 태그와 다이제스트로 고정해 기록 | 검수 기록, 양식 05. 증적 |
| 7. 등재 | 정보보호 관리자 | 양식 02. 보안기능 정보통신제품 목록과 정보자산목록에 등재 | 양식 02. 목록 |

- 승인 전에는 계약·구매와 운영 클러스터 배포를 진행하지 않는다. 긴급 도입이 필요한 경우 정보보호 최고책임자의 사전 승인을 받고 5영업일 이내에 검토서를 사후 작성한다.
- 운영 클러스터에 설치하는 소프트웨어는 Helm chart · values 변경 PR 로 들어오므로, PR 리뷰 시 본 절차 대상 여부를 확인한다(13.2.1 변경 관리와 연계).

## 6. 운영 중 인증 유효성 관리

1. 정보보호 관리자는 연 1회 이상 양식 04. 안전성 인증 유효성 점검표로 운영 중인 제품 전체의 인증 유효성(유효기간, 운영 버전과 인증 버전의 일치, 형상 변경 여부)을 점검한다.
2. 제품의 버전 업그레이드, 패치, 모듈 추가, 컨테이너 기본 이미지 교체 등 형상 변경 전에 변경 후에도 인증 효력이 유지되는지(인증 유지 버전 범위, 재인증 필요 여부) 확인하고 결과를 기록한다. 인증 요건 대상이 아닌 구성 소프트웨어는 이 확인을 생략하고 취약점 점검 결과만 기록한다.
3. 인증 유효기간 만료 6개월 전까지 갱신 인증 확인, 후속 버전 전환, 대체 제품 도입 중 하나로 계획을 수립한다.
4. 미인증 버전 운영, 인증 효력을 상실한 형상 변경, 유효기간 초과가 확인되면 지체 없이 정보보호 최고책임자에게 보고하고 인증 유효 버전 전환, 대체 제품 도입, 보안적합성 검증 이행 중 하나로 조치한다. 조치 완료까지 위험 평가를 거쳐 보완 통제(접근 최소화, 모니터링 강화 등)를 적용한다.
5. 제품을 폐기·교체하면 양식 02. 목록에서 상태를 변경하고 정보자산목록에 반영한다.
6. 관리형 보안 서비스는 연 1회 제공자의 CSAP 인증 유효성과 해당 서비스의 인증 현황을 확인한다.

## 7. 역할과 책임

| 역할 | 책임 |
| --- | --- |
