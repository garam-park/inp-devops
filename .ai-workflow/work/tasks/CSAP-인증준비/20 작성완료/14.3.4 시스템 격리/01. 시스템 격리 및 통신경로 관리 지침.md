> [!info] 법령 기준
> 행정기관 및 공공기관의 클라우드컴퓨팅서비스 이용 기준 및 안전성 확보 등에 관한 고시 제11조(행정안전부고시 제2025-79호, 2025. 12. 29. 시행)와 개인정보의 안전성 확보조치 기준 제8조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 국가 사이버보안 기본지침 제131조(보안관제센터 설치·운영)는 비공개 지침으로 문서명만 인용한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 공공기관에 제공하는 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS)에서 보안관제가 이루어지는 서비스 네트워크 이외의 비정상 통신경로가 발생하지 않도록, 시스템 격리 원칙과 정상 통신경로 관리 기준, 주기적 점검·검토 체계를 본 지침으로 정한다.

## 2. 적용 범위

- 지반침하 스마트관리 시스템 인증 범위 내 모든 클라우드 자원: NKS 클러스터(워커 노드, web · api · pipeline 워크로드, Ingress 컨트롤러), Cloud DB for PostgreSQL, Object Storage 버킷, VPC·서브넷·ACG(보안 그룹)·로드밸런서
- 관리 환경: NCP 콘솔, NKS API 엔드포인트(kubectl), 관리 VPN·배스천, 배포 파이프라인(GitHub Actions self-hosted runner), 컨테이너 레지스트리
- 서비스 운영·관리 목적으로 클라우드 자원에 접근하는 모든 임직원과 외부인력
- 공공 이용 기관에 할당된 자원·데이터와 그 통신경로
- 사내 개발·스테이지(`dev0`)와 로컬 환경은 인증 범위 밖이다. 다만 운영과의 통신경로가 생기지 않도록 6.3항의 통제를 받는다(운영 데이터 반입 금지, 운영 자격증명 미보관).

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 정상 통신경로 | 서비스 제공과 운영·관리에 필요하여 양식 02. 정상 통신경로 목록에 등재하고 승인받은 통신경로 |
| 비정상 통신경로 | 정상 통신경로 목록에 없는 모든 통신경로. 미승인 개방 포트, 허가되지 않은 원격 접속 경로, 테넌트 간 미차단 통신, 가상머신 탈출·은닉 채널 등을 포함한다. |

## 5. 격리 및 접근통제 원칙

### 5.1 관리자 접근통제

1. 운영·관리자는 이용 기관에 할당된 자원(메모리, 저장공간 등)과 데이터에 임의로 접근할 수 없으며, 접근이 필요한 경우 사전 승인(장애 조치 등 긴급 시 사후 1영업일 이내 승인)을 받고 접근 기록을 남긴다. 승인권자는 정보보호 관리자이고, 접근 사유·대상·기간을 변경 요청 기록에 남긴다.
2. 관리자 접근은 관리 네트워크(관리 VPN 접속 후 배스천 경유, 또는 VPN 출구 IP 로 제한된 NCP 콘솔·NKS API 엔드포인트)로만 허용하고, TOTP 다중 인증을 적용한다(공통 기준 §3.1).
3. 원격관리서버(SSH 등)는 6.1항의 설정 기준을 준수하며, 인터넷에서 직접 접근할 수 없게 한다. 당사는 NKS 워커 노드에 SSH 로 접속하지 않는 것을 원칙으로 한다.
4. 관리자 계정·권한은 2.1.2 주요 직무자 지정 절차를 따르고 최소 인원으로 제한한다. 응용 관리자 역할(`admin` · `service`)도 같은 원칙을 따른다.
5. 운영 DB 의 앱 계정은 감사 테이블(`audit_events`)에 INSERT·SELECT 만 가진다. 운영자 개인 DB 계정은 조회 전용을 기본으로 하고 변경 권한은 승인 기간에만 부여한다.

### 5.2 이용자(테넌트) 간 격리

1. 이용자가 본인에게 할당된 자원 이외의 자원에 접근하지 못하도록 인증·인가를 적용한다. api 가 모든 요청을 세션으로 인증하고, 역할(`admin` · `service` · `user`)과 레이어 권한(`role_permissions`, 민감 레이어 `pipes` · `excavation`)을 서버에서 집행한다. 브라우저는 스토리지를 직접 접근하지 않고 api 중계만 쓴다.
2. 컨테이너 기반 구성에서는 네임스페이스·워크로드 간 네트워크 통신을 기본 차단(default deny)하고, 필요한 통신만 NetworkPolicy 로 명시적으로 허용한다. 허용 목록은 양식 02 2항과 같다.
3. 이용 기관(계약)별 운영 인스턴스를 분리한다. 계약마다 전용 네임스페이스, 전용 database(관리형 PostgreSQL 안의 별도 database 와 계정), 전용 버킷(또는 버킷과 접근 키 분리)을 두어 다른 이용 기관의 워크로드·데이터와 혼용하지 않는다. 공공 이용 기관의 인스턴스를 민간 고객과 공유하지 않는다(gis-sass CSAP ADR, 14.3.5).
4. 같은 계약 안의 사용자(발주처와 산하 기관 사용자) 사이 구분은 이 항 1호의 역할·레이어 권한으로 통제한다.
5. 격리 설계와 적용 현황은 양식 02. 정상 통신경로 목록 5항에 기록한다.

### 5.3 무선망 분리

1. 클라우드 서비스 운영 네트워크(NCP 공공기관용 VPC)는 무선망과 분리되어 있고 무선 접점이 없다. 무선망에서 운영 자원·관리 네트워크로 직접 접속할 수 없게 한다.
2. 업무용 무선망(사내 Wi-Fi 포함)에서 운영 자원에 접근해야 하는 경우에도 관리 VPN·다중 인증을 거친 관리 네트워크 경유만 허용한다. 운영 자원의 관리 접점(NCP 콘솔 허용 IP, NKS API 엔드포인트 허용 대역, 배스천 ACG)은 VPN 출구 IP 만 허용한다.
3. 운영 네트워크에 무선 접점이 없음과 관리 접점의 허용 IP 목록을 반기 1회 점검으로 확인한다.

### 5.4 정상 통신경로 관리

1. 서비스 제공과 운영·관리에 필요한 모든 통신경로는 양식 02. 정상 통신경로 목록에 등재하고 정보보호 최고책임자의 승인을 받는다.
2. 목록에 없는 통신경로(포트 개방, ACG·네트워크 ACL 규칙, NetworkPolicy, 원격 접속 수단, `kubectl port-forward` 상시 사용)는 생성하지 않으며, 필요 시 6.3항의 변경 절차를 거친다.
3. 모든 외부 진입은 로드밸런서 → Ingress 컨트롤러 하나로만 받고, 모든 통신경로는 로그가 수집되는 구간(보안관제 대상)을 경유하도록 구성한다.
4. 아웃바운드는 DNS, 운영 DB, Object Storage, 허용 목록에 고정한 외부 호스트(브이월드 443)만 허용하고, 사설·루프백·링크로컬 대역으로의 egress 를 차단한다(공통 기준 §3.4).

## 6. 통제 기준

### 6.1 원격관리서버(SSH 등) 설정 기준

당사의 원격관리 경로는 NCP 콘솔, NKS API 엔드포인트(kubectl), DB 관리 접속(배스천 경유)이다. 워커 노드 SSH 는 상시 사용하지 않으며, 장애 분석 등 비상 시에만 6.3항 승인을 받아 아래 기준으로 연다.

| No | 설정 항목 | 기준 |
| --- | --- | --- |
| 1 | 접근 경로 | 배스천 호스트 또는 관리 VPN 경유만 허용, 인터넷 직접 접근 차단. 워커 노드 ACG 에 SSH(22) 인바운드 규칙을 두지 않는다 |
| 2 | 접근 IP | 관리 VPN 대역(양식 02 3항에 기재)으로 제한 |
| 3 | 인증 방식 | 키 기반 인증, 패스워드 인증 비활성화. kubectl 은 개인별 인증 정보(공용 kubeconfig 금지) |
| 4 | 루트 직접 로그인 | 금지(PermitRootLogin no) |
| 5 | 포트 | 해당 없음 — 노드 SSH 를 상시 열지 않으므로 포트 변경 대상이 없다. 비상 개방 시 기본 22 를 배스천 출발지로만 허용하고 작업 종료 즉시 규칙 삭제. 미사용 포트 차단 |
| 6 | 세션 | 유휴 세션 타임아웃 30분(공통 기준 §3.1), 배스천 접속 기록 3년 보관(공통 기준 §3.2) |
| 7 | 다중 인증 | 관리 VPN 진입과 NCP 콘솔 로그인에 TOTP 적용 |

### 6.2 취약점 점검 및 패치

1. 가상머신 탈출, 은닉 채널 생성, 컨테이너 격리 우회(런타임·커널 취약점) 등 비정상 통신경로를 발생시킬 수 있는 최신 보안 취약점을 월 1회 이상 점검·확인한다. 자동 점검(야간 trivy 이미지·잠금파일 점검, ZAP)은 매일 수행한다(공통 기준 §3.4).
2. 영향받는 취약점은 위험도에 따라 긴급(Critical·악용 확인) 72시간, 고위험(High) 14일 이내 보안패치를 적용하고, 패치 이력을 보관한다(공통 기준 §3.4 · §3.6). 기본 이미지는 주 1회 재빌드한다.
3. IaaS/PaaS 제공자의 보안 공지·긴급 패치 안내(NCP 공공기관용 공지, NKS 버전·노드 이미지 안내)를 구독하고, 제공자 책임 영역의 조치 완료 여부를 확인한다.

### 6.3 통신경로 변경 절차

| 단계 | 담당 | 내용 | 기록 |
| --- | --- | --- | --- |
| 1. 신청 | 요청 부서 | 구간, 프로토콜·포트, 용도, 기간을 적어 신청 | 변경 요청서(제품 저장소 GitHub 이슈, 인프라 변경은 Pull Request) |

## 7. 주기적 점검·검토 체계

| 활동 | 내용 | 주기 | 담당 | 기록 |
| --- | --- | --- | --- | --- |
| 통신경로 점검 | 외부·내부 포트 스캔(nmap), ACG·NetworkPolicy 설정 내보내기 결과를 양식 02. 정상 통신경로 목록과 대조하여 비정상 통신경로 식별 | 월 1회 이상 | 정보보호 담당자 | 양식 03. 점검 및 검토 결과서 |
| 격리 통제 점검 | 관리자 접근통제, 테넌트 간 격리(NetworkPolicy, 네임스페이스·database·버킷 분리), 무선망 분리, 원격관리 설정 확인 | 분기 1회 이상 | 정보보호 담당자 | 양식 03. 점검 및 검토 결과서 |
| 취약점 점검 | 가상머신 탈출·은닉 채널·컨테이너 격리 우회 취약점 점검과 패치 적용 확인 | 월 1회 이상(자동 점검은 매일) | 정보보호 담당자 | 취약점 점검·패치 이력 |
| 상시 모니터링 | 보안관제 대상 네트워크의 비정상 통신 탐지(Ingress·api 로그, NetworkPolicy 거부, ACG 변경 알림), 이상징후 알림 | 상시 | 정보보호 담당자(모니터링) | 모니터링·탐지 기록 |
| 접속기록 자동 분석 | 감사 로그(`audit_events`)를 자동 규칙으로 분석하여(대량 내보내기, 민감 레이어 반복 열람, 업무시간 외 관리자 행위, 비허용 IP 접속 등) 불법적인 개인정보 유출, 오용·남용 시도를 탐지하고 해당자에게 사유를 소명하게 함 | 월 1회 이상 점검, 탐지 시 즉시 | 정보보호 담당자, 개인정보 보호책임자 | 접속기록 분석·소명 기록(10.1.2 와 공용) |
| 정기 검토 | 점검 결과 종합, 기준선(02 목록) 현행화 필요 여부, 통제 개선 사항을 정보보호 최고책임자가 검토·승인 | 분기 1회 이상 | 정보보호 최고책임자 | 양식 03. 점검 및 검토 결과서 검토·승인란 |

- 비정상 통신경로가 발견되면 즉시 차단(또는 위험 완화 조치)하고, 원인 분석과 재발 방지 대책을 양식 03. 점검 및 검토 결과서에 기록한다. 침해 징후가 있으면 5.1.1 침해사고 대응 절차를 따른다.
- 점검에 사용하는 기술적 대책(스캔 도구, 모니터링 도구)과 수집 증적은 양식 04. 증적 수집 점검표를 따른다.
