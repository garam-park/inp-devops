## 2. 권장 작성 순서

1. 01 강화된 인증 정책: 강화된 인증의 기본 제공·필수 적용 원칙과 다중 요소 인정 기준을 정하고 정보보호 최고책임자 승인을 받는다.
2. 02 강화된 인증 수단 관리 절차: 제공 인증 수단 카탈로그, 접점별 적용 기준, 추가 통제 방안, 이용자 요청 처리 절차를 정한다.
3. 03 인증 수단 적용 현황표: DNS·로드밸런서·NCP Sub Account·GitHub 조직 구성원 목록 등과 대조해 인터넷에서 로그인할 수 있는 접점을 전수 식별하고 접점별 적용 현황을 작성한다.
4. 05 증적 수집 점검표: 접점별 적용 화면·설정 증적을 확인 항목에 따라 수집하고, 미흡 사항은 조치 후 재수집한다.
5. 04 강화된 인증 수단 요청 처리 대장: 안내 채널을 정비하고, 이용자 요청의 접수·검토·적용·회신 이력을 기록한다.

## 3. 심사 대비 체크리스트

기준일 2026-10-20 현재 충족 여부다.

- [ ] 인터넷을 통해 로그인할 수 있는 관리자 포털·이용자 포털·클라우드 콘솔·원격 접속 경로 등 접점을 전수 식별했고, 아이디·비밀번호 외 강화된 인증 수단이 적용되어 있다. — 접점 식별은 목표 구조로 완료(03 현황표 2항). 적용은 미충족: 로그인·TOTP 미구현, NCP 콘솔·VPN 구축 전, GitHub 조직 필수 설정 꺼짐
- [ ] 2차 인증이 아이디·비밀번호 재입력, 2차 비밀번호, PIN 등 지식 요소의 반복이 아니라 소유·생체 요소 기반이다. — 설계는 TOTP(소유)로 확정(02 절차 4·5항), 구현 전
- [ ] 이용자 요구 시 인증서(PKI) 기반, OTP, 지문 등 다중 인증 수단을 제공할 수 있고, 제공하지 않는 수단은 검토·제공 계획으로 대응한다. — 제공 계획(04 대장 3항)은 작성. OTP 미구현
- [ ] 강화된 인증 수단을 기본적으로 제공하고 이용자가 사용 여부를 선택할 수 있으며, 이용 기관이 요청하면 기관 단위로 강제할 수 있다. — 정책·절차만 있음, 기능 미구현
- [ ] IP(국가) 제한, MAC 제한, 브라우저 제한 등 추가 통제 방안을 제공하되 인증 요소를 대체하는 수단으로 쓰지 않는다. — 기준은 02 절차 7항, Ingress 허용 IP·WAF 는 운영 환경 구축 전
- [ ] 정보통신망을 통해 외부에서 관리시스템에 접속하는 경우 VPN 등 안전한 접속 수단과 추가 인증 수단을 함께 적용한다. — VPN·배스천 구축 전
- [ ] IaaS/PaaS 콘솔의 루트 계정과 모든 IAM 사용자에 다중 요소 인증이 활성화되어 있고, 관리자 포털·콘솔 루트 계정에는 예외를 허용하지 않는다. — 예외 불허 원칙은 정책에 반영. NCP 운영 계정 미개설
- [ ] 강화된 인증 없이 관리 기능에 도달할 수 있는 우회 경로(구 로그인 화면, 기본 인증 API 등)가 없음을 주기적으로 점검한다. — 점검 방법(라우트 순회 시험)만 정함. 현재는 인증 자체가 없어 모든 경로가 우회 상태
- [ ] 이용자 요청의 접수·검토·적용·회신 이력이 대장에 기록되어 있고, 안내 자료가 현재 제공 수단과 일치한다. — 대장 양식은 준비, 안내 자료 미게시(운영 전)
- [ ] 적용 화면·설정 증적을 확인 항목에 따라 수집했고, 수집일이 6개월을 지난 증적은 다시 수집했다. — 수집 대상 미구축, 미수집

## 4. 관련 산출물(다른 항목)

- 10.3.2 사용자 인증: 로그인 실패 제한(5회·30분), 세션 관리(비활동 30분·절대 12시간) 등 기본 인증 통제와 연계한다. 강화된 인증은 기본 인증 위에 더하는 수단이다.
- 10.3.4 패스워드 관리: 1차 인증 요소인 비밀번호의 작성 규칙·관리 기준을 따른다.
- 10.1.2 접근기록 관리: 인증 성공·실패 로그(`audit_events` 의 `auth.*`)와 MFA 관련 이상 징후 검토 기록을 연계한다.
- 2.1.2 주요 직무자 지정 및 감독: 관리시스템에 접근하는 주요 직무자 계정에 강화된 인증을 적용하고, 주요 직무자 목록과 접점별 대상 계정을 대조한다.
- 9.1.5 공개서버 보안: 공개서버 목록(web · api)을 접점 전수 식별의 대조 자료로 활용한다.

## 5. 작성 규칙

- 이중 중괄호로 남은 자리표시자는 각 문서의 `> [!warning] 대기` 블록에 적은 조건이 충족되거나, 비기술 양식(1.2.1 조직 구성 등)이 확정되면 채운다.
- 서명이 필요한 문서는 서명본을 스캔해 사내 문서 저장소 `CSAP/서명본/10.3.3/` 에 보관하고, md 원본에는 서명본 보관 위치를 적는다.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신한다.
- 현황표·대장(03, 04)은 버전을 올릴 때 이전 버전을 삭제하지 않고 3년간 보관해서 특정 시점의 현황을 확인할 수 있게 한다.
- 증적 화면 캡처에는 시스템명·URL·캡처 일시가 보이게 하고, 개인정보와 비밀 값(OTP 시드·QR 코드·백업 코드)은 마스킹한다.
- 법령 인용은 개인정보의 안전성 확보조치 기준 제6조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.
