> [!info] 법령 기준
> 사이버안보 업무규정 제14조(대통령령 제34287호, 2024. 3. 5. 시행)를 기준으로 작성했다. 제14조제2항에 따라 국가기관등은 통합보안관제체계와 연계된 보안관제센터를 설치·운영하거나 다른 기관의 보안관제센터를 활용하며, 제14조제4항에 따라 국가정보원장은 클라우드컴퓨팅서비스 제공자에게 보안관제에 필요한 협조 또는 지원을 요청할 수 있다. 국가 사이버보안 기본지침 제24조의3·제24조의4·제131조와 국가 클라우드 컴퓨팅 보안 가이드라인(부록7 민간 클라우드 컴퓨팅 서비스 보안관제 체계 포함)은 비공개 문서라 문서명만 적는다. 법령이 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS, 하등급 SaaS)을 국가기관등에 제공할 때, 이용기관이 공공 영역 대상 사이버공격·위협을 탐지하기 위한 보안관제를 수행하고 그 탐지정보를 정부보안관제체계와 연계할 수 있도록 필요한 제반환경을 지원하는 기준과 절차를 정한다.

## 2. 적용 범위

- 지반침하 스마트관리 시스템을 이용하는 모든 국가기관등(중앙행정기관, 지방자치단체, 공공기관)과의 계약. 2026-10-20 현재 대상은 제주특별자치도(발주처)와 산하 공공기관이다.
- 이용기관의 보안관제센터(자체 운영 또는 다른 국가·공공기관 보안관제센터 위탁)와 정부보안관제체계에 대한 연계 지원 업무
- 보안관제 지원을 위해 당사가 제공하는 로그, 보안이벤트, 탐지정보, 계정, 연계 구간 전체
- 인증 대상이 아닌 사내 개발·스테이지(`dev0`)와 로컬 환경은 적용 대상이 아니다. 이 환경의 로그를 이용기관에 제공하지 않는다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 보안관제 | 사이버공격·위협을 즉시 탐지·대응하는 활동(사이버안보 업무규정 제14조제1항) |
| 정부보안관제체계 | 국가정보원장이 구축·운영하는 통합보안관제체계와 이에 연계된 국가·공공기관 보안관제 체계 |
| 이용기관 보안관제 영역 | 이용기관이 보안관제를 수행하는 영역. 자체 보안관제센터 또는 위탁받은 다른 기관의 보안관제센터를 포함한다. |
| 탐지정보 | 이용기관 보안관제 영역에서 탐지기술을 적용해 생성하거나, 당사가 서비스 운영 중 탐지하여 제공하는 사이버공격·위협 관련 정보 |
| 제반환경 | 이용기관의 보안관제 수행과 정부보안관제체계 연계에 필요한 로그·이벤트 제공 체계, 관제용 접근 수단, 연계 구간, 협조 체계 등 일체 |

## 4. 책임공유모델에 따른 지원 범위

당사는 IaaS/PaaS 제공자의 인프라 위에서 SaaS를 제공하므로, 보안관제 제반환경 지원 책임을 다음과 같이 구분한다.

| 주체 | 책임 범위 |
| --- | --- |
| 당사(SaaS 제공자) | 서비스·응용 계층의 로그와 보안이벤트 생성·제공(Ingress 접근 로그, api 인증·감사 이벤트, 웹 방화벽 탐지 이벤트), 보안관제용 접근 수단 제공, 이용기관 보안관제 영역·정부보안관제체계와의 연계 기반 제공, 침해사고 관련 협조 |
| IaaS/PaaS 제공자 | 물리 인프라·하이퍼바이저·네트워크 기반 계층의 보안관제 기반. 네이버클라우드 플랫폼(공공기관용)의 CSAP IaaS 인증과 이용 계약으로 확인하고(인증서 사본은 양식 04 No 8 로 보관), 당사가 활용 가능한 관제 지원 기능(관리형 로그 서비스 Cloud Log Analytics, 콘솔 행위 감사 기록, 보안 그룹·로드밸런서 로그 — 공공기관용 영역 제공 여부는 운영 환경 구축 시 확인)의 범위를 5항에 반영한다. |
| 이용기관 | 보안관제 수행 주체 결정(자체 또는 위탁), 보안관제 영역에서 탐지기술 적용·보안관제 수행, 탐지정보의 정부보안관제체계 연계 |

- 지반침하 스마트관리 시스템이 이용기관 전용 격리 영역(전용 VPC 등)을 이용기관에 할당하는 구조인지: 해당 없음 — 당사는 SaaS 로 제공하며 이용기관에 VPC·서버 접근을 할당하지 않는다. 운영 인스턴스는 계약(이용기관) 단위로 분리해 당사 공공기관용 영역 안에서 운영하고(14.3.4 01 5.2항), 이용기관의 보안관제는 ENV-01–ENV-04 의 로그·이벤트 제공으로 지원한다.

## 5. 제공 가능한 제반환경 항목

당사가 국가기관등에 제공할 수 있는 제반환경 항목을 다음과 같이 정의한다. 기관별 제공 여부와 구성 내용은 양식 02. 보안관제 연계 환경 구성 내역서에 기록한다.

| 항목 코드 | 항목 | 내용 | 제공 방식 | 비고 |
| --- | --- | --- | --- | --- |
| ENV-01 | 서비스 로그 제공 | Ingress 접근 로그, api 요청 로그(request_id 포함), 이용자·관리자 접근기록(공통 기준 §3.2 필수 항목: 계정·일시·접속지 IP·행위·대상·결과·request_id), 인증 성공·실패·잠금 기록, 관리자 행위(권한 변경·데이터셋 활성화·설정 변경) 기록 | 기관이 지정한 방식 중 하나: syslog over TLS(RFC 5425) 실시간 전송, 또는 JSON Lines 파일 주기 전송(HTTPS, 1일 1회 이상) | 10.1.2 접근기록 관리와 연계. 원천 로그는 국내 리전 로그 저장소(공통 기준 §3.2)에서 추출한다 |
| ENV-02 | 보안이벤트·탐지정보 제공 | 당사 보안 시스템(NCP 공공 웹 방화벽, Ingress rate limit·본문 크기 제한 차단, api 로그인 연속 실패 잠금·인가 거부)의 탐지 이벤트와 침해 시도 정보 | ENV-01 과 같은 경로로 실시간(syslog) 또는 주기(파일) 전송. 침해사고로 판단된 건은 14.1.4 절차로 별도 통지 | 웹 방화벽은 도입 예정(공통 기준 §3.4) |
| ENV-03 | 보안관제용 접근 수단 | 이용기관 또는 위탁 관제센터의 관제 요원에게 해당 기관 로그만 조회할 수 있는 조회 전용 계정 제공. 응용(서비스) 관리자 계정·운영 콘솔 계정은 제공하지 않는다 | 로그 저장소의 조회 전용 하위 계정 | 조회 전용 권한, TOTP 다중 인증 필수, 분기 1회 계정 검토(공통 기준 §3.1) |
| ENV-04 | 정부보안관제체계 연계 기반 | 이용기관 보안관제 영역이 탐지정보를 정부보안관제체계와 연계할 수 있도록 기관 요구 형식(필드 매핑, 시각 표기 KST/UTC, 인코딩)·전송 방식에 맞춘 로그·탐지정보 제공 | 기관 요구 형식에 따름(양식 02 2항에 협의 결과 기록) | 부적합 사례 1 예방 |
| ENV-05 | 연계 구간 구성 | 당사 서비스와 이용기관 보안관제 영역 간 전송 구간의 구성(출발지·목적지·포트 고정, 허용 목록 기반 egress)과 전송 구간 암호화 | TLS 1.2 이상(1.3 우선), 취약 cipher 비활성(공통 기준 §3.3). 기관이 요구하면 IPsec VPN | 검증필 암호모듈 적용 방식은 14.3.1 산출물의 결정을 따른다(14.3.1 연계) |
| ENV-06 | 연계 시험 지원 | 연계 구성·변경 시 로그 수신, 탐지정보 연계, 암호화 적용을 확인하는 시험 지원 | 시험 계획·결과 상호 확인 | 양식 02 5항 |
| ENV-07 | 침해사고 협조 | 침해사고·이상징후 관련 정보 공유, 국가정보원·보안관제센터의 협조 또는 지원 요청 대응 | 협조 창구: 정보보호 관리자 | 사이버안보 업무규정 제14조제4항, 14.1.4 연계 |

- 이용기관이 위 항목 외의 환경을 요구하면 지원 가능성을 검토해 항목을 추가하고, 본 절차를 개정한다.
- 제공하는 로그에는 다른 이용기관의 로그, 비밀값(세션 토큰·쿠키·키), 비밀번호를 포함하지 않는다. 로그 생성 단계에서 해당 필드를 기록하지 않거나 마스킹한다.

## 7. 계약 전 사전 검토 체크리스트

부적합 사례(정부보안관제체계 연계 제반환경 마련 불가, 기관 요구 연계 지원 불가)를 예방하기 위해 계약 체결 전에 확인한다. 결과는 계약(기관)별로 ○ 또는 X 로 기록하고, 양식 02 1항에 수행일과 지원 불가 판정 여부를 옮겨 적는다.

| No | 확인 항목 | 결과 | 확인자 |
