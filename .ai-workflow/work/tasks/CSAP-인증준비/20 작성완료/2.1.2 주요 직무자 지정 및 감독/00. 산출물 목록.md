## 2. 권장 작성 순서

1. 01 주요 직무 기준: 중요 정보자산 유형과 주요 직무 기준, 지정 원칙과 절차를 정하고 정보보호 최고책임자 승인을 받는다.
2. 02 주요 직무 기술서: 직무별 취급 자산, 필요 최소 권한, 자격요건, 적정 인원을 정의하고 담당 부서장이 검토한다. 5항의 당사 주요 시스템과 직무 대응을 쓴다.
3. 05 주요 직무자 지정 신청서: 현재 주요 직무를 수행하는 인원을 부서별로 신청·검토·승인한다. 최초 일괄 지정도 개인 단위로 작성한다.
4. 03 주요 직무자 목록: 승인 결과를 시스템 계정·권한 현황(NCP 공공기관용 하위 계정, NKS 접근 권한, DB 개인 계정, GitHub 조직 권한, 응용 `admin` · `service` 계정)과 대조해 작성하고, 대조 자료의 기준일을 기록한다.
5. 04 개인정보취급자 목록: 개인정보 취급이 ○인 인원을 개인정보처리시스템 권한 목록과 대조해 작성한다. 개인정보처리시스템 해당 여부가 발주처 확인 전이므로 확인 결과에 따라 "해당 없음 — 사유"로 둘 수 있다.
6. 06 주요 직무자 적정성 검토서: 반기마다 인사·시스템 자료와 전면 대조하고 결과를 03·04 목록에 반영한다. 계정 검토(분기 1회, 공통 기준 §3.1)와 같은 자료를 쓴다.

## 3. 심사 대비 체크리스트

- [ ] 중요 정보자산을 취급하는 직무를 내부 기준으로 정의했고, 정보보호시스템 관리자·클라우드 콘솔 관리자·형상관리 관리자·네트워크 관리자·암호키 관리자를 빠뜨리지 않았다. — 미충족: 01·02 미작성
- [ ] 주요 직무자를 개인 단위로 신청·검토·승인 절차를 거쳐 공식 지정했고 승인 문서를 보관하고 있다. — 미충족: 05 미작성
- [ ] 주요 직무자 목록의 인원과 실제 시스템 계정·권한 보유자가 일치하며, 대조에 사용한 자료와 기준일을 기록했다. — 미충족: 03 미작성, 운영 계정 미생성
- [ ] 퇴직·인사이동·업무 변경 시 지체 없이 권한을 회수하고 목록을 갱신하는 절차가 있고 해제 이력이 남아 있다. — 미충족: 01 미작성
- [ ] 직무별 적정 인원을 정했고 부서 단위 일괄 지정이나 부서 단위 권한 부여가 없다. — 미충족: 02 미작성
- [ ] 외부인력은 원칙적으로 지정에서 제외했고, 지정한 경우 관리 방안(계정 만료일, 감독자, 서약, 접근기록 검토)을 문서화하고 이행 기록이 있다. — 미충족: 01·05 미작성
- [ ] 개인정보를 취급하는 인원을 개인정보취급자로 지정했고, 권한 부여·변경·말소 기록을 3년 이상 보관하며 개인정보 보호 교육을 연 1회 이상 실시했다. — 미충족: 04 미작성, 개인정보처리시스템 해당 여부 확인 전
- [ ] 주요 직무자 교육 이수, 서약서, 접근기록 검토 등 관리·통제 이행 기록이 있다. — 미충족: 미작성
- [ ] 반기 1회 이상 적정성 검토를 수행하고 결과를 목록 버전에 반영했다. — 미충족: 06 미작성

## 4. 관련 산출물(다른 항목)

- 1.2.1 조직 구성: 정보보호 조직 구성 승인서와 정보보호 직무기술서에서 정한 정보보호 최고책임자·관리자·담당자를 주요 직무자 목록에 등재한다. 정보보호 조직 직무의 책임·자격요건은 1.2.1 직무기술서를 따른다.
- 2.3.2 교육 시행: 주요 직무자 직무별 보안 교육과 개인정보취급자 개인정보 보호 교육의 이수 기록을 통제 이행 증빙으로 활용한다.
- 10.1.2 접근기록 관리: 주요시스템과 개인정보처리시스템의 접근기록 검토 기록(월 1회, 공통 기준 §3.2)을 모니터링 증빙으로 활용한다. 당사 접속·감사 기록 보존은 3년이다.
- 10.3.2 사용자 인증, 10.3.3 강화된 인증 수단 제공: 주요 직무자 계정(관리자 역할, NCP 콘솔, 클러스터·DB 운영 접근)에 TOTP 다중 인증을 적용한다.
- 12.3.1 암호 정책 수립: 암호키 관리자 직무의 키 관리 절차(세션 서명키·DB 비밀번호·스토리지 키, SealedSecrets 봉인 키)를 암호 정책과 맞춘다.
- 14.3.3 데이터 유출 방지, 14.3.4 시스템 격리, 14.3.5 영역분리: 공공 가상자원·데이터와 공공기관용 영역에 접근하는 인력을 주요 직무자로 한정한다.

## 5. 작성 규칙(당사 기준)

- 문서번호는 `JAS-2.1.2-<양식 번호>`, 버전 1.0 으로 시작한다(공통 기준 §2).
- 양식의 자리표시자는 실제 값으로 바꾼다. 표의 빈 칸은 해당 값을 채운다.
- 직무 코드 KD-01–KD-11은 양식 예시다. 당사에 없는 직무는 삭제하고, 추가 직무는 01 기준 5항과 02 기술서에 함께 신설한다. 당사 주요 시스템(주요시스템 접근권한 칸의 기준)은 다음과 같다.
  - NCP 공공기관용 콘솔(하위 계정·권한 관리 포함) — 클라우드 콘솔 관리자
  - NKS 클러스터(kubectl 운영 권한) — 시스템 관리자
  - Cloud DB for PostgreSQL(개인 DB 계정) — DB 관리자
  - Object Storage 버킷·접근 키 — 스토리지 관리자
  - 관리 VPN·배스천·ACG — 네트워크 관리자
  - GitHub 조직·저장소·Actions·배포 runner — 형상관리·배포 관리자
  - k8s Secret·SealedSecrets 봉인 키·세션 서명키 — 암호키 관리자
  - 응용 관리자 역할(`admin` · `service`) — 서비스 관리자
- 서명이 필요한 문서는 서명본을 스캔해 사내 문서 저장소 `CSAP/서명본/2.1.2/` 에 보관하고, md 원본에는 서명본 보관 위치를 적는다. 문서는 3년 보관한다.
- 목록 문서(03, 04)는 버전을 올릴 때 이전 버전을 삭제하지 않고 보관해서 특정 시점의 지정 현황을 확인할 수 있게 한다.
- 법령 인용은 개인정보 보호법 제28조(법률 제20897호, 2025. 10. 2. 시행), 개인정보의 안전성 확보조치 기준 제4조·제5조·제8조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.
- 접속기록 점검 주기는 현행 고시가 내부 관리계획으로 정하도록 위임하고 있어서, "월 1회 이상"은 당사 내부 기준이다(공통 기준 §3.2 로그 검토 주기와 같다).
