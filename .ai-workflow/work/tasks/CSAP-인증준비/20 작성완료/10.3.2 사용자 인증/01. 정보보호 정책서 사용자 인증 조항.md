> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제5조제5항·제6항, 제6조제1항·제2항·제4항(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)을 기준으로 작성했다. 이 고시는 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행)에 근거한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

본 문서는 ㈜이노팸 정보보호 정책서 중 사용자 인증에 해당하는 절이다. 세부 기준과 절차는 JAS-10.3.2-02 사용자 인증 관리 절차(접근통제관리지침의 사용자 인증 절)에 위임한다.

## 1. 목적

㈜이노팸은 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(이하 "서비스")을 제공하기 위한 클라우드 시스템에 대한 모든 접근을 안전한 사용자 인증절차로 통제하여 비인가 접근을 방지하고, 클라우드 시스템과 이용 기관 정보의 기밀성·무결성·가용성을 보호하기 위하여 사용자 인증에 관한 기본 정책을 정한다.

## 2. 적용 범위

- 서비스(하등급 SaaS) 인증 범위 내 클라우드 시스템 전체
  - 이용자 포털: 서비스 web·api(일반 사용자 `user` 기능)
  - 관리자 포털(관리시스템): 서비스의 관리자 기능(`admin`·`service` 역할 전용 라우트)
  - IaaS/PaaS 콘솔·API: NCP 콘솔(메인 계정, Sub Account), NCP API 인증키
  - 운영 서버: NKS 클러스터 API(kubectl), 배스천, NKS 워커 노드
  - DBMS: NCP Cloud DB for PostgreSQL 계정
  - 네트워크: VPN, ACG(보안 그룹)·Load Balancer 관리(NCP 콘솔)
  - 정보보호시스템: 접근기록 저장소, 웹 방화벽(도입 예정)
  - 형상관리·배포 도구: GitHub 조직 `innopam`, GitHub Actions self-hosted runner, NCP Container Registry
  - 모니터링 도구: NCP Cloud Insight(도입 예정)
  - 인증·계정 연동: NKS 의 NCP IAM 연동 인증, 발주처 SSO(OIDC) 연동(도입 검토 중)
- 위 시스템에 접근하는 모든 사용자: 임직원, 외부인력(파견·용역·위탁), 이용 기관 관리자, 이용자
- 책임공유모델에 따라 NCP(IaaS/PaaS 제공자)가 책임지는 물리 시설과 하이퍼바이저 계층, NKS 컨트롤 플레인 내부의 인증 통제는 제공자의 인증·계약으로 확인하고, 당사는 제공자 콘솔·API 계정의 인증 설정과 그 위 계층의 인증 통제를 책임진다.
- 사내 개발 클러스터 `dev0`와 로컬 개발 환경은 인증 범위가 아니다.

## 3. 정책 선언

1. 클라우드 시스템에 대한 접근은 개인별로 발급된 계정과 승인된 인증수단으로 사용자를 인증한 뒤에만 허용하며, 인증을 거치지 않은 접근과 공용 계정 사용을 금지한다. 서비스의 로그인 식별자에는 실명·이메일을 쓰지 않는다.
2. 모든 클라우드 시스템에 시스템 유형과 위험도에 맞는 인증 방식, 로그인 실패 횟수 제한, 세션 관리, 불법 로그인 시도 경고를 적용하며, 그 최소 기준은 사용자 인증 관리 절차에 정한다.
3. 비밀번호 등 인증정보는 길이(10자 이상), 복잡도(3종 이상 조합), 변경 주기, 재사용 제한(최근 3개)을 포함한 강도 기준에 따라 생성·관리하며, 세부 기준은 10.3.4 패스워드 관리 절차를 따른다. 비밀번호는 Argon2id 로 단방향 저장한다.
4. 5회 연속 인증에 실패하면 계정을 30분 잠그거나 관리자가 해제할 때까지 잠그고, 실패 사유를 상세히 노출하지 않는다.
5. 공개 인터넷망으로 접속하는 관리자 기능과 위험도가 높은 접근(관리자 역할 계정, 원격접속, 외부업체 접속, NCP 콘솔, 클러스터·DB 운영 접근)에는 아이디·비밀번호 외의 강화된 인증수단(TOTP 기반 다중 인증)을 적용한다. 이용자에게는 강화된 인증수단을 제공하고 이용 기관이 선택할 수 있게 한다.
6. 관리자 기능 등 관리시스템에는 세션 유휴 시간 제한(30분), 최대 세션 유지 시간(12시간)과 재인증, 동일 계정 동시 접속 제한을 적용하며, 타당한 사유가 있는 예외는 정보보호 최고책임자의 승인과 보완 통제를 조건으로 기한을 정해 허용한다.
7. 싱글사인온(SSO) 등 계정 연동 방식으로 인증하는 경우 인증 도용 시 피해 확대를 막기 위한 별도의 보호대책(중요 시스템 재인증·다중 인증, 토큰 보호, 권한 승계 최소화, 인증 로그 모니터링)을 수립·이행한다.
8. 클라우드 시스템을 새로 도입·개발·변경할 때 설계 단계에서 사용자 인증 통제방안을 검토하고, 인증 통제가 기준을 충족하지 않으면 운영에 반영하지 않는다.
9. 개인정보 보호법과 그 고시, 이용 기관과의 계약, 공공기관 이용 기관의 보안 요구사항 등 법적·계약적 요구사항에 따른 강화된 인증방식을 준수한다.
10. 사용자 인증 설정의 기준 충족 여부와 불법 로그인 시도 경고를 정기적으로 점검·검토하고 결과를 기록한다.

## 5. 역할과 책임

| 역할 | 책임 |
| --- | --- |
| 최고경영자 | 사용자 인증 정책 승인, 인증 강화에 필요한 자원 지원 |
| 정보보호 최고책임자(CISO) | 사용자 인증 관리 절차와 SSO 보호대책 승인, 인증 통제 예외 승인, 점검 결과 승인 |
| 개인정보 보호책임자(CPO) | 사고 기록 등 개인정보가 포함될 수 있는 기능의 인증 통제가 개인정보 보호법과 고시 요구사항을 충족하는지 확인 |
| 정보보호 관리자 | 인증 통제 기준 관리, 시스템별 인증 설정 현황 관리, 정기 점검 수행, 예외 검토 |
| 정보보호 담당자 | 불법 로그인 시도 경고 모니터링·대응, 점검 증적 수집 |
| 시스템 담당자(운영(인프라) 담당자·개발 책임자) | 담당 시스템의 인증 설정 적용·유지, 변경 시 정보보호 관리자 통보 |
| 개발 책임자 | 서비스 설계·개발 시 인증 통제 요구사항 반영, 시험 결과 제출 |
| 임직원·외부인력 | 개인별 계정 사용, 인증수단·인증정보 보호, 이상 로그인 알림 수신 시 즉시 신고 |
| 이용 기관(이용자) | 이용 기관 계정·인증수단 관리, 강화된 인증 선택·적용, 이상 징후 신고 |
| IaaS/PaaS 제공자(NCP) | 물리 시설·하이퍼바이저 계층 인증 통제, 콘솔 다중 인증 기능 제공(제공자 인증·계약으로 확인) |

## 6. 위반 시 조치

- 인증 통제 기준을 충족하지 않는 시스템은 정보보호 관리자가 시스템 담당자에게 시정을 요구하고, 기한 내 시정되지 않으면 정보보호 최고책임자에게 보고한다.
- 공용 계정 사용, 인증정보 공유, 인증 우회 등 정책 위반 행위는 인사 규정과 계약에 따라 조치한다.
- 불법 로그인 시도가 침해사고 또는 그 징후로 판단되면 침해사고 대응 절차(5.1.1)를 따른다.
