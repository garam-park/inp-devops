## 2. 권장 작성 순서

1. 01 정보보호 정책서 사용자 인증 조항: 사용자 인증 기본 정책과 통제 요소를 정하고 최고경영자 승인을 받는다.
2. 02 사용자 인증 관리 절차: 시스템 유형별 최소 기준, 실패 처리, 세션 관리, 다중 인증, 경고·대응, 예외 절차를 정하고 정보보호 최고책임자 승인을 받는다. 서비스 인증 구현의 요구사항으로 개발 책임자에게 전달한다.
3. 04 SSO 및 계정 연동 보호대책서: NKS 의 NCP IAM 연동과 발주처 OIDC 연동에 적용한다. 발주처 SSO 역할 출처 결정(제품 설계 05 §4-4) 후 3.4항을 확정한다.
4. 03 시스템별 사용자 인증 설정 현황: 운영 환경 구축·인증 구현 후 정보자산 목록·NCP 자원 목록과 대조해 모든 시스템의 실제 설정을 적고, 미충족 항목은 예외 승인을 받는다.
5. 05 사용자 인증 통제 점검 기록: 반기마다 설정 점검·동작 시험·경고 검토를 수행하고 결과를 03·04에 반영한다. 사전 확인에서 나온 GitHub 2단계 인증 필수화는 지금 조치한다.
6. 06 증적 수집 점검표: 정기 주기와 심사 전에 화면·설정 증적을 수집하고 최신 상태를 확인한다.

## 4. 관련 산출물(다른 항목)

- 2.1.2 주요 직무자 지정 및 감독: 특수권한 사용자(`admin`, NCP 관리자 Sub Account, 클러스터·DB 관리자, GitHub 조직 소유자)를 주요 직무자로 지정하고, 역할·그룹 매핑 검토 시 주요 직무자 목록과 대조한다.
- 5.1.1 침해사고 대응 절차 수립: 불법 로그인 시도가 침해 성공·유출 의심으로 판단되면 침해사고 대응 절차로 전환한다.
- 10.1.2 접근기록 관리: 로그인 성공·실패·잠금·세션 이벤트를 `audit_events` 접근기록으로 남기고 3년 보관한다.
- 10.3.3 강화된 인증 수단 제공: TOTP 등록·분실·재발급과 이용자 제공 방식은 10.3.3 산출물을 따른다.
- 10.3.4 패스워드 관리: 비밀번호 생성 규칙(10자·3종), 초기 비밀번호 변경, 변경 주기(관리자 90일·이용자 180일 권고) 등 세부 기준은 10.3.4 산출물을 따른다.
- 13.2.1 시험 계획 및 결과: 인증 기능 개발·변경 시 실패 잠금, 오류 메시지, 세션 만료, 다중 인증 우회 불가 시험 결과(api 통합 테스트·E2E)를 보관한다.
- 14.1.1 보안서비스 수준 협약: 공공기관 이용 기관의 인증 관련 보안 요구사항(서비스 관리자 다중 인증 등)을 계약에 반영하고 이용자 기준을 상향한다.

## 5. 작성 규칙

- 02 절차의 실패 횟수·잠금 시간·세션 시간 등 수치는 법령·고시가 정하지 않은 당사 내부 기준(공통 기준 §3.1)이다. 부적합 사례가 걸리는 통제(실패 제한, 세션 타임아웃, 동시 접속 제한, 24시간 세션 금지)는 없애지 않는다.
- 자리표시자(이중 중괄호) 중 사람 이름·시행일·승인일은 1.2.1 조직 구성 확정 후 일괄 치환한다. 그 밖의 자리표시자는 대기중 문서의 `[!warning] 대기` 블록에 적은 조건이 갖춰지면 채운다.
- 서명이 필요한 문서는 서명본을 스캔해 사내 문서 저장소 `CSAP/서명본/10.3.2/` 에 보관하고, md 원본에는 서명본 보관 위치를 적는다.
- 현황 문서(03)와 점검 기록(05)은 버전을 올릴 때 이전 버전을 삭제하지 않고 3년 보관해서 특정 시점의 설정을 확인할 수 있게 한다.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신한다.
- 법령 인용은 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 개인정보의 안전성 확보조치 기준 제5조·제6조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.
