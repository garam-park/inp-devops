> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제7조제4항(인터넷망 구간 송·수신 암호화)과 제9조(악성프로그램 등 방지)(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 공개서버가 개인정보를 송·수신하거나 개인정보처리시스템에 해당하는 경우에 적용하며, 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

> [!note] 현 구현과 차이
> 3항 기준은 운영 타깃(NCP 공공 NKS)의 목표 상태다. 운영 환경은 구축 전이라 4항 점검 기록은 **현재 코드·이미지·dev0 매니페스트를 대상으로 한 사전 검토(정적)** 결과다. 운영 공개서버의 신설 전 점검은 NKS 구축 후 4항에 행을 추가해 기록하며, 부적합이 남아 있으면 서비스를 개시하지 않는다.

## 1. 개요

- 목적: JAS-9.1.5-01 공개서버 보안 관리 지침 6항의 보호대책을 가상 서버·컨테이너·PaaS 환경의 공개서버에 실제로 적용하기 위한 설정 기준과 확인 방법을 정한다.
- 적용 범위: JAS-9.1.5-03 공개서버 네트워크 및 시스템 구성도의 공개서버 목록에 등재된 전체 공개서버
- 적용 시점: 공개서버 신설 전, 소프트웨어·구성 변경 후, 정기 점검 월 1회
- 기준 표의 VM은 가상 서버, CT는 관리형 컨테이너 워크로드, PaaS는 관리형 실행 환경(서버리스, 관리형 웹 앱)을 뜻한다. **당사 공개서버(web·api)의 실행 형태는 CT(NCP NKS 관리형 컨테이너 워크로드)이며, CT 열이 당사 기본 적용 기준이다.** VM 열은 관리 영역의 배스천 서버에 적용하고, PaaS 열은 당사 공개서버에 해당하지 않는다(Cloud DB for PostgreSQL·Object Storage 는 관리형 서비스이나 공개서버가 아니다). 표기 기준은 다음과 같다.

| 표기 | 의미 |
| --- | --- |
| ○ | 당사가 설정·확인한다. |
| △ | 플랫폼이 제공하는 설정 범위 안에서 당사가 적용한다. 미제공 기능은 비고에 근거를 적는다. |
| 제공자 | IaaS/PaaS 제공자 책임 범위이다. 제공자 문서·인증으로 확인하고 비고에 근거를 적는다. |
| 해당 없음 | 해당 실행 형태에 적용되지 않는다. |

## 2. 실행 형태별 책임 구분

| 계층 | VM(가상 서버) | CT(관리형 컨테이너) | PaaS(관리형 실행 환경) |
| --- | --- | --- | --- |
| 호스트 OS 패치·백신 | 당사 | 관리형 노드는 제공자, 자체 관리 노드는 당사 | 제공자 |
| 컨테이너 런타임·오케스트레이션 제어 영역 | 해당 없음 | 제공자 | 제공자 |
| 워크로드 설정(Pod 보안, 네트워크 정책, 이미지) | 해당 없음 | 당사 | 당사(런타임 설정 범위 내) |
| 웹서버·미들웨어 설정 | 당사 | 당사(이미지 내) | 당사(플랫폼 설정 범위 내) |
| 응용 프로그램·TLS 설정·에러 처리 | 당사 | 당사 | 당사 |
| 네트워크 접근통제(보안 그룹·방화벽) | 당사 | 당사 | 당사(플랫폼 제공 기능) |
| 접속이력 로그 전송 | 당사 | 당사 | 당사(플랫폼 로그 연동) |

- 당사 CT 환경의 구분: NKS 제어 영역(쿠버네티스 API 서버·etcd)은 제공자, 워커 노드는 NCP 가 제공하는 노드 이미지를 쓰되 노드 풀 버전 업그레이드 실행과 노드 서브넷·ACG 설정은 당사가 맡는다. 워크로드(파드 보안 컨텍스트, NetworkPolicy, 이미지)는 당사 책임이다.

## 3. 설정 기준

### 3.1 A. 서비스별 전용 운영

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| A-1 | 공개서버(그룹)마다 하나의 서비스만 탑재하고, 인증 범위 밖 서비스·내부 업무 시스템·개발·시험 기능을 함께 두지 않는다. 운영 NKS 클러스터에는 본 서비스 워크로드(web·api·pipeline)만 둔다. | 03 양식 공개서버 목록의 전용 여부, `kubectl get pods -A` 목록 | ○ | ○ | ○ |
| A-2 | 운영·개발·시험 환경은 계정(프로젝트) 또는 VPC 단위로 분리하고, 시험용 엔드포인트를 인터넷에 노출하지 않는다. 당사 개발·스테이지는 사내 `dev0`, 로컬로 운영과 물리적으로 분리한다. | 환경별 계정·VPC 목록, 공인 IP·도메인 조회 | ○ | ○ | ○ |
| A-3 | 배포 서버는 배포 파일의 무결성 검증 정보(해시·서명)를 함께 제공하고, 업로드 기능은 인증된 관리자만 사용한다. 당사는 배포 서버가 없어 해당 없음 — 설치형 배포물이 없다. 데이터셋 업로드는 `admin`·`service` 역할만 허용한다. | 업로드 경로 인증 설정 | ○ | ○ | ○ |

### 3.2 B. 암호화 통신

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| B-1 | 개인정보·인증정보를 송·수신하는 모든 구간에 TLS 1.2 이상(1.3 우선)만 허용하고 SSLv3, TLS 1.0, TLS 1.1을 비활성화한다. | Load Balancer·Ingress 컨트롤러 TLS 정책(예: ssl_protocols TLSv1.2 TLSv1.3), 외부 TLS 스캔 결과 | ○ | ○ | ○ |
| B-2 | 안전한 암호 스위트만 허용하고 RC4, 3DES, NULL, EXPORT, anon 스위트를 제외한다. | ssl_ciphers 설정, TLS 스캔 결과 | ○ | ○ | ○ |
| B-3 | HTTP 요청은 HTTPS로 리다이렉트하고 HSTS 헤더(`max-age=31536000`)를 설정한다. | 응답 헤더(Strict-Transport-Security), 리다이렉트 응답 코드 | ○ | ○ | ○ |
| B-4 | 인증서는 신뢰할 수 있는 기관에서 발급받고 유효기간을 관리하며 만료 30일 전에 갱신(또는 자동 갱신)한다. | NCP Certificate Manager, 만료일 알림 설정 | ○ | ○ | ○ |
| B-5 | 공개서버와 내부 DB·스토리지 사이에 중요정보가 이동하면 그 구간도 암호화한다(JAS-11.1.4-01 네트워크 암호화 지침). api ↔ DB `sslmode=require`, api·pipeline ↔ Object Storage HTTPS. | DB 연결 설정의 TLS 옵션, `S3_ENDPOINT` 스킴 | ○ | ○ | ○ |

### 3.3 C. 접근통제 및 식별·인증

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| C-1 | ACG·Network ACL 과 호스트 방화벽(iptables, nftables)은 기본 거부로 설정하고 서비스 포트(443)와 승인된 관리 경로만 허용한다. | ACG 규칙, iptables -L -n 출력 | ○ | ○ | △ |
| C-2 | 컨테이너는 Pod 보안 표준 restricted(또는 PodSecurityPolicy 대체 어드미션 정책)를 적용하여 특권 컨테이너, 호스트 네트워크·PID·경로 마운트, root 실행을 금지한다. 비루트, `readOnlyRootFilesystem`, `capabilities.drop: [ALL]`, seccomp `RuntimeDefault`, `automountServiceAccountToken: false` 를 기본으로 한다. | 네임스페이스 pod-security 레이블, 어드미션 정책, securityContext(runAsNonRoot, allowPrivilegeEscalation=false, readOnlyRootFilesystem) | 해당 없음 | ○ | 제공자 |
| C-3 | CNI 네트워크 정책으로 공개 워크로드 네임스페이스의 인그레스·이그레스를 기본 거부하고 필요한 목적지·포트(DNS, DB, Object Storage, 허용 외부 브이월드 443)만 허용한다. 사설·루프백·링크로컬 대역 egress 는 차단한다. | NetworkPolicy 목록(default-deny 포함) | 해당 없음 | ○ | 해당 없음 |
| C-4 | 관리자 접속은 접근통제솔루션(SSL VPN → 배스천)을 경유하며, 인터넷에서 SSH(22)·RDP(3389)·쿠버네티스 API 등 관리 포트로 직접 접속할 수 없다. | ACG 인바운드 규칙, NKS API 엔드포인트 접근 제한 설정, 외부 포트 스캔 결과 | ○ | ○ | 해당 없음 |
| C-5 | 관리자 계정은 개인별로 발급하고 root·administrator 직접 로그인을 금지하며 sudo 등 권한 상승을 기록한다. 클러스터 권한은 개인별 NCP Sub Account 와 쿠버네티스 RBAC 로 부여한다. | sshd_config(PermitRootLogin no), sudo 로그, Sub Account 목록, RBAC 바인딩 | ○ | ○ | △ |
| C-6 | 관리자 인증은 패스워드 단독 인증을 금지하고 키 기반 인증과 TOTP 다중 인증을 적용한다. | sshd_config(PasswordAuthentication no), SSL VPN·NCP 콘솔 다중 인증 설정 | ○ | ○ | △ |
| C-7 | 관리 접속 미사용 세션은 10분 후 자동 종료하고 로그인 실패 5회 시 계정 잠금(30분 또는 관리자 해제)을 적용한다. | 접근통제솔루션 세션 정책, PAM 설정 | ○ | ○ | △ |
| C-8 | 서비스 계정·인스턴스 역할은 필요한 최소 권한만 부여하고(api·pipeline 의 스토리지 자격증명은 역할별 분리) 자격증명을 소스코드·이미지·환경 파일에 평문으로 포함하지 않는다. 비밀은 k8s Secret(SealedSecrets 봉인)으로 환경변수에만 주입한다. | IAM 역할 정책, gitleaks·trivy secret 스캔 결과 | ○ | ○ | ○ |
| C-9 | 웹 응용의 관리자 기능(`admin`·`service` 역할 화면·API)은 서버 측 역할 검사와 TOTP 다중 인증을 적용하고, Ingress 에서 사내 VPN 대역만 허용한다. | 관리 URL 접근 시험, Ingress IP 허용 목록 | ○ | ○ | ○ |

### 3.4 D. 악성코드 방지 및 패치

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |

| D-3 | OS·미들웨어(웹서버, 런타임)·라이브러리에 최신 보안 패치를 적용한다. 긴급 패치는 공표 후 72시간, 일반 패치는 7일(주 1회 기본 이미지 재빌드) 이내에 적용한다. 의존성 고위험 취약점의 유예는 14일을 넘기지 않는다. | 패키지 버전, 이미지 빌드 이력, 05 양식 조치 현황 | ○ | 베이스 이미지 재빌드로 적용 | 제공자 |
| D-4 | 컨테이너 이미지는 신뢰된 저장소의 베이스 이미지를 사용하고(태그 고정, `latest` 금지), 빌드·배포 시 취약점 스캔을 통과한 이미지만 배포한다. 릴리스 전 trivy HIGH/CRITICAL 0(예외는 `.trivyignore` 에 이유 기록). | 이미지 스캔 결과, 레지스트리 정책 | 해당 없음 | ○ | ○ |
| D-5 | 악성프로그램 경보가 발령되거나 제조사의 보안 업데이트 공지가 있으면 정당한 사유가 없는 한 즉시 업데이트한다(같은 기준 제9조제2항). | 경보 대응 기록 | ○ | ○ | 제공자 |

### 3.5 E. 불필요 서비스·포트 제거

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| E-1 | 실행 중인 서비스·데몬을 목록화하고 서비스 제공에 불필요한 것(원격 관리 데몬, 프린터, 파일 공유, 메일 등)을 비활성화한다. 컨테이너는 단일 프로세스(web: nginx, api: node)만 실행한다. | systemctl list-units, 프로세스 목록, 컨테이너 프로세스 | ○ | ○ | 제공자 |
