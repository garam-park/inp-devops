## 1. 목적

㈜이노팸은 법적 요구사항과 외부 위협요인을 고려하여 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS)의 사용자 및 이용자 패스워드에 대한 복잡도 기준, 초기 패스워드 변경, 변경 주기 등 관리 절차를 정하고, 패스워드 관리 책임이 사용자와 이용자에게 있음을 주지시키기 위해 본 절차를 수립한다. 본 절차는 당사 정보보호 정책서와 접근통제관리지침 중 패스워드 관리에 해당하는 사항을 구체화한 것이다.

## 2. 적용 범위

### 2.1 적용 대상자

| 구분 | 대상 | 적용 사항 |
| --- | --- | --- |
| 사용자 | 지반침하 스마트관리 시스템 운영·개발·보호 업무를 수행하는 임직원과 외부인력 | 4항 생성 규칙, 5항 운영 기준, 6항 기록·보관 통제 |
| 관리자 | 클라우드 시스템의 관리자 계정(NCP 메인 계정·관리자 Sub Account, Cloud DB 관리자, 서비스 `admin` 계정, GitHub 조직 Owner, VPN 관리자 등)을 사용하는 인원 | 사용자 적용 사항 + 7항 관리자 패스워드 보호대책 |
| 이용자 | 지반침하 스마트관리 시스템을 이용하는 이용 기관 담당자(`service` 역할)와 최종 이용자(`user` 역할) | 4항 생성 규칙(서비스 구현), 8항 공지 |

### 2.2 적용 대상 시스템

당사가 운영하는 다음의 모든 클라우드 시스템에 본 절차를 적용한다. 신규 시스템은 도입 시점에 본 표에 추가한다.

| 구분 | 대상 시스템 | 관리 계정 예시 |
| --- | --- | --- |
| 가상 서버(VM)·컨테이너 | 운영 NKS 워커 노드, 배스천 서버, web · api · pipeline 컨테이너 | 노드·배스천 OS 계정은 키 방식만 허용하고 비밀번호 로그인을 끈다. 컨테이너는 로그인 계정·셸 접속이 없다(비루트 실행) |
| DBMS | Cloud DB for PostgreSQL | DB 관리자 계정, 앱 접속 계정(api, pipeline — 역할별 분리, `audit_events` 는 INSERT·SELECT 만) |
| 응용 프로그램(Application) | 지반침하 스마트관리 시스템 계정 체계(`users` 표) | `admin`(시스템 관리자), `service`(서비스 관리자), `user`(일반 사용자) |
| 클라우드 콘솔·IAM | NCP 공공기관용 콘솔, Sub Account | 메인 계정(루트), 관리자 Sub Account, 운영자 Sub Account |
| 네트워크 | VPN, ACG·Load Balancer·DNS(NCP 콘솔로 관리) | VPN 관리자·운영자 계정. ACG·LB·DNS 는 NCP 콘솔 계정 기준을 따른다 |
| 정보보호시스템 | NCP WAF(도입 예정), Cloud Log Analytics, Cloud Insight | NCP 콘솔 계정 기준을 따른다(별도 로그인 계정 없음) |
| 개발·배포 환경 | GitHub 조직 `innopam`(소스·Actions·GHCR), NCP Container Registry, self-hosted runner | GitHub 조직 Owner·구성원(개인 계정), 레지스트리는 NCP 콘솔·API 인증키, runner 는 등록 토큰(비밀번호 아님) |
| 내부 업무 시스템 | 해당 없음 — 인증 범위 내 별도 내부 업무 시스템 없음 | 해당 없음 |

- 하이퍼바이저와 물리 인프라의 계정 관리는 책임공유모델에 따라 IaaS/PaaS 제공자(NCP)의 책임이며, 제공자의 CSAP 인증과 계약으로 확인한다.
- 개인정보를 처리하지 않는 시스템에도 내부 기준으로 본 절차를 동일하게 적용한다.
- 개발·스테이지 `dev0` 클러스터와 로컬 환경은 인증 범위 밖이다. 다만 운영과 같은 패스워드를 쓰지 않는다.
- API 인증키·세션 서명키·스토리지 키 등 비밀번호가 아닌 자격증명은 12.3.x 키 관리 기준(연 1회 회전, Secret 으로만 주입)을 따른다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 패스워드 | 시스템 접속 시 식별자와 함께 입력하여 정당한 접속 권한을 인증하는, 타인에게 공개되지 않는 고유의 문자열 |
| 관리자 패스워드 | 시스템 전체에 대한 설정·운영 권한을 가진 계정(NCP 메인 계정, DB 관리자, 서비스 `admin` 등)의 패스워드 |
| 초기·임시 패스워드 | 계정 최초 발급 시 또는 재발급 시 시스템·담당자가 부여하는 일회성 패스워드 |

## 4. 패스워드 생성 규칙

사용자·관리자·이용자 패스워드는 다음 규칙을 만족해야 하며, 각 시스템은 이 규칙을 강제하도록 설정한다.

| 항목 | 기준 |
| --- | --- |
| 길이·조합 | 문자(영문 대문자·소문자), 숫자, 특수문자 중 3종류 이상을 조합하여 10자리 이상. 2종류 조합은 허용하지 않는다 |
| 사용 금지 | 연속된 자판 배열(qwerty, asdf 등), 연속·반복 문자(1234, aaaa 등) |
| 사용 금지 | 생일, 전화번호, 사번, 계정명 등 추측하기 쉬운 개인 신상정보. 서비스는 로그인 식별자(`login`)와 같거나 이를 포함한 패스워드를 거부한다 |
| 재사용 금지 | 최근 3개 이내에 사용한 패스워드와 동일한 패스워드 |
| 관리자 강화 기준 | 관리자 패스워드는 3종류 이상 조합 10자리 이상, 시스템별로 서로 다른 값 사용, 강화된 인증(TOTP) 필수(10.3.3) |

## 5. 패스워드 운영 기준

| 구분 | 기준 |
| --- | --- |
| 초기·임시 패스워드 | 무작위로 생성하여 안전한 방법(별도 채널, 일회용 링크 등)으로 전달하고, 최초 로그인 시 강제로 변경하게 한다. 유효 시간은 24시간이며 지나면 재발급한다. 시드·기본 계정에 고정 비밀번호를 두지 않는다 |
| 변경 주기 | 관리자 계정(`admin` · `service`, NCP 콘솔, DB 관리자, VPN)과 사용자(임직원·외부인력) 운영 계정 패스워드는 90일마다 변경한다. 이용자(`user`) 패스워드는 180일 주기 변경을 권고·안내하고, 유출 의심 시에는 변경을 강제한다 |
| 즉시 변경 | 침해사고가 발생하거나 패스워드 노출 징후가 의심되면 즉시 변경한다. 관리자 퇴직·인사이동 시 해당 인원이 알던 관리자 패스워드를 당일 변경한다(퇴직자 계정은 즉시 삭제) |
| 입력·표시 | 패스워드 입력·변경 시 화면에 마스킹 처리한다. |
| 자동 로그인 | 패스워드만 입력하는 자동 로그인은 금지한다. 서비스는 "로그인 상태 유지" 기능을 두지 않고 세션은 비활동 30분·절대 12시간에 만료한다 |
| 로그인 실패 제한 | 5회 연속 인증 실패 시 계정을 잠그고, 30분 경과 후 자동 해제하거나 관리자가 본인확인 후 해제한다. 인증 요청은 IP+계정 기준 분당 20회로 제한한다 |
| 저장·전송 보호 | 패스워드는 Argon2id 로 일방향 암호화하여 저장하고, 전송 구간은 TLS 1.2 이상으로 암호화한다. 로그·감사 기록·오류 메시지에 패스워드를 남기지 않는다 |
| 재발급 | 분실·도용 우려 시 본인확인(이용자: 이용 기관 관리자(`service`)의 확인 요청, 운영자: 부서장 확인)을 거쳐 임시 패스워드를 재발급하고 최초 로그인 시 변경하게 한다. 이메일·문자 재설정은 연락처를 수집하지 않으므로 쓰지 않는다 |

## 6. 패스워드 기록·보관 통제

1. 패스워드는 수첩, 메모, 모니터 부착물, 일반 문서·파일 등에 기록하지 않는 것을 원칙으로 한다.
2. 업무상 불가피하게 패스워드를 별도 문서 또는 파일로 보관하는 경우(관리자 패스워드 등) 해당 문서·파일을 비밀등급으로 분류하고 비인가자가 접근할 수 없도록 통제한다. 관리자 패스워드는 [02. 시스템 관리자 패스워드 관리대장](../../11%20%EB%8C%80%EA%B8%B0%EC%A4%91/10.3.4%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC/02.%20%EC%8B%9C%EC%8A%A4%ED%85%9C%20%EA%B4%80%EB%A6%AC%EC%9E%90%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC%EB%8C%80%EC%9E%A5.md)에 따라 관리한다.
3. 브라우저 자동 저장 등 패스워드 저장 기능의 사용을 제한한다.
   - 운영자·관리자 단말의 브라우저에서 패스워드 저장 기능을 비활성화하고, 이미 저장된 운영 계정 정보(NCP 콘솔, 서비스 관리자 화면, VPN)를 삭제한다.
   - 가능한 경우 단말 관리 정책으로 저장 기능을 기술적으로 차단한다: Chrome·Edge 정책 `PasswordManagerEnabled=false` 를 운영자 단말에 배포한다(macOS 구성 프로파일, Windows 그룹 정책). 단말 관리 도구가 없는 단말은 반기 전수 점검으로 확인한다.
   - 메신저, 이메일, 공유 문서, 이슈·PR 본문, 저장소 파일에 패스워드를 평문으로 기재·전달하지 않는다. 저장소는 gitleaks(커밋 훅·CI)로 비밀값 커밋을 차단한다.
4. 이행 여부는 [05. 패스워드 정책 이행 점검표](../../11%20%EB%8C%80%EA%B8%B0%EC%A4%91/10.3.4%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC/05.%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EC%A0%95%EC%B1%85%20%EC%9D%B4%ED%96%89%20%EC%A0%90%EA%B2%80%ED%91%9C.md)의 저장 기능 점검으로 확인한다.

## 7. 관리자 패스워드 보호대책

1. 클라우드 시스템 관리자 패스워드는 일반 사용자 패스워드와 별도로 관리하며, [02. 시스템 관리자 패스워드 관리대장](../../11%20%EB%8C%80%EA%B8%B0%EC%A4%91/10.3.4%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC/02.%20%EC%8B%9C%EC%8A%A4%ED%85%9C%20%EA%B4%80%EB%A6%AC%EC%9E%90%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC%EB%8C%80%EC%9E%A5.md)에 별도 목록으로 유지한다.
2. 관리자 패스워드를 기록한 문서 또는 저장매체는 비밀에 준하여 관리하고, 내화금고 등 잠금장치로 비인가자의 접근을 통제한다. 평시 사용하지 않는 비상용 관리자 계정(NCP 메인 계정, Cloud DB 최초 관리자, 서비스 최초 `admin`)의 패스워드는 계정별로 밀봉 봉투에 봉인해 내화금고에 보관한다.
3. 관리자 부재 또는 패스워드 분실 시의 확인 목적 열람은 정보보호 최고책임자의 승인을 받아 수행하고, 열람 후 해당 패스워드를 즉시 변경한다.
4. 관리자 계정 접속에는 10.3.3 강화된 인증 수단 제공에 따른 다중 인증(TOTP)을 함께 적용한다.
5. 공용 관리자 계정은 최소화하고, 일상 운영은 개인별 Sub Account·개인별 서비스 계정으로 한다. 공용 계정 사용이 불가피한 경우 사용 기록을 남기고 사용자를 식별할 수 있게 한다.

## 8. 이용자 공지

1. 이용자 계정 및 패스워드 관리 절차(생성 규칙, 변경 유도, 재발급, 로그인 실패, 장기 미사용, 관리 책임)를 양식 03. 이용자 패스워드 관리 공지문으로 작성하여 서비스 화면 공지사항, 로그인 화면 안내, 이용 기관 공문 등 이용자가 쉽게 확인할 수 있는 채널에 공지한다.
2. 공지 내용은 본 절차의 기준(10자리 이상·3종류 조합, 최근 3개 재사용 금지, 이용자 180일 변경 권고, 5회 실패 시 30분 잠금, 장기 미사용 90일 비활성화)과 일치하게 유지하고, 본 절차 개정 시 공지문을 갱신하여 재게시한다.

## 9. 시스템 설계·도입 시 적용

1. 신규 시스템·서비스 기능을 설계하거나 상용 솔루션을 도입할 때 4항·5항의 요구사항을 설계 요구사항에 반영하고, 검수 시 설정 화면·시험으로 충족 여부를 확인한다. 서비스 api 는 4항·5항의 검증을 단위 시험으로 고정하고 CI 게이트에서 실행한다.
2. 생성 규칙을 기술적으로 강제할 수 없는 시스템은 사유와 보완 통제(수기 점검 주기 단축 등)를 [05. 패스워드 정책 이행 점검표](../../11%20%EB%8C%80%EA%B8%B0%EC%A4%91/10.3.4%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EA%B4%80%EB%A6%AC/05.%20%ED%8C%A8%EC%8A%A4%EC%9B%8C%EB%93%9C%20%EC%A0%95%EC%B1%85%20%EC%9D%B4%ED%96%89%20%EC%A0%90%EA%B2%80%ED%91%9C.md)에 기록한다. 현재 확인된 대상: GitHub 조직(개인 계정 패스워드 정책을 조직이 강제할 수 없음 → 2단계 인증 조직 필수 설정으로 보완).

## 11. 책임 주지

1. 사용자에게는 연 1회 이상 정보보호 교육과 보안 서약을 통해 패스워드 관리 책임(비공유, 기록 금지, 노출 시 즉시 변경·신고)이 본인에게 있음을 주지시킨다.
2. 이용자에게는 8항의 공지로 패스워드 관리 책임이 이용자에게 있음을 안내한다.
