> 기준일(2026-10-20) 현재 서비스(지반침하 스마트관리 시스템, JAS)에서 발생한 침해사고는 없으며 작성된 침해사고 보고서도 없다. 운영 환경(NCP 공공기관용)은 구축 전이다. 아래 서식은 당사 기준값(공통 기준 §3.7, 5.1.1 양식 02 침해사고 대응지침)을 반영해 두었고, 사고가 발생하면 사고 번호마다 본 서식을 복제해 빈 칸을 채운다.

# 침해사고 보고서

| 사고 번호 | 보고 구분 | 보고 회차 | 사고 등급 | 작성일시 | 작성자 |
| --- | --- | --- | --- | --- | --- |
| 기록 없음(기준일 2026-10-20 현재) | — | — | — | — | — |
| `INC-RPT-YYYY-NNN` 형식 | 최초 / 중간 / 최종 | n차 | 1 심각 / 2 중대 / 3 보통 | YYYY-MM-DD hh:mm | 성명/직위 |

- 최초 보고는 확인된 사실만 적고 미확인 사항은 "확인 중"으로 표시한다. 같은 사고의 중간·최종 보고는 같은 사고 번호를 쓰고 회차를 올린다.
- 최초 보고 시한은 1등급 즉시(30분 이내 1차), 2등급 2시간, 3등급 24시간이다(공통 기준 §3.7, 5.1.1 양식 02 4.3항). 최종 보고서는 복구 후 5영업일 이내에 작성한다.
- 이용자 정보 또는 개인정보 유출 가능성이 있으면 최초 보고와 함께 양식 05 법적 신고 통지 의무 판단서 작성을 시작한다.
- 공공기관 이용 기관에 제공하는 사고 발생 보고서는 본 보고서에서 해당 기관 관련 내용을 옮겨 14.1.4 양식 04 로 작성한다.

## 3. 사고 내용

### 3.1 발견 사항

탐지·발견 경위, 확인된 사실, 관련 로그·알림의 요약을 적는다. 로그를 인용할 때는 request_id 와 시각을 함께 적는다.

### 3.2 피해 내용

| 항목 | 내용 |
| --- | --- |
| 영향 시스템·서비스 | |
| 영향 이용 기관 수 | n개 기관(기관명). 서비스 이용 기관은 모두 공공기관이다 |
| 영향 이용자(사용자) 수 | n명(역할별 `admin` · `service` · `user`) |
| 이용자 정보 유출 여부 | 확인 / 의심 / 없음, 정보 종류(원본 자료, 데이터셋 번들, 민감 레이어(관로·굴착), 사고 기록, 내보내기 파일, 설정 정보), 건수 |
| 개인정보 유출등 여부 | 확인 / 의심 / 없음, 항목, 정보주체 수(서비스는 설계상 개인정보를 수집하지 않으나 사고 기록의 주소·피해 내용 포함 여부를 확인한다) |
| 민감정보·고유식별정보 포함 | ○ / X (○이면 건수와 무관하게 개인정보 유출 신고 대상) |
| 외부 불법 접근에 의한 유출 | ○ / X (○이면 건수와 무관하게 개인정보 유출 신고 대상) |
| 개인정보처리자 지위 | 당사 / 이용 기관(당사 수탁) / 혼재 |

| 데이터 무결성·가용성 영향 | 위·변조, 삭제, 암호화(랜섬웨어) 여부 |
| 2차 피해 가능성 | |
