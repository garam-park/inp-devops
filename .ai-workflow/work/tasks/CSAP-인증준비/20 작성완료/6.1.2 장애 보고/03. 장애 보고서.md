# 장애 보고서

| 문서번호 | 장애번호 | 보고 구분 | 보고일시 | 보고자 | 수신 |
| --- | --- | --- | --- | --- | --- |
| 기록 없음(기준일 2026-10-20 현재) | — | — | — | — | — |
| `FLT-RPT-YYYY-NNN` 형식 | `FLT-YYYY-NNN` | 초동 / 중간 / 최종 | YYYY-MM-DD hh:mm | 성명/직위 | 최고경영자, 정보보호 최고책임자, 이해관계 부서장 |

- 초동 보고는 인지 후 15분 이내에 1항과 2항, 7항의 초동 보고 행만 채워 발신한다. 최종 보고는 복구 후 5영업일 이내에 전체 항목을 채워 결재한다.
- 공공기관 이용 기관이 사고 발생 보고서를 요구하면 본 문서에서 옮겨 14.1.4 양식 04. 사고 및 장애 발생 보고서(기관 지정 서식이 있으면 그 서식)로 제공한다. 서비스 이용 기관은 모두 공공기관이다.

## 1. 장애 개요

| 항목 | 내용 |
| --- | --- |
| 발생일시 | |
| 인지일시·인지 경로 | 모니터링 경보 / 이용자 신고 / IaaS·PaaS 제공자(NCP) 통지 |
| 복구일시 | 복구 전이면 예상 복구 시각 |
| 중단 시간 | 연속 n분, 24시간 내 누적 n회 n분(02. 장애 관리대장 3항) |
| 영향 서비스·기능 | 지반침하 스마트관리 시스템의 기능(로그인, 지도·위험도 조회, 레이어 표시, 사고 기록, 데이터셋 올리기·빌드, 내보내기) |
| 영향 이용 기관·이용자 규모 | 이용 기관 n곳(공공기관 n곳), 이용자 약 n명 |
| 장애 등급 | 1급(서비스 전면 중단) / 2급(주요 기능 중단) / 3급(일부 저하), 판정 근거 |
| 사전 예고 여부 | 예고 없음 / 예고함(공지일, 채널) |
| 원인 구분 | 당사 / IaaS·PaaS 제공자 / 외부 연계 서비스(브이월드, 레지스트리) / 이용 기관 |
| 침해사고·정보 유출 동반 여부 | 없음 / 침해사고 / 이용자 정보 유출 / 개인정보 유출(동반 시 5.2.1 양식 02 사고 번호 기재) |

## 2. 발생 내용

이용자가 겪은 증상, 영향받은 기능·범위, 발생 경위를 시간 순으로 기술한다.

## 3. 발생 원인

| 구분 | 내용 |
| --- | --- |
| 원인 확인 상태 | 확인 / 추정 / 미확인(확인 예정일) |
| 직접 원인 | |
| 근본 원인 | 설정 오류, 배포 결함, 용량 부족, 제공자 장애, 외부 연계 장애 등 |
| 원인 확인 근거 | 요청 로그(request_id), 모니터링 지표, 배포 이력(이미지 태그·커밋 SHA), 제공자 사후 보고서(RCA) |

- 원인이 미확인인 상태로 이용자에게 1차 통지했으면, 원인 확인 후 지체 없이(24시간 이내) 추가 통지하고 8항에 기록한다.
