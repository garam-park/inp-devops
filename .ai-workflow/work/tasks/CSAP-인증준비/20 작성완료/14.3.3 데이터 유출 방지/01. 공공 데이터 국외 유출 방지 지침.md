> - 운영 자원(NKS · Cloud DB · Object Storage)은 구축 전이다. 데이터는 로컬 SeaweedFS 와 사내 `dev0`(인증 대상 아님)에만 있다.

> - api 의 스토리지 설정은 환경변수(`S3_ENDPOINT` · `S3_REGION` · `S3_BUCKET`)로 주입한다. 코드 기본값(`http://localhost:8333`, `us-east-1`)은 로컬 SeaweedFS 용이며 물리 위치와 무관하다. 운영은 기본값에 의존하지 않고 공공 사설 엔드포인트를 values 에 명시한다(6항 No 1).
> - 관리자 인증·RBAC·감사 로그(`audit_events`)는 미구현이다(6항 No 4 · 7 의 앱 계층 통제).

> [!info] 법령 기준
> 「행정기관 및 공공기관의 클라우드컴퓨팅서비스 이용 기준 및 안전성 확보 등에 관한 고시」 제13조(저장정보의 보호와 관리)(행정안전부고시 제2025-79호, 2025. 12. 29. 시행)를 관련 근거로 참고했다. 국가 사이버보안 기본지침 제24조의3(클라우드컴퓨팅 도입 가능 목록)은 비공개 지침이라 문서명만 표기한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS)을 이용하는 국가기관등의 가상자원과 데이터(이하 "공공 데이터등")가 국외로 유출되지 않도록 데이터 관리 방안과 기술적 보호조치를 정하고, 공공 데이터등의 물리적 위치를 국내로 제한하며, 물리적 위치를 확인·추적하고 증적으로 제공하는 기준을 수립한다.

## 2. 적용 범위

- 지반침하 스마트관리 시스템(하등급 SaaS)의 공공기관용 서비스 인증 범위 내 모든 구성요소: 운영 시스템(NKS 클러스터의 web · api · pipeline 컨테이너, Cloud DB for PostgreSQL, Object Storage), 이용 기관 데이터(위성 변위 · 지질 · 관로 · 사고 이력 · 굴착 허가 원본과 산출한 격자 위험도·레이어, 사고 기록), 백업 데이터, 로그, 임시 저장 데이터(pipeline 작업 디렉터리 `/work`, 내보내기 파일)
- 공공 데이터등에 접근하거나 이를 처리·운영하는 임직원과 외부인력
- 공공 데이터등이 저장·전송·처리되는 외부 연동 서비스(브이월드, 컨테이너 레지스트리, 로그·모니터링 서비스 등)
- 사내 개발 클러스터 `dev0` 와 로컬 환경은 인증 범위 밖이며, 공공 데이터등의 운영 사본을 반입하지 않는다.

## 5. 데이터 유출 방지 원칙

1. 공공 데이터등은 국내에 위치한 인증받은 공공 영역(네이버 클라우드 플랫폼 공공기관용)에만 저장하며, 국외 리전·국외 시설과 인증 범위 밖 영역(일반 리전, 사내 `dev0`, 개인 단말)에 저장·복제하지 않는다.
2. 공공 영역에는 국외 리전·인증 범위 밖 영역에 가상자원을 생성할 수 없도록 기술적 차단 정책을 적용한다.
3. 지반침하 스마트관리 시스템의 데이터 저장 위치는 국내 공공기관용 리전으로 고정하며, 이용 기관에 국내 저장을 보장하고 그 사실을 서비스 안내(이용 계약, 서비스 소개 자료)에 명시한다.
4. 공공 데이터등에는 공공 주요 직무자 외의 인원(다른 제품·민간 서비스 운영 인력, 그 외 임직원·외부인력 등)이 접근·제어할 수 없다.
5. 공공 데이터등을 국외로 전송하거나 국외 소재 외부 서비스에 저장하지 않으며, 외부 연동 서비스를 추가할 때는 데이터 저장·처리 위치를 사전에 확인한다. 소스 저장소·CI·컨테이너 이미지에는 공공 데이터등과 비밀값을 넣지 않는다.
6. 공공 데이터등의 물리적 위치를 확인·추적할 수 있는 기술적 방안을 유지하고, 이용 기관이 요청하면 물리적 위치를 증명하는 증적을 제공한다.

## 7. 데이터 위치 관리 및 검토

1. 정보보호 담당자는 공공 데이터등의 저장 위치를 양식 02. 공공 데이터 저장 위치 관리대장으로 관리하고, 자원·설정 변경 시 5영업일 이내에 현행화한다.
2. 정보보호 관리자는 반기 1회 이상 양식 03. 데이터 물리적 위치 검토서로 실제 자원·설정과 대장을 대조하여 국외 위치·국외 전송이 없음을 검토하고, 정보보호 최고책임자의 승인을 받는다.
3. 검토에서 국외 저장·전송이 발견되면 즉시 해당 자원·전송을 차단하고, 침해사고 대응 절차(5.1.1)에 따라 보고하며, 재발 방지 대책을 수립한다. 이용 기관 데이터가 실제로 국외에 저장·유출되었으면 인지 즉시 이용 기관에 통지한다.
4. 신규 서비스 기능·외부 연동·인프라 변경으로 데이터 저장 위치가 바뀔 수 있는 변경(운영 values 의 엔드포인트·버킷·레지스트리 변경, NetworkPolicy egress 추가, 신규 외부 API 호출)은 PR 리뷰와 변경 관리 절차에서 본 지침 준수 여부를 사전 검토한다.

## 8. 이용 기관 증적 제공

1. 이용 기관이 공공 데이터등의 물리적 위치 증명을 요청하면 양식 04. 물리적 위치 증적 제공 관리대장의 절차에 따라 접수일부터 5영업일 이내에 증적을 제공한다.
2. 제공하는 표준 증적은 양식 04의 2항(표준 증적 구성)을 따르고, 최신 상태로 유지한다.
3. 제공한 증적과 제공 이력은 양식 04에 기록하고 3년 이상 보관한다.
