본 문서는 서비스연속성관리지침 중 성능 및 용량 관리에 관한 절을 독립 문서로 정리한 것이다. 서비스연속성관리지침을 단일 문서로 운영하게 되면 본 문서의 4항부터 8항까지를 해당 지침의 "성능 및 용량 관리" 절로 편입한다.

## 1. 목적

㈜이노팸은 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS, 이하 "JAS")의 가용성을 보장하기 위하여 서비스 운영환경의 성능 및 용량 요구사항을 정의하고, 이를 지속적으로 모니터링하며, 정의된 임계치를 초과하는 경우 조치하는 기준을 본 지침으로 정한다.

## 2. 적용 범위

- JAS(하등급 SaaS) 인증 범위 내 운영환경을 구성하는 모든 클라우드 자원과 응용 프로그램
  - 컨테이너: Ncloud Kubernetes Service(NKS) 워커 노드 풀, 네임스페이스의 web · api · pipeline 워크로드
  - 관리형 DB: Cloud DB for PostgreSQL(PostGIS)
  - 스토리지: Object Storage(S3 호환) 버킷 — 레이어 자료, 데이터셋 번들, 내보내기, 업로드, 백업(`backups/`)
  - 네트워크: NCP Load Balancer, NKS Ingress 컨트롤러, NAT 게이트웨이(브이월드 WMTS 중계 egress), 관리용 VPN
  - 응용 프로그램: web(nginx 정적 화면 · `/api/` 프록시), api(Node.js · Fastify), pipeline(Python 워커, `jobs` 표 처리)
- 서비스 운영을 지원하는 내부 시스템: 모니터링(NCP Cloud Insight, 클러스터 metrics-server/Prometheus), 로그(NCP Cloud Log Analytics 또는 별도 Object Storage 버킷), 백업(관리형 DB 자동 백업, `pg_dump` CronJob), 배포(GitHub Actions self-hosted runner, Helm chart)
- 위 자원의 성능·용량을 관리하는 임직원과 외부인력
- 개발·스테이지(사내 `dev0` 클러스터)와 로컬 환경은 인증 범위가 아니므로 적용하지 않는다. 다만 운영 전 성능 시험(야간 k6)은 6.2항 요구사항의 사전 확인 수단으로 활용한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 성능 | 서비스가 요구되는 시간 안에 요청을 처리하는 능력. 응답시간, 처리량, 오류율 등으로 측정한다. |
| 용량 | 서비스가 처리할 수 있는 자원의 총량. CPU, 메모리, 디스크, 네트워크 대역폭, 연결 수, 서비스 한도(quota) 등으로 측정한다. |
| 관리 대상 | 성능·용량을 모니터링하고 임계치를 관리하는 자원·지표. 양식 03. 모니터링 대상 및 임계치 현황에 등재한다. |
| 임계치 | 관리 대상 지표별로 정한 기준값. 주의, 경고, 위험의 3단계로 정한다. |
| 모니터링 | 관리 대상 지표를 도구로 자동 수집하고, 담당자가 정한 주기로 확인·기록·보고하는 활동 |
| 조치 | 임계치 초과 원인을 검토하고 가상자원 증설, 네트워크 대역폭 증설 등으로 성능·용량을 확보하는 활동 |
| 서비스 한도(quota) | IaaS/PaaS 제공자가 계정·리전 단위로 정한 자원 생성·사용 상한 |
| 복제 수(replica) | 같은 워크로드를 동시에 실행하는 파드 수. 수평 확장(스케일아웃)의 단위다. |

## 4. 정보보호 정책 반영 사항

정보보호 정책서 제{{정보보호 정책서 조항 번호}}조(서비스 가용성)에 다음 조항을 둔다. 정책서 조항은 원칙만 정하고 세부 기준은 본 지침을 따른다.

1. 회사는 클라우드컴퓨팅서비스의 가용성을 보장하기 위하여 서비스 운영환경의 성능 및 용량 요구사항을 정의하고 문서화한다.
2. 회사는 성능 및 용량 관리 대상을 식별하고 임계치를 정하여 지속적으로 모니터링하며, 그 결과를 기록하고 보고한다.
3. 회사는 임계치 초과 시 원인을 검토하고 후속 조치를 수립·이행하는 절차를 운영한다.
4. 회사는 성능 및 용량 관리를 담당하는 담당자와 책임자를 지정한다.
5. IaaS/PaaS 제공자가 책임지는 물리 인프라의 용량은 제공자의 인증과 계약으로 확인하고, 회사는 책임공유모델에 따라 회사가 통제하는 자원의 성능·용량을 관리한다.

## 5. 책임공유모델에 따른 관리 범위

JAS는 네이버클라우드 NCP 공공기관용 영역(CSAP IaaS 인증 — 인증 번호·유효기간 확인 필요, 14.1.2 02 목록 3항과 함께 확인)의 인프라 위에서 운영된다. 계층별 성능·용량 관리 책임은 다음과 같다.

| 계층 | IaaS/PaaS 제공자 | 당사(SaaS 제공자) | 당사 확인 방법 |
| --- | --- | --- | --- |
| 데이터센터 물리 시설(전력, 냉방, 회선) | 용량 확보와 이중화 | 없음 | 제공자 CSAP 인증서, SLA·이용 약관 |
| 물리 서버, 하이퍼바이저, 백본 네트워크 | 자원 풀 용량 확보 | 없음 | 제공자 인증·서비스 한도 공지, 제공자 상태 페이지 |
| 가상 서버·컨테이너(NKS 워커 노드 CPU, 메모리, 디스크, NIC, 파드 자원) | 노드 유형과 자원 풀, NKS 컨트롤 플레인 제공 | 노드 유형·수량 결정, 파드 requests/limits·복제 수 결정, 사용률 모니터링, 증설 | 03 현황, 04 점검 기록 |
| 관리형 DB·PaaS 서비스(Cloud DB for PostgreSQL, Object Storage) | 서비스 가용성, 기반 인프라 | 인스턴스 사양, 스토리지, 연결 수, 서비스 한도 모니터링·증설 | 03 현황, 04 점검 기록 |
| 네트워크 대역폭(Load Balancer, NAT 게이트웨이, VPN) | 백본·게이트웨이 용량 | 처리량·연결 수 모니터링, LB·NAT 용량 증설 | 03 현황, 04 점검 기록 |
| 응용 프로그램(응답시간, 처리량, 오류율, `jobs` 작업 적체) | 없음 | 성능 지표 정의·계측, 튜닝·확장 | 03 현황, 06 보고서 |
| 이용 규모(이용 기관·이용자 수, 데이터 증가량) | 없음 | 증가 추이 분석, 용량 예측·증설 계획 | 06 보고서 |
| 백업·로그 저장 공간 | 저장소 제공 | 사용량 모니터링, 보존 기간·용량 관리 | 03 현황 |

- 제공자 책임 계층의 장애·용량 부족은 제공자 상태 페이지와 공지로 확인하고, 당사 서비스에 영향이 있으면 6.1.2 장애 보고 절차를 따른다.
- 제공자 인증서와 SLA 사본의 보관 위치: `CSAP-인증준비/30 증적/6.2.1/`(제공자 인증서는 14.1.2 증적과 같은 사본을 참조한다)

### 6.1 가용성 목표

| 항목 | 요구사항 | 근거 |

| 지표 | 요구사항 | 측정 대상·방법 |
| --- | --- | --- |
| 웹 화면 응답시간 | 95 백분위수 500ms 이내(동시 이용자 50명 부하) | web(nginx) 경로 5종: `index.html`, 해시 번들 JS·CSS, 글꼴, SPA 깊은 주소, `/api/` 프록시. 운영 전에는 야간 k6(`e2e/k6/web.js`), 운영에서는 Ingress·LB 응답시간 지표 |

### 6.3 용량 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 자원 사용률 상한 | 평시 평균 70% 이하, 피크 85% 이하(CPU, 메모리, 네트워크 대역폭) |
| 스토리지 여유율 | 디스크·DB 스토리지 여유 30% 이상, 오브젝트 스토리지는 월 증가량의 6개월분 확보 |
| 서비스 한도 여유율 | 제공자 서비스 한도 사용률 80% 이하 |
| 용량 예측 기간 | 향후 6개월의 사용량을 예측하고, 경고 임계치 도달 예상 시점 2개월 전에 증설 착수 |
| 확장 방식 | web·api는 복제 수 2 이상(PDB minAvailable 1)으로 운영하고, 자원 기준선을 측정한 뒤 수평 자동 확장(HPA)을 활성화한다. 그 전까지는 복제 수를 수동 조정한다. pipeline은 복제 수 1, 빌드는 한 번에 하나만 실행한다. NKS 노드 풀·DB·스토리지는 계획 증설 |
| 증설 리드타임 | 파드 복제 수 조정 즉시, NKS 노드 풀 증설 4시간 이내, 서비스 한도 상향 5영업일, 예산 승인 필요 시 10영업일 |

### 6.4 요구사항의 정합성

- 위 요구사항은 이용 기관과 체결한 SLA(14.1.1 보안서비스 수준 협약)와 서비스 이용 약관의 수준 이상으로 정한다.
- 요구사항을 변경하면 03 현황의 임계치, 모니터링 도구의 알림 규칙, 야간 k6 임계값(`thresholds`), SLA 문서를 함께 갱신한다.

## 8. 관리 원칙

### 8.1 관리 대상 식별

1. 인증 범위 정보자산 목록과 서비스 구성도에 있는 모든 클라우드 자원과 응용 프로그램을 대상으로 성능·용량 관리 필요성을 검토하고, 관리 대상을 03 현황에 등재한다.
2. 자원을 신규 생성·변경·삭제하면 5영업일 이내에 03 현황을 갱신한다. 변경 관리 절차(PR 리뷰·Helm values 변경)의 완료 조건에 03 현황 갱신을 포함한다.
3. 제공자 책임 계층은 관리 대상에서 제외하되, 제외 사유와 확인 방법을 03 현황 5항에 기록한다.

### 8.2 임계치 설정

1. 관리 대상 지표별로 주의·경고·위험 3단계 임계치를 정한다. 사용률 지표의 기본값은 주의 70%, 경고 85%, 위험 95%이며, 단계별 대응 시한은 02 절차서 5항을 따른다.
2. 임계치는 6항의 요구사항, 평시 최대 사용률, 증설 리드타임을 근거로 정하고 근거를 03 현황에 기록한다.
3. 임계치는 모니터링 도구의 알림 규칙과 일치시키고, 불일치가 없는지 분기 1회 대조한다.
4. 임계치는 연 1회 이상, 그리고 임계치 초과 조치나 정기 분석에서 부적정으로 판정되면 즉시 재검토한다.

### 8.3 모니터링

1. 관리 대상 지표는 모니터링 도구로 24시간 자동 수집하고, 임계치 초과 시 담당자에게 자동 알림을 보낸다.
2. 담당자는 02 절차서 7항의 주기(일일·주간·월간)로 점검하고, 결과를 04 점검 기록에 기록한다. 이상이 없어도 점검 사실과 확인 값을 기록한다.
3. 점검 미수행이 발생하면 사유와 보완 점검일을 04 점검 기록에 남기고 책임자에게 보고한다.

### 8.4 임계치 초과 시 조치

1. 임계치 초과를 인지하면 02 절차서 8항에 따라 초동 확인, 원인 검토, 조치계획 수립·승인, 이행, 결과 확인, 보고를 수행하고 건별로 05 조치계획서를 작성한다.
2. 조치 방안은 가상자원 증설(파드 복제 수·자원 상한 조정, NKS 노드 유형 상향·노드 추가), 네트워크 대역폭 증설(LB 용량 상향), 스토리지 확장, 서비스 한도 상향, 응용 프로그램 튜닝 등에서 선택하며, 자동 확장으로 해소된 건도 원인 검토와 기록을 생략하지 않는다.
3. 위험 단계 초과나 서비스 영향이 있는 초과는 인지 즉시 책임자에게 보고하고, 서비스 중단이 발생하면 6.1.2 장애 보고 절차를 병행한다.
4. 자원을 증설할 때는 NCP 공공기관용 영역과 국내 리전 안에서만 자원을 생성한다(14.2.1).
