## 2. 권장 작성 순서

1. 01 시스템 개발 보안 지침 인증 및 암호화 조항: 인증·암호화·시큐어 코딩 보안 요구사항과 기준값을 정하고 정보보호 최고책임자 승인을 받는다.
2. 02 보안요구사항 정의 및 반영 절차: 요구사항이 설계부터 배포까지 반영·검증되도록 단계별 절차와 필수 시험 항목을 정한다.
3. 03 시스템 설계서 보안 요구사항 반영표: 시스템(이용자 웹 화면, 관리자 화면, API, 운영 관리 수단)별로 설계를 등재하고 요구사항 ID별 반영 여부를 확인한다.
4. 05 증적 수집 점검표: 반영표의 설계가 실제로 구현되어 있음을 보여주는 화면·설정·점검 결과 증적을 수집한다.
5. 04 시스템 변경 내역서: 이후 변경이 생길 때마다 영향 검토와 반영·시험 확인을 기록하고 반영표·증적을 현행화한다.

## 3. 심사 대비 체크리스트

2026-10-20 현재 충족 여부다.

- [x] 개발 관련 지침에 사용자 인증 보안 요구사항(인증 시기, 패스워드 잠금 임계치·암호화·길이·조합·변경 주기, 동시 접근·IP 제한, 세션 타임아웃, 추가 인증, API 인증)이 빠짐없이 정의되어 있다. — 01 4항
- [x] 이용자 웹 화면뿐 아니라 관리 기능, API, 운영 관리 수단의 인증도 설계에 포함했다(개인정보 수집·과금 기능은 없음). — 03 2항
- [ ] 관리자 기능은 일반 사용자와 분리했고 추가 인증(OTP)을 요구한다. — 설계만 있음. 관리자 경로·TOTP 미구현
- [ ] SaaS 접근 권한 정책을 수립하여 사용 권한과 관리 권한을 구분해 부여하도록 설계했다. — 설계(제품 설계안 04 §8 RBAC)는 있으나 `role_permissions` 미구현
- [ ] API 연동 호출에 안전한 인증을 적용했고 인증키를 비밀정보 저장소 등으로 보호하며 평문 저장이 없다. — 커밋 차단(gitleaks)은 동작. api 인증과 운영 Secret(SealedSecrets)은 미구현
- [ ] 중요정보 저장 시 안전성이 입증된 알고리즘·키 길이로 암호화하고(12.3.1 암호 정책과 일치), 비밀번호는 일방향 암호화로 저장한다. — DB · 운영 스토리지 미구성
- [ ] 전송 구간에 TLS 1.2 이상을 적용했고, SSL v3·TLS 1.0/1.1 등 취약 프로토콜이 비활성화되어 있음을 스캔으로 확인했다. — 운영 도메인 미구축. HSTS 헤더만 구현
- [ ] 접속 시도 횟수 제한과 임계치 초과 시 계정 잠금 등 정의한 요구사항이 실제로 동작함을 시험·화면으로 입증할 수 있다. — 로그인 미구현
- [ ] 입력값 검증과 Prepared Statement 사용을 코드 리뷰·취약점 점검으로 확인했고 SQL Injection 취약점이 없다. — 입력값 검증·ZAP·semgrep 은 확인(High 0, 0건). DB 미구현이라 매개변수화 쿼리 확인 전

## 4. 관련 산출물(다른 항목)

- 10.3.2 사용자 인증: 본 항목은 설계·개발 단계의 요구사항 정의·반영을, 10.3.2는 운영 단계의 인증 통제를 다룬다. 기준값(5회 잠금, 유휴 30분 등)은 공통 기준 §3.1 로 일치시킨다.
- 10.3.3 강화된 인증 수단 제공: 관리자 TOTP 의 제공·운영 방식을 따른다.
- 10.3.4 패스워드 관리: 패스워드 길이·조합·변경 주기의 세부 기준을 맞춘다.
- 11.1.4 네트워크 암호화: 전송 구간의 프로토콜·암호 스위트·인증서 기준과 운영 현황 관리를 따른다.
- 12.3.1 암호 정책 수립: 저장·전송 암호화에 사용하는 알고리즘·키 길이·키 관리의 전사 기준이다.
- 13.2.1 구현 및 시험: 보안 요구사항 반영 여부를 확인하는 시험의 계획·결과 양식을 따른다.
- 14.3.1 검증필 암호화 기술 제공: 공공기관에 제공하는 암호화 기능은 국가정보원 검증필 암호모듈 요구를 따른다.

## 5. 작성 규칙

- 자리표시자 중 사람 이름·시행일(`{{… 성명}}`, `{{승인일}}`)은 1.2.1 조직 구성 확정 후 일괄 치환한다. 그 밖의 자리표시자는 개발·인프라 완료를 기다리는 칸이며 각 문서 머리의 대기 블록에 사유가 있다.
- 01 조항의 잠금 임계치·세션 시간 등 수치는 법령·고시가 정하지 않은 당사 내부 기준(공통 기준 §3)이다. 조정하더라도 부적합 사례가 걸리는 통제(실패 잠금, 세션 타임아웃, 취약 프로토콜 금지, 입력값 검증)는 없애지 않는다.
- 서명이 필요한 문서는 서명본을 스캔해 사내 문서 저장소 `CSAP/서명본/13.1.2/` 에 보관한다.
- 반영표(03)와 변경 내역서(04)는 버전을 올릴 때 이전 버전을 삭제하지 않고 3년 보관한다.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신한다.
- 법령 인용은 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 개인정보의 안전성 확보조치 기준 제6조·제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.
- 허용·금지 프로토콜과 알고리즘 기준은 KISA 암호이용 안내서의 권고가 바뀌면 01 조항의 표를 함께 개정한다.
