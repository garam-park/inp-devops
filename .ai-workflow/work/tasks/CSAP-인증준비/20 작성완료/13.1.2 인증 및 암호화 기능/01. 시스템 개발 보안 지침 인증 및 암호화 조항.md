## 1. 목적

㈜이노팸은 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS, 이하 "서비스", 하등급 SaaS)의 설계·개발·변경 시 사용자 인증과 중요정보 암호화에 대한 보안 요구사항을 본 조항으로 정의하고, 모든 설계·개발 산출물에 반영하여 인증 우회, 중요정보 유출, 취약한 암호화 사용을 예방한다. 본 문서는 시스템개발보안지침 중 13.1.2 인증 및 암호화 기능에 해당하는 조항이며, 정보보호 정책서의 하위 지침으로 시행한다.

## 2. 적용 범위

- 서비스 인증 범위 내 응용 프로그램 — 이용자 웹 화면(web: React + nginx), 관리자 화면(web 의 관리자 경로, `admin` · `service` 역할 전용), API(api: Node.js + Fastify, 유일한 진입점), 데이터 처리 워커(pipeline: Python) — 와 운영 관리 수단(NCP 콘솔, NKS 클러스터 관리, Cloud DB for PostgreSQL 관리)의 설계·개발·변경 업무 전체. 서비스는 과금 기능과 개인정보 수집 기능을 두지 않는다.
- 소스코드 저장소: `jeju-ai-saas-be`(api · pipeline), `jeju-ai-saas-fe`(web)
- 당사 임직원과 개발 업무를 수행하는 외부인력
- 책임공유모델에 따라 애플리케이션 계층의 인증·암호화 설계는 당사 책임이다. 하이퍼바이저·물리 인프라 등 IaaS/PaaS 제공자(NCP 공공기관용) 책임 영역의 인증은 제공자 인증(CSAP 등)·계약으로 확인하고, 당사가 사용하는 NCP 콘솔·NKS·Cloud DB 관리 계정의 인증 설정은 당사 책임으로 본 조항을 적용한다.
- 사내 개발·스테이지 환경(`dev0` 클러스터)과 로컬 환경은 인증 대상이 아니나, 운영 데이터를 반입하지 않는 조건으로 본 조항의 코드 요구사항(4.4항 · 7항)을 동일하게 적용한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 중요정보 | 개인정보, 인증정보, 이용 기관 데이터 등 유출·변조 시 서비스와 이용 기관에 중대한 영향을 주는 정보. 서비스에서는 인증정보, 민감 레이어(관로 `pipes` · 굴착 `excavation`), 사고 기록(주소·피해 내용 포함 가능), 감사 기록, 내보내기 파일을 말한다. 암호화 대상 분류는 5항을 따른다. |
| 인증정보 | 비밀번호, TOTP 비밀값, 세션 식별자·세션 서명키, CSRF 토큰, API 키(브이월드 인증키), 스토리지·DB 자격 증명, 인증서 개인키 등 사용자·시스템 인증에 사용되는 정보 |
| 안전한 암호 알고리즘 | 12.3.1 암호 정책에서 정한 안전성이 입증된 알고리즘과 키 길이(보안강도 112비트(2^112) 이상, KISA 암호이용 안내서 권고 준용). 당사 기준: 대칭 AES-256-GCM, 비대칭 RSA-2048 이상 또는 ECDSA P-256, 해시 SHA-256 이상, 비밀번호 Argon2id. MD5 · SHA-1 · DES 금지 |
| 보안 요구사항 ID | 본 조항 4–7항의 요구사항 식별자. 설계 반영표(양식 03)와 시험 결과에서 추적에 사용한다. |

## 4. 사용자 인증 보안 요구사항

클라우드 시스템 설계 시 다음 요구사항을 정의하여 반영한다. 세부 수치는 당사 기준값이며, 조정하더라도 요구사항 자체를 삭제하지 않는다.

### 4.1 인증 시기와 대상

| ID | 요구사항 | 적용 대상 |
| --- | --- | --- |
| AUTH-01 | 서비스 기능·데이터에 접근하기 전에 사용자를 인증하며, 인증 없이 접근 가능한 기능은 공개 대상으로 한정하여 명세한다. 서비스의 공개 대상은 로그인(`POST /api/auth/login`)과 프로브(`GET /api/health`, `GET /api/ready`), 정적 화면 자원뿐이다. 그 밖의 모든 `/api` 라우트는 서버의 인증 훅을 지난다. | 이용자 웹 화면, API |
| AUTH-02 | 관리 기능(데이터셋 업로드·빌드·활성화, 권한 표, 감사 조회, 작업 상태)과 운영 관리 수단(NCP 콘솔, NKS 클러스터, Cloud DB 관리)도 사용자 인증을 거쳐 접근한다. pipeline 워커는 외부 접근 경로가 없고 DB · 스토리지에 역할별 자격 증명으로만 접근한다. | 관리 기능, 운영 관리 수단 |
| AUTH-03 | 관리자 기능은 일반 사용자 기능과 분리(관리자 전용 경로·화면, 서버의 역할 검사)하고, 접근 시 추가 인증(TOTP)을 요구한다. 화면 숨김만으로 통제하지 않고 서버가 거부한다. | 관리자 화면, 관리자 API |
| AUTH-04 | 관리자 역할(`admin` · `service`) 로그인과 NCP 콘솔, 클러스터·DB 운영 접근에는 TOTP(앱 기반 OTP)를 필수로 적용한다. 일반 이용자는 선택 적용한다. 정보통신망을 통한 외부 접속에는 안전한 인증수단을 적용한다(안전성 확보조치 기준 제6조제2항). 발주처 확인으로 개인정보처리시스템에 해당하면 해당 기능 접근에도 TOTP 를 필수로 한다. | 관리자 화면, 운영 관리 수단 |

### 4.2 패스워드

| ID | 요구사항 | 기준값 |
| --- | --- | --- |
| AUTH-05 | 패스워드 길이·조합 규칙을 정의하여 서버에서 강제한다. | 10자 이상, 영문 대문자·소문자·숫자·특수문자 중 3종 이상 조합 |
| AUTH-06 | 로그인 실패가 임계치를 초과하면 계정을 잠근다. 인증 요청에는 요청 수 제한을 함께 둔다. | 연속 5회 실패 시 30분 잠금(또는 관리자 해제). 인증 요청 IP+계정 기준 분당 20회 |
| AUTH-07 | 패스워드는 복호화되지 않도록 일방향 암호화(솔트 적용 해시)하여 저장한다(안전성 확보조치 기준 제7조제1항). | Argon2id(솔트 내장) |
| AUTH-08 | 패스워드 변경 주기와 초기 패스워드 강제 변경을 적용하고, 최근 패스워드 재사용을 금지한다. | 관리자 계정(`admin` · `service` · 운영 콘솔) 90일, 일반 이용자 180일 권고(유출 의심 시 강제). 최근 3개 재사용 금지. 초기·임시 패스워드는 유효 24시간, 첫 로그인 시 변경 강제 |
| AUTH-09 | 로그인 오류 메시지는 아이디 존재 여부와 패스워드 오류를 구분하여 표시하지 않는다. | 일반화된 메시지 |

- 패스워드 세부 기준(생성 규칙, 변경 절차 등)은 10.3.4 패스워드 관리 절차와 일치시킨다.
- 로그인 식별자(`login`)에는 실명·이메일을 쓰지 않는다(하등급 조건 유지).

### 4.3 접근 권한과 세션

| ID | 요구사항 | 기준값 |
| --- | --- | --- |
| AUTH-10 | 동일 사용자·동일 권한의 동시 접근 제한을 설계에 정의한다(관리자 계정은 필수). | 관리자 역할(`admin` · `service`) 동시 세션 1개 — 새 로그인 시 기존 세션을 서버에서 폐기. 일반 이용자는 제한하지 않는다 |
| AUTH-11 | 관리자 등 필요 시 접근 IP 제한을 적용할 수 있게 설계한다. | 관리자 화면·관리자 API · 운영 콘솔은 사내 VPN 대역만 허용(Ingress IP 허용 목록, NCP ACG) |
| AUTH-12 | 접근 후 활동을 수행하지 않으면 세션이 자동 만료되도록 타임아웃을 설정한다(안전성 확보조치 기준 제6조제4항). 로그아웃 시 서버 세션을 폐기한다. | 유휴 30분(관리자 15분), 절대 만료 12시간 |
| AUTH-13 | 서비스 사용을 위한 접근 권한 정책(역할 `admin` · `service` · `user`, 역할별 레이어·내보내기 권한 `role_permissions`)을 수립하고, 그에 따라 사용 권한과 관리 권한을 구분하여 부여하도록 설계한다. 민감 레이어(관로·굴착)와 사고 기록에 대한 접근 권한도 정책에 따라 부여하며, 서버가 파일 중계·내보내기·관리자 라우트·사고 기록 변경에서 집행한다. | 권한 정책 문서(10.2 접근통제 산출물), 제품 설계안 04 §8 |

### 4.4 API 및 연동 서비스

| ID | 요구사항 | 기준값 |
| --- | --- | --- |
| AUTH-14 | API 등을 통한 연동 서비스 호출에 안전한 인증 방안을 적용한다. 인증 없는 API 엔드포인트를 두지 않는다(AUTH-01 의 공개 대상 제외). web → api 는 같은 출처 세션 쿠키(`httpOnly; Secure; SameSite=Lax`) + 상태 변경 요청의 CSRF 토큰(`X-CSRF-Token`)으로 인증한다. 외부로 나가는 호출(브이월드 WMTS)은 서버가 고정 호스트로만 중계하고 인증키를 서버에서 붙인다. 외부 기관이 호출하는 대외 연동 API 는 두지 않으며, 신설 시 OAuth 2.0 클라이언트 자격 증명 또는 API 키 + TLS 를 적용하고 본 조항을 개정한다. | 세션 쿠키 + CSRF 토큰, TLS 1.2 이상 |
| AUTH-15 | 인증에 사용되는 인증키(세션 서명키, DB 비밀번호, 스토리지 자격 증명, 브이월드 인증키, TLS 개인키)는 비밀정보 저장소로 보호하고, 소스코드·설정 파일·이미지·번들·로그에 평문으로 저장하지 않는다. 커밋 시 gitleaks 로 차단한다. | k8s Secret(SealedSecrets 로 봉인해 저장소에 보관), 환경변수로만 주입. 회전 연 1회·유출 의심 시 즉시, 키 식별자(`kid`)로 무중단 회전 |

## 5. 저장 암호화 보안 요구사항

중요정보로 분류된 데이터는 저장 시 암호화·복호화를 적용하도록 설계한다. 암호 알고리즘과 키 길이는 12.3.1 암호 정책의 안전성이 입증된 알고리즘을 사용한다.

| ID | 대상 | 요구사항 | 근거 |
| --- | --- | --- | --- |
| ENC-S-01 | 비밀번호, TOTP 비밀값 등 인증정보 | 저장 시 암호화하며, 비밀번호는 일방향 암호화(Argon2id). TOTP 비밀값은 AES-256-GCM 으로 암호화하여 DB 에 저장하고 암호화 키는 Secret 으로 분리 | 안전성 확보조치 기준 제7조제1항 |
| ENC-S-02 | 이용자의 주민등록번호·여권번호·운전면허번호·외국인등록번호·신용카드번호·계좌번호·생체인식정보 | 서비스는 이 정보를 수집하지 않는다(설계상 수집 항목 없음). 수집이 필요해지면 안전한 암호 알고리즘(AES-256-GCM)으로 암호화하여 저장하고 본 조항을 개정한다 | 안전성 확보조치 기준 제7조제2항 |
| ENC-S-03 | 그 밖의 중요정보(민감 레이어, 사고 기록, 감사 기록, 내보내기 파일, 백업) | 관리형 DB(Cloud DB for PostgreSQL)와 Object Storage 의 서버측 암호화(AES-256)를 적용한다. 컬럼 단위 암호화는 적용하지 않으며 근거(공개 공공데이터 기반·개인정보 미수집, 접근 권한·감사로 통제)를 설계 반영표에 기록한다 | 내부 데이터 분류 기준 |
| ENC-S-04 | 개인정보취급자 컴퓨터·모바일 기기·보조저장매체에 저장하는 이용자 개인정보 | 서비스는 이용자 개인정보를 PC 로 내려받는 기능을 두지 않는다. 사고 기록 내보내기에 개인 식별 정보가 포함되는 경우 내려받은 파일은 안전한 암호 알고리즘으로 암호화하여 보관한다 | 안전성 확보조치 기준 제7조제5항 |
| ENC-S-05 | 암호키 | 키 생성·보관·교체·폐기는 12.3.1 암호 정책의 키 관리 기준을 따르고, 암호화 대상 데이터와 분리하여 보관한다(k8s Secret, 환경변수 주입, 코드·이미지·로그 금지). KMS 도입 여부는 12.3.1 · 14.3.1 의 결정을 따른다 | 12.3.1 암호 정책 |

- 공공기관에 제공하는 암호화 기능의 검증필 암호모듈(KCMVP) 적용은 14.3.1 검증필 암호화 기술 제공 산출물의 결정을 따른다.

## 6. 전송 암호화 보안 요구사항

중요정보를 송·수신하는 경우 기밀성과 무결성을 지원하는 안전한 채널을 사용하도록 설계한다.

| ID | 요구사항 | 기준값 |
| --- | --- | --- |
| ENC-T-01 | 웹 화면·관리자 화면·API 의 송·수신 구간에 TLS 1.2 이상을 적용한다. 외부 구간은 NCP Load Balancer/Ingress 에서 TLS 를 종단하고 HSTS(1년)를 보낸다. 내부 구간은 api ↔ DB `sslmode=require`, api · pipeline ↔ Object Storage HTTPS 를 적용한다. | TLS 1.2 이상(1.3 우선) |
| ENC-T-02 | SSL(전 버전), TLS 1.0, TLS 1.1 등 취약한 암호화 프로토콜은 지원하지 않도록 설정하고, 설계·구축 시 비활성화를 확인한다. RC4 · 3DES · export 등급 cipher 도 비활성화한다. | 금지 목록 고정 |
| ENC-T-03 | 서버 원격 접근·데이터 이관 등 관리 목적 통신에는 암호화된 통신수단을 사용한다. 운영자는 VPN 으로 접속한 뒤 배스천·콘솔(HTTPS)과 `kubectl`(TLS)로만 관리한다. | VPN + TLS |
| ENC-T-04 | 개인정보·인증정보를 정보통신망(인터넷망 구간)으로 송·수신하는 경우 안전한 암호 알고리즘으로 암호화한다(로그인 요청·세션 쿠키는 HTTPS 로만 전송, 쿠키 `Secure`). | 안전성 확보조치 기준 제7조제1항·제4항 |
| ENC-T-05 | 지원 암호 스위트의 보안강도는 112비트(2^112) 이상으로 구성한다(11.1.4 네트워크 암호화 지침과 일치). | 인증서 RSA-2048 이상 또는 ECDSA P-256, 서명 SHA-256 이상, AEAD(AES-GCM · CHACHA20-POLY1305) 스위트 |

## 7. 시큐어 코딩 보안 요구사항

| ID | 요구사항 | 기준값 |
| --- | --- | --- |
| SEC-C-01 | 사용자 입력값은 서버 측에서 검증한 뒤 사용하고, 검증 없이 SQL 쿼리·명령어·경로에 직접 연결(문자열 연결)하지 않는다. 경로는 manifest 조회 또는 검증 함수로만 해석한다. | Fastify 라우트 JSON 스키마(경로·쿼리·본문), 슬러그 패턴 `^[a-z0-9][a-z0-9-]{0,62}$`, `safeFilePath` |
| SEC-C-02 | DB 질의는 Prepared Statement(매개변수화된 쿼리) 또는 검증된 쿼리 빌더·ORM 을 사용하여 SQL Injection 을 차단한다. 검색 기능 등 동적 조건이 필요한 경우에도 문자열 연결 방식을 사용하지 않는다. 정렬 열 등 식별자는 허용 목록과 대조한다. | 코드 리뷰 필수 확인 항목, semgrep |
| SEC-C-03 | 인증·세션·암호화 기능은 검증된 표준 라이브러리·프레임워크 기능을 사용하고 자체 구현하지 않는다. | Fastify 생태계(`@fastify/helmet`, 세션·CSRF 플러그인), Node.js `crypto`(OpenSSL), 검증된 Argon2id 라이브러리 |
| SEC-C-04 | 오류 발생 시 내부 정보(스택 트레이스, 쿼리문, 서버 정보)를 사용자 화면에 노출하지 않는다. | 공통 오류 응답 `{ error: <일반 메시지> }`, nginx `server_tokens off` |

## 10. 예외 관리

1. 기술적 제약으로 요구사항을 적용할 수 없으면 대체 통제와 적용 기한을 적어 정보보호 최고책임자의 승인을 받는다.
2. 예외는 양식 03의 반영 확인표에 예외 승인 번호와 함께 기록하고, 반기마다 지속 필요성을 재검토한다.
3. 취약 프로토콜 허용(ENC-T-02 위반)과 인증 없는 중요 기능 접근(AUTH-01·02 위반)은 예외로 승인하지 않는다.
