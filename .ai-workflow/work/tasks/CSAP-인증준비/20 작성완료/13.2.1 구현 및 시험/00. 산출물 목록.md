## 2. 권장 작성 순서

1. 01 시큐어 코딩 표준: 외부 환경 분석과 참조 표준(KISA·OWASP)을 반영해 코딩 규칙을 정하고, 코드 리뷰·정적 분석 적용 절차까지 포함해 승인을 받는다.
2. 05 증적 수집 점검표(No 1–4): 코딩표준 게시, 정적 분석 룰셋, CI 차단 설정, 코드 리뷰 필수 설정을 먼저 갖추고 증적을 수집한다.
3. 03 보안 시험 계획 및 시나리오: 13.1.2 설계 단계 보안 요구사항과 코딩표준 요구사항을 추적표에 모두 올리고, 케이스가 없는 요구사항이 없도록 시나리오를 작성한다.
4. 04 보안 시험 결과서: 시험을 수행해 케이스별 결과와 증적을 남기고, 결함은 조치·재시험 후 운영 반영을 판정한다.
5. 02 시큐어 코딩 준수 점검 결과서: 반기(또는 릴리스)마다 정적 분석·코드 리뷰 이행을 점검하고 위반 사항을 조치한다.

- [x] 코딩표준에 서버 측 입력값 검증, 입력 데이터 유효성 확인과 안전한 오류 처리, SQL 삽입 방지, 검증되지 않은 URL 리다이렉션 방지, 안전한 세션 관리가 모두 포함되어 있다. — 01 4항

## 4. 관련 산출물(다른 항목)

- 13.1.2 인증 및 암호화 기능: 설계 단계에서 정의한 사용자 인증·암호화 보안 요구사항(JAS-13.1.2-01 · 03)이 03 시험 계획 추적표의 입력이다.
- 12.3.1 암호 정책 수립: 코딩표준 4.8항의 암호 알고리즘·키 길이 기준과 저장 암호화 시험(TC-11) 기준을 암호 정책과 맞춘다.
- 11.1.4 네트워크 암호화: 전송 구간 TLS 시험(TC-12) 증적을 공용으로 활용한다.
- 10.3.2 사용자 인증, 10.3.3 강화된 인증 수단 제공, 10.3.4 패스워드 관리: 인증·계정 잠금·패스워드 규칙의 구현 기준을 따르고, 관련 시험 케이스(TC-01–TC-03, TC-14 · TC-15)의 기준 값을 일치시킨다.
- 9.1.5 공개서버 보안: 공개서버(web · api) 취약점 점검(야간 ZAP · trivy) 결과를 시험·결함 조치와 연계한다.
- 14.1.3 보안관리 수준: 소프트웨어 개발보안 절차와 보안약점 진단 결과서가 같은 도구(semgrep) 결과를 쓴다.
- 7.1.1 법적요구사항 준수: 코딩표준 3.2항의 외부 환경 분석(법·제도·규정)은 법적 요구사항 식별 결과를 활용한다.
- 2.3.2 교육 시행: 개발자 시큐어 코딩 교육 이수 기록을 증적으로 활용한다.
- 2.1.2 주요 직무자 지정 및 감독: 운영 배포·형상관리 권한자의 개발·배포 승인 분리를 시험·배포 절차에 반영한다.

## 5. 작성 규칙

- 자리표시자 중 사람 이름·시행일(`{{… 성명}}`, `{{승인일}}`)은 1.2.1 조직 구성 확정 후 일괄 치환한다. 그 밖의 자리표시자는 개발·인프라 완료를 기다리는 칸이며 각 문서 머리의 대기 블록에 사유가 있다.
- 서명이 필요한 문서는 서명본을 스캔해 사내 문서 저장소 `CSAP/서명본/13.2.1/` 에 보관한다.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신한다.
- 02·03·04는 점검·릴리스 건마다 문서번호(`JAS-13.2.1-02-<연도>-<회차>`, `JAS-13.2.1-03-<연도>-<회차>`, `JAS-13.2.1-04-<연도>-<회차>`)를 새로 부여해 회차별로 3년 보관한다.
- 03 추적표의 요구사항 ID(SR-nn)와 케이스 ID(TC-nn)는 기능이 늘면 추가하되, 케이스가 없는 요구사항이 남지 않게 한다.
- 시험은 운영과 분리된 환경(CI 임시 스택, `dev0`, 스테이지)에서 수행하고, 시험 데이터에 운영 데이터·개인정보를 사용하지 않는다.
- 법령 인용은 개인정보의 안전성 확보조치 기준 제6조·제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.
