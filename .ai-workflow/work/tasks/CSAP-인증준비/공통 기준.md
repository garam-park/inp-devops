### 1.1 시스템 구성 (목표 구조)

실행 단위 3개 + 저장소 2개. 브라우저는 스토리지를 모르고 모든 요청은 Ingress → `/api` 단일 경로다.

| 단위 | 기술 | 역할 | 현재 구현 (2026-10-20) |
| --- | --- | --- | --- |
| web | React 19 + TypeScript, Vite, `nginxinc/nginx-unprivileged:1.30-alpine` | 정적 화면. `/api/` 는 api 로 프록시. 보안 응답 헤더(CSP · HSTS · nosniff · X-Frame-Options DENY · Referrer-Policy · Permissions-Policy) | 구현됨 (`jeju-ai-saas-fe`) |
| api | Node.js 24 + TypeScript, Fastify, `@fastify/helmet`, `@fastify/swagger` | 유일한 진입점. 인증·권한·감사, 조회, 내보내기, 업로드, 번들 파일 중계, 작업 등록 | 스토리지 중계 API만 구현(`/api/catalog`, 워크스페이스, 레이어 파일). **인증·권한·감사·DB 미구현** |
| pipeline | Python 3.12 워커 | 원본 → 데이터셋 번들(변환·채점·군집·레이어). `jobs` 표 폴링. 지수 레이어는 격리 컨테이너(네트워크 없음 · 읽기 전용 · nobody · 자원 제한) | 로컬 CLI 로만 실행(`build_data.py`, `run_index.py`) |
| PostgreSQL + PostGIS | 운영은 NCP Cloud DB for PostgreSQL | 계정·권한·감사·사고 기록·데이터셋 버전·작업·내보내기 | **미구성** |
| 오브젝트 스토리지 | S3 호환 (운영 NCP Object Storage 공공, 개발 SeaweedFS/MinIO) | `orgs/` 레이어 자료(현재), 목표 `raw/` · `datasets/{버전}/` · `exports/` · `incidents/uploads/` · `backups/` | 버킷 `jeju-ai-saas` (로컬 SeaweedFS) |

### 1.2 네트워크 · 영역 (목표)

| 영역 | 구성 요소 | 비고 |
| --- | --- | --- |
| 외부(인터넷) | 이용자 브라우저 | HTTPS 만 |
| 진입 영역 | NCP ALB(ALB Ingress Controller, IngressClass `alb`) — TLS 종단 · path 라우팅. rate limit · 본문 크기 제한을 ALB 로 할 수 있는지는 확인 전 | 유일한 공개 진입점. 관리 포트·DB·스토리지는 비노출. TLS 종단 위치는 ALB 로 결정(2026-10-21, index 결정 5). ALB → 파드 구간 평문은 index 결정 4 |
| 서비스 영역 | web · api · pipeline 파드 (네임스페이스 분리, NetworkPolicy 기본 거부) | PSA `restricted`, 비루트, `readOnlyRootFilesystem`, `drop: [ALL]`, seccomp `RuntimeDefault`, `automountServiceAccountToken: false` |
| 데이터 영역 | Cloud DB for PostgreSQL(TLS `require`, 사설 서브넷) · Object Storage(사설 엔드포인트, 역할별 자격증명) | api · pipeline 만 접근. 접근은 NetworkPolicy egress 로 한정 |
| 관리 영역 | 운영자 PC → VPN → 배스천/콘솔(NCP 콘솔 MFA, kubectl) · GitHub Actions self-hosted runner(push 배포) | 운영 접근은 MFA + 접근기록 |
| 개발·시험 | 사내 `dev0`, 로컬 | 운영과 물리·논리 분리. 운영 데이터 반입 금지 |
| 외부 연계 | 브이월드 WMTS(서버 중계, 허용 목록 고정 호스트), 컨테이너 레지스트리(GHCR → **NCP Container Registry 공공으로 전환 예정**, ADR D5) | 허용 목록 외 egress 차단. Private 서브넷의 외부 출구는 NAT Gateway 하나다. GHCR pull 은 NAT 로 된다(2026-10-21 시험) |

## 4. 작성 규칙

1. **양식을 그대로 가져와 채운다.** 구조·절 번호·표 열은 유지한다. 양식이 요구하는 절을 빼지 않는다. 양식 안의 설명문("...예요" 체)은 당사 문서체("...한다")로 바꿔도 되고, 안내 문구(예: "지우고 실제 내용으로")는 지운다.
2. **자리표시자 처리**
   - `{{자유 입력}}` · `{{예: …}}` → 실제 값. 이 문서 §1–§3 의 값을 쓴다.
   - `{{A / B}}` 선택지 → 하나만 남긴다.
   - `{{n}}` · `{{주기}}` 기본값 → §3 의 값. §3 에 없으면 양식 기본값을 유지하고 index 의 "당사 기준값 결정 목록"에 올린다.
   - 해당 없으면 지우지 않고 **"해당 없음 — 사유"** 를 적는다.
   - 비기술 양식에서 정해지는 값(§2)은 `{{...}}` 그대로.
   - 개발·인프라 미완으로 못 채우는 값은 `{{...}}` 그대로 두고 **대기 사유**를 문서 머리의 `> [!warning] 대기` 블록에 적는다. 그 문서는 `11 대기중`.
3. **목표 상태 기준, 차이는 표시.** 정책·지침·절차·기준은 gis-sass 설계와 §3 을 기준으로 끝까지 쓴다. 구성도·현황·결과서처럼 "지금 무엇이 있는가"를 적는 문서는 현재 코드로 채울 수 있는 데까지 채우고, 목표와 다른 곳은 `> [!note] 현 구현과 차이` 블록 또는 표의 비고에 적는다.
4. **지킬 수 있는 것만 적는다.** 심사는 문서대로 하는지를 본다. 과장하지 않는다. 미구현은 미구현이라고 쓴다.
5. **상태 판정**
   - `20 작성완료`: 개발·인프라 미완 사유의 `{{...}}` 가 0개. (사람 이름·시행일 자리표시자는 허용)
   - `11 대기중`: 그런 `{{...}}` 가 1개 이상. 머리의 대기 블록에 "무엇이 생기면 채울 수 있는지"를 항목으로 적는다.
   - `10 작성중`: 쓰는 중. 끝나면 둘 중 한 곳으로 옮긴다.
6. **front matter** — 양식의 front matter 를 유지하되 다음을 바꾼다.
   - `doc_type: 양식` → `doc_type: 작성본`
   - `문서 양식 번호` · `문서 양식 버전` 은 유지하고 `문서번호: JAS-...` · `문서 버전: 1.0` · `상태: 작성완료 | 대기중` · `작성일: 2026-10-20` 를 추가한다. 대기중이면 `대기 사유:` 한 줄 요약.
7. **근거 링크** — `> [!note] 근거` 의 해설서 링크는 작업 폴더 기준 상대 경로로 바꾼다. 세 상태 폴더 모두 깊이가 같다:
   `../../../../../../projects/jeju-ai/docs/CSAP/해설서/하등급-SaaS/<분류>/<통제항목>.md` (공백은 `%20`).
   같은 폴더 안 다른 양식 링크는 작성본 파일명(`-양식_v0.0.1` 제거)으로 바꾼다.
8. **파일명** — 양식 파일명에서 `-양식_v0.0.1` 을 뺀다. 예: `02. 공개서버 보안 설정 기준.md`. 폴더명은 통제항목 폴더명 그대로.
9. **법령 기준 박스**(`> [!info] 법령 기준`)는 유지한다. 고시 번호·시행일은 양식 작성 시점 값이므로 그대로 두고 바꾸지 않는다.
10. **비밀값·개인정보**를 쓰지 않는다. 설정 키 이름·경로·도구 이름은 쓴다.
11. **00. 산출물 목록**은 그 폴더 문서를 다 쓴 뒤 채운다. 표에 `상태`(작성완료 / 대기중 / 비기술-미작성) 열을 더하고, 비기술 47건에 속하는 양식은 "비기술 — 별도 작성(TODO 목록)" 으로 적는다. 심사 대비 체크리스트는 현재 충족 여부를 `[x]`/`[ ]` 로 표시하고 미충족은 사유를 붙인다.
12. 문장은 간결한 공문서체. 범위 표기에 `~` 를 쓰지 않는다(`–` 사용).
