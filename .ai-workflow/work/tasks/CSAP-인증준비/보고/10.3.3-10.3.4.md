# 10.3.3 · 10.3.4 작성 보고 요약

- 결과: 11건. 작성완료 5건(10.3.3 00 · 01 · 02, 10.3.4 00 · 01), 대기중 6건(10.3.3 03 · 04 · 05, 10.3.4 02 · 04 · 05)
- 확인 사실: GitHub 조직 innopam 의 2단계 인증 필수 설정이 꺼져 있다. 구성원 17명 중 7명이 미설정이다. web 은 로그인 없이 고정 사용자로 동작하고, 관리자 화면은 해시 라우트(#admin)다.

## 새로 정한 기준값
- 이메일·문자 인증코드는 제공하지 않는다.
- TOTP 는 RFC 6238 30초·6자리로 하고 백업 코드를 발급한다.
- MFA 요청 처리 기한은 분류 1, 검토 3(C 유형 10), 적용 5, 회신 1영업일이다. 예외는 최대 6개월이고 반기마다 재검토한다. 준수율 목표는 90 % 다.
- 패스워드는 2종 조합을 허용하지 않는다. 관리자 패스워드 길이는 10자이고 TOTP 를 필수로 둔다. 임직원 운영 계정은 90일, DB 앱 계정은 연 1회 바꾼다.
- 브라우저 패스워드 저장은 PasswordManagerEnabled=false 로 막는다. 비상 계정은 밀봉 봉투와 내화금고에, 앱 계정은 SealedSecrets 에 둔다.
- 재발급 본인확인은 service 관리자 또는 부서장이 한다. "로그인 상태 유지" 는 두지 않는다.

## 쟁점
1. service 역할에 관리자 IP 제한을 걸지 정해야 한다. VPN 제한은 admin API 에만 걸었고, admin 과 service 의 주체는 1.2.1 · 2.1.2 에서 확정해야 한다.
2. GitHub 조직의 2FA 필수 설정이 꺼져 있다. 해설서 부적합 사례 1 에 해당하며 즉시 조치할 수 있다.
3. NCP 공공 콘솔의 MFA·IP·패스워드 기능을 실측하지 않았다.
4. NKS kubectl 의 MFA 는 VPN+OTP 배스천 구조가 확정돼야 근거가 된다.
