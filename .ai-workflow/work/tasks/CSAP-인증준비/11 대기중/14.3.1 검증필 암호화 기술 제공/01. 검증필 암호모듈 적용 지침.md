> [!note] 적용 방침 (공통 기준 §3.3)
> 공공기관 이용 기관의 중요자료 전송·저장 암호화에는 검증필 암호모듈 사용을 원칙으로 한다. 기준일 현재 서비스 스택(Node.js·nginx의 OpenSSL, Python 3.12 의 OpenSSL, PostgreSQL)은 KCMVP 검증필 모듈이 아니다. 당사는 NCP 공공 영역이 제공하는 검증필 기반(KMS·Load Balancer TLS 등 — 탑재 현황 확인 필요)을 우선 활용하고, 당사가 직접 운영하는 암호화 구간은 검증필 모듈 적용 방안을 결정한 뒤 본 지침 4항과 02·03 목록에 반영한다. 결정 전까지 해당 구간은 12.3.1 데이터보호 및 암호화 지침의 알고리즘 기준(AES-256-GCM, TLS 1.2 이상 등)을 적용한다.

> [!info] 법령 기준
> 국가 사이버보안 기본지침 제20조(정보통신제품 도입)·제22조(검증필 암호모듈 운용 및 관리)를 근거로 한다. 비공개 지침이라 문서명과 조 번호만 인용하며, 필수 제품 유형·검증 요건 등 세부사항은 국가정보원의 보안적합성 검증 정책과 암호모듈 검증 정책에 따르고 국가정보원 공지로 확인한다. 개인정보 암호화는 개인정보의 안전성 확보조치 기준 제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)와 12.3.1 데이터보호 및 암호화 지침을 함께 따른다. 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 공공기관에 제공하는 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(이하 "서비스")을 통해 생성된 중요자료를 암호화하는 수단을 제공하는 경우 검증필 국가표준암호화 기술을 제공하기 위하여, 중요자료 전송·저장에 사용하는 제품의 검증필 암호모듈 탑재 요건과 도입·운용·유효기간 관리 기준을 정한다.

## 2. 적용 범위

| 구분 | 범위 | 책임 |
| --- | --- | --- |
| 당사 도입·운영 제품 | 서비스 인증 범위에서 당사가 도입·운영하는 VPN(관리 영역 운영자 접속), 보안 USB, 호스트 자료유출 방지제품 등 중요자료 전송·저장용 정보보호제품과 암호화 제품. 기준일 현재 도입한 제품은 없다 | 당사(본 지침 적용) |
| 서비스 구현 암호화 기능 | 서비스 응용(api · pipeline · web)에 직접 구현·구성하는 암호화 기능 — 비밀번호 Argon2id, 세션 HMAC-SHA-256, MFA 시크릿 AES-256-GCM, 클러스터 Ingress TLS 종단, api ↔ DB TLS. 서비스는 이용 기관에 중요자료를 암호화하는 별도 수단(파일 암호화 기능 등)을 제공하지 않는다 | 당사(12.3.1 암호 정책, 13.1.2 인증 및 암호화 기능 연계). 검증필 모듈 적용 여부는 대기 블록의 결정에 따른다 |
| 제공자 관리형 암호화 기능 | IaaS/PaaS 제공자(네이버클라우드 NCP 공공기관용 영역)가 제공하는 Key Management Service, Load Balancer TLS, Object Storage·Cloud DB 저장 암호화 등 관리형 기능 | 제공자 인증(CSAP)·계약으로 안전성 확인. 검증필 모듈 탑재 현황은 확인 필요 |
| 이용 기관 영역 | 이용 기관이 자체 도입하는 암호화 수단과 내보내기로 받은 자료의 반출 후 보호 | 이용 기관(보안 이용 가이드로 안내) |

- 중요자료 전송·저장용 암호화 제품을 도입·운영하지 않는 경우에도 본 지침을 유지하고, 그 사실과 판단 근거를 [02. 정보보호제품 목록](02.%20정보보호제품%20목록.md)에 기록한다. 신규 도입 시점부터 4항 이하를 적용한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 검증필 암호모듈 | 국가정보원의 암호모듈 검증(KCMVP)을 받아 검증필 암호모듈 목록에 등재된 암호모듈 |
| 국가표준 암호 알고리즘 | 검증필 암호모듈이 구현하도록 승인된 암호 알고리즘. 블록암호 ARIA·SEED·LEA·HIGHT, 해시 SHA-2 계열, 메시지 인증 HMAC, 난수발생기 DRBG, 전자서명 RSA-PSS·ECDSA·KCDSA 등이며, 검증 시점의 승인 목록을 IT보안인증사무국 「검증대상 암호알고리즘 목록」으로 재확인한다 |
| 검증대상 동작모드 | 검증필 암호모듈이 검증받은 조건(승인 알고리즘·설정)으로 동작하는 모드. 제품 설정으로 활성화 여부가 결정된다 |
| CC 인증 | 공통평가기준(Common Criteria)에 따른 정보보호제품 평가·인증 |
| 보안기능 확인서 | 국가정보원장이 정보통신제품의 보안기능을 확인하여 발급하는 확인서 |
| 보안적합성 검증 | 검증필 제품 목록에 없는 제품을 국가·공공기관이 도입할 때 취약점을 확인·제거하는 국가정보원 검증 제도 |
| 중요자료 | 서비스를 통해 생성·처리되는 공공기관 데이터 중 유출·변조 시 기관 업무에 영향을 주는 자료(관로·굴착 민감 레이어, 사고 기록, 감사 기록, 내보내기 파일)와 개인정보 |

## 4. 검증필 암호모듈 필수 제품 유형과 도입 요건

중요자료 전송·저장을 위해 다음 유형의 제품을 도입·운영하는 경우 검증필 암호모듈이 탑재된 제품을 사용하고, CC 인증 또는 보안기능 확인서를 획득한 제품을 사용한다.

| 제품 유형 | 도입 요건 | 당사 운영 여부 |
| --- | --- | --- |
| 가상사설망(VPN) | 검증필 암호모듈 탑재 | 운영 예정 — 관리 영역 운영자 접속(운영자 PC → VPN → 배스천). 제품: {{VPN 제품 — 선정 후 기록}} |
| 보안 USB | 검증필 암호모듈 탑재 | 해당 없음 — 운영 데이터의 보조저장매체 반출 금지(12.3.1 지침 8항) |
| 호스트 자료유출 방지제품(암호화 저장 기능 보유 시) | 검증필 암호모듈 탑재 | 해당 없음 — 미도입 |
| 메일 암호화제품 | 검증필 암호모듈 탑재 | 해당 없음 — 미도입. 중요자료는 메일로 전송하지 않고 서비스 내 내보내기(HTTPS)로 전달 |
| 구간 암호화제품 | 검증필 암호모듈 탑재 | {{TLS 종단 지점의 검증필 모듈 적용 방안 결정 후 기록 — NCP Load Balancer TLS 또는 클러스터 Ingress}} |
| 하드웨어 보안토큰 | 검증필 암호모듈 탑재 | 해당 없음 — MFA 는 앱 기반 TOTP |
| 디스크·파일 암호화제품 | 검증필 암호모듈 탑재 | 해당 없음 — 당사 도입 제품 없음. 저장 암호화는 제공자 관리형 기능(02 목록 4항) |
| DB 암호화제품 | 검증필 암호모듈 탑재 | 해당 없음 — 미도입. Cloud DB 저장 암호화는 제공자 관리형 기능(02 목록 4항) |
| 문서 암호화제품(DRM 등) | 검증필 암호모듈 탑재 | 해당 없음 — 미도입 |
| SSO 제품 | 검증필 암호모듈 탑재 및 CC 인증(국가용 보호프로파일 준수) 또는 보안기능 확인 제품 | 해당 없음 — 현재 자체 계정만. 발주처 SSO(OIDC) 연동은 열린 결정이며 도입 시 5항 절차로 검토 |
| 기타 암호화제품 | 검증필 암호모듈 탑재 | {{응용 자체 암호화(Node.js OpenSSL)의 검증필 모듈 적용 여부 결정 후 기록}} |

- 검증필 암호모듈 탑재 필수 제품 유형은 국가 사이버보안 기본지침과 국가정보원 공지에 따라 달라질 수 있으므로, 도입 검토 시마다 IT보안인증사무국(<https://www.itscc.kr>), 국가정보원(<https://www.nis.go.kr>), 국가사이버안보센터(<https://www.ncsc.go.kr>)에서 최신 기준을 확인하고 확인 결과를 [04. 검증필 암호모듈 적용 검토서](04.%20검증필%20암호모듈%20적용%20검토서.md)에 기록한다.
- 표에 없는 제품이라도 중요자료를 암호화하여 전송·저장하는 기능을 가지면 정보보호 관리자가 필수 대상 여부를 검토한다.

## 5. 도입 절차

| 단계 | 담당 | 내용 | 기록 |
| --- | --- | --- | --- |
| 1. 도입 요건 판단 | 정보보호 관리자 | 도입 예정 제품이 4항의 필수 제품 유형과 중요자료 전송·저장 용도에 해당하는지 판단 | 04. 검토서 2항 |
| 2. 검증필 암호모듈 확인 | 정보보호 관리자 | 탑재 암호모듈의 검증번호·유효기간·검증대상 동작모드 지원을 검증필 암호모듈 목록에서 확인 | 04. 검토서 3항 |
| 3. 인증 확인 | 정보보호 관리자 | CC 인증서 또는 보안기능 확인서의 번호·대상 버전·유효기간 확인, 도입 버전과 인증 버전의 일치 확인 | 04. 검토서 4항 |
| 4. 유효기간 이중 확인 | 정보보호 관리자 | 검증필 암호모듈 유효기간과 CC 인증(보안기능 확인서) 유효기간을 각각 확인하여 둘 다 유효한 제품만 적합 판정 | 04. 검토서 5항 |
| 5. 승인 | 정보보호 최고책임자 | 도입 승인 또는 반려. 요건 미충족 제품은 도입하지 않는다 | 04. 검토서 7항 |
| 6. 등재·증적 수집 | 정보보호 담당자 | [02. 정보보호제품 목록](02.%20정보보호제품%20목록.md)과 [03. 검증필 암호모듈 목록](03.%20검증필%20암호모듈%20목록.md)에 등재하고 인증서 사본 등 증적 수집 | 02·03 목록, 05. 증적 수집 점검표 |
| 7. 검증대상 동작모드 설정 | 운영(인프라) 담당자 | 제품을 검증대상 동작모드로 설정하고 설정 화면 증적 보관 | 05. 증적 수집 점검표 |

- 요건 미충족 제품을 긴급하게 사용해야 하는 예외는 인정하지 않는다. 대체 제품이 없으면 도입을 보류하고 국가정보원 보안적합성 검증 정책에 따른 처리 방안을 확인한다.

## 6. 유효기간 관리

1. 검증필 암호모듈의 검증 유효기간과 CC 인증(보안기능 확인서)의 유효기간은 별도이므로 각각 관리하며, 둘 중 하나라도 만료되면 해당 제품은 유효하지 않은 것으로 판정한다.
2. 정보보호 담당자는 [02. 정보보호제품 목록](02.%20정보보호제품%20목록.md)의 "다음 만료일"을 기준으로 만료 90일 전에 정보보호 관리자에게 통보한다.
3. 정보보호 관리자는 만료 예정 제품에 대해 다음 중 하나의 조치 계획을 수립하고 정보보호 최고책임자 승인을 받는다.
   - 제조사의 검증·인증 갱신 확인(갱신된 검증번호·인증번호로 목록 갱신)
   - 검증·인증이 유효한 버전으로 업그레이드(양식 04. 검토서로 재확인)
   - 요건을 충족하는 대체 제품 도입(5항 도입 절차 적용)
4. 만료일까지 조치가 완료되지 않으면 해당 제품을 유효하지 않은 제품으로 관리하고, 중요자료 전송·저장 경로에서 제외하거나 서비스 영향이 없는 범위에서 사용을 중단하며, 불가피하게 계속 운영하는 동안의 보완 통제와 조치 기한을 04. 검토서에 기록한다.
5. 연 1회 이상 운영 중인 제품 전체의 두 유효기간을 04. 검토서(정기)로 재점검하고 결과를 02·03 목록에 반영한다.

## 7. 검증필 암호모듈 운용·관리

1. 제품은 검증필 암호모듈의 검증대상 동작모드로 운용하고, 승인되지 않은 알고리즘·설정으로 변경하지 않는다.
2. 각 암호모듈은 검증 시 공개된 보안정책서에 따라 운용하며, 보안정책서 사본은 [03. 검증필 암호모듈 목록](03.%20검증필%20암호모듈%20목록.md)에 기록한 위치에 보관한다.
3. 제품 패치·모듈 교체 등 형상 변경 전에 검증·인증 효력 유지 여부를 확인하고, 확인 기록을 05. 증적 수집 점검표에 따라 보관한다.
4. 암호모듈이 사용하는 암호키의 생성·배포·폐기는 12.3.1 암호키 관리대장에 따라 관리한다.
5. 그 밖의 운용·관리 세부사항은 국가 사이버보안 기본지침 제22조(검증필 암호모듈 운용 및 관리)와 국가정보원 암호모듈 검증 정책에 따른다.
