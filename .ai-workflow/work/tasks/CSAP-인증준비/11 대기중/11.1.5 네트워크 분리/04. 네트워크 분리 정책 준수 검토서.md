## 3. 발견 사항

| No | 발견 사항 | 관련 점검 항목 | 위험도 | 원인 |
| --- | --- | --- | --- | --- |
| 1 | 서비스 Helm chart 와 NetworkPolicy 가 없다. 개발 환경 `dev0` 의 jeju-ai-saas 리소스에도 NetworkPolicy 가 없어 파드 간·외부 egress 가 기본 허용이다 | 7, 8 | 상 | 서비스가 gis-sass chart 구조로 옮기기 전 단계(원시 매니페스트 배포) |
| 2 | 운영자용 관리 기능(`admin` 화면·관리자 API)이 이용자 기능과 같은 호스트·같은 앱에 있어, 인터넷 비노출은 Ingress 경로별 IP 허용 목록에 의존한다. 관리자 API 가 공통 접두어로 묶여 있지 않아 경로 목록 누락 위험이 있다 | 11 | 중 | 제품 설계(관리자 화면을 같은 SPA 에 둠, 해시 라우팅) |
| 3 | 개발 환경 `dev0` 에서 LAN 이 Cilium Ingress IP 로 바로 들어오면 앞단 프록시의 IP 허용 목록을 거치지 않는다 | 해당 없음(개발 환경, 인증 범위 밖) | 하 | 사내 네트워크 구성. 운영과 무관하나 운영 데이터 반입 금지 원칙을 계속 지켜야 한다 |

## 5. 종합 의견

운영 네트워크가 아직 없어 17개 항목 중 설계로 판정할 수 있는 4개(1·2·3·15)는 적합, 해당 없음 1개(14), 나머지 12개는 운영 구성 후 판정한다. 운영과 개발·시험의 분리는 물리적으로(NCP 공공 계정 대 사내 `dev0`) 설계되어 있어 부적합 사례 1·4·5 의 위험은 낮다. 반면 서비스 수준의 네트워크 정책(NetworkPolicy)이 아직 없고, 관리자 기능의 인터넷 비노출이 경로별 IP 허용 목록에 의존하는 점은 운영 개시 전에 고쳐야 한다. 운영 구성 직후 구조 변경 검토를 새 회차로 수행해 미판정 항목을 닫는다.
