## 2. 사용자 인증 설계 내역

인증이 필요한 접근 경로를 빠짐없이 식별하여 한 줄씩 적는다. 서비스는 과금 기능과 개인정보 수집 기능을 두지 않는다.

| No | 접근 경로(시스템·기능) | 사용자 구분 | 인증 시점 | 인증 수단 | 추가 인증 | 실패 잠금(임계치·처리) | 세션 타임아웃 | 동시 접근 제한 | 접근 IP 제한 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 이용자 웹 화면 · `/api` 조회·내보내기 | 이용자(`user`) | 로그인 시, 이후 매 요청 세션 확인 | ID/패스워드 → 세션 쿠키(`httpOnly; Secure; SameSite=Lax`) + CSRF 토큰 | 선택: TOTP | 5회 실패 시 30분 잠금, IP+계정 분당 20회 제한 | 유휴 30분, 절대 12시간 | 미적용 | 미적용 |
| 2 | 관리자 화면 · 관리자 API(데이터셋 업로드·빌드·활성화, 사고 기록 변경, 권한 표, 감사 조회) | 관리자(`admin` · `service`) | 로그인 시, 관리자 라우트마다 역할 검사 | ID/패스워드 → 세션 쿠키 + CSRF 토큰 | TOTP 필수 | 5회 실패 시 30분 잠금(관리자 해제 가능) | 유휴 15분, 절대 12시간 | 세션 1개(새 로그인 시 기존 폐기) | 사내 VPN 대역(Ingress 허용 목록) |
| 3 | 운영 관리 수단(NCP 콘솔, NKS `kubectl`, Cloud DB 관리) | 운영(인프라) 담당자 | 콘솔 로그인 · 클러스터 접속 시 | NCP 계정(서브 계정) · VPN · 배스천 | TOTP 필수(NCP 콘솔 MFA) | NCP 콘솔 로그인 실패 제한(제공자 기능) | NCP 콘솔 세션 설정값 적용 | 개인별 서브 계정, 공용 계정 금지 | 사내 VPN 대역(ACG) |
| 4 | pipeline 워커 → DB · Object Storage | 시스템(워커) | 접속 시 | 역할별 자격 증명(DB 계정, 스토리지 접근 키 — 읽기 `raw/`, 쓰기 `datasets/` · `exports/`) | 해당 없음 — 사람의 접근 경로가 아님 | 해당 없음 | 해당 없음 | 해당 없음 | NetworkPolicy egress 로 DB · 스토리지만 허용 |
| 5 | api → 브이월드 WMTS(배경지도 중계) | 시스템(api, 발신) | 호출 시 | 브이월드 인증키(서버 보관) + HTTPS | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 고정 호스트 허용 목록 egress |

- 관리자 기능은 일반 사용자 기능과 분리하여 설계한다: 관리자 전용 화면 경로와 관리자 API 를 두고, 서버가 역할(`role_permissions`)을 검사해 거부한다. web 은 `GET /api/me` 의 권한으로 메뉴를 숨기기만 하며 통제는 서버가 한다. 관리자 경로는 Ingress 에서 사내 VPN 대역만 허용한다.
- 패스워드 길이·조합·변경 주기·저장 방식은 양식 01의 4.2항 기준값(10자 이상 3종 조합, 관리자 90일, 최근 3개 재사용 금지, Argon2id)을 그대로 적용한다. 다르게 설계한 항목은 없다.

> [!note] 현 구현과 차이
> 2026-10-20 현재 api 에는 인증·세션·권한이 없다(`README.md` "권한은 아직 막지 않는다"). 공개된 경로는 `GET /api/catalog`, `GET /api/orgs/{org}/workspaces/{ws}`, `GET /api/orgs/{org}/layers/{layer}/files/{path}`, `GET /api/openapi.json`, `GET /api/health` 이며 모두 조회 전용이다. 운영(NCP) 환경도 구축 전이다. 개발 환경(`dev0`)은 인증 대상이 아니다.

## 3. 저장 암호화 설계 내역

| No | 데이터 항목 | 분류(양식 01의 5항 ID) | 저장 위치 | 암호화 방식·알고리즘 | 키 관리 | 비고 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 비밀번호 | ENC-S-01 | Cloud DB `users` | 일방향 해시 Argon2id(솔트 내장) | 해당 없음 | 미구현 |
| 2 | TOTP 비밀값 | ENC-S-01 | Cloud DB `users` | AES-256-GCM | 암호화 키는 k8s Secret(SealedSecrets), 환경변수 주입 | 미구현 |
| 3 | 세션 서명키 · DB 비밀번호 · 스토리지 접근 키 · 브이월드 인증키 | ENC-S-05 | k8s Secret | SealedSecrets 봉인(저장소 보관분), 클러스터 etcd 저장 | 회전 연 1회·유출 의심 즉시, `kid` 무중단 회전 | 현재 로컬 `.env` 만(커밋 금지, gitleaks 차단) |
| 4 | 민감 레이어 · 데이터셋 번들 · 원본(`raw/` · `datasets/`) | ENC-S-03 | Object Storage(NCP 공공) | 서버측 암호화 AES-256 | 제공자 관리 키 | 접근은 api 중계 + 레이어 권한 |
| 5 | 사고 기록 · 감사 기록 · 계정·권한 | ENC-S-03 | Cloud DB for PostgreSQL | 저장소 암호화 AES-256(관리형 DB 기능) | 제공자 관리 키 | 감사 표는 추가 전용 권한 |
| 6 | 내보내기 파일 · 업로드 엑셀 · DB 백업(`exports/` · `incidents/uploads/` · `backups/`) | ENC-S-03 | Object Storage | 서버측 암호화 AES-256 | 제공자 관리 키 | 내보내기 30일 후 lifecycle 삭제, 백업 30일 |
| 7 | 고유식별정보·계좌번호 등 | ENC-S-02 | 해당 없음 | 해당 없음 — 수집하지 않는다 | 해당 없음 | 설계상 수집 항목 없음 |

- 암호 알고리즘·키 길이는 12.3.1 암호 정책의 안전성이 입증된 알고리즘 목록에서 선택한다.
- 암호화하지 않기로 결정한 중요정보: 사고 기록·민감 레이어의 **컬럼 단위** 암호화는 적용하지 않는다. 근거 — 서비스는 공개 공공데이터를 운영하고 개인정보를 수집하지 않으며(하등급 조건), 저장소 단위 암호화(AES-256)와 레이어 권한·감사로 통제한다. 발주처 확인으로 개인정보처리시스템에 해당하면 사고 기록의 주소 항목에 컬럼 암호화를 추가한다.
