## 1. 작성 원칙

- [02. 데이터보호 및 암호화 지침](../../20%20%EC%9E%91%EC%84%B1%EC%99%84%EB%A3%8C/12.3.1%20%EC%95%94%ED%98%B8%20%EC%A0%95%EC%B1%85%20%EC%88%98%EB%A6%BD/02.%20%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B3%B4%ED%98%B8%20%EB%B0%8F%20%EC%95%94%ED%98%B8%ED%99%94%20%EC%A7%80%EC%B9%A8.md) 5항의 암호화 대상 정의에 따라, 인증 범위 내 모든 중요정보의 저장·전송 암호화 적용 내역을 시스템·구간 단위로 등재한다.
- 정보자산 목록, DB 스키마, 클라우드 콘솔 자원 목록, 네트워크 구성도와 대조하여 누락 없이 작성하고, 대조 자료의 기준일을 6항에 기록한다.
- 적용 확인은 설정 화면·설정값 조회 결과·시험 결과 등 증적과 함께 기록하여 "정의만 있고 적용은 없는" 상태(부적합 사례 2)를 방지한다.
- 개인정보 처리 여부: 처리하지 않음. 판단 근거: 하등급 인증 조건(개인정보 미포함, 공개 공공데이터 운영)과 제품 설계안 `docs/design/jeju-subsidence-ai/04.data-and-storage.md` §5 DB 스키마·§11 보안 체크리스트(굴착 허가 신청인 미수집, 로그인 식별자에 실명·이메일 미사용) 검토 결과. 법적 요구사항 대상 중 고유식별정보·금융정보·생체인식정보 행은 "해당 없음"으로 표기한다. 다만 계정의 성명·부서(`users.name` · `users.dept`), 감사 기록의 성명·부서(`audit_events.user_name` · `dept`), 사고 기록의 주소·피해 항목에는 개인정보가 들어올 수 있어 저장·전송 암호화 대상에 포함한다. 개인정보처리시스템 해당 여부는 발주처 확인 전이다.

> [!note] 현 구현과 차이
> 2026-10-21 현재 운영 환경(NCP)은 VPC·NAT·NKS 와 인프라 state 버킷만 있고 Cloud DB·앱 데이터 버킷은 없다. 현재 코드(`jeju-ai-saas-be` api)는 스토리지 중계 API만 있고 인증·세션·DB가 없다. 로컬 개발 스택(SeaweedFS S3, `http://localhost:8333`)은 저장·전송 암호화가 없으나 인증 범위 밖이며 운영 데이터를 두지 않는다. 아래 표의 "적용 여부"는 기준일 현재 운영 기준이다.
