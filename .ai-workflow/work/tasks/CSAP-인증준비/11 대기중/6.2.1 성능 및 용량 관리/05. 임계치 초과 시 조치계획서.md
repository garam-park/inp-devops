### 3.1 원인 분류

- [ ] 이용 규모 증가(정상 성장): 이용 기관·이용자·데이터 증가에 따른 지속적 수요 증가 — 해당 없음(시험 부하 고정)
- [ ] 일시적 피크: 이벤트, 마감, 배치·집계 작업, 이용 기관의 일괄 처리
- [ ] 응용 프로그램 결함: 메모리 누수, 비효율 쿼리, 무한 재시도, 캐시 미적용
- [ ] 구성 오류: 자동 확장 정책·한도 부적정, 연결 풀·워커 수 설정, 로그 과다
- [ ] 비정상 트래픽: 크롤러, 공격 의심(→ 5.1.1 전환) — 해당 없음
- [ ] 제공자 측 이슈: 제공자 장애·성능 저하·유지보수(제공자 상태 페이지 확인) — 해당 없음(사내 러너)
- [ ] 임계치 부적정: 실제 위험이 없는데 임계치가 낮거나 지속 조건이 짧음
- [x] 기타: **시험 환경 요인 의심(미확정)** — api k6 스크립트(`api/test/k6/api.js`)는 VU 사이에 대기(`sleep`)가 없어 50 VU 가 쉬지 않고 요청한다. FE k6 스크립트(`e2e/k6/web.js`) 주석은 대기 없이 돌리면 k6 자신이 러너 CPU 를 다 써 지연이 서버가 아니라 k6 쪽에서 난다고 기록했다. 같은 러너에서 api · storage 컨테이너와 k6 가 함께 돈다. 확정 분류: {{원인 분석 후 분류}}
