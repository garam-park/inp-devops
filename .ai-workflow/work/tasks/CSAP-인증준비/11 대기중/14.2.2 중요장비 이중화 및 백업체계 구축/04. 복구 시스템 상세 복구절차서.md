## 1. 개요

- 목적: 장애·재해·침해사고로 지반침하 스마트관리 시스템의 시스템·데이터가 손상되었을 때, 담당자가 본 절차서만으로 복구를 수행할 수 있도록 시스템별 상세 복구 절차를 정한다.
- 적용 범위: [02. 정보자산 및 백업 대상 목록](02.%20정보자산%20및%20백업%20대상%20목록.md)의 백업 대상 자산 전체와 [03. 네트워크 구성도](03.%20네트워크%20구성도.md)의 구성요소 전체
- 사용 시점: 시스템 장애, 데이터 손상·유실, 침해사고(랜섬웨어 등), 가용영역·리전 장애, 재해 복구 선언 시
- 작성 원칙: 각 절차는 수행 명령·콘솔 메뉴 수준까지 구체적으로 적고, 복원 시험(양식 06)으로 검증한 내용만 확정한다. 담당자 부재 시에도 수행할 수 있어야 한다.
- 표기: `<버킷>` · `<DB 엔드포인트>` · `<release>` 같은 꺾쇠 값은 5항 "복구용 도구·변수" 표의 값으로 바꿔 실행한다. 비밀값은 명령에 직접 쓰지 않고 환경변수로 넣는다.

## 3. 복구 판단과 선언

| 등급 | 상황 | 선언 권한 | 초동 조치 |
| --- | --- | --- | --- |
| 1(부분 장애) — 장애 등급 3급 | 단일 파드·노드 장애, 서비스 일부 지연 | 정보보호 관리자 | 복제·재스케줄 동작 확인(`kubectl get pods -o wide`), 해당 시스템 절차(6항) 수행 |
| 2(주요 장애) — 장애 등급 1·2급 | api·web 전면 중단, DB 장애, 데이터 손상 | 정보보호 최고책임자 | 6항 복구 수행, 1시간 내 이용 기관 통지, 6.1.2 장애 보고 병행 |
| 3(재해) | 가용영역·리전 전체 사용 불가, 클러스터 유실, 대규모 침해사고 | 정보보호 최고책임자 | 재해 복구 선언, 같은 존(`KR-1`)에 새 클러스터 재구축(공공존은 리전당 존 1개라 다른 가용영역이 없다). KR 리전 전체 사용 불가 시 KRS(남부권) 리전 백업·복구 절차를 따른다(절차 수립 대기). 5.1.1 침해사고 대응 병행(해당 시) |

- 침해사고로 인한 복구는 증거 보전이 필요한지 침해사고 대응 조직과 먼저 협의하고, 오염 시점 이전의 백업본을 선택한다. 침해 의심 시 해당 자격증명(스토리지 키·DB 비밀번호·세션 서명키)을 먼저 회전한다.

## 7. 복구 후 확인

복구 완료를 선언하기 전에 다음을 모두 확인하고 결과를 기록한다.

- [ ] 핵심 기능 점검 목록(로그인, 지도·격자 위험도 조회, 레이어 파일 중계, 내보내기, 관리자 화면, `/api/health`)이 모두 정상이다.
- [ ] 복원 데이터의 정합성(건수·최신성)이 확인 기준을 충족한다.
- [ ] 보안 설정(ACG, 서브 계정 권한, 웹 방화벽, NetworkPolicy, 관리자 IP 허용 목록)이 복구 전 승인된 상태와 일치하며, 복구 과정에서 임시로 완화한 설정을 원복했다.
- [ ] 로그 수집·모니터링·백업 작업이 재개되었다.
- [ ] 복구 결과와 소요 시간(RTO·RPO 달성 여부)을 장애 보고서(6.1.2) 또는 침해사고 보고서(5.1.1)에 기록했다.
- [ ] 이용 기관 통지가 필요한 경우 통지를 완료했다(14.1.4 사고 및 장애 대응 기준 — 1·2급 1시간 내, 복구 후 24시간 내 결과 보고).
