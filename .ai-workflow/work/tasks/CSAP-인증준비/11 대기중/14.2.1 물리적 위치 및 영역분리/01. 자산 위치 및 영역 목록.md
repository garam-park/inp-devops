## 1. 목적과 작성 기준

- 지반침하 스마트관리 시스템(제주 GEO-AI 지반침하 SaaS, 하등급 SaaS)의 국가기관용 서비스 제공에 사용되는 모든 시스템·데이터·백업 자산의 물리적 위치가 국내(대한민국의 배타적 법적관할하에 있는 시설)이고, 인증받은 공공기관용 영역에 배치되어 있음을 확인·관리한다.
- 정보자산 목록(자산 관리 항목의 산출물)에 등재된 자산 중 국가기관용 서비스에 관련된 자산 전체를 대상으로 하며, 본 목록은 위치·영역 관점의 확인 결과를 담는다.
- 국내 여부와 배치 영역은 추정하지 않고 클라우드 콘솔의 리전·저장 위치 설정 화면, 제공자 인증서·계약서 등 확인 근거를 남긴다. 확인 증적의 수집은 [05. 증적 수집 점검표](05.%20증적%20수집%20점검표.md)를 따른다.
- 인증 대상은 운영 환경(NCP 공공기관용)뿐이다. 사내 개발 클러스터 `dev0`(네임스페이스 `dev`)와 로컬 환경(docker compose · k3d)은 인증 대상이 아니며 이용 기관 운영 데이터를 반입하지 않는다. 이 목록에는 대조를 위해 비대상으로 표시해 둔다.

## 2. 이용 인프라 현황(IaaS/PaaS 제공자)

당사는 물리 시설(데이터센터)을 직접 운영하지 않고 CSAP 인증을 받은 IaaS/PaaS 인프라를 이용한다. 물리자원·시설의 국내 위치와 출입통제는 제공자 인증·계약으로 확인한다.

## 5. 외부 연동 서비스 데이터 위치 확인

서비스에 연동된 외부 서비스(CDN, 모니터링·APM, 오류 수집, 메일·알림 발송, 통계 분석 등)를 통해 이용자 데이터가 인증받지 않은 영역(국외, 민간 등)으로 나가지 않는지 확인한다.

| No | 외부 서비스 | 용도 | 전송·저장되는 데이터 | 이용자 데이터 포함 여부 | 데이터 저장 위치 | 판정 | 조치 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | GHCR(GitHub Container Registry) | 컨테이너 이미지 보관 | api · web 이미지(코드·런타임) | X — 이미지에 데이터·비밀값을 넣지 않는다 | 국외 | 부적정 소지 — 14.2.1 "클라우드 시스템 국내 한정"을 레지스트리에 적용하는지 해석 필요(ADR D5) | NCP Container Registry(공공)로 전환(D5 결정, D4 실측 4 이후) |
| 2 | GitHub(소스 저장소·Actions 조정) | 코드 관리, CI 작업 지시 | 소스 코드, 빌드 로그 | X — 레이어 자료는 `.gitignore` 로 제외, 비밀값은 gitleaks 차단. CI 는 합성 자료만 사용 | 국외(작업 실행은 사내 `dev0` 러너) | 적정 — 이용자 데이터 없음 | 운영 배포는 self-hosted runner(국내)에서 실행. 운영 자격증명은 러너 쪽에만 둔다 |
| 3 | 브이월드(국토교통부 공간정보 오픈플랫폼) | 배경지도 WMTS, 굴착 허가 주소 지오코딩 | 지도 타일 요청 좌표, 지오코딩 주소 문자열(`pipeline/geocode_excavation.py`) | ○ (굴착 허가 주소 — 공개 행정 정보) | 국내(정부 운영) | 적정 | 목표: 서버 중계·허용 목록 고정 호스트. 현재 브라우저가 `https://api.vworld.kr` 에서 타일 직접 수신(CSP `img-src` 허용) |
| 4 | NCP Cloud Insight · 관리형 로그 서비스 | 모니터링, 로그 수집(목표) | 지표, 애플리케이션·접근 로그 | ○ (접근 기록의 계정·IP) | NCP 공공기관용(국내) — 제공 여부 확인 대기 | 확인 대기 | 공공 영역 미제공 시 Object Storage 별도 버킷으로 대체 |
| 5 | CDN · 오류 수집 · 통계 분석 · 메일 발송 | — | — | — | — | 해당 없음 — 연동 없음(웹 CSP `connect-src 'self'`, 글꼴은 자체 호스팅) | 신규 연동 시 이 표에 추가하고 국내 위치 확인 후 도입 |

- 이용자 데이터가 국외 또는 민간 영역에 저장되는 연동이 확인되면 지체 없이 차단하고, 조치 결과를 기록한다.

## 7. 현행화 규칙

- 자산 신규 생성·변경·폐기, 리전·저장 위치 변경, 외부 서비스 연동 추가 시 5영업일 이내에 본 목록을 갱신하고 버전을 올린다.
- 반기 1회 이상 클라우드 콘솔의 실제 자원 목록·리전 설정과 전면 대조하고, 대조에 사용한 자료의 기준일을 기록한다: 최근 대조일 {{YYYY-MM-DD}}, 대조 자료 NCP 공공 콘솔 자원 목록 내보내기, `kubectl get nodes -L topology.kubernetes.io/zone` 출력
- 새 리전·영역 사용은 국내 여부와 공공기관용 영역 포함 여부를 확인한 뒤 정보보호 관리자의 승인을 받아 적용한다.
