> [!info] 법령 기준
> 정보통신망 이용촉진 및 정보보호 등에 관한 법률 제46조(법률 제21305호, 2026. 7. 7. 시행)는 집적정보통신시설 사업자등에게 시설 보호조치 의무를 부과한다. 당사는 CSAP 인증을 받은 IaaS 제공자의 시설을 이용하므로 해당 시설의 보호조치는 제공자 인증·계약으로 확인한다. 법령이 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

㈜이노팸은 국가기관·지방자치단체·공공기관(이하 "국가기관등")에 제공하는 클라우드컴퓨팅서비스 지반침하 스마트관리 시스템(이하 "서비스", 하등급 SaaS)의 정보자산과 이용자 데이터(백업 포함)의 물리적 위치를 식별하고, 관련 시설에 대한 물리적 접근통제 정책 현황을 본 문서로 관리하여 국가기관등 내부 정보시스템 운영 보안수준에 준하는 시설·물리 보안을 유지한다.

## 2. 적용 범위

- 서비스 인증 범위 내 모든 클라우드 자원(NKS 클러스터와 web · api · pipeline 워크로드, Cloud DB for PostgreSQL, Object Storage, 로그 저장소, 백업, 컨테이너 이미지 저장소)과 그 물리적 위치
- 서비스 관리·운영 인력과 그 근무 위치
- ㈜이노팸이 직접 운영하는 업무 공간 — 본사 사무실(운영 단말 사용 공간)과 사내 개발 클러스터 `dev0` 장비(Proxmox 호스트 3대) 설치 공간. `dev0` 는 인증 대상이 아니고 운영 데이터를 반입하지 않지만, 소스코드 빌드(CI 러너)와 개발 배포가 이루어지므로 당사 책임 공간으로 함께 관리한다.

## 3. 책임 구분(책임공유모델)

| 영역 | 책임 주체 | 당사 확인 방법 |
| --- | --- | --- |
| 데이터센터 시설·물리적 출입통제·재해 대비 설비 | IaaS/PaaS 제공자 — 네이버클라우드(NCP 공공기관용) | 제공자 CSAP 인증·계약으로 확인(6항) |
| 클라우드 자원의 물리적 위치 선택(공공기관용 리전)과 위치 확인·추적 | 당사 | 4항·5항 |
| 당사 운영 공간(본사 사무실, `dev0` 장비 설치 공간)의 물리적 접근통제 | 당사 | 7항 |
| 물리적 접근통제 증적의 주기적 검토 | 당사 | 8항, 양식 02. 시설 보안 점검 이력 관리대장 |

> [!tip] 해설서 간주 조항
> IaaS 사업자가 아닌 타 사업자(SaaS 등)는 CSAP 인증받은 IaaS 클라우드서비스 이용 시 해당 부분에 대하여 시설 및 물리적 통제에 대한 보안요구사항을 준수하는 것으로 간주한다. 간주의 전제인 제공자 인증의 유효성을 6항에서 주기적으로 확인한다. NCP 의 CSAP IaaS 인증 범위는 "네이버 클라우드 플랫폼(공공기관용)"이며 일반 리전은 범위가 아니므로, 서비스 운영 자원은 공공기관용에만 둔다(gis-sass ADR 2026-09-26.02 D4).

> 2026-10-20 현재 운영 자원은 없다(공공기관용 가입만 완료). 소스코드는 GitHub(`innopam/jeju-ai-saas-be` · `jeju-ai-saas-fe`, 비공개), 개발 이미지는 GHCR(`ghcr.io/innopam/jeju-ai-saas-api`)에 있으며 둘 다 국외 사업자다. 이용자 데이터는 들어 있지 않다(합성 자료·코드만). 운영 이미지는 공공 레지스트리로 옮긴다(ADR D5). 개발 데이터는 사내 `dev0`(Longhorn 볼륨)와 로컬에만 있다.

## 5. 데이터 물리적 위치 확인·추적 방안

기관 데이터(백업 포함)의 물리적 위치를 언제든지 확인하고 추적할 수 있도록 다음 방안을 적용한다.

| 방안 | 내용 | 확인 방법 |
| --- | --- | --- |
| 리전 고정 | 서비스 자원을 NCP 공공기관용(gov-ncloud) 국내 리전으로 한정하고 일반 리전·다른 사업자에 운영 자원을 만들지 않는다. 운영 계정은 공공기관용 계정만 쓴다. | 공공 콘솔의 리전별 자원 현황, 일반 리전 계정 자원 현황(운영 자원 0) |
| 리전 외 복제 차단 | Object Storage · Cloud DB 의 교차 리전 복제 기능을 사용하지 않는다. 사용이 필요하면 국내 리전 간으로 한정하고 정보보호 최고책임자 승인을 받는다. | 버킷 복제 설정 화면, Cloud DB 복제 설정 화면 |
| 백업 위치 통제 | DB 백업은 관리형 자동 백업과 `pg_dump` CronJob 을 운영 버킷 `backups/postgres/` 에 두고, 백업 정책(14.2.2)에 위치를 명시한다. | 백업 설정 화면, CronJob 대상 버킷 설정(chart values) |
| 위치 변경 통제 | 리전 추가·이전 등 위치 변경은 변경 관리 절차(PR · 수동 승인)를 거치고 본 문서 4항을 갱신한다. 위치를 정하는 값(엔드포인트 · 리전)은 클러스터 저장소 values 에만 둔다. | 변경 관리 기록, values 이력 |
| 주기적 확인 | 4항의 위치 현황을 반기마다 콘솔 자원 현황과 대조한다. | 양식 02. 시설 보안 점검 이력 관리대장 P-05 |

- 자체 서버실(`dev0` 장비 설치 공간)에는 화재감지기, 소화기, UPS 등 필요한 설비를 갖추고 7.3항의 점검 대상에 포함한다: {{설비 목록 — 총무·인프라 확인}}. `dev0` 에는 운영 데이터가 없으므로 장애가 서비스 가용성에 영향을 주지 않는다(운영은 NCP).

### 7.2 출입 통제 규칙

1. 보호구역 출입 권한은 업무상 필요한 인원에게만 부여하고, 부여·회수 내역을 기록한다. 퇴직·인사이동 시 지체 없이 회수한다.
2. 외부인(방문자, 유지보수 인력)은 사전 승인 후 담당자 동행 하에 출입하고 방문 기록을 남긴다.
3. 출입 기록(출입통제 시스템 로그, 출입대장)은 1년 이상 보관한다.
4. 보호구역 내 장비(서버, 네트워크 장비, 저장매체, 운영 단말)의 반출입은 사전 신청·승인하고 반출입 기록을 남긴다. `dev0` 호스트의 디스크 교체·폐기는 12.1.6 데이터 폐기 절차를 따른다.
5. 보호구역 내 시스템 작업(설치, 교체, 유지보수 등)은 작업내용을 기록한다. `dev0` 의 OS · 클러스터 작업은 클러스터 저장소(`innopam/dev0`)의 커밋과 작업 기록으로 남긴다.
