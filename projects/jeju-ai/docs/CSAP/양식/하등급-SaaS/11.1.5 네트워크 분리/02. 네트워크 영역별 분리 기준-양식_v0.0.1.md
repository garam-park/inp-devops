## 1. 개요

- 목적: 01. 네트워크 분리 관리 지침이 정한 분리 원칙을 영역별 배치·구현 기준으로 구체화하여, 네트워크를 신설·변경할 때 일관되게 적용한다. 본 문서는 당사 네트워크보안지침 중 네트워크 분리에 해당하는 기준이다.
- 적용 범위: {{서비스명}} 인증 범위 내 모든 네트워크 영역과 그 구성 자원
- 해설서의 영역별 네트워크 분리 예시와 당사 영역의 대응은 다음과 같다. 영역 명칭은 9.1.5 공개서버 네트워크 및 시스템 구성도와 동일하게 사용한다.

## 2. 영역 정의 및 배치 기준

| 영역 | 정의 | 배치하는 자산 | 배치 금지 | 인터넷 노출 | 분리·보호 수단 |
| --- | --- | --- | --- | --- | --- |
| DMZ | 인터넷 이용자가 접근하는 완충 영역(퍼블릭 서브넷) | 로드밸런서, 웹 방화벽, 웹서버·API 게이트웨이, 이용 기관 포털, 배포 서버 | DB·DBMS, 캐시, 백업, 운영자용 관리 포털, 개인정보·고유식별정보 저장 | 인바운드는 로드밸런서·웹 방화벽 경유 서비스 포트만 | 보안 그룹, 네트워크 ACL, 웹 방화벽 |
| 내부 - 앱 | 응용 계층 프라이빗 서브넷 | WAS, 배치 서버, 내부 API, 운영자용 서비스 관리 포털 | 인터넷 게이트웨이 라우팅, 공인 IP | 없음(아웃바운드는 NAT 경유 목적지 한정) | 보안 그룹(DMZ 특정 출발지만 허용) |
| 내부 - DB | 이용 기관 중요정보·개인정보가 저장되는 DB 계층 프라이빗 서브넷 | DB, 캐시, 백업 스토리지 접점 | 인터넷 게이트웨이 라우팅, 공인 IP, DMZ에서의 직접 접속 경로 | 없음 | 보안 그룹(내부 - 앱 계층만 허용), 저장 암호화 |
| 관리망 | 운영 인력 진입·관리 시스템 영역 | 배스천(접근통제솔루션), 로그 저장소·SIEM, 모니터링 | 서비스 트래픽 처리 자산 | 없음(VPN 경유) | VPN 허용 IP 제한, 다중 인증, 세션 기록 |
| 개발·시험 | 개발·시험·스테이징 환경 | 개발 서버, 시험 서버, 스테이징, 개발용 DB | 운영 데이터 원본, 운영 자격증명 | 없음(시험 엔드포인트 인터넷 비노출) | 운영과 계정·VPC 분리, 상호 접속 차단 |

- 새 자산은 위 기준에 따라 배치 영역을 먼저 정한 뒤 생성한다. 어느 영역에도 해당하지 않으면 정보보호 관리자가 영역 신설 여부를 검토하여 본 기준에 반영한다.
- 사무 업무망(사무실 PC·내부 업무 시스템)은 서비스 VPC와 연결하지 않으며, 운영 인력은 VPN을 통해 관리망으로만 진입한다.

## 3. 분리 구현 수단 기준

분리 대상의 신뢰 수준 차이에 따라 다음 수단 이상을 적용한다. 하위 수단(서브넷·보안 그룹)만으로 상위 수준의 분리를 갈음하지 않는다.

| 분리 대상 | 최소 분리 수단 | 비고 |
| --- | --- | --- |
| 운영 환경 ↔ 개발·시험 환경 | 계정(프로젝트) 분리, 최소 VPC 분리 | 동일 VPC 내 서브넷 구분만으로 분리 금지 |
| 운영 VPC 내 영역(DMZ, 내부 - 앱, 내부 - DB, 관리망) | 서브넷 분리 + 라우팅 구분 + 보안 그룹·네트워크 ACL | 퍼블릭·프라이빗 서브넷은 라우팅 테이블로 구분 |
| 동일 영역 내 자산 간 | 보안 그룹(역할별) | 예: sg-web, sg-app, sg-db, sg-bastion, sg-log |
| 컨테이너 워크로드 간 | 네임스페이스 분리 + 네트워크 정책 | 컨테이너 오케스트레이션 사용 시 |
| 이용자(테넌트) 간 | 응용·DB 계층 논리 분리(5항) | 네트워크 계층 분리가 필요한 계약은 별도 구성 |
| 서비스 네트워크 ↔ 사무 업무망 | 물리·논리 네트워크 분리, VPN 접점만 허용 | |

- 보안 그룹 규칙의 출발지는 IP 대역 대신 출발지 보안 그룹 ID로 한정하는 것을 기본으로 한다.
- 라우팅 테이블은 영역별로 두고, 프라이빗 서브넷의 라우팅에 인터넷 게이트웨이 경로를 추가하지 않는다.

## 4. 환경(개발·시험·운영) 분리 기준

1. 개발(dev), 시험·스테이징(staging), 운영(prod) 환경은 별도 계정 또는 별도 VPC로 구성한다. 세 환경을 동일 VPC 안의 서브넷으로만 구분하는 구성을 금지한다.
2. 개발·시험 환경과 운영 환경 간에는 VPC 피어링, 라우팅, 공유 스토리지 마운트 등 네트워크 상호 접속 경로를 두지 않는다. 개발 서버에서 운영 DB로 접속할 수 없어야 하며, 운영 DB 보안 그룹의 인바운드에 개발·시험 출발지(보안 그룹·IP 대역)를 등록하지 않는다.
3. 배포는 네트워크 상호 접속 대신 승인된 배포 경로(CI/CD 파이프라인, 이미지 저장소)를 통해서만 수행하고, 배포 파이프라인의 운영 환경 자격증명은 개발 환경과 분리하여 관리한다.
4. 개발·시험 환경의 엔드포인트는 인터넷에 노출하지 않는다. 외부 시험이 필요하면 기간을 정해 접근 IP를 한정하고 종료 후 즉시 회수한다.
5. 운영 데이터는 개발·시험 환경으로 복제하지 않는다(01. 네트워크 분리 관리 지침 8항).

## 5. 이용자(테넌트) 간 분리 기준

{{서비스명}}은 멀티테넌트 SaaS로, 이용자 간 서비스 영역은 다음과 같이 논리적으로 분리한다.

| 계층 | 분리 방식 | 확인 방법 |
| --- | --- | --- |
| 응용 | 모든 요청에 테넌트 식별자({{조직 ID 등}})를 검증하고, 인증 세션과 다른 테넌트 자원 접근을 차단하는 인가 로직 적용 | 코드 리뷰, 테넌트 격리 시험 |
| DB | {{테넌트 식별자 기반 행 분리 / 테넌트별 스키마 분리 / 테넌트별 DB 분리}} 적용, 모든 조회·변경 쿼리에 테넌트 조건 강제 | 쿼리 계층 공통 모듈, 시험 |
| 스토리지·캐시 | 객체 키·캐시 키에 테넌트 식별자를 포함하고 테넌트 간 키 접근 차단 | 설정·코드 확인 |
| 계약상 강화 분리 요구 시 | {{전용 인스턴스 / 전용 DB / 전용 VPC}} 구성 | 해당 이용 기관 계약·구성도 |

1. 테넌트 간 격리는 릴리스 전 시험 항목에 포함하고, 연 {{1}}회 이상 취약점 점검 시 다른 테넌트 데이터 접근 시도(권한 상승·식별자 변조)를 점검한다.
2. 이용 기관이 계약으로 강화된 분리(전용 자원)를 요구하면 별도 구성으로 제공하고 03. 네트워크 분리 구성도에 반영한다.

## 6. 영역 간 연계 기준

1. 영역 간 통신은 03. 네트워크 분리 구성도 4항의 접근통제 요약에 등록된 경로만 허용한다. 등록되지 않은 통신은 기본 거부한다.
2. VPC 피어링, 전용 연결, VPC 엔드포인트 등 연계 구성은 다음 조건을 모두 충족할 때만 신설한다.
   - 업무 목적과 통신 범위(출발지·목적지·포트)가 문서화되어 있다.
   - 신뢰 수준이 다른 환경 간(개발 ↔ 운영) 연계가 아니다.
   - 정보보호 최고책임자의 승인을 받았다.
3. 연계 구성은 03. 네트워크 분리 구성도 3항에 등록하고, 분기 준수 검토에서 사용 여부와 필요성을 재확인하여 불필요한 연계를 해지한다.
4. 클라우드 관리형 서비스(스토리지, 키 관리 등) 접근은 인터넷 경유 대신 VPC 엔드포인트를 우선 사용한다.

## 7. 관리자 접근 경로 기준

1. 운영 인력의 서버·DB·관리 시스템 접근은 VPN → 배스천(접근통제솔루션) 경로로만 허용하고, 다중 인증과 세션 기록을 적용한다. 상세 기준은 9.1.5 공개서버 보안 관리 지침 8항과 동일하게 적용한다.
2. VPN은 허용된 계정·기기·출발지에만 발급하고, 관리망 외 영역으로의 직접 라우팅을 제공하지 않는다.
3. 클라우드 콘솔 접근은 다중 인증을 적용하고, 네트워크 구성 변경 권한은 네트워크 관리자(2.1.2 주요 직무자)로 한정한다.
