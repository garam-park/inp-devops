> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제6조(접근통제)·제6조의2(인터넷망의 차단 조치 등)(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 당사가 개인정보처리자로서 개인정보처리시스템을 운영하는 경우에 적용하며, 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

{{회사명}}은(는) 클라우드컴퓨팅서비스 {{서비스명}}을 제공하는 네트워크를 서비스, 사용자 그룹, 정보자산의 중요도, 법적 요구사항에 따라 물리적 또는 논리적으로 분리하고 영역 간 접근을 통제하여, 한 영역의 침해가 다른 영역(특히 이용 기관 데이터가 저장된 DB와 운영 관리 영역)으로 확산되지 않도록 한다. 당사의 관리 영역과 이용자의 서비스 영역, 이용자 간 서비스 영역의 네트워크 접근 분리를 포함한다.

## 2. 적용 범위

- {{서비스명}} 인증 범위 내 모든 클라우드 네트워크 자원(VPC, 서브넷, 라우팅, 보안 그룹, 네트워크 ACL, 로드밸런서, VPN, 피어링·연계 구성)
- 인증 범위 내 서버·컨테이너·DB·관리 시스템이 사용하는 모든 통신 경로
- 네트워크를 설계·운영·변경하는 임직원과 외부인력
- 당사 사무실 업무망은 서비스 네트워크와의 접점(VPN 등 관리자 진입 경로)에 한하여 적용한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 네트워크 영역 | 동일한 신뢰 수준과 용도를 가진 자산을 묶어 다른 영역과 분리하여 운영하는 네트워크 단위. 당사 영역 구분은 02. 네트워크 영역별 분리 기준을 따른다. |
| 물리적 분리 | 별도의 물리 회선·장비로 네트워크를 나누는 방식. 클라우드 환경에서는 IaaS/PaaS 제공자의 물리 인프라 격리로 제공된다. |
| 논리적 분리 | 계정(프로젝트), VPC, 서브넷, 보안 그룹, 네트워크 ACL, 가상화 기술 등으로 하나의 물리 인프라 위에서 네트워크를 나누는 방식 |

| 관리망 | 클라우드 시스템을 운영하는 인력의 접속과 로그·모니터링 시스템이 위치한 영역 |

## 5. 네트워크 분리 원칙

1. 네트워크 영역은 다음 기준에 따라 구분하고, 서로 다른 신뢰 수준의 영역을 같은 네트워크에 두지 않는다.
   - 클라우드서비스 구성 요소의 역할(공개서버, 응용, DB, 관리)
   - 사용자 그룹(인터넷 이용자, 이용 기관, 운영 인력, 개발 인력)
   - 정보자산의 중요도(이용 기관 데이터·개인정보 저장 여부)
   - 법적 요구사항(개인정보처리시스템 접근통제, 공공기관 요건)
2. 분리는 물리적 또는 논리적 방식으로 하되, 당사는 클라우드 환경 특성상 계정(프로젝트)·VPC·서브넷·보안 그룹을 이용한 논리적 분리를 기본으로 한다. 물리적 분리 수준은 제공자의 인프라 격리로 충족됨을 확인한다.
3. 영역 간 통신은 기본 거부(deny by default)로 하고, 업무상 필요한 통신만 출발지·목적지·포트를 한정하여 허용한다. 전체 허용(any) 규칙을 두지 않는다.
4. 신뢰 수준이 다른 환경(개발, 시험·스테이징, 운영) 간 분리는 계정 또는 VPC 단위로 하며, 동일 VPC 안의 서브넷 구분만으로 갈음하지 않는다.
5. 업무 특성과 중요도에 따라 새 영역이 필요하면 02. 네트워크 영역별 분리 기준에 영역과 분리 기준을 먼저 정의한 뒤 구성한다.

## 6. 영역 구분과 영역 간 접근통제

당사 네트워크는 다음 영역으로 구분한다. 영역별 상세 정의·배치 기준은 02. 네트워크 영역별 분리 기준을, 실제 구성과 연계 방법은 03. 네트워크 분리 구성도를 따른다.

| 영역 | 용도 | 핵심 통제 |
| --- | --- | --- |
| DMZ | 인터넷에 공개되는 웹서버·API 게이트웨이·이용 기관 포털·배포 서버 | 로드밸런서·웹 방화벽 경유, 공개서버를 경유한 내부망 접근 통제 |
| 내부 - 앱 | WAS·배치 등 응용 계층 | 인터넷 비노출, DMZ의 특정 출발지만 허용 |
| 내부 - DB | 이용자(이용 기관)의 중요정보가 저장된 DB·캐시·백업 | 별도 서브넷 분리, WAS 계층만 허용, DMZ·인터넷 직접 경로 차단 |
| 관리망 | 운영 인력 진입점(배스천), 로그 저장소·모니터링 | VPN·다중 인증 경유, 다른 영역과 분리 |
| 개발·시험 | 개발·시험·스테이징 서버 | 운영과 계정·VPC 분리, 운영 영역과 상호 접속 차단 |
| 이용자 간 서비스 영역 | 이용 기관별 서비스 영역 | 응용·DB 계층의 테넌트 논리 분리 |

1. DMZ의 공개서버를 경유하여 내부 네트워크로 접근이 이루어지지 않도록, DMZ에서 내부 영역으로 향하는 통신은 기본 거부하고 승인된 최소 규칙만 허용한다. DMZ에서 내부 - DB로 직접 향하는 경로는 두지 않는다.
2. 이용자의 중요정보가 저장된 DB는 내부 - DB 영역에만 배치하고, 퍼블릭 서브넷 배치와 공인 IP 할당을 금지한다.
3. 클라우드 시스템을 운영하는 인력이 사용하는 접속 경로와 관리 시스템은 관리망으로 분리하고, 운영 인력은 VPN과 배스천(접근통제솔루션)을 경유해서만 각 영역에 접근한다.
4. 개발·시험 환경은 운영 환경과 별도 계정·VPC로 구성하고, 두 환경 간 네트워크 상호 접속(피어링, 라우팅)을 두지 않는다.
5. 이용자 간 서비스 영역은 응용·DB 계층에서 논리적으로 분리하고, 분리 방식과 검증 방법은 02. 네트워크 영역별 분리 기준 5항을 따른다.
6. 외부 네트워크에서 접근할 필요가 없는 운영자용 서비스 관리 포털은 이용자용 포털과 분리하여 내부 네트워크에 두고 인터넷에 노출하지 않는다. 접근은 관리망(VPN·배스천)을 경유해서만 허용한다.

## 7. 내부 서버의 인터넷 접근 제한

1. 내부 네트워크(내부 - 앱, 내부 - DB)와 관리망의 서버에서 인터넷으로 직접 나가는 통신은 기본 차단한다.
2. 패치·업데이트, 외부 API 호출 등 업무상 필요한 아웃바운드 통신은 NAT 게이트웨이 또는 프록시를 경유하게 하고, 목적지(도메인·IP·포트)를 한정하여 허용 목록으로 관리한다. DMZ 공개서버의 아웃바운드도 필요한 목적지로 한정한다.
3. 내부 - DB 영역에서 인터넷으로 향하는 아웃바운드는 원칙적으로 두지 않는다. 불가피하면 목적지를 한정하고 사유·승인을 03. 네트워크 분리 구성도 4항에 기록한다.
4. 개인정보처리시스템에 대한 접속 권한은 IP 주소 등으로 제한하여 인가받지 않은 접근을 차단하고, 접속한 IP를 분석하여 유출 시도를 탐지·대응한다(안전성 확보조치 기준 제6조제1항).
5. 전년도 말 기준 직전 3개월간 일일평균 이용자 수 100만명 이상에 해당하면 접근 권한 설정·다운로드·파기가 가능한 개인정보취급자 컴퓨터에 인터넷망 차단 조치를 적용한다. 클라우드컴퓨팅서비스로 개인정보처리시스템을 구성·운영하는 당사는 해당 서비스 접속 외의 인터넷을 차단하는 방식으로 적용한다(같은 기준 제6조의2제1항). 대상 여부 판단: {{해당 없음(일일평균 이용자 {{n}}명) / 해당(적용 방식: )}}, 판단 기준일 {{YYYY-MM-DD}}

## 8. 망간 자료전송 통제

1. 신뢰 수준이 다른 영역 간(운영 ↔ 개발·시험, 서비스 네트워크 ↔ 사무 업무망) 자료전송은 승인된 전송 수단을 통해서만 수행한다. 승인된 수단: {{예: 전송 전용 스토리지 버킷, 반출 승인 절차를 거친 파일 전송 시스템}}
2. 자료전송은 건별로 부서장 신청과 정보보호 관리자 승인을 거치고, 전송 일시·대상 자료·사유·승인자를 기록하여 {{1년}} 이상 보관한다. 정기·반복 전송은 범위와 주기를 정해 일괄 승인할 수 있다.
3. 운영 데이터(개인정보, 이용 기관 데이터)는 개발·시험 환경으로 복제하지 않는다. 시험에 필요한 경우 가명·더미 데이터를 사용하고, 불가피하게 원본이 필요하면 정보보호 최고책임자 승인과 사용 후 삭제 확인을 기록한다.
4. 영역 간 직접 공유 스토리지 마운트, 임의 파일 서버 개설 등 승인되지 않은 전송 경로를 만들지 않는다.

## 9. 우회 경로 차단

1. 각 영역의 진입점은 03. 네트워크 분리 구성도에 정의된 경로(인터넷 → 로드밸런서·웹 방화벽, 운영자 → VPN·배스천)로 한정한다.
2. 다음 우회 경로를 금지하고, 발견 시 즉시 차단한 뒤 경위를 조사한다.
   - 내부 서버에 대한 공인 IP 직접 할당, 인터넷 게이트웨이 라우팅 추가
   - 배스천을 경유하지 않는 관리 포트(SSH·RDP·DB 포트) 직접 개방
   - 승인되지 않은 VPC 피어링·VPN 터널·포트 포워딩·릴레이 구성
   - 개발·시험 환경에서 운영 영역으로의 접속 경로
3. 정보보호 담당자는 흐름 로그·클라우드 감사 로그로 우회 경로 생성·사용 여부를 모니터링하고, 발견 사항과 조치 결과를 04. 네트워크 분리 정책 준수 검토서에 기록한다.

## 10. 분리 정책 준수 검토

1. 정보보호 관리자는 네트워크 분리 정책 준수 여부를 **분기 1회 이상** 정기 검토하고, 네트워크 구조 변경(영역·서브넷 신설, 연계 구성 변경, 진입점 변경) 시 수시 검토한다.
2. 검토는 04. 네트워크 분리 정책 준수 검토서로 수행하며, 실제 클라우드 구성(서브넷·라우팅·보안 그룹·피어링 내보내기 자료)과 03. 네트워크 분리 구성도를 대조한다.
3. 검토 결과 부적합 사항은 조치 기한을 정해 조치하고, 구성도·기준 문서를 현행화한다.
