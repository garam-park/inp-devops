## 2. 권장 작성 순서

1. 01 패스워드 관리 절차: 적용 대상 시스템을 빠짐없이 식별하고 생성 규칙·운영 기준을 정한 뒤 정보보호 최고책임자 승인을 받아요.
2. 02 시스템 관리자 패스워드 관리대장: 관리자 계정을 목록화하고 보관 방식(내화금고 봉인 또는 비밀정보 저장소)을 확정해요.
3. 03 이용자 패스워드 관리 공지문: 01 절차와 일치하는 공지문을 게시하고 게시 화면을 보관해요.
4. 04 증적 수집 점검표: 시스템별 설정 화면 등 증적을 수집해요.
5. 05 패스워드 정책 이행 점검표: 반기마다 실제 설정·변경 주기·저장 기능을 점검하고, 불일치를 조치한 뒤 증적을 갱신해요.

## 3. 심사 대비 체크리스트

- [ ] VM, DBMS, 응용 프로그램, 네트워크, 정보보호시스템 등 당사가 운영하는 모든 클라우드 시스템을 패스워드 관리 대상으로 식별했다.
- [ ] 복잡도 기준, 초기·임시 패스워드 강제 변경, 변경 주기, 재사용 금지, 로그인 실패 제한을 포함한 관리 절차를 수립하고 승인받았다.
- [ ] 모든 대상 시스템의 실제 패스워드 설정이 내부 기준과 일치함을 점검했고, 불일치는 조치 기록이 있다.
- [ ] 내부 기준에서 정한 변경 주기대로 패스워드를 변경하고 있으며 변경 이력이 남아 있다.
- [ ] 관리자 패스워드를 별도 목록으로 유지하고, 내화금고 등 잠금장치와 접근통제로 비밀등급에 준하게 보호하며, 열람·개봉 기록이 있다.
- [ ] 운영자·관리자 단말에서 브라우저 자동 저장 등 패스워드 저장 기능을 제한했고 점검 기록이 있다.
- [ ] 패스워드는 일방향 암호화로 저장하고 입력·변경 시 마스킹 처리하며 자동 로그인을 금지한다.
- [ ] 분실·도용 우려 시 본인확인을 거치는 안전한 재발급 절차가 있다.
- [ ] 이용자 계정·패스워드 관리절차를 홈페이지·메일 등으로 공지했고 게시 화면 증적을 보관하고 있다.
- [ ] 패스워드 관리 책임이 사용자·이용자에게 있음을 교육·서약·공지로 주지시켰다.
- [ ] 시스템 설계·도입 시 패스워드 요구사항을 반영하고 검수에서 확인하는 절차가 있다.

## 4. 관련 산출물(다른 항목)

- 10.3.2 사용자 인증: 계정 발급·인증 절차와 패스워드 기준을 일치시켜요.
- 10.3.3 강화된 인증 수단 제공: 관리자 계정에는 패스워드 외 다중 인증을 함께 적용해요.
- 10.1.2 접근기록 관리: 로그인 실패·계정 잠금 기록을 접근기록 검토에 활용해요.
- 2.1.2 주요 직무자 지정 및 감독: 02 관리대장의 관리자 계정 보유자를 주요 직무자 목록과 대조해요.
- 2.3.2 교육 시행: 패스워드 관리 책임 주지를 정보보호 교육 내용에 포함해요.
- 12.3.1 암호 정책 수립: 패스워드 일방향 암호화 저장 기준을 암호 정책과 맞춰요.
- 7.1.1 법적요구사항 준수: 개인정보의 안전성 확보조치 기준 등 법적 요구사항 식별 결과와 연계해요.

## 5. 양식 작성 규칙

- `{{ }}`로 표시한 자리표시자는 실제 값으로 바꿔요. 표의 빈 칸은 해당 값을 채워요.
- 서명이 필요한 문서는 서명본을 스캔해 보관하고, md 원본에는 서명본 보관 위치를 적어요.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신해요.
- 02 관리대장은 비밀등급 문서로 보관하고, 패스워드 원본은 대장에 적지 않고 봉인 봉투나 암호화된 비밀정보 저장소에 보관해요. 심사 시에도 열람 절차를 거쳐 제시해요.
- 01 절차의 길이·조합·변경 주기 값과 03 공지문, 05 점검표의 기준 값은 항상 같게 유지해요.
- 법령 인용은 개인정보의 안전성 확보조치 기준 제5조·제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이에요. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인해요.
- 개인정보를 처리하지 않는 시스템에도 내부 기준으로 동일한 패스워드 기준을 적용해요.
