## 1. 목적

{{회사명}}은(는) 법적 요구사항과 외부 위협요인을 고려하여 클라우드컴퓨팅서비스 {{서비스명}}의 사용자 및 이용자 패스워드에 대한 복잡도 기준, 초기 패스워드 변경, 변경 주기 등 관리 절차를 정하고, 패스워드 관리 책임이 사용자와 이용자에게 있음을 주지시키기 위해 본 절차를 수립한다. 본 절차는 당사 정보보호 정책서와 접근통제관리지침 중 패스워드 관리에 해당하는 사항을 구체화한 것이다.

## 2. 적용 범위

### 2.1 적용 대상자

| 구분 | 대상 | 적용 사항 |
| --- | --- | --- |
| 사용자 | {{서비스명}} 운영·개발·보호 업무를 수행하는 임직원과 외부인력 | 4항 생성 규칙, 5항 운영 기준, 6항 기록·보관 통제 |
| 관리자 | 클라우드 시스템의 관리자 계정(root, admin, super admin 등)을 사용하는 인원 | 사용자 적용 사항 + 7항 관리자 패스워드 보호대책 |
| 이용자 | {{서비스명}}을 이용하는 이용 기관 담당자와 최종 이용자 | 4항 생성 규칙(서비스 구현), 8항 공지 |

### 2.2 적용 대상 시스템

당사가 운영하는 다음의 모든 클라우드 시스템에 본 절차를 적용한다. 신규 시스템은 도입 시점에 본 표에 추가한다.

| 구분 | 대상 시스템 | 관리 계정 예시 |
| --- | --- | --- |
| 가상 서버(VM)·컨테이너 | 운영 서버 OS 계정 | root, sudo 사용자 |
| DBMS | 운영 DB 계정 | DB 관리자, 응용 접속 계정 |
| 응용 프로그램(Application) | {{서비스명}} 관리자 기능, 이용자 계정 체계 | super admin, 이용 기관 관리자 |
| 클라우드 콘솔·IAM | IaaS/PaaS 콘솔 계정, IAM 사용자 | 루트 계정, 관리자 역할 |
| 네트워크 | 보안 그룹·방화벽·VPN·DNS 관리 계정 | 네트워크 관리자 |
| 정보보호시스템 | 백신·EDR, 로그 관리, 웹 방화벽, 접근제어 솔루션 | 각 시스템 관리자 |
| 개발·배포 환경 | 형상관리 저장소, CI/CD, 이미지 저장소 | 저장소 관리자 |
| 내부 업무 시스템 | 사내 포털, 문서 저장소 등 인증 범위 내 시스템 | 시스템 관리자 |

- 하이퍼바이저와 물리 인프라의 계정 관리는 책임공유모델에 따라 IaaS/PaaS 제공자의 책임이며, 제공자의 CSAP 등 인증과 계약으로 확인한다.
- 개인정보를 처리하지 않는 시스템에도 내부 기준으로 본 절차를 동일하게 적용한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 패스워드 | 시스템 접속 시 식별자와 함께 입력하여 정당한 접속 권한을 인증하는, 타인에게 공개되지 않는 고유의 문자열 |
| 관리자 패스워드 | 시스템 전체에 대한 설정·운영 권한을 가진 계정(root, admin 등)의 패스워드 |
| 초기·임시 패스워드 | 계정 최초 발급 시 또는 재발급 시 시스템·담당자가 부여하는 일회성 패스워드 |

## 4. 패스워드 생성 규칙

사용자·관리자·이용자 패스워드는 다음 규칙을 만족해야 하며, 각 시스템은 이 규칙을 강제하도록 설정한다.

| 항목 | 기준 |
| --- | --- |
| 길이·조합 | 문자(영문 대소문자), 숫자, 특수문자 중 3종류 이상을 조합하여 {{8}}자리 이상, 2종류 조합 시 {{10}}자리 이상 |
| 사용 금지 | 연속된 자판 배열(qwerty, asdf 등), 연속·반복 문자(1234, aaaa 등) |
| 사용 금지 | 생일, 전화번호, 사번, 계정명 등 추측하기 쉬운 개인 신상정보 |
| 재사용 금지 | 직전 {{n}}회 이내에 사용한 패스워드와 동일한 패스워드 |
| 관리자 강화 기준 | 관리자 패스워드는 3종류 이상 조합 {{10}}자리 이상, 시스템별로 서로 다른 값 사용 |

## 5. 패스워드 운영 기준

| 구분 | 기준 |
| --- | --- |
| 초기·임시 패스워드 | 무작위로 생성하여 안전한 방법(별도 채널, 일회용 링크 등)으로 전달하고, 최초 로그인 시 강제로 변경하게 한다. |
| 변경 주기 | 사용자·관리자 패스워드는 {{분기 1회}} 이상 변경한다. 이용자 패스워드는 이용자 정책에 따라 주기적 변경(분기 1회 이상 권고)을 유도한다. |
| 즉시 변경 | 침해사고가 발생하거나 패스워드 노출 징후가 의심되면 즉시 변경한다. 관리자 퇴직·인사이동 시 해당 인원이 알던 관리자 패스워드를 당일 변경한다. |
| 입력·표시 | 패스워드 입력·변경 시 화면에 마스킹 처리한다. |
| 자동 로그인 | 패스워드만 입력하는 자동 로그인은 금지한다. |
| 로그인 실패 제한 | {{5}}회 이상 연속 인증 실패 시 계정 잠금 등 접근을 제한하고, 잠금 해제는 본인확인 절차를 거친다. |
| 저장·전송 보호 | 패스워드는 일방향 암호화하여 저장하고, 전송 구간은 암호화한다. |
| 재발급 | 분실·도용 우려 시 본인확인(본인인증, 등록된 연락처 확인 등)을 거쳐 임시 패스워드를 재발급하고 최초 로그인 시 변경하게 한다. |

## 6. 패스워드 기록·보관 통제

1. 패스워드는 수첩, 메모, 모니터 부착물, 일반 문서·파일 등에 기록하지 않는 것을 원칙으로 한다.
2. 업무상 불가피하게 패스워드를 별도 문서 또는 파일로 보관하는 경우(관리자 패스워드 등) 해당 문서·파일을 비밀등급으로 분류하고 비인가자가 접근할 수 없도록 통제한다. 관리자 패스워드는 양식 02. 시스템 관리자 패스워드 관리대장에 따라 관리한다.
3. 브라우저 자동 저장 등 패스워드 저장 기능의 사용을 제한한다.
   - 운영자·관리자 단말의 브라우저에서 패스워드 저장 기능을 비활성화하고, 이미 저장된 운영 계정 정보를 삭제한다.
   - 가능한 경우 단말 관리 정책(그룹 정책, MDM 등)으로 저장 기능을 기술적으로 차단한다: {{적용 방식}}
   - 메신저, 이메일, 공유 문서에 패스워드를 평문으로 기재·전달하지 않는다.
4. 이행 여부는 양식 05. 패스워드 정책 이행 점검표의 저장 기능 점검으로 확인한다.

## 7. 관리자 패스워드 보호대책

1. 클라우드 시스템 관리자 패스워드는 일반 사용자 패스워드와 별도로 관리하며, 양식 02. 시스템 관리자 패스워드 관리대장에 별도 목록으로 유지한다.
2. 관리자 패스워드를 기록한 문서 또는 저장매체는 비밀에 준하여 관리하고, 내화금고 등 잠금장치로 비인가자의 접근을 통제한다. 전자적으로 보관하는 경우 암호화된 비밀정보 저장소를 사용하고 접근 권한을 최소화한다.
3. 관리자 부재 또는 패스워드 분실 시의 확인 목적 열람은 승인권자의 승인을 받아 수행하고, 열람 후 해당 패스워드를 즉시 변경한다.
4. 관리자 계정 접속에는 10.3.3 강화된 인증 수단 제공에 따른 다중 인증을 함께 적용한다.
5. 공용 관리자 계정은 최소화하고, 사용이 불가피한 경우 사용 기록을 남기고 사용자를 식별할 수 있게 한다.

## 8. 이용자 공지

1. 이용자 계정 및 패스워드 관리 절차(생성 규칙, 변경 유도, 재발급, 로그인 실패, 장기 미사용, 관리 책임)를 양식 03. 이용자 패스워드 관리 공지문으로 작성하여 홈페이지 공지사항, 서비스 알림 메시지, 전자 우편 등 이용자가 쉽게 확인할 수 있는 채널에 공지한다.
2. 공지 내용은 본 절차의 기준과 일치하게 유지하고, 본 절차 개정 시 공지문을 갱신하여 재게시한다.

## 9. 시스템 설계·도입 시 적용

1. 신규 시스템·서비스 기능을 설계하거나 상용 솔루션을 도입할 때 4항·5항의 요구사항을 설계 요구사항에 반영하고, 검수 시 설정 화면으로 충족 여부를 확인한다.
2. 생성 규칙을 기술적으로 강제할 수 없는 시스템은 사유와 보완 통제(수기 점검 주기 단축 등)를 양식 05. 패스워드 정책 이행 점검표에 기록한다.

## 11. 책임 주지

1. 사용자에게는 연 1회 이상 정보보호 교육과 보안 서약을 통해 패스워드 관리 책임(비공유, 기록 금지, 노출 시 즉시 변경·신고)이 본인에게 있음을 주지시킨다.
2. 이용자에게는 8항의 공지로 패스워드 관리 책임이 이용자에게 있음을 안내한다.
