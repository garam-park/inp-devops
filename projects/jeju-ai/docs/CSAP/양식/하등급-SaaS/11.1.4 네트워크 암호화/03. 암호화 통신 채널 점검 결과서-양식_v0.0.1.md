## 1. 점검 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 암호화 통신 채널이 전 구간에 적용되어 있는지, 취약한 프로토콜(SSL, TLS 1.0/1.1 등)이 비활성화되어 있는지, 지원 암호의 보안강도가 2^112 이상인지 확인하고 부적합을 조치한다. |
| 수시 점검 사유(해당 시) | {{신규 구간 오픈 / 구성 변경 / 프로토콜·알고리즘 취약점 공개 / 침해사고 / 심사 대비}} |
| 점검 대상 | 양식 02. 암호화 통신 채널 사용 현황 버전 {{ }}의 전 구간 |
| 직전 점검 | {{NWE-CHK-YYYY-NN}}, {{YYYY-MM-DD}}, 미완료 조치 {{n}}건 |

## 2. 판정 기준

양식 01. 네트워크 암호화 지침 6~9항을 기준으로 판정한다.

| 구분 | 적합 기준 |
| --- | --- |
| 프로토콜 | TLS 1.2 이상만 활성화. SSL 2.0/3.0, TLS 1.0, TLS 1.1, SSH-1, Telnet, FTP, PPTP 비활성화 |
| 암호 스위트 | 블록 암호 키 길이 128bit 이상(AES, SEED, ARIA 등), 키 교환 ECDHE·DHE(2048bit 이상), 해시 SHA-256 이상. RC4·DES·익명 키 교환·EXPORT 급 미지원 |
| 인증서 | 신뢰된 CA 발급(내부 구간은 관리되는 사설 CA), RSA 2048bit 이상 또는 ECDSA P-256 이상, 서명 알고리즘 SHA-256 이상, 유효기간 내이며 만료까지 {{30}}일 이상 |
| SSH | SSH-2만 허용, 취약 알고리즘(CBC 모드 구버전, MD5·SHA-1 MAC 등) 제거, 키 기반 인증 |
| VPN | IPsec(IKEv2) 또는 SSL VPN(TLS 1.2 이상), 인증서·계정 유효 |
| 적용 범위 | 양식 01 지침 5항의 대상 구간에 누락 없이 적용, 예외 구간은 승인·보완 통제·기한 유효 |

## 3. 점검 방법

| 방법 | 도구·명령(예) | 확인 내용 |
| --- | --- | --- |
| 프로토콜·암호 스위트 스캔 | {{예: nmap --script ssl-enum-ciphers -p 443 대상호스트}} | 활성 프로토콜 버전, 지원 암호 스위트 목록 |
| TLS 접속 시험 | {{예: openssl s_client -connect 대상:443 -tls1_1}} | 취약 버전 접속이 거부되는지 확인 |
| 인증서 확인 | {{예: openssl x509 -text}}, 브라우저 인증서 보기 | 키 길이, 서명 알고리즘, 유효기간, 발급기관 |
| 설정 검토 | 로드밸런서 TLS 정책 화면, 웹서버·DB 설정 파일, sshd_config, VPN 장비 설정 | 허용 프로토콜·알고리즘 설정값 |
| 온라인 점검 서비스(외부 공개 구간) | {{예: SSL 점검 서비스}} | 종합 등급, 취약 항목 |

- 스캔·시험 결과 화면은 양식 04. 증적 수집 점검표에 따라 보관한다.
