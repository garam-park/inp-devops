## 1. 목적

{{회사명}}은(는) 공공기관에 제공하는 클라우드컴퓨팅서비스 {{서비스명}}에서 보안관제가 이루어지는 서비스 네트워크 이외의 비정상 통신경로가 발생하지 않도록, 시스템 격리 원칙과 정상 통신경로 관리 기준, 주기적 점검·검토 체계를 본 지침으로 정한다.

## 2. 적용 범위

- {{서비스명}} 인증 범위 내 모든 클라우드 자원(가상 서버, 컨테이너, 스토리지, 네트워크)과 관리 환경(클라우드 콘솔, 원격관리 접점, 배포 파이프라인)
- 서비스 운영·관리 목적으로 클라우드 자원에 접근하는 모든 임직원과 외부인력
- 공공 이용 기관에 할당된 자원·데이터와 그 통신경로

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 정상 통신경로 | 서비스 제공과 운영·관리에 필요하여 양식 02. 정상 통신경로 목록에 등재하고 승인받은 통신경로 |
| 비정상 통신경로 | 정상 통신경로 목록에 없는 모든 통신경로. 미승인 개방 포트, 허가되지 않은 원격 접속 경로, 테넌트 간 미차단 통신, 가상머신 탈출·은닉 채널 등을 포함한다. |
| 테넌트 | 서비스에서 논리적으로 격리되는 이용 기관 단위(네임스페이스, 계정, 스키마 등) |
| 격리 | 테넌트 간, 그리고 관리자와 이용 기관 자원 간에 승인되지 않은 접근·통신이 불가능하도록 분리하는 기술적 통제 |
| 관리 네트워크 | 운영·관리자가 서비스 자원에 접근하기 위한 통신 구간(VPN, 배스천 호스트 등) |

## 5. 격리 및 접근통제 원칙

### 5.1 관리자 접근통제

1. 운영·관리자는 이용 기관에 할당된 자원(메모리, 저장공간 등)과 데이터에 임의로 접근할 수 없으며, 접근이 필요한 경우 사전 승인(장애 조치 등 긴급 시 사후 {{n}}영업일 이내 승인)을 받고 접근 기록을 남긴다.
2. 관리자 접근은 관리 네트워크(VPN 접속 후 배스천 호스트 경유)로만 허용하고, 다중 인증을 적용한다.
3. 원격관리서버(SSH 등)는 6.1항의 설정 기준을 준수하며, 인터넷에서 직접 접근할 수 없게 한다.
4. 관리자 계정·권한은 2.1.2 주요 직무자 지정 절차를 따르고 최소 인원으로 제한한다.

### 5.2 이용자(테넌트) 간 격리

1. 이용자가 본인에게 할당된 자원 이외의 자원에 접근하지 못하도록 인증·인가, 테넌트 식별자 검증 등 기술적 통제 수단을 적용한다.
2. 컨테이너 기반 구성에서는 테넌트(네임스페이스) 간 네트워크 통신을 기본 차단(default deny)하고, 필요한 통신만 NetworkPolicy 등으로 명시적으로 허용한다.
3. 이용자별 컨테이너·워크로드를 혼용 운영하여 상호 통신이 가능해지지 않도록 격리 단위를 설계하고, 공유 구성요소(공용 DB, 캐시 등)는 테넌트 식별자 기반 접근통제를 적용한다.
4. 격리 설계와 적용 현황은 양식 02. 정상 통신경로 목록 5항에 기록한다.

### 5.3 무선망 분리

1. 클라우드 서비스 운영 네트워크는 무선망과 분리하고, 무선망에서 운영 자원·관리 네트워크로 직접 접속할 수 없게 한다.
2. 업무용 무선망에서 운영 자원에 접근해야 하는 경우에도 VPN·다중 인증을 거친 관리 네트워크 경유만 허용한다.
3. 운영 네트워크에 무선 접점(무선 AP 연결 등)이 없음을 정기 점검으로 확인한다.

### 5.4 정상 통신경로 관리

1. 서비스 제공과 운영·관리에 필요한 모든 통신경로는 양식 02. 정상 통신경로 목록에 등재하고 정보보호 최고책임자의 승인을 받는다.
2. 목록에 없는 통신경로(포트 개방, 방화벽·보안 그룹 규칙, 원격 접속 수단)는 생성하지 않으며, 필요 시 6.3항의 변경 절차를 거친다.
3. 모든 통신경로는 보안관제(모니터링) 대상 네트워크를 경유하도록 구성한다.

## 6. 통제 기준

### 6.1 원격관리서버(SSH 등) 설정 기준

| No | 설정 항목 | 기준 |
| --- | --- | --- |
| 1 | 접근 경로 | 배스천 호스트 또는 VPN 경유만 허용, 인터넷 직접 접근 차단 |
| 2 | 접근 IP | 관리 네트워크 대역({{CIDR}})으로 제한 |
| 3 | 인증 방식 | 키 기반 인증, 패스워드 인증 비활성화 |
| 4 | 루트 직접 로그인 | 금지(PermitRootLogin no) |
| 5 | 포트 | 기본 포트 변경 여부 {{변경: n / 유지(사유: )}}, 미사용 포트 차단 |
| 6 | 세션 | 유휴 세션 타임아웃 {{n}}분, 접속 기록 보관 |
| 7 | 다중 인증 | 관리 네트워크 진입 시 적용 |

### 6.2 취약점 점검 및 패치

1. 가상머신 탈출, 은닉 채널 생성, 컨테이너 격리 우회 등 비정상 통신경로를 발생시킬 수 있는 최신 보안 취약점을 {{월/분기}} 1회 이상 점검·확인한다.
2. 영향받는 취약점은 위험도에 따라 {{n}}일 이내 보안패치를 적용하고, 패치 이력을 보관한다.
3. IaaS/PaaS 제공자의 보안 공지·긴급 패치 안내를 구독하고, 제공자 책임 영역의 조치 완료 여부를 확인한다.

### 6.3 통신경로 변경 절차

| 단계 | 담당 | 내용 | 기록 |
| --- | --- | --- | --- |
| 1. 신청 | 요청 부서 | 구간, 프로토콜·포트, 용도, 기간을 적어 신청 | 변경 요청서 {{양식·시스템명}} |
| 2. 검토 | 정보보호 관리자 | 업무 필요성, 최소 개방 원칙, 격리 원칙 위배 여부, 보안관제 경유 여부 검토 | 검토 의견 |
| 3. 승인 | 정보보호 최고책임자 | 승인 또는 반려. 한시 경로는 종료일 지정 | 승인 기록 |
| 4. 반영 | 네트워크·인프라 담당 | 보안 그룹·NetworkPolicy·방화벽 규칙 반영 | 설정 변경 이력 |
| 5. 목록 갱신 | 정보보호 관리자 | 양식 02. 정상 통신경로 목록 갱신, 버전 상향 | 02 목록 |
| 6. 확인 | 정보보호 담당자 | 다음 정기 점검에서 반영 결과와 기준선 일치 확인 | 양식 03. 점검 및 검토 결과서 |
