본 문서는 {{회사명}} 정보보호 정책서 중 사용자 인증에 해당하는 절이다. 정보보호 정책서에 이미 해당 절이 있으면 그 내용을 본 양식의 항목과 대조하여 빠진 항목을 보완하고, 세부 기준과 절차는 양식 02. 사용자 인증 관리 절차(접근통제관리지침의 사용자 인증 절)에 위임한다.

## 1. 목적

{{회사명}}은(는) 클라우드컴퓨팅서비스 {{서비스명}}을 제공하기 위한 클라우드 시스템에 대한 모든 접근을 안전한 사용자 인증절차로 통제하여 비인가 접근을 방지하고, 클라우드 시스템과 이용 기관 정보의 기밀성·무결성·가용성을 보호하기 위하여 사용자 인증에 관한 기본 정책을 정한다.

## 2. 적용 범위

- {{서비스명}}(하등급 SaaS) 인증 범위 내 클라우드 시스템 전체: 이용자 포털, 관리자 포털(관리시스템), 당사가 이용하는 IaaS/PaaS 콘솔·API, 운영 서버(가상 서버·컨테이너), DBMS, 네트워크 장비·VPN, 정보보호시스템, 형상관리·배포 도구, 모니터링 도구, 인증·계정 연동 시스템(SSO, IdP, 디렉터리)
- 위 시스템에 접근하는 모든 사용자: 임직원, 외부인력(파견·용역·위탁), 이용 기관 관리자, 이용자
- 책임공유모델에 따라 IaaS/PaaS 제공자가 책임지는 물리 시설과 하이퍼바이저 계층의 인증 통제는 제공자의 인증·계약으로 확인하고, 당사는 제공자 콘솔·API 계정의 인증 설정과 그 위 계층의 인증 통제를 책임진다.

## 3. 정책 선언

1. 클라우드 시스템에 대한 접근은 개인별로 발급된 계정과 승인된 인증수단으로 사용자를 인증한 뒤에만 허용하며, 인증을 거치지 않은 접근과 공용 계정 사용을 금지한다.
2. 모든 클라우드 시스템에 시스템 유형과 위험도에 맞는 인증 방식, 로그인 실패 횟수 제한, 세션 관리, 불법 로그인 시도 경고를 적용하며, 그 최소 기준은 사용자 인증 관리 절차에 정한다.
3. 비밀번호 등 인증정보는 길이, 복잡도, 변경 주기, 재사용 제한을 포함한 강도 기준에 따라 생성·관리하며, 세부 기준은 패스워드 관리 절차를 따른다.
4. 일정 횟수 이상 인증에 실패하면 계정 잠금, 자동입력 방지(CAPTCHA) 등으로 접근을 제한하고, 실패 사유를 상세히 노출하지 않는다.
5. 공개 인터넷망으로 접속하는 관리자 포털과 위험도가 높은 접근(특수권한 계정, 원격접속, 외부업체 접속, IaaS/PaaS 콘솔, 개인정보처리시스템 외부 접속)에는 아이디·비밀번호 외의 강화된 인증수단(다중 인증)을 적용한다. 이용자에게는 강화된 인증수단을 제공하고 이용 기관이 선택할 수 있게 한다.
6. 관리자 포털 등 관리시스템에는 세션 유휴 시간 제한, 최대 세션 유지 시간과 재인증, 동일 계정 동시 접속 제한을 적용하며, 타당한 사유가 있는 예외는 정보보호 최고책임자의 승인과 보완 통제를 조건으로 기한을 정해 허용한다.
7. 싱글사인온(SSO) 등 계정 연동 방식으로 인증하는 경우 인증 도용 시 피해 확대를 막기 위한 별도의 보호대책(중요 시스템 재인증·다중 인증, 토큰 보호, 권한 승계 최소화, 인증 로그 모니터링)을 수립·이행한다.
8. 클라우드 시스템을 새로 도입·개발·변경할 때 설계 단계에서 사용자 인증 통제방안을 검토하고, 인증 통제가 기준을 충족하지 않으면 운영에 반영하지 않는다.
9. 개인정보 보호법과 그 고시, 이용 기관과의 계약, 공공기관 이용 기관의 보안 요구사항 등 법적·계약적 요구사항에 따른 강화된 인증방식을 준수한다.
10. 사용자 인증 설정의 기준 충족 여부와 불법 로그인 시도 경고를 정기적으로 점검·검토하고 결과를 기록한다.

## 4. 사용자 인증 통제 요소

| 통제 요소 | 정책 요구사항 | 세부 기준 문서 |
| --- | --- | --- |
| 사용자 인증 | 개인별 계정, 시스템 유형별 최소 인증 방식, 인증정보 강도 기준 | 사용자 인증 관리 절차 6·7항, 패스워드 관리 절차 |

| 세션 관리 | 유휴 시간 제한, 최대 세션 유지 시간과 재인증, 동시 접속 제한 | 사용자 인증 관리 절차 9항 |
| 강화된 인증 | 고위험 접근 다중 인증 필수, 이용자 강화된 인증수단 제공 | 사용자 인증 관리 절차 10항, 10.3.3 강화된 인증 수단 제공 |
| 불법 로그인 시도 경고 | 사용자 알림과 관리자 경고, 탐지 규칙, 대응·침해사고 연계 | 사용자 인증 관리 절차 11항 |
| SSO·계정 연동 보호 | 재인증·다중 인증, 토큰 보호, 권한 승계 최소화, 로그 모니터링 | SSO 및 계정 연동 보호대책서 |
| 설계·변경 시 검토 | 신규·변경 시스템의 인증 통제 검토와 설정 현황 반영 | 사용자 인증 관리 절차 12항 |

## 5. 역할과 책임

| 역할 | 책임 |
| --- | --- |
| 최고경영자 | 사용자 인증 정책 승인, 인증 강화에 필요한 자원 지원 |
| 정보보호 최고책임자(CISO) | 사용자 인증 관리 절차와 SSO 보호대책 승인, 인증 통제 예외 승인, 점검 결과 승인 |
| 개인정보 보호책임자(CPO) | 개인정보처리시스템의 인증 통제가 개인정보 보호법과 고시 요구사항을 충족하는지 확인 |
| 정보보호 관리자 | 인증 통제 기준 관리, 시스템별 인증 설정 현황 관리, 정기 점검 수행, 예외 검토 |
| 정보보호 담당자 | 불법 로그인 시도 경고 모니터링·대응, 점검 증적 수집 |
| 시스템 담당자(인프라·DB·개발·네트워크·정보보호시스템) | 담당 시스템의 인증 설정 적용·유지, 변경 시 정보보호 관리자 통보 |
| 개발 부서장 | 서비스 설계·개발 시 인증 통제 요구사항 반영, 시험 결과 제출 |
| 임직원·외부인력 | 개인별 계정 사용, 인증수단·인증정보 보호, 이상 로그인 알림 수신 시 즉시 신고 |
| 이용 기관(이용자) | 이용 기관 계정·인증수단 관리, 강화된 인증 선택·적용, 이상 징후 신고 |
| IaaS/PaaS 제공자 | 물리 시설·하이퍼바이저 계층 인증 통제, 콘솔 다중 인증 기능 제공(제공자 인증·계약으로 확인) |

## 6. 위반 시 조치

- 인증 통제 기준을 충족하지 않는 시스템은 정보보호 관리자가 시스템 담당자에게 시정을 요구하고, 기한 내 시정되지 않으면 정보보호 최고책임자에게 보고한다.
- 공용 계정 사용, 인증정보 공유, 인증 우회 등 정책 위반 행위는 인사 규정과 계약에 따라 조치한다.
- 불법 로그인 시도가 침해사고 또는 그 징후로 판단되면 침해사고 대응 절차(5.1.1)를 따른다.
