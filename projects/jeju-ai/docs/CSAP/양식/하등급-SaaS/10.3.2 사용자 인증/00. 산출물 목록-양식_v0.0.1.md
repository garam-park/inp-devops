## 2. 권장 작성 순서

1. 01 정보보호 정책서 사용자 인증 조항: 사용자 인증 기본 정책과 통제 요소를 정하고 최고경영자 승인을 받아요.
2. 02 사용자 인증 관리 절차: 시스템 유형별 최소 기준, 실패 처리, 세션 관리, 다중 인증, 경고·대응, 예외 절차를 정하고 정보보호 최고책임자 승인을 받아요.
3. 04 SSO 및 계정 연동 보호대책서: SSO·계정 연동을 사용하면 작성하고, 사용하지 않으면 02 절차 13항에 해당 없음을 표기해요.
4. 03 시스템별 사용자 인증 설정 현황: 정보자산 목록·클라우드 콘솔 자원 목록과 대조해 모든 시스템을 등재하고, 기준과 실제 설정을 대조해 미충족 항목은 예외 승인을 받아요.
5. 05 사용자 인증 통제 점검 기록: 반기마다 설정 점검·동작 시험·경고 검토를 수행하고 결과를 03·04에 반영해요.
6. 06 증적 수집 점검표: 정기 주기와 심사 전에 화면·설정 증적을 수집하고 최신 상태를 확인해요.

## 3. 심사 대비 체크리스트

- [ ] 인증 범위 내 모든 클라우드 시스템(VM, DBMS, 네트워크, 응용프로그램, 정보보호시스템, IaaS/PaaS 콘솔)에 사용자 인증 절차를 수립했고 03 현황에 빠짐없이 등재했다.
- [ ] 로그인 실패 시 아이디 존재 여부나 비밀번호 오류를 구분해 표시하지 않고 일반화된 오류 메시지를 사용한다.
- [ ] 관리자 포털 등 관리시스템에 세션 타임아웃(유휴 시간 제한)이 설정되어 있고, 예외는 승인과 보완 통제가 있다.
- [ ] 관리자 포털과 이용자 포털에 내부 절차에서 정한 로그인 횟수 제한을 적용했고, 잠금·CAPTCHA가 실제로 동작한다.
- [ ] 관리자 포털에서 동일 계정에 의한 동시 접속을 제한한다.
- [ ] 최대 세션 유지 시간을 제한해 최초 로그인 후 재인증 없이 장시간(24시간 세션 유지 등) 작업할 수 없다.
- [ ] 공개 인터넷망으로 접속하는 관리자 포털, 특수권한 계정, 원격접속, 외부업체 접속, IaaS/PaaS 콘솔에 다중 인증을 적용했다.
- [ ] 이용자에게 강화된 인증수단을 제공하고 이용 기관이 선택·적용할 수 있다.
- [ ] SSO·계정 연동을 사용하면 중요 시스템 재인증·다중 인증, 토큰 보호, 권한 승계 최소화, 인증 로그 별도 모니터링 보호대책을 수립·이행하고 있다.
- [ ] 개인정보처리시스템의 로그인 실패 제한, 유휴 시간 제한, 외부 접속 안전한 인증수단 등 법정 의무 항목에 예외가 없다.
- [ ] 불법 로그인 시도 경고가 설정되어 있고, 경고 처리와 잠금 해제의 본인 확인 기록이 있다.
- [ ] 반기 점검 기록(05)과 최신 화면·설정 증적(06)이 있고, 미충족 항목은 예외 승인 또는 조치 계획이 있다.

## 4. 관련 산출물(다른 항목)

- 2.1.2 주요 직무자 지정 및 감독: 특수권한 사용자·IdP 관리자를 주요 직무자로 지정하고, SSO 그룹-역할 매핑 검토 시 주요 직무자 목록과 대조해요.
- 5.1.1 침해사고 대응 절차 수립: 불법 로그인 시도가 침해 성공·유출 의심으로 판단되면 침해사고 대응 절차로 전환해요.
- 10.1.2 접근기록 관리: 로그인 성공·실패·잠금·세션 이벤트를 접근기록으로 남기고 보관 기간을 맞춰요.
- 10.3.3 강화된 인증 수단 제공: 다중 인증 수단의 등록·분실·재발급과 이용자 제공 방식은 10.3.3 산출물을 따라요.
- 10.3.4 패스워드 관리: 비밀번호 생성 규칙, 초기 비밀번호 변경, 변경 주기 등 세부 기준은 10.3.4 산출물을 따라요.
- 13.2.1 시험 계획 및 결과: 인증 기능 개발·변경 시 실패 잠금, 오류 메시지, 세션 만료, 다중 인증 우회 불가 시험 결과를 보관해요.
- 14.1.1 보안서비스 수준 협약: 공공기관 이용 기관의 인증 관련 보안 요구사항(관리자 다중 인증 등)을 계약에 반영하고 이용자 포털 기준을 상향해요.

## 5. 양식 작성 규칙

- `{{ }}`로 표시한 자리표시자는 실제 값으로 바꿔요. 표의 빈 칸은 해당 값을 채워요.
- 02 절차의 실패 횟수·잠금 시간·세션 시간 등 수치는 법령·고시가 정하지 않은 당사 내부 기준이에요. 조직 상황에 맞게 조정하되 부적합 사례가 걸리는 통제(실패 제한, 세션 타임아웃, 동시 접속 제한, 24시간 세션 금지)는 없애지 않아요.
- 서명이 필요한 문서는 서명본을 스캔해 보관하고, md 원본에는 서명본 보관 위치를 적어요.
- 현황 문서(03)와 점검 기록(05)은 버전을 올릴 때 이전 버전을 삭제하지 않고 보관해서 특정 시점의 설정을 확인할 수 있게 해요.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신해요.
- 법령 인용은 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 개인정보의 안전성 확보조치 기준 제5조·제6조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이에요. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인해요.
