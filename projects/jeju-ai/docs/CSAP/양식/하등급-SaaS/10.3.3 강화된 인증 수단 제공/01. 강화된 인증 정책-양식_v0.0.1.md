> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제6조제2항(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)은 개인정보취급자가 정보통신망을 통해 외부에서 개인정보처리시스템에 접속하려는 경우 인증서, 보안토큰, 일회용 비밀번호 등 안전한 인증수단을 적용하도록 정한다. 본 정책은 이 기준을 당사가 운영하는 모든 관리시스템으로 확대 적용한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

본 문서는 {{회사명}} 정보보호 정책서 중 강화된 인증 수단에 관한 절({{정보보호 정책서 제n장 제n절}})을 인증 심사 제출용으로 발췌·정리한 것이다. 정보보호 정책서 본문과 내용이 다르면 정보보호 정책서를 우선하고 본 문서를 갱신한다.

## 1. 목적

{{회사명}}은(는) 클라우드컴퓨팅서비스 {{서비스명}}의 계정 보안성과 서비스 신뢰성을 높이기 위하여, 아이디·비밀번호 외에 다중 요소 인증 등 강화된 인증 수단을 기본적으로 제공하고, 이용자가 요청하는 강화된 인증 수단을 제공하기 위한 방안을 마련하는 원칙을 정한다.

## 3. 정책

### 3.1 강화된 인증 수단의 기본 제공

1. 당사는 인증 접점에 아이디·비밀번호(지식 요소) 외에 소유 요소 또는 생체 요소에 기반한 강화된 인증 수단(OTP, 인증서, 이메일·휴대폰 인증코드, 지문 등)을 기본적으로 제공한다.
2. 불특정 다수가 이용하는 클라우드 서비스의 특성을 고려하여, 이용자 포털의 이용자는 강화된 인증 수단의 사용 여부를 스스로 선택할 수 있게 하고, 이용 기관이 요청하면 기관 단위로 사용을 강제할 수 있게 한다.
3. 제공하는 인증 수단의 종류와 접점별 적용 기준은 접근통제관리지침(양식 02. 강화된 인증 수단 관리 절차)에 정한다.

### 3.2 관리시스템의 강화된 인증 필수 적용

1. 관리자 포털, IaaS/PaaS 제공자 콘솔, 운영 서버·DB 원격 접속 경로, 그 밖의 관리시스템에 접속하는 모든 계정에는 강화된 인증을 필수로 적용하며, 사용자가 임의로 해제할 수 없게 한다.
2. 정보통신망을 통해 외부에서 관리시스템에 접속하는 경우 가상사설망(VPN) 등 안전한 접속 수단과 추가 인증 수단을 함께 적용한다.
3. 강화된 인증을 거치지 않고 관리 기능에 도달할 수 있는 우회 경로(구 버전 로그인 화면, 기본 인증만 사용하는 API, 내부 URL 직접 접근 등)를 두지 않는다.

### 3.3 다중 요소의 인정 기준

1. 다중 요소 인증은 지식 요소(비밀번호, PIN 등), 소유 요소(OTP 생성기·앱, 인증서·보안토큰, 등록된 휴대폰·이메일 등), 생체 요소(지문, 얼굴 등) 중 서로 다른 두 가지 이상의 요소를 조합한 인증을 말한다.
2. 아이디·비밀번호 인증 후 다시 아이디·비밀번호 또는 다른 지식 요소(2차 비밀번호, PIN, 보안 질문 등)만으로 인증하는 방식은 강화된 인증 수단으로 인정하지 않는다.
3. IP(국가) 제한, MAC 제한, 브라우저·기기 제한 등 추가 통제 방안은 강화된 인증을 보완하는 수단으로 적용하며, 인증 요소를 대체하지 않는다.

### 3.4 이용자 요청 시 제공 방안

1. 당사는 이용자가 강화된 인증 수단이나 추가 통제 방안을 요청할 수 있는 채널을 서비스 이용 가이드, 이용 계약 문서, 고객지원 채널에 안내한다.
2. 이용자가 현재 제공 중인 인증 수단의 사용을 요청하면 정한 처리 기한 이내에 적용하고, 제공하지 않는 수단(인증서 기반 인증, 생체 인증 등)을 요청하면 제공 가능성을 검토하여 대안과 제공 계획을 회신한다.
3. 요청의 접수·검토·적용·회신 이력은 기록하여 보관한다.

### 3.5 예외

1. 기술적 제약으로 강화된 인증을 적용할 수 없는 접점은 정보보호 최고책임자의 승인을 받아 예외로 등록하고, 보완 통제와 적용 기한을 정한다. 관리자 포털과 IaaS/PaaS 콘솔 루트 계정에는 예외를 허용하지 않는다.
2. 예외는 {{반기}}마다 재검토하며, 예외 사유가 해소되면 즉시 강화된 인증을 적용한다.

## 4. 책임공유모델에 따른 책임 구분

| 영역 | IaaS/PaaS 제공자 | 당사(SaaS 제공자) | 이용 기관·이용자 |
| --- | --- | --- | --- |
| IaaS/PaaS 콘솔·API의 강화된 인증 | 다중 요소 인증 기능 제공, 콘솔 자체의 보안 | 루트·관리자·IAM 계정 전체에 다중 요소 인증 활성화·강제, 설정 점검 | 해당 없음 |
| 관리자 포털·원격 접속 경로 | 해당 없음(제공자 내부 관리시스템은 제공자 인증·계약으로 확인) | 강화된 인증 필수 적용, VPN 등 안전한 접속 수단 운영, 우회 경로 차단 | 해당 없음 |
| 이용자 포털의 강화된 인증 | 해당 없음 | 인증 수단 기본 제공, 기관 단위 강제 기능 제공, 이용 안내, 요청 처리 | 사용 여부 선택, 기관 내부 정책에 따른 강제 요청, 인증 수단(기기·앱) 보호 |
| 추가 통제(IP·국가·브라우저 제한) | 네트워크 수준 통제 기능(보안 그룹 등) 제공 | 서비스 수준 통제 기능 제공·설정, 요청 처리 | 허용 IP 대역 등 통제 조건 제공 |

## 5. 역할과 책임

| 역할 | 책임 |
| --- | --- |
| 정보보호 최고책임자 | 본 정책 승인, 예외 승인, 제공 불가 요청에 대한 제공 계획 승인 |
| 정보보호 관리자 | 접근통제관리지침의 강화된 인증 절차 관리, 인증 수단 적용 현황 관리, 예외 재검토, 요청 처리 점검 |
| 정보보호 담당자(계정·접근통제) | 관리시스템 강화된 인증 설정 점검, 인증 로그 검토, 증적 수집 |
| 서비스 개발 부서장 | 이용자 포털·관리자 포털의 인증 수단 구현과 우회 경로 제거, 신규 접점 배포 전 인증 설계 검토 |
| 인프라 운영 담당 | IaaS/PaaS 콘솔·VPN·배스천 호스트의 강화된 인증 설정과 유지 |
| 고객지원 담당 | 이용자 요청 접수·회신, 요청 처리 대장 기록, 안내 자료 현행화 |
| 임직원·외부인력 | 부여된 인증 수단의 보호, 분실·이상 징후 즉시 신고 |

## 6. 위반 시 조치

강화된 인증을 임의로 해제하거나 우회 경로를 만든 임직원·외부인력은 정보보호 정책서의 위반 조치 규정에 따라 처리하고, 해당 접점은 즉시 강화된 인증을 복구한다.
