> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제6조제2항(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)에 따라 개인정보취급자가 정보통신망을 통해 외부에서 개인정보처리시스템에 접속하려는 경우 인증서, 보안토큰, 일회용 비밀번호 등 안전한 인증수단을 적용한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

본 문서는 {{회사명}} 접근통제관리지침 중 강화된 인증 수단에 관한 절({{접근통제관리지침 제n장}})을 인증 심사 제출용으로 발췌·정리한 것이다. 접근통제관리지침 본문과 내용이 다르면 지침을 우선하고 본 문서를 갱신한다.

## 1. 목적

이용자와 당사 운영자가 {{서비스명}}에 접속할 때 아이디·비밀번호 외에 다중 요소 인증 등 강화된 인증 수단을 적용하고, 이용자가 요청하는 인증 수단과 추가 통제 방안을 제공하기 위한 기준과 절차를 정한다.

## 2. 적용 범위

- {{서비스명}}(하등급 SaaS) 인증 범위 내 모든 인증 접점과 그 접점에 로그인하는 모든 계정
- 당사 임직원·외부인력의 관리시스템 접속과 이용 기관 관리자·이용자의 이용자 포털 접속
- IaaS/PaaS 제공자 콘솔·API에 대한 당사 계정의 접속. 제공자 내부 관리시스템은 제공자 인증·계약으로 확인하며 본 절차의 대상이 아니다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 인증 접점 | 이용자 또는 운영자가 자격증명을 제시하여 로그인하는 시스템·화면·프로토콜 종단. 03. 인증 수단 적용 현황표에 목록화한다. |
| 관리시스템 | 당사 운영자가 서비스와 인프라를 운영·관리하기 위해 접속하는 시스템. 관리자 포털(백오피스), IaaS/PaaS 제공자 콘솔·API, VPN·배스천 호스트, 운영 서버·DB, 형상관리·CI/CD, 정보보호시스템 관리 콘솔 등 |
| 이용자 포털 | 이용 기관 관리자와 이용자가 서비스를 이용하기 위해 로그인하는 화면과 인증 API |
| 인증 요소 | 지식 요소(아는 것), 소유 요소(가진 것), 생체 요소(본인의 신체·행동 특성) |
| 다중 요소 인증(MFA) | 서로 다른 두 가지 이상의 인증 요소를 조합하는 인증 |
| 강화된 인증 수단 | 아이디·비밀번호에 더하여 적용하는 소유·생체 요소 기반 인증 수단(OTP, 인증서(PKI), 보안토큰, 이메일·휴대폰 인증코드, 지문 등) |
| 추가 통제 방안 | 인증 요소 외에 접속 조건을 제한하는 수단(IP·국가 제한, MAC 제한, 브라우저·기기 제한, 접속 시간 제한 등) |
| 안전한 접속 수단 | 외부에서 관리시스템에 접속할 때 통신 구간과 접속 주체를 제한하는 수단(VPN, 배스천 호스트 등) |

## 4. 인증 요소 유형과 인정 기준

### 4.1 인증 요소 유형

| 요소 유형 | 정의 | 예시 | 비고 |
| --- | --- | --- | --- |
| 지식 | 이용자만 아는 정보 | 비밀번호, PIN, 보안 질문 답 | 1차 인증에 사용한다. 2차 인증으로 단독 사용할 수 없다. |
| 소유 | 이용자만 가진 물리·논리 매체 | OTP 앱·기기, 하드웨어 보안토큰(FIDO2), 인증서(PKI)·보안토큰, 등록된 휴대폰(문자 인증코드), 등록된 이메일(인증코드) | 이메일·문자 인증코드는 매체 탈취 위험이 있어 관리시스템의 2차 요소로는 {{허용 / 비허용}}한다. |
| 생체 | 이용자 신체·행동 특성 | 지문, 얼굴, 홍채 | 기기 내 생체 인증(FIDO2·패스키)으로 제공한다. |

### 4.2 인정·불인정 조합

| 조합 | 판정 | 사유 |
| --- | --- | --- |
| 비밀번호 + OTP | 인정 | 지식 + 소유 |
| 비밀번호 + 인증서(PKI)·보안토큰 | 인정 | 지식 + 소유 |
| 비밀번호 + 이메일 또는 문자 인증코드 | 인정(이용자 포털), 관리시스템은 4.1의 비고에 따름 | 지식 + 소유 |
| 비밀번호 + 지문·얼굴(기기 생체 인증) | 인정 | 지식 + 생체 |
| 패스키(기기 소유 + 생체 또는 PIN) | 인정 | 소유 + 생체 또는 소유 + 지식 |
| 아이디·비밀번호 인증 후 다시 아이디·비밀번호 입력 | 불인정 | 같은 지식 요소의 반복 |
| 비밀번호 + 2차 비밀번호·PIN·보안 질문 | 불인정 | 지식 + 지식 |
| 비밀번호 + IP·국가 제한 | 불인정(추가 통제로만 취급) | IP 제한은 인증 요소가 아님 |
| 이용 기관 SSO(IdP) 연동 | 이용 기관 IdP에서 다중 요소 인증을 수행하는 경우에 한해 인정 | IdP의 인증 정책을 계약·설정으로 확인 |

## 5. 제공 인증 수단 카탈로그

| No | 인증 수단 | 요소 유형 | 제공 상태 | 적용 가능 접점 | 구현 방식 | 등록·사용 방법 요약 | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | OTP(앱 기반 TOTP) | 소유 | {{제공 / 계획}} | 관리자 포털, 이용자 포털, 클라우드 콘솔, VPN | {{자체 구현 / 라이브러리명 / 제공자 기능}} | 설정 화면에서 QR 코드로 등록하고 로그인 시 6자리 코드 입력 | 기본 권장 수단 |
| 2 | 하드웨어 보안토큰·FIDO2 인증기 | 소유 | {{제공 / 계획}} | 관리자 포털, 클라우드 콘솔 | WebAuthn | 인증기 등록 후 로그인 시 터치·PIN | 관리자 계정 권장 |
| 3 | 패스키(기기 생체 인증) | 소유 + 생체 | {{제공 / 계획}} | 이용자 포털, 관리자 포털 | WebAuthn | 기기에 패스키 등록 후 지문·얼굴로 인증 | 지문 등 생체 인증 요청에 대응하는 수단 |
| 4 | 이메일 인증코드 | 소유 | {{제공 / 계획}} | 이용자 포털 | 이메일 발송 | 로그인 시 등록 이메일로 발송된 코드 입력 | 유효시간 {{n}}분, 1회 사용 |
| 5 | 휴대폰 문자 인증코드 | 소유 | {{제공 / 계획}} | 이용자 포털 | 문자 발송 서비스 | 로그인 시 등록 휴대폰으로 발송된 코드 입력 | 유효시간 {{n}}분, 1회 사용 |
| 6 | 인증서(PKI) 기반 인증 | 소유 | {{제공 / 계획}} | 이용자 포털(공공기관 이용자), 관리자 포털 | {{공동인증서 / 기관 인증서(GPKI) 연동 모듈}} | 인증서 선택 후 인증서 비밀번호 입력 | 공공기관 이용 기관 요청에 대응하는 수단 |
| 7 | 이용 기관 SSO 연동(SAML·OIDC) | 이용 기관 IdP에 위임 | {{제공 / 계획}} | 이용자 포털 | SAML 2.0 / OIDC | 이용 기관 IdP에서 인증 후 서비스 접속 | IdP의 다중 요소 인증 정책 확인 필요 |
| 8 | IaaS/PaaS 제공자 콘솔 다중 요소 인증 | 소유 | 제공 | 클라우드 콘솔·API | 제공자 기능({{기능명}}) | 제공자 콘솔 보안 설정에서 가상·하드웨어 MFA 등록 | 당사가 전체 계정에 활성화·강제 |

- 제공 상태가 "계획"인 수단은 04. 강화된 인증 수단 요청 처리 대장 3항의 제공 계획에 따라 개발하고, 제공을 시작하면 본 표와 03. 인증 수단 적용 현황표를 갱신한다.

## 6. 접점별 적용 기준

| 접점 구분 | 적용 방식 | 허용 인증 수단 | 안전한 접속 수단 | 추가 통제 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 관리자 포털(당사 운영자용) | 필수(전 계정, 해제 불가) | OTP, FIDO2, 패스키 | 인터넷 노출 시 {{VPN 경유 필수 / 허용 IP 제한}} | 허용 IP 대역, 국가 제한, 세션 시간 제한 | 아이디·비밀번호만으로 로그인되는 화면·API를 두지 않는다 |
| IaaS/PaaS 제공자 콘솔·API | 필수(루트·IAM 사용자 전 계정) | 제공자 MFA(가상·하드웨어) | 콘솔 접속 허용 IP 조건 {{적용 / 미적용}} | IAM 정책으로 MFA 미인증 세션의 권한 차단 | 루트 계정은 하드웨어 MFA 권장, 봉인 관리 |
| VPN·배스천 호스트(운영 서버·DB 원격 접속) | 필수 | OTP, 인증서 | VPN 자체가 안전한 접속 수단. 배스천은 VPN 경유만 허용 | 국가 제한, 접속 시간 제한 | 외부에서 관리시스템 접속 시 안전한 접속 + 추가 인증 |
| 형상관리·CI/CD·정보보호시스템 관리 콘솔 | 필수 | OTP, FIDO2, 사내 SSO(MFA 적용) | {{VPN 경유 / 사내망 한정}} | 허용 IP 대역 | |
| 이용자 포털: 이용 기관 관리자 계정 | {{기본 활성화(기관 요청 시 해제 가능) / 선택}} | OTP, 이메일·문자 인증코드, 패스키, 인증서, SSO | 해당 없음 | 기관 허용 IP 대역(요청 시) | 기관 관리자 계정은 기본 활성화 권장 |
| 이용자 포털: 일반 이용자 | 기본 제공, 이용자 선택. 기관 요청 시 기관 단위 강제 | OTP, 이메일·문자 인증코드, 패스키, SSO | 해당 없음 | 기관 허용 IP 대역(요청 시) | 불특정 다수 이용 특성 반영 |
| 이용 기관 시스템 연동 API(비대화형) | 다중 요소 인증 대상이 아니며 대체 통제 적용 | API 키·토큰 + {{상호 TLS / 요청 서명}} | 해당 없음 | 허용 IP 제한, 키 주기적 교체, 권한 최소화 | 예외가 아닌 별도 통제 기준 |

- 신규 접점(새 관리 화면, 새 도메인, 새 로그인 API)을 배포할 때는 변경 관리 절차에서 본 기준 적합 여부를 검토하고, 배포 후 03. 인증 수단 적용 현황표에 등재한다.
- 관리자 포털 계정은 최초 로그인 시 인증 수단 등록을 강제하고, 등록 전에는 등록 화면 외 기능에 접근할 수 없게 한다.

- 이용자가 이용자 포털 설정 화면에서 스스로 인증 수단을 등록·사용하는 경우는 요청 처리 대장에 기록하지 않고 시스템 기록으로 갈음한다.
- 공공기관 이용 기관이 기관 인증서(GPKI) 연동, 국내 IP 한정 등을 요청하면 유형 B·C로 처리하고 보안서비스 수준 협약과 연계한다.
