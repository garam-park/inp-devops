# 14.3.2 보안관제 제반환경 지원 산출물 목록

## 2. 권장 작성 순서

1. 01 보안관제 제반환경 지원 절차: 제공 가능한 제반환경 항목(ENV-01~ENV-07)과 지원 절차, 계약 전 사전 검토 체크리스트를 정하고 정보보호 최고책임자 승인을 받아요.
2. 02 보안관제 연계 환경 구성 내역서: 국가기관등 계약별로 보안관제 주체와 요구사항을 확인·협의하고, 구성 내역·구성도·연계 시험 결과를 기록한 뒤 기관 확인을 받아요.
3. 04 증적 수집 점검표: 구성이 완료되면 전송 설정·연계 시험·암호화 설정 화면 등 기술 증적을 항목별 주기에 맞춰 수집해요.
4. 03 보안관제 월간보고자료: 매월 제반환경 제공 상태와 보안이벤트 현황을 작성해 기관에 발송하고 수신 확인을 보관해요.

## 3. 심사 대비 체크리스트

- [ ] 국가기관등에 제공할 수 있는 보안관제 제반환경 항목(로그·이벤트 제공, 관제용 접근 수단, 연계 구간 등)을 문서로 정의했다.
- [ ] 계약 체결 전에 기관의 보안관제 주체와 요구 연계 방식을 확인하고 지원 가능 여부를 사전 검토하는 절차가 있다.
- [ ] 기관별로 보안관제 주체(자체 보안관제센터 또는 다른 기관 보안관제센터 위탁)를 확인해 구성 내역서에 기록했다.
- [ ] 이용기관 보안관제 영역이 당사 서비스의 로그·보안이벤트를 받아 보안관제를 수행할 수 있는 기반을 제공하고 있고, 전송 설정·수신 확인 증적이 있다.
- [ ] 기관의 보안관제 영역과 정부보안관제체계를 연계할 수 있는 기반을 제공하고 있고, 연계 시험 결과와 기관 확인이 있다.
- [ ] 이용기관이 요구한 연계 방식·요구사항의 협의·이행 기록이 있고, "지원 불가"로 남아 있는 요구가 없다.
- [ ] 연계 구간 전송 암호화에 국가정보원 검증필 암호모듈이 적용된 방식을 사용하고 있다(14.3.1과 연계).
- [ ] 연계 상태를 모니터링하고 전송 중단·장애 시 기관에 통보·복구한 기록이 있다.
- [ ] 보안관제 월간보고자료를 주기적으로 작성해 기관에 발송했고, 발송·수신 확인 증적을 보관하고 있다.
- [ ] IaaS/PaaS 제공자가 담당하는 인프라 계층 관제 기반은 제공자의 CSAP 인증·계약으로 확인했고, 활용하는 기능이 있으면 그 범위를 확인했다.

## 4. 관련 산출물(다른 항목)

- 14.1.1 보안서비스 수준 협약: 협약서의 보안관제 연계·기술 지원 조항이 본 항목 지원의 계약 근거예요. 구성 내역서 1항에 협약 조항을 인용해요.
- 14.1.4 사고 및 장애 대응: 침해사고 탐지 시 국가기관등·국가정보원 협조 체계는 해당 항목의 대응 절차를 따라요.
- 14.3.1 검증필 암호화 기술 제공: 연계 구간 전송 암호화의 검증필 암호모듈 적용 현황·증적을 공유해요.
- 10.1.2 접근기록 관리: 기관에 제공하는 접근기록·로그의 생성·보관 체계가 제공 로그의 원천이에요.
- 5.2.1 침해사고 보고: 월간보고와 별개로 침해사고로 판단된 건의 보고 절차·기록을 연계해요.

## 5. 양식 작성 규칙

- `{{ }}`로 표시한 자리표시자는 실제 값으로 바꿔요. 표의 빈 칸은 해당 값을 채워요.
- 제반환경 항목 코드 ENV-01~ENV-07은 01 절차 5항 기준이에요. 항목을 추가·삭제하면 02 구성 내역서, 03 보고서, 04 점검표의 항목 코드를 함께 맞춰요.
- 구성 내역서(02)는 기관·계약 단위로, 월간보고자료(03)는 기관·월 단위로 사본을 만들어 작성하고, 기관 확인 서명본·발송 공문은 스캔해 보관하며 md 원본에 보관 위치를 적어요.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신해요.
- 법령 인용은 사이버안보 업무규정 제14조(대통령령 제34287호, 2024. 3. 5. 시행) 기준이에요. 국가 사이버보안 기본지침과 국가 클라우드 컴퓨팅 보안 가이드라인은 비공개 문서라 문서명만 적었어요. 법령이 개정되면 국가법령정보센터에서 조문을 다시 확인해요.
