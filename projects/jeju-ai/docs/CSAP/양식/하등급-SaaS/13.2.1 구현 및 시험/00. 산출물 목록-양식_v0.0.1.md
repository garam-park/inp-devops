## 2. 권장 작성 순서

1. 01 시큐어 코딩 표준: 외부 환경 분석과 참조 표준(KISA·OWASP·CERT)을 반영해 코딩 규칙을 정하고, 코드 리뷰·정적 분석 적용 절차까지 포함해 승인을 받아요.
2. 05 증적 수집 점검표(No 1~4): 코딩표준 게시, 정적 분석 룰셋, CI 차단 설정, 코드 리뷰 필수 설정을 먼저 갖추고 증적을 수집해요.
3. 03 보안 시험 계획 및 시나리오: 13.1.2 설계 단계 보안 요구사항과 코딩표준 요구사항을 추적표에 모두 올리고, 케이스가 없는 요구사항이 없도록 시나리오를 작성해요.
4. 04 보안 시험 결과서: 시험을 수행해 케이스별 결과와 증적을 남기고, 결함은 조치·재시험 후 운영 반영을 판정해요.
5. 02 시큐어 코딩 준수 점검 결과서: 반기(또는 릴리스)마다 정적 분석·코드 리뷰 이행을 점검하고 위반 사항을 조치해요.

## 3. 심사 대비 체크리스트

- [ ] 시큐어 코딩 표준을 문서로 제정·승인했고, 개발자가 상시 참조할 수 있게 게시하고 제·개정 시 공지했다.
- [ ] 코딩표준에 서버 측 입력값 검증, 입력 데이터 유효성 확인과 안전한 오류 처리, SQL 삽입 방지, 검증되지 않은 URL 리다이렉션 방지, 안전한 세션 관리가 모두 포함되어 있다.
- [ ] 법·제도·규정 등 외부 환경 분석으로 식별한 항목(개인정보 암호화·접근통제 등)이 코딩표준에 반영되어 있다.
- [ ] 운영 반영되는 모든 변경이 코드 리뷰와 정적 분석을 거치도록 형상관리 저장소·CI 파이프라인에 강제 설정되어 있다.
- [ ] 사용자 입력값을 문자열 연결로 SQL에 결합하는 코드가 없고, Prepared Statement 또는 ORM을 사용한다.
- [ ] 분석·설계 과정에서 정의한 보안 요구사항이 빠짐없이 시험 케이스와 매핑되어 있다(추적표 커버리지 100%).
- [ ] 시험 시나리오·체크리스트에 인증(계정 잠금·세션), 접근권한(관리자 기능·테넌트 분리), 입력값 검증, 암호화(저장·전송), 오류 처리가 포함되어 있다.
- [ ] 시험을 실제 수행한 케이스별 결과와 화면 증적이 있고, 실패 케이스는 결함 조치와 재시험 기록이 있다.
- [ ] 전송 구간에 TLS 1.2 이상만 허용되고 SSL v3·TLS 1.0·1.1이 비활성화되어 있음을 시험으로 확인했다.
- [ ] 보안 시험을 통과한 버전만 운영에 반영되며, 미해소 결함을 남길 때는 위험 수용 승인 기록이 있다.
- [ ] 개발자(외부인력 포함)가 시큐어 코딩 교육을 이수했다.

## 4. 관련 산출물(다른 항목)

- 13.1.2 인증 및 암호화 기능: 설계 단계에서 정의한 사용자 인증·암호화 보안 요구사항이 03 시험 계획 추적표의 입력이에요. 시스템 설계서·보안요구사항 정의 절차와 연계해요.
- 12.3.1 암호 정책 수립: 코딩표준 4.8항의 암호 알고리즘·키 길이 기준과 저장 암호화 시험(TC-11) 기준을 암호 정책과 맞춰요.
- 11.1.4 네트워크 암호화: 전송 구간 TLS 시험(TC-12) 증적을 공용으로 활용해요.
- 10.3.2 사용자 인증, 10.3.3 강화된 인증 수단 제공, 10.3.4 패스워드 관리: 인증·계정 잠금·패스워드 규칙의 구현 기준을 따르고, 관련 시험 케이스(TC-01~TC-05)의 기준 값을 일치시켜요.
- 9.1.5 공개서버 보안: 공개서버(웹) 취약점 점검 결과를 시험·결함 조치와 연계해요.
- 7.1.1 법적요구사항 준수: 코딩표준 3.2항의 외부 환경 분석(법·제도·규정)은 법적 요구사항 식별 결과를 활용해요.
- 2.3.2 교육 시행: 개발자 시큐어 코딩 교육 이수 기록을 증적으로 활용해요.
- 2.1.2 주요 직무자 지정 및 감독: 운영 배포·형상관리 권한자(KD-08)의 개발·배포 승인 분리를 시험·배포 절차에 반영해요.

## 5. 양식 작성 규칙

- `{{ }}`로 표시한 자리표시자는 실제 값으로 바꿔요. 표의 빈 칸은 해당 값을 채워요.
- 서명이 필요한 문서는 서명본을 스캔해 보관하고, md 원본에는 서명본 보관 위치를 적어요.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신해요.
- 02·03·04는 점검·릴리스 건마다 문서번호({{SDT-CHK-YYYY-NN}}, {{SDT-TP-YYYY-NN}}, {{SDT-TR-YYYY-NN}})를 새로 부여해 회차별로 보관해요.
- 03 추적표의 요구사항 ID(SR-nn)와 케이스 ID(TC-nn)는 예시예요. 설계서에서 식별한 요구사항에 맞게 추가·삭제하되, 케이스가 없는 요구사항이 남지 않게 해요.
- 시험은 운영과 분리된 환경에서 수행하고, 시험 데이터에 운영 개인정보를 사용하지 않아요.
- 법령 인용은 개인정보의 안전성 확보조치 기준 제6조·제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이에요. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인해요.
