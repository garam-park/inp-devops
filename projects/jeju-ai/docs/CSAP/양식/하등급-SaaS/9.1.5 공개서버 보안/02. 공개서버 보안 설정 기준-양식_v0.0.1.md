> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제7조제4항(인터넷망 구간 송·수신 암호화)과 제9조(악성프로그램 등 방지)(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 공개서버가 개인정보를 송·수신하거나 개인정보처리시스템에 해당하는 경우에 적용하며, 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 개요

- 목적: 01. 공개서버 보안 관리 지침 6항의 보호대책을 가상 서버·컨테이너·PaaS 환경의 공개서버에 실제로 적용하기 위한 설정 기준과 확인 방법을 정한다.
- 적용 범위: 03. 공개서버 네트워크 및 시스템 구성도의 공개서버 목록에 등재된 전체 공개서버
- 적용 시점: 공개서버 신설 전, 소프트웨어·구성 변경 후, 정기 점검 {{반기}} 1회
- 기준 표의 VM은 가상 서버, CT는 관리형 컨테이너 워크로드, PaaS는 관리형 실행 환경(서버리스, 관리형 웹 앱)을 뜻한다. 표기 기준은 다음과 같다.

| 표기 | 의미 |
| --- | --- |
| ○ | 당사가 설정·확인한다. |
| △ | 플랫폼이 제공하는 설정 범위 안에서 당사가 적용한다. 미제공 기능은 비고에 근거를 적는다. |
| 제공자 | IaaS/PaaS 제공자 책임 범위이다. 제공자 문서·인증으로 확인하고 비고에 근거를 적는다. |
| 해당 없음 | 해당 실행 형태에 적용되지 않는다. |

| 계층 | VM(가상 서버) | CT(관리형 컨테이너) | PaaS(관리형 실행 환경) |
| --- | --- | --- | --- |
| 호스트 OS 패치·백신 | 당사 | 관리형 노드는 제공자, 자체 관리 노드는 당사 | 제공자 |
| 컨테이너 런타임·오케스트레이션 제어 영역 | 해당 없음 | 제공자 | 제공자 |
| 워크로드 설정(Pod 보안, 네트워크 정책, 이미지) | 해당 없음 | 당사 | 당사(런타임 설정 범위 내) |
| 웹서버·미들웨어 설정 | 당사 | 당사(이미지 내) | 당사(플랫폼 설정 범위 내) |
| 응용 프로그램·TLS 설정·에러 처리 | 당사 | 당사 | 당사 |

## 3. 설정 기준

### 3.1 A. 서비스별 전용 운영

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| A-1 | 공개서버(그룹)마다 하나의 서비스만 탑재하고, 인증 범위 밖 서비스·내부 업무 시스템·개발·시험 기능을 함께 두지 않는다. | 03 양식 공개서버 목록의 전용 여부, 실행 중 프로세스·컨테이너 목록 | ○ | ○ | ○ |
| A-2 | 운영·개발·시험 환경은 계정(프로젝트) 또는 VPC 단위로 분리하고, 시험용 엔드포인트를 인터넷에 노출하지 않는다. | 환경별 계정·VPC 목록, 공인 IP·도메인 조회 | ○ | ○ | ○ |
| A-3 | 배포 서버는 배포 파일의 무결성 검증 정보(해시·서명)를 함께 제공하고, 업로드 기능은 인증된 관리자만 사용한다. | 배포 페이지, 업로드 경로 인증 설정 | ○ | ○ | ○ |

### 3.2 B. 암호화 통신

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| B-1 | 개인정보를 송·수신하는 모든 구간에 TLS 1.2 이상만 허용하고 SSLv3, TLS 1.0, TLS 1.1을 비활성화한다. | 로드밸런서·웹서버 TLS 정책(예: ssl_protocols TLSv1.2 TLSv1.3), 외부 TLS 스캔 결과 | ○ | ○ | ○ |
| B-2 | 안전한 암호 스위트만 허용하고 RC4, 3DES, NULL, EXPORT, anon 스위트를 제외한다. | ssl_ciphers 설정, TLS 스캔 결과 | ○ | ○ | ○ |
| B-3 | HTTP 요청은 HTTPS로 리다이렉트하고 HSTS 헤더를 설정한다. | 응답 헤더(Strict-Transport-Security), 리다이렉트 응답 코드 | ○ | ○ | ○ |
| B-4 | 인증서는 신뢰할 수 있는 기관에서 발급받고 유효기간을 관리하며 만료 {{30}}일 전에 갱신(또는 자동 갱신)한다. | 인증서 관리 서비스, 만료일 알림 설정 | ○ | ○ | ○ |
| B-5 | 공개서버와 내부 WAS·DB 사이에 개인정보가 이동하면 그 구간도 암호화한다(11.1.4 네트워크 암호화 기준). | WAS·DB 연결 설정의 TLS 옵션 | ○ | ○ | ○ |

### 3.3 C. 접근통제 및 식별·인증

| No | 설정 기준 | 확인 방법 | VM | CT | PaaS |
| --- | --- | --- | --- | --- | --- |
| C-1 | 보안 그룹과 호스트 방화벽(iptables, nftables)은 기본 거부로 설정하고 서비스 포트({{443}})와 승인된 관리 경로만 허용한다. | 보안 그룹 규칙, iptables -L -n 출력 | ○ | ○ | △ |
| C-2 | 컨테이너는 Pod 보안 표준 restricted(또는 PodSecurityPolicy 대체 어드미션 정책)를 적용하여 특권 컨테이너, 호스트 네트워크·PID·경로 마운트, root 실행을 금지한다. | 네임스페이스 pod-security 레이블, 어드미션 정책, securityContext(runAsNonRoot, allowPrivilegeEscalation=false, readOnlyRootFilesystem) | 해당 없음 | ○ | 제공자 |
| C-3 | CNI 네트워크 정책으로 공개 워크로드 네임스페이스의 인그레스·이그레스를 기본 거부하고 필요한 목적지·포트만 허용한다. | NetworkPolicy 목록(default-deny 포함) | 해당 없음 | ○ | 해당 없음 |
| C-4 | 관리자 접속은 접근통제솔루션(배스천, 세션 관리 서비스)을 경유하며, 인터넷에서 SSH(22)·RDP(3389)·컨테이너 API 등 관리 포트로 직접 접속할 수 없다. | 보안 그룹 인바운드 규칙, 외부 포트 스캔 결과 | ○ | ○ | 해당 없음 |
| C-5 | 관리자 계정은 개인별로 발급하고 root·administrator 직접 로그인을 금지하며 sudo 등 권한 상승을 기록한다. | sshd_config(PermitRootLogin no), sudo 로그, IAM 사용자 목록 | ○ | ○ | △ |
| C-6 | 관리자 인증은 패스워드 단독 인증을 금지하고 키 기반 인증과 다중 인증을 적용한다. | sshd_config(PasswordAuthentication no), 접근통제솔루션·IAM 다중 인증 설정 | ○ | ○ | △ |
| C-7 | 미사용 세션은 {{10}}분 후 자동 종료하고 로그인 실패 {{5}}회 시 계정 잠금 또는 지연을 적용한다. | 접근통제솔루션 세션 정책, PAM 설정 | ○ | ○ | △ |
| C-8 | 서비스 계정·인스턴스 역할은 필요한 최소 권한만 부여하고 자격증명을 소스코드·이미지·환경 파일에 평문으로 포함하지 않는다. | IAM 역할 정책, 이미지·저장소 비밀정보 스캔 결과 | ○ | ○ | ○ |
| C-9 | 웹 응용의 관리자 기능(관리 콘솔, 관리 API)은 인터넷에서 접근할 수 없게 하거나 별도 인증과 출발지 IP 제한을 적용한다. | 관리 URL 접근 시험, 웹 방화벽·보안 그룹 규칙 | ○ | ○ | ○ |

### 3.7 G. 정보 노출 방지
