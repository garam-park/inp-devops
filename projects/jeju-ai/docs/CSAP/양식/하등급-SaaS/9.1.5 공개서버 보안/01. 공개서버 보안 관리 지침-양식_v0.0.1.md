> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제6조(접근통제)·제7조(개인정보의 암호화)·제8조(접속기록의 보관 및 점검)·제9조(악성프로그램 등 방지)(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 공개서버가 개인정보처리시스템에 해당하거나 개인정보를 송·수신하는 경우에 적용하며, 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

{{회사명}}은(는) 클라우드컴퓨팅서비스 {{서비스명}}을 제공하기 위해 인터넷에 공개하는 웹서버, API 서버, 배포 서버 등 공개서버가 외부 공격의 1차 대상이 되는 점을 고려하여, 공개서버에 대한 물리적·기술적 보호대책과 운영 절차를 정하고, 공개서버가 침해되더라도 내부 네트워크와 이용 기관 데이터로 침입이 확산되지 않도록 한다.

## 2. 적용 범위

- {{서비스명}} 인증 범위에서 인터넷을 통해 불특정 이용자 또는 이용 기관이 직접 접근할 수 있는 모든 서버, 컨테이너, 관리형 서비스 엔드포인트
- 공개서버를 운영·개발·보호하는 임직원과 외부인력
- 공개서버를 보호하는 보안시스템(침입차단, 웹 방화벽, 백신, 접근통제솔루션, 로그 수집)과 그 운영 업무

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 공개서버 | 인터넷에서 직접 접근 가능한 공인 IP 또는 도메인이 할당된 서버·컨테이너·엔드포인트. 이용자용 웹서버, API 게이트웨이, 이용 기관 포털, 앱·응용프로그램·에이전트를 배포하는 배포 서버, 정적 콘텐츠 서버를 포함한다. |
| DMZ | 인터넷과 내부 네트워크 사이에 두는 완충 영역. 클라우드 환경에서는 인터넷 게이트웨이가 연결된 퍼블릭 서브넷 또는 이에 준하는 논리 영역을 말한다. |
| 내부 네트워크 | 인터넷에서 직접 접근할 수 없는 영역. WAS, DB, 캐시, 내부 관리 시스템이 위치한 프라이빗 서브넷을 말한다. |
| 침입차단시스템 | 출발지·목적지·포트 기준으로 통신을 허용·차단하는 수단. 클라우드 제공자의 보안 그룹, 네트워크 ACL, 관리형 방화벽과 호스트 방화벽(iptables, nftables)을 포함한다. |
| 접근통제솔루션 | 관리자가 공개서버에 접속할 때 경유하도록 강제하여 계정별 인증, 권한 통제, 세션 기록을 수행하는 수단. 배스천 호스트, 제공자의 세션 관리 서비스, 서버 접근제어 솔루션을 포함한다. |
| 접속이력 | 공개서버에 대한 관리자 접속 기록(접속 계정, 일시, 출발지 IP, 수행 명령·행위)과 이용자 접근 기록(웹 접근 로그, 웹 방화벽 로그, 방화벽 로그) |

## 5. 공개서버 식별 및 등록

1. 정보보호 관리자는 다음 기준에 해당하는 자산을 공개서버로 식별하여 03. 공개서버 네트워크 및 시스템 구성도의 공개서버 목록에 등록한다.
   - 공인 IP 또는 인터넷에서 조회되는 도메인이 할당된 가상 서버, 컨테이너 서비스, 로드밸런서 뒤의 서버 그룹
   - 이용자·이용 기관이 접속하는 웹 서비스, API, 포털
   - 앱·응용프로그램·에이전트·업데이트 파일을 배포하는 서버와 저장소 엔드포인트
   - 외부 연계 기관이 호출하는 연계 서버
2. 공개서버는 서비스별 전용으로 운영한다. 하나의 공개서버에 인증 범위 밖 서비스, 개발·시험 기능, 내부 업무 시스템을 함께 두지 않는다.
3. 공개서버를 신설·변경·폐기할 때는 11항의 변경 절차를 따르고, 구성도·공개서버 목록·보안시스템 운영 현황을 {{n}}영업일 이내에 현행화한다.
4. 정보보호 관리자는 {{분기}}마다 클라우드 콘솔의 공인 IP·로드밸런서·DNS 레코드 목록을 조회하여 등록되지 않은 공개서버가 없는지 확인한다.

## 6. 공개서버 보호대책

공개서버를 운영하는 경우 다음 보호대책을 모두 적용하고, 상세 설정 기준과 확인 방법은 02. 공개서버 보안 설정 기준을 따른다.

| No | 보호대책 | 요구사항 | 설정 기준(02 양식) |
| --- | --- | --- | --- |
| 1 | 서비스별 전용 운영 | 공개서버 1대(그룹)에 하나의 서비스만 탑재하고 용도 외 기능을 두지 않는다. | A |
| 2 | 암호화 통신 | 웹서버를 통해 개인정보를 송·수신하는 경우 TLS 1.2 이상만 허용하고 취약한 프로토콜·암호 스위트를 비활성화한다. | B |
| 3 | 접근통제와 식별·인증 | 호스트 방화벽(iptables 등), 보안 그룹, Pod 보안 표준, CNI 네트워크 정책으로 통신을 최소 허용하고, 관리자 접근은 개인별 계정과 다중 인증으로 식별·인증한 뒤 권한을 부여한다. | C |
| 4 | 악성코드 방지와 패치 | 백신·EDR(또는 제공자가 제공하는 악성코드 방지 기능)을 설치하여 최신으로 유지하고, OS·미들웨어·베이스 이미지를 최신 패치 상태로 유지한다. | D |
| 5 | 불필요 서비스·포트 제거 | 서비스에 필요한 프로세스·포트만 활성화하고 관리 포트는 인터넷에 노출하지 않는다. | E |
| 6 | 불필요 소프트웨어 설치 금지 | 컴파일러·개발 도구·스크립트·샘플·실행파일 등 서비스에 불필요한 소프트웨어를 설치하지 않고, 설치는 승인 절차를 거친다. | F |
| 7 | 정보 노출 방지 | 테스트·기본·샘플 페이지를 제거하고, 에러 처리에서 서버 버전·스택 트레이스·내부 경로 등 시스템 정보가 노출되지 않게 한다. | G |
| 8 | 접속이력 저장 | 관리자 접속 로그와 웹 접근 로그를 생성하여 중앙 로그 저장소로 전송·보관한다. | H |

## 7. DMZ 배치 및 접근통제

1. 공개서버는 내부 네트워크와 분리된 DMZ(퍼블릭 서브넷)에만 배치한다. WAS, DB, 캐시, 내부 관리 시스템은 인터넷 게이트웨이 경로가 없는 프라이빗 서브넷에 배치하고 공인 IP를 할당하지 않는다.
2. 인터넷에서 공개서버로 향하는 통신은 로드밸런서 또는 웹 방화벽을 경유하게 하고, 공개서버로 유입되는 통신은 서비스 포트({{443}})만 허용한다.
3. 공개서버가 침해되더라도 내부 네트워크로 침입할 수 없도록 DMZ에서 내부 네트워크로 향하는 통신은 기본 거부하고, 다음 조건을 모두 충족하는 경우에만 허용한다.
   - 출발지를 해당 공개서버(보안 그룹 또는 IP)로, 목적지를 특정 WAS·DB 인스턴스로, 포트를 해당 서비스 포트로 한정한다.
   - 공개서버에서 DB로 직접 접속하지 않고 WAS 계층을 경유한다. 불가피하면 사유와 보완 통제를 03 양식의 통신 허용 매트릭스에 기록한다.
   - 허용 규칙마다 업무 목적, 등록일, 승인 근거를 기록한다.
4. 공개서버에서 관리망(배스천, 로그 저장소 관리 포트 등)으로 향하는 통신과 공개서버 간 불필요한 통신은 차단한다. 공개서버에서 인터넷으로 나가는 통신은 패치·업데이트·외부 API 호출 등 필요한 목적지로 한정한다.
5. 침입차단시스템(보안 그룹, 네트워크 ACL, 방화벽)의 정책은 서비스를 위한 최소 서비스만 허용하도록 관리한다. 전체 허용(any) 규칙을 두지 않으며 임시 규칙에는 만료일을 정한다.
6. 정보보호 관리자는 {{분기}}마다 침입차단 정책을 검토하여 불필요한 규칙을 삭제하고, 검토 결과를 04. 공개서버 보안시스템 운영 현황에 기록한다.
7. 공개서버(DMZ)에는 개인정보와 고유식별정보를 저장하지 않는다. 처리 과정에서 임시 저장이 불가피하면 암호화하고(안전성 확보조치 기준 제7조제3항제1호 참고) 보관 기간을 최소화한다.

## 8. 공개서버 접근권한 관리

1. 공개서버에 대한 관리자 접근(SSH, RDP, 콘솔, 컨테이너 exec 등)은 접근통제솔루션을 경유해서만 허용하고, 인터넷에서 관리 포트로 직접 접속하는 경로를 두지 않는다.
2. 접근권한은 업무상 반드시 필요한 인원에게만 부여한다. 다음 조건을 모두 충족해야 한다.
   - 2.1.2 주요 직무자 목록에 공개서버 운영 관련 직무(서버·클라우드 인프라 운영, 응용 배포 등)로 등재되어 있다.
   - 담당 업무에 해당 공개서버 접근이 필요함을 부서장이 확인하고 정보보호 관리자가 검토했다.
   - 개인별 계정을 사용하며 공용 계정·공용 키를 사용하지 않는다.
   - 다중 인증을 적용한다.
3. 접근통제솔루션의 권한은 서버 단위·권한 수준(관리자, 운영자, 조회) 단위로 최소 부여하고, 부서·그룹 단위 일괄 부여를 하지 않는다.
4. 퇴직, 인사이동, 업무 변경, 외부인력 계약 종료 시 지체 없이(내부 기준: 당일) 권한을 회수한다.
5. 정보보호 관리자는 {{분기}}마다 접근통제솔루션에 등록된 전체 사용자·권한을 04. 공개서버 보안시스템 운영 현황 5항의 접근권한 검토 기록으로 검토하여 업무 필요성이 없는 권한을 회수한다. 검토 시 2.1.2 주요 직무자 목록과 인사 현황과 대조한다.
6. 긴급 장애 조치 등으로 임시 권한이 필요하면 정보보호 최고책임자 또는 정보보호 관리자의 승인을 받아 만료일이 있는 권한을 부여하고, 종료 후 즉시 회수한다.

## 9. 접속이력 저장 및 점검

### 9.1 저장

모든 공개서버는 다음 접속이력을 생성하고 중앙 로그 저장소({{로그 시스템명}})로 전송하여 보관한다. 공개서버 로컬에만 로그를 두지 않는다.

| 로그 유형 | 필수 기록 항목 | 생성 위치 |
| --- | --- | --- |
| 관리자 접속 로그 | 계정, 접속·종료 일시, 출발지 IP, 인증 성공·실패, 수행 명령 또는 세션 기록 | 접근통제솔루션, OS 인증 로그, 컨테이너 exec 감사 로그 |
| 웹 접근 로그 | 일시, 출발지 IP, 요청 URL·메서드, 응답 코드, User-Agent | 웹서버·로드밸런서 접근 로그 |
| 웹 방화벽 로그 | 일시, 출발지 IP, 탐지 규칙, 차단·탐지 여부 | 웹 방화벽 |
| 침입차단 로그 | 허용·차단된 통신의 출발지·목적지·포트 | 방화벽, 흐름 로그 |
| 설정 변경 로그 | 보안 그룹·방화벽·인스턴스 설정 변경의 주체·일시·내용 | 클라우드 감사 로그 |

- 보관 기간은 최소 {{1년}}으로 한다. 공개서버가 개인정보처리시스템에 해당하면 개인정보취급자 접속기록을 1년 이상, 5만명 이상 정보주체의 개인정보 또는 고유식별정보·민감정보를 처리하면 2년 이상 보관한다(안전성 확보조치 기준 제8조제1항).
- 접속이력이 위·변조·삭제되지 않도록 로그 저장소의 삭제·수정 권한을 정보보호 담당자로 제한하고, 변경 불가 저장 옵션 또는 별도 백업을 적용한다(같은 기준 제8조제3항).
- 공개서버는 NTP로 시간을 동기화하여 로그 시각의 정확성을 유지한다.

### 9.2 점검

- 정보보호 담당자는 공개서버 접속이력의 적정성을 **월 1회 이상** 점검하고 결과를 04. 공개서버 보안시스템 운영 현황 7항의 접속이력 점검 기록에 남긴다. 이 주기는 본 지침이 정한 접근통제 절차상의 점검 주기이며, 위험평가 결과에 따라 단축할 수 있다.
- 점검 항목은 최소 다음을 포함한다.
  - 접근권한이 없는 계정 또는 회수된 계정의 접속
  - 접근통제솔루션을 경유하지 않은 직접 접속
  - 업무 시간 외 접속, 비인가 출발지 IP 접속, 다수 인증 실패 후 성공
  - root 등 관리자 계정 직접 로그인, 설정 변경·계정 생성 명령
  - 웹 방화벽·침입차단 로그의 차단 급증, 스캔·관리 URL 접근 시도
- 이상 접속이 확인되면 담당자 확인으로 정상 사유를 검증하고, 침해가 의심되면 5.1.1 침해사고 대응 절차에 따라 보고·대응한다.
- 점검자와 확인자는 분리한다. 점검은 정보보호 담당자가, 확인은 정보보호 관리자가 수행한다.

## 10. 취약점 점검 및 조치

- 공개서버의 OS, 미들웨어, 응용 프로그램, 웹서비스에 대한 취약점 점검을 {{연 1회}} 이상 정기적으로 수행하고, 공개서버 신설·주요 변경·중대 취약점 공표 시 수시로 수행한다.
- 웹서버·API는 OWASP Top 10 등 웹 응용프로그램 취약점 점검을 포함한다.
- 발견된 취약점은 위험도별 조치 기한(05. 공개서버 취약점 점검 및 조치 현황 2항) 안에 조치하고 재점검으로 해소를 확인한다. 기한 내 조치가 불가하면 위험 수용 사유와 보완 통제를 정보보호 최고책임자 승인으로 기록한다.
- 점검 계획, 결과, 조치 이력은 05. 공개서버 취약점 점검 및 조치 현황에 기록한다.
