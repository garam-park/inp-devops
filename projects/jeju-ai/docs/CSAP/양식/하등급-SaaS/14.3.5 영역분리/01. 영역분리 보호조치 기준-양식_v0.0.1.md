## 1. 목적

{{회사명}}은(는) 국가기관용 클라우드컴퓨팅서비스 {{서비스명}}을 일반 이용자용(민간) 클라우드컴퓨팅서비스와 영역분리하여 데이터 및 프로세스 등의 간섭 없이 운영하고, 국가정보원과 이용기관(국가기관등)의 보안관제·사고조사·예방 보안활동 유지를 위한 제반환경을 제공한다. 영역분리를 훼손하여 데이터에 접근할 수 있는 취약점을 방지·완화·제거하고, 비인가 접근을 모니터링하기 위한 기준을 정한다.

## 2. 적용 범위

- {{서비스명}}(하등급 SaaS)의 국가기관용 서비스 제공에 사용되는 모든 클라우드 자원(계정, VPC, 서버·컨테이너, DB, 스토리지, 백업, 로그)과 응용·데이터 계층
- 당사가 함께 제공하는 일반 이용자용(민간) 서비스의 자원 중 국가기관용 서비스 영역과의 분리·통제에 관련된 부분
- 영역분리 구성을 설계·운영·변경·점검하는 임직원과 외부인력

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 공공기관용 영역 | 국가기관용 클라우드컴퓨팅서비스를 제공하는 영역. IaaS/PaaS 제공자의 공공기관용 영역(공공 클라우드 존 등) 위에 당사가 구성한 계정·VPC({{계정/VPC-A}})와 그 안의 자원 전체 |

| 영역분리 | 공공기관용 영역과 민간용 영역이 데이터·프로세스 등의 간섭 없이 상호 접근할 수 없도록 물리적 또는 논리적으로 분리하는 것 |
| 논리적 분리 | 계정(프로젝트), VPC, 보안 그룹·네트워크 ACL, 가상화 기술 등으로 하나의 물리 인프라 위에서 영역을 나누는 방식 |
| 영역분리 훼손 취약점 | 영역 간 분리 설정을 우회·훼손하여 다른 영역의 데이터에 접근할 수 있게 하는 설정 오류·결함(미승인 피어링, 교차 IAM 권한, 공용 저장소, 테넌트 격리 결함 등) |
| 비인가 접근 | 승인된 접근 경로·권한에 따르지 않은 영역 자원 접근 또는 영역 간 접근 시도 |
| 제반환경 | 국가정보원과 이용기관이 보안관제, 사고조사, 예방 보안활동을 수행하는 데 필요한 환경(로그·자료 제공, 연계 환경, 협조 체계 등) |

## 5. 영역분리 구성 기준

### 5.1 분리 방식

1. 국가기관용 서비스와 일반 이용자용 서비스는 물리적 또는 논리적으로 영역을 분리한다. 당사가 적용한 방식: {{물리적(별도 인프라) / 논리적(제공자 공공기관용 영역 + 계정·VPC 분리)}}
2. 논리적 분리를 적용하는 경우 다음 계층의 분리를 모두 유지한다. 각 계층의 설정 값과 구성은 14.2.1 양식 02. 네트워크 구성도 3항과 동일하게 관리한다.

| 분리 계층 | 적용 기준 |
| --- | --- |
| 인프라 영역 | 공공기관용 자원은 제공자의 공공기관용 영역(공공 클라우드 존 등)에만 생성한다 |
| 계정 | 공공용·민간용 클라우드 계정(프로젝트)을 분리하고, 계정 간 교차 IAM 권한(역할 위임 등)을 두지 않는다 |
| 네트워크 | VPC(가상 네트워크)를 분리하고, 영역 간 피어링·라우팅·VPN 터널을 두지 않는다 |
| 트래픽 통제 | 보안 그룹·네트워크 ACL로 영역 간 통신을 차단한다(기본 거부) |
| 데이터 | DB·스토리지·백업·로그 저장소를 영역별로 분리하고, 영역 간 공용 저장소를 두지 않는다 |
| 응용 | 서비스 도메인·인증 체계·관리자 기능을 영역별로 분리한다 |

- 공공기관용 영역 내부의 네트워크 영역 구분(DMZ, 내부 - 앱, 내부 - DB, 관리망, 개발·시험)과 영역 간 접근통제는 11.1.5 네트워크 분리 산출물을 따른다.

### 5.2 영역분리 유지 원칙

1. 공공기관용 영역 안에 민간용 서비스의 자산, 데이터, 가상자산(가상 서버, 컨테이너, 스토리지 등)을 두지 않는다. 반대로 민간용 영역에 국가기관등의 데이터를 저장·처리하지 않는다.
2. 자원을 새로 생성할 때는 배치 영역(공공/민간)을 먼저 지정하고, 소속 영역을 식별할 수 있도록 명명 규칙·태그({{태그 키}})를 적용한다.
3. 영역 간에 불가피한 공용 구성요소(배포 파이프라인, 형상관리 저장소 등)가 있으면 목록으로 관리하고, 공용 구성요소를 통해 데이터·프로세스 간섭이 발생하지 않도록 통제(자격증명 분리, 단방향 배포, 접근기록 검토)를 적용한다: {{공용 구성요소 목록과 통제}}
4. 영역분리 구성(계정, VPC, 보안 그룹, 공용 구성요소)을 변경할 때는 정보보호 관리자의 사전 검토를 거치고, 변경 후 14.2.1 양식 02. 네트워크 구성도를 현행화한다.
5. 영역분리 유지 여부는 양식 02. 영역분리 적정성 점검서로 분기 1회 이상, 그리고 자원·구조 변경 시 점검한다.

## 6. 영역분리 훼손 취약점의 방지·완화·제거

1. 방지(설계·구성 단계)
   - 영역 간 통신·권한은 기본 거부로 설계하고, 5.1항의 분리 계층별 기준을 벗어나는 구성을 금지한다.
   - 공공기관용 영역의 IAM 권한은 최소 권한으로 부여하고, 민간용 영역 담당자에게 공공기관용 영역 권한을 부여하지 않는다. 접근 권한 보유자는 2.1.2 주요 직무자 목록으로 관리한다.
   - SaaS 응용의 테넌트 격리(인가 로직, 테넌트 식별자 검증)는 릴리스 전 시험 항목에 포함한다(13.2.1 연계).
2. 점검(운영 단계)
   - 정기 취약점 점검에 영역분리 훼손 취약점 항목(미승인 피어링·라우팅, 교차 IAM 권한, 공용 저장소 접근, 테넌트 격리 결함, 영역 간 통신 차단 우회)을 포함하여 연 {{n}}회 이상 점검한다.
   - 점검 결과는 양식 02. 영역분리 적정성 점검서와 취약점 점검 결과서에 기록한다.
3. 조치
   - 발견된 취약점은 위험도에 따라 조치 기한을 정해 제거하고, 즉시 제거할 수 없으면 보완 통제(추가 차단 규칙, 모니터링 강화)로 완화한 뒤 제거 계획을 관리한다.
   - 취약점을 통한 실제 접근 흔적이 확인되면 5.1.1 침해사고 대응 절차에 따라 처리한다.

## 7. 비인가 접근 모니터링

1. 다음 대상을 모니터링한다.
   - 민간용 영역(또는 외부)에서 공공기관용 영역으로의 통신·접근 시도
   - 공공기관용 영역 자원에 대한 비인가 콘솔·IAM 접근과 권한 변경
   - 영역 간 피어링·라우팅·터널 등 우회 경로의 생성·변경
   - 승인된 관리자 접근 경로(VPN·배스천)를 거치지 않은 접근 시도
2. 모니터링 수단은 흐름 로그, 클라우드 감사 로그, 보안 그룹·IAM 변경 알림 규칙으로 하고, 탐지 시 정보보호 담당자에게 실시간 통보되도록 구성한다.
3. 정보보호 담당자는 월 1회 이상 모니터링 결과를 검토하고 양식 03. 비인가 접근 모니터링 결과서에 기록한다. 비인가 접근으로 판정되면 5.1.1 침해사고 대응 절차와 5.2.1 침해사고 보고 절차에 따라 처리한다.
4. 모니터링에 사용하는 로그의 수집·보관은 10.1.2 접근기록 관리 산출물을 따른다.

## 8. 보안관제·사고조사·예방활동 제반환경 제공

1. 공공기관용 영역은 민간용 영역과 분리된 상태에서 국가정보원과 이용기관의 보안관제, 사고조사, 예방 보안활동 등 사이버위협 대응활동을 유지할 수 있도록 구성한다. 보안관제 연계 환경의 구성·운영은 14.3.2 보안관제 제반환경 지원 산출물을 따른다.
2. 국가정보원 또는 이용기관이 사고조사·예방활동을 요청하면 다음 절차로 대응한다.

| 단계 | 담당 | 내용 | 기한(내부 기준) |
| --- | --- | --- | --- |
| 1. 접수 | {{대응 창구 부서}} | 요청 기관, 요청 내용, 대상 범위 확인 후 정보보호 최고책임자 보고 | 접수 즉시 |
| 2. 범위 확인 | 정보보호 관리자 | 요청 대상이 공공기관용 영역·해당 이용기관 범위에 한정되는지 확인 | {{n}}영업일 이내 |
| 3. 환경·자료 제공 | 정보보호 담당자, 인프라 담당 | 로그·구성 자료 제공, 조사용 접근 환경 제공, 필요 시 제공자 협조 요청 | 협의한 기한 |
| 4. 기록 | 정보보호 관리자 | 요청·제공 내역을 양식 04. 보안관제 및 예방 활동 결과보고서 5항에 기록 | 대응 종료 후 {{n}}영업일 이내 |

- 사고조사·예방활동 지원 과정에서 다른 이용기관의 데이터나 민간용 영역의 데이터가 함께 제공되지 않도록 제공 범위를 확인한다.
- 예방 보안활동(취약점 점검, 모의훈련 등)에 대한 협조 요청도 같은 절차로 대응한다.

## 9. 이용자 자료 제출

1. 클라우드서비스를 이용하는 이용자(이용기관)가 영역분리(물리적 또는 논리적) 방식과 영역분리를 위한 보호조치에 대한 자료를 요청하면 제출한다.
2. 제출 대상 자료: 본 기준, 영역분리 구성 자료(14.2.1 양식 02. 네트워크 구성도의 심사 제출본 수준), 최근 양식 02. 영역분리 적정성 점검서 요약, 제공자 CSAP 인증 확인 자료
3. 제출 자료에는 다른 이용기관의 정보, 실제 자격증명, 필요 이상의 상세 설정 값을 포함하지 않는다. 제출 전에 정보보호 관리자가 범위를 검토·승인한다.
