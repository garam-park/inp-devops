> [!info] 법령 기준
> 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 같은 법 시행령 제30조제1항제5호(대통령령 제36121호, 2026. 8. 20. 시행), 개인정보의 안전성 확보조치 기준 제2조제3호·제4조·제5조제3항·제8조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

본 문서는 {{회사명}} 접근통제관리지침 중 접근기록 관리에 해당하는 절이다. 접근통제관리지침에 이미 해당 절이 있으면 그 내용을 본 양식의 항목과 대조하여 빠진 항목(특히 6.1항의 검토 주기·대상·방법·수행자·확인자와 6.4항의 개인정보 다운로드 검토 기준)을 보완한다. 개인정보처리시스템에 관한 사항은 개인정보 내부 관리계획의 접속기록 보관·점검 사항과 일치하게 유지한다.

## 1. 목적

양식 01. 정보보호 정책서 접근기록 관리 조항에 따라, 접근기록 생성 대상의 정의, 기록 항목, 보관·보호, 검토, 이상 발견 시 조치의 세부 절차를 정한다.

## 2. 적용 범위

- {{서비스명}}(하등급 SaaS) 인증 범위 내 시스템과 그 접근기록
- 접근기록 생성·전송·보관·검토·조치에 관여하는 정보보호 조직, 시스템 담당자, 개발 부서, 접근기록 저장소 관리자, 외부인력 감독자
- 제공자 책임 영역(물리 시설, 하이퍼바이저, 제공자 내부 관리 콘솔)은 제외하며, 제공자 인증·계약으로 확인한다.

## 3. 접근기록 생성 대상 정의

### 3.1 대상 선정 기준

서비스와 업무 중요도를 고려하여 다음 유형에 해당하는 시스템은 접근기록 생성 대상으로 정의한다. 시스템에 로그인한 접속 기록과 접속 후 수행한 행위 기록을 모두 생성하는 시스템을 포함한다.

| 시스템 유형 | 대상 포함 기준 | 대상 예시 | 생성해야 하는 접근기록 |
| --- | --- | --- | --- |
| 운영 서버 | 서비스를 구성하는 가상 서버·컨테이너 노드 전부 | 웹·앱 서버, 배치 서버, 컨테이너 클러스터 노드 | 운영체제 로그인(SSH 등) 성공·실패, sudo·루트 전환, 명령 실행 |
| 관리 서버 | 운영 서버·DB에 접근하는 경유 서버 | 배스천 호스트, 점프 서버, 원격 접속 게이트웨이 | 로그인, 세션 기록, 실행 명령, 접속 대상 |
| DBMS | 개인정보·이용 기관 데이터를 저장하는 모든 DB | 운영 DB(관리형 DB 포함), 캐시·검색 저장소 중 개인정보 저장분 | DB 계정 접속, 실행 문장(개인정보 테이블 조회·변경·삭제, 대량 조회), 계정·권한 변경 |
| 응용 서비스 | 이용자·이용 기관 관리자가 접속하는 기능 중 개인정보·이용 기관 데이터를 처리하는 기능 | {{서비스명}} 웹·모바일·API | 로그인 성공·실패, 개인정보 조회·입력·변경·삭제·다운로드·출력, 이용 기관 데이터 접근 |
| API·클라우드 콘솔 | 당사 클라우드 계정의 콘솔·CLI·API 호출 | IaaS/PaaS 콘솔, IAM, CLI·SDK 호출 | 콘솔 로그인, 루트 사용, IAM 사용자·역할·정책 변경, 자원 생성·변경·삭제, 로그 설정 변경 |
| 클라우드 관리 포털 | 당사가 이용 기관·이용자를 관리하는 포털 | 서비스 관리 포털(super admin), 이용 기관 관리자 계정 발급 기능 | 관리자 로그인, 관리 기능 사용(계정 발급·초기화, 권한 설정, 데이터 열람) |
| 정보보호시스템 | 보안 정책·로그를 관리하는 시스템 | 접근기록 저장소, 웹 방화벽, 접근제어 솔루션, 백신·EDR 관리 콘솔 | 관리자 로그인, 정책 변경, 로그 삭제·보존 설정 변경 |
| 개발·배포 환경 | 운영 배포에 영향을 주는 시스템 | 형상관리 저장소, CI/CD, 이미지 저장소 | 관리자 로그인, 권한 변경, 운영 배포 실행·승인 |
| 백업 시스템 | 개인정보·이용 기관 데이터의 백업 저장소 | 백업 서비스, 스냅샷 저장소 | 접근, 복원, 삭제 |

### 3.2 중요도 판단

| 중요도 | 기준 | 접근기록 생성 범위 | 검토 기본 주기 |
| --- | --- | --- | --- |
| 상 | 개인정보처리시스템, 이용 기관 데이터 저장·처리, 클라우드 콘솔·IAM, 서비스 관리 포털, 접근기록 저장소 | 필수(접속 기록 + 행위 기록) | 월 1회 이상, 고위험 이벤트는 실시간 알림 |
| 중 | 운영에 필요하나 개인정보·이용 기관 데이터를 직접 저장하지 않는 서버·도구 | 필수(접속 기록 + 관리자 행위 기록) | 월 1회 이상 |
| 하 | 인증 범위 내이지만 중요 정보에 접근할 수 없는 시스템 | 접속 기록 | {{분기}} 1회 이상 |

- 중요도 판단 근거는 정보자산 목록의 기밀성·무결성·가용성 등급과 위험평가 결과를 따르고, 양식 03. 접근기록 생성 대상 목록에 기록한다.
- 중요도 하로 판단하여 행위 기록을 생략하는 시스템은 사유와 승인자를 양식 03의 제외·완화 항에 기록한다.

### 3.3 목록 관리

1. 시스템 담당자는 신규 시스템 도입, 시스템 변경(개인정보 처리 시작, 관리 기능 추가 등), 폐기 시 정보보호 관리자에게 통보한다.
2. 정보보호 관리자는 3.1·3.2의 기준으로 대상 여부와 중요도를 판단하고 양식 03에 등재·변경·삭제한다.
3. 반기 1회 이상 정보자산 목록, 클라우드 자원 목록, 개인정보처리시스템 현황(2.1.2 개인정보취급자 목록 1항)과 대조하여 누락된 시스템이 없는지 확인한다.
4. 목록의 각 시스템은 접속 기록과 행위 기록의 정확한 생성 위치(로그 파일 경로, 로그 서비스명, 감사 테이블명 등)를 함께 기록한다.

### 3.4 생성 위치 파악

운영체제·DBMS 등 상용 프로그램의 접근기록은 프로그램별로 생성 위치와 기본 설정이 다르므로, 시스템 담당자는 다음 예시를 참고하여 실제 위치를 확인하고 필요한 로그 생성 설정을 활성화한다.

| 구분 | 접속 기록 위치(예시) | 행위 기록 위치(예시) | 활성화가 필요한 설정(예시) |
| --- | --- | --- | --- |
| Linux 운영체제 | {{/var/log/auth.log 또는 /var/log/secure}}, journald의 sshd 로그 | auditd 감사 로그(명령 실행·권한 상승), sudo 로그 | auditd 규칙(명령 실행·권한 상승·주요 파일 변경), 셸 히스토리 시각 기록, 로그 전송 에이전트 |
| Windows 운영체제 | 보안 이벤트 로그(로그온·로그오프 이벤트) | 프로세스 생성·PowerShell 로그 | 감사 정책(로그온, 계정 관리, 프로세스 추적), 로그 전송 에이전트 |
| 관계형 DBMS(직접 운영) | 감사 로그의 접속 이벤트, 일반 로그 | 감사 로그(감사 플러그인·확장)의 실행 문장 | 감사 기능 활성화, 개인정보 테이블 대상 문장 기록, 대량 조회 임계치 |
| 관리형 DB(PaaS) | 제공자 DB 감사 로그 옵션의 접속 이벤트 | 같은 옵션의 실행 문장 | 감사 로그 옵션 활성화, 로그 서비스로 내보내기 |
| 웹·응용 서버 | 접근 로그(요청 IP·시각·URI·계정 식별자) | 응용 감사 로그(테이블 또는 로그 파일) | 감사 로그 기능 구현(4.1항 필수 항목), 접근 로그에 계정 식별자 포함 |
| 클라우드 콘솔·API | 제공자 감사 로그 서비스의 콘솔 로그인 이벤트 | 같은 서비스의 관리 이벤트(자원·IAM 변경) | 모든 리전 기록, 관리 이벤트 전체 기록, 로그 파일 무결성 검증, 저장소 전달 |
| 서비스 관리 포털 | 포털 로그인 로그 | 관리 기능 사용 감사 로그 | 관리 기능별 감사 로그 구현 |
| 정보보호시스템 | 관리 콘솔 로그인 로그 | 정책 변경·설정 변경 로그 | 시스템 로그 외부 전송 |

## 4. 접근기록 항목

### 4.1 필수 기록 항목

| 항목 | 기록 내용 | 기록 기준 |
| --- | --- | --- |
| 접근 주체 | 계정 ID(개인별 식별 가능), 역할·권한, 외부인력·이용 기관 구분 | 공용 계정을 사용하면 실제 사용자를 식별할 수 있는 추가 기록(배스천 세션, 인증 연계)을 남긴다 |
| 접근 시간 | 접속·행위 발생 일시(초 단위 이상), 시간대 | 모든 시스템을 표준 시각원에 동기화하고 시간대 표기를 {{KST}}로 통일한다 |
| 접근 IP 또는 MAC | 접속 원 IP(프록시·로드밸런서 경유 시 원 IP 헤더 포함), 필요 시 MAC·단말 식별자 | 내부망 NAT 뒤의 접근은 원 IP를 식별할 수 있게 한다 |
| 수행업무 | 접근한 데이터(테이블·기능·파일), 행위 유형(조회·입력·변경·삭제·다운로드·출력·명령 실행·설정 변경·권한 변경), 처리 건수 | 개인정보 다운로드·출력과 대량 조회는 별도 식별자로 표시한다 |
| 처리한 정보주체 정보 | 처리 대상 정보주체를 식별할 수 있는 정보(회원 번호·식별자, 또는 검색 조건과 대상 건수) | 개인정보처리시스템에 적용하며, 정보주체 정보 자체를 로그에 과도하게 복제하지 않고 식별자·조건으로 기록한다 |

- 접속자의 계정·일시·IP만 남기고 수행업무나 처리한 정보주체 정보를 남기지 않는 개인정보처리시스템은 부적합이다. 응용 서비스와 관리 포털은 개인정보 처리 기능마다 위 다섯 항목을 남기는 감사 로그를 구현한다.
- 상용 프로그램이 다섯 항목을 모두 남기지 못하면 접근제어 솔루션, 배스천 세션 기록, 응용 감사 로그를 조합하여 보완하고, 보완 방법을 양식 03의 기록 항목 충족 현황에 적는다.

### 4.2 행위 기록 필수 범위

| 대상 | 반드시 기록하는 행위 |
| --- | --- |
| 운영 서버·관리 서버 | 로그인 성공·실패, sudo·루트 전환, 실행 명령, 주요 설정 파일 변경, 계정·권한 변경, 로그 설정 변경 |
| DBMS | 접속 성공·실패, 개인정보·이용 기관 데이터 테이블에 대한 조회·변경·삭제 문장, 대량 조회(임계치 {{n}}건 이상), 계정·권한 변경, 스키마 변경, 백업·복원 |
| 응용 서비스·관리 포털 | 로그인 성공·실패, 개인정보 조회·입력·변경·삭제·다운로드·출력, 이용 기관 데이터 열람, 관리자 기능 사용(계정 발급·초기화, 권한 설정), 설정 변경 |
| 클라우드 콘솔·API | 콘솔 로그인, 루트 계정 사용, IAM 사용자·역할·정책·키 변경, 자원 생성·변경·삭제, 보안 그룹 변경, 로그·감사 설정 변경, 저장소 정책 변경 |
| 접근기록 저장소 | 저장소 접근, 검색·내보내기, 보존 정책·삭제 설정 변경, 삭제 시도 |
| 개발·배포 환경 | 관리자 로그인, 저장소 권한 변경, 운영 배포 승인·실행 |

### 4.3 시각 동기화

- 시스템마다 적용되는 기준 중 가장 긴 기간을 적용하고 양식 03에 기록한다.

- 정보주체 수, 처리 항목(고유식별정보·민감정보) 변동을 반기 1회 확인하여 보관 기간을 재판단한다.

### 5.2 별도 보관

1. 대상 시스템에서 생성된 접근기록은 생성 후 {{n}}분 이내에 접근기록 저장소로 전송하여 원본 시스템과 분리 보관한다.
2. 원본 시스템 관리자(서버·DB·응용·클라우드 담당자)는 접근기록 저장소의 기록을 수정·삭제할 수 있는 권한을 갖지 않는다.
3. 전송이 중단되면 {{n}}분 이내에 접근기록 저장소 관리자와 정보보호 담당자에게 알림이 가도록 설정하고, 전송 중단 구간(로그 공백)은 월별 검토에서 확인한다.
4. 접근기록 저장소와 백업은 국내 리전·위치에 둔다.

### 5.4 백업

- 접근기록 저장소를 {{일 1회}} 이상 별도 위치(다른 계정·리전·저장소)에 백업하고, 백업 보관 기간은 5.1의 보관 기간 이상으로 한다.
- 백업 성공 여부를 매일 확인하고, {{반기}} 1회 이상 복원 시험으로 조회 가능함을 확인한다.
- 백업본에도 5.3의 삭제 제한과 접근 통제를 적용한다.

### 5.5 용량 관리

1. 시스템별 일 평균 접근기록 생성량을 측정하고, 필요 용량을 "일 평균 생성량 × 보관 일수 × 여유율 {{1.5}}"로 산정하여 양식 03에 기록한다.
2. 저장소 사용률 임계치를 {{70}}%(주의), {{85}}%(경고)로 정하고 6.2.1 성능 및 용량 관리의 모니터링 대상에 포함한다. 경고 도달 시 {{n}}영업일 이내에 용량을 증설한다.
3. 월별 검토 시 시스템별로 저장소에 남아 있는 가장 오래된 접근기록의 일자를 확인하여 실측 보관 기간이 5.1의 기준을 충족하는지 기록한다. 용량 부족으로 기준보다 짧은 기간만 남아 있으면 즉시 용량을 증설하고 원인과 조치를 양식 04에 기록한다.
4. 대상 시스템 추가, 행위 기록 범위 확대, 보관 기간 상향 시 필요 용량을 재산정한다.

### 5.6 접근기록 내 개인정보 보호

- 접근기록 저장소의 열람·검색 권한은 검토 수행자, 확인자, 접근기록 저장소 관리자, 사고 조사 담당자로 제한하고 권한자를 양식 03에 기록한다.
- 접근기록에 개인정보(정보주체 식별자, 이용자 정보)가 포함되므로 저장소 접근에 다중 인증을 적용하고, 심사·조사 목적으로 제출할 때는 필요 최소한으로 마스킹한다.

### 6.5 감사기록 및 모니터링과의 연계

접근기록 검토는 7.2.2 감사기록 및 모니터링의 점검항목(감사기록 대상·항목, 모니터링, 이상징후 대응)과 함께 수행한다. 보안 이벤트·이상징후 모니터링에서 탐지된 건은 접근기록으로 상세 행위를 확인하고, 접근기록 검토에서 발견한 이상은 모니터링 규칙에 반영한다.

### 6.6 검토 기록

- 검토 결과는 양식 04. 접근기록 검토 기록에 기록하고 검토 수행자·확인자가 서명한다. 검토에 사용한 리포트·조회 결과 원본은 양식 05에 따라 함께 보관한다.
- 검토 기록과 원본은 {{3}}년 이상 보관한다.
- 정보보호 관리자는 검토 결과를 {{분기}}마다 정보보호 최고책임자에게 보고하고, 중대한 이상은 즉시 보고한다.

## 7. 이상 징후 발견 시 조치

```mermaid
flowchart LR
    A[이상 징후 검출] --> B{판정}
    B -- 정상 소명 --> C[정상 처리 기록]
    B -- 오용·규정 위반 --> D[권한 축소·회수, 재교육, 인사 조치]
    B -- 침해 의심 --> E[계정 잠금·접근 차단, 증적 보존]
    E --> F[침해사고 대응 절차 5.1.1]
    F --> G[보고·신고·통지 5.2.1]
    C --> H[양식 04 기록, 재발 방지]
    D --> H
    G --> H
```

| 단계 | 담당 | 내용 | 시한 |
| --- | --- | --- | --- |
| 1. 확인·소명 요청 | 검토 수행자 | 해당 계정 소유자·부서장에게 접근 사유와 작업 근거를 요청하고, 관련 접근기록을 보존한다 | 검출 후 {{1}}영업일 이내 |
| 2. 긴급 조치 | 정보보호 관리자 | 침해 의심, 퇴직자 계정 접근, 미등재 계정 접근은 소명과 병행하여 계정 잠금·권한 회수·접근 차단을 한다 | 즉시 |
| 3. 판정 | 정보보호 관리자(개인정보 관련은 개인정보 보호책임자 참여) | 정상·오용(규정 위반)·침해 의심으로 판정하고 근거를 기록한다 | 소명 접수 후 {{2}}영업일 이내 |
| 4. 침해사고 연계 | 정보보호 최고책임자 | 침해 의심 건은 5.1.1 침해사고 대응 절차로 전환하고, 이용자 정보 유출이 의심되면 5.2.1 침해사고 보고 절차에 따라 신고·통지를 판단한다 | 판정 즉시 |
| 5. 이용 기관 통지 | 정보보호 최고책임자 | 이용 기관 데이터·계정에 영향이 있으면 해당 기관에 통지한다 | 판정 후 지체 없이 |
| 6. 재발 방지 | 정보보호 관리자 | 권한 정비, 모니터링 규칙 추가, 절차·교육 보완 | {{n}}영업일 이내 |
| 7. 기록 | 검토 수행자 | 양식 04 6항에 건별 조치 결과를 기록하고 확인자 확인을 받는다 | 조치 완료 시 |

## 8. 이용 기관 접근기록 제공

1. 이용 기관(공공기관)이 자기 기관 이용자·관리자의 접근기록을 요청하면 {{요청 접수 창구}}로 접수하고 요청자의 권한(이용 기관 관리자 또는 공문)을 확인한다.
2. 제공 범위는 해당 기관의 계정·데이터와 관련된 기록으로 한정하고, 다른 기관·다른 정보주체의 정보는 제외하거나 마스킹한다.
3. 제공 내역(요청일, 요청자, 범위, 제공일, 제공 방법, 담당자)을 기록하고 {{3}}년 보관한다. 서비스 관리 포털에서 이용 기관 관리자가 직접 조회하는 기능을 제공하면 그 기능과 조회 범위를 양식 03 비고에 적는다.
4. 14.3.2 보안관제 제반환경 지원에 따라 이용 기관 보안관제와 접근기록 연계가 필요하면 협약에 따른 범위·방법으로 제공한다.
