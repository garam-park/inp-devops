# 백업 및 복구 관리 절차

> [!info] 법령 기준
> 행정기관 및 공공기관의 클라우드컴퓨팅서비스 이용 기준 및 안전성 확보 등에 관한 고시 제15조(행정안전부고시 제2025-79호, 2025. 12. 29. 시행)는 행정기관등의 장이 재난·재해, 계약 종료, 사업 중단 등으로 클라우드컴퓨팅서비스가 중단되지 않도록 필요한 조치를 하고, 재난·재해 시 서비스 제공자의 재해복구 서비스를 이용할 수 있도록 정하고 있다. 당사는 공공기관 이용 기관이 이 조치를 이행할 수 있도록 본 절차의 백업·복구 체계를 갖춘다. 국가 사이버보안 기본지침 제92조(재해 복구체계)는 비공개 지침으로 문서명만 적는다. 고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

{{회사명}}은(는) 클라우드컴퓨팅서비스 {{서비스명}}의 장애·재해·침해사고 발생에 대비하여 가상자원, 데이터, 설정 정보를 백업하고 복구하는 체계를 수립·운영함으로써 공공기관 이용 기관에 제공하는 서비스의 가용성을 보장한다.

## 2. 적용 범위

- {{서비스명}}(하등급 SaaS) 인증 범위 내 모든 가상자원(가상 서버, 컨테이너), 데이터(DB, 스토리지, 파일), 설정 정보(인프라·보안·응용 설정), 소스코드·배포 환경
- 백업의 생성, 보관, 모니터링, 복원 시험과 장애·재해 시 복구 활동 전반
- 인프라의 물리 계층(데이터센터, 물리 장비, 하이퍼바이저)은 IaaS/PaaS 제공자의 책임 범위이며, 5항의 책임 구분에 따라 제공자 인증·계약으로 확인한다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 백업 | 장애·재해·침해사고로 인한 손상에 대비하여 가상자원, 데이터, 설정 정보의 사본을 별도 위치에 보관하는 활동 |
| 복원 시험 | 백업본으로 시스템·데이터를 실제로 복원하여 백업의 유효성과 복구 절차의 완전성을 검증하는 활동 |
| RTO(복구 목표 시간) | 서비스 중단 시점부터 복구 완료까지 허용되는 최대 시간 |
| RPO(복구 목표 시점) | 복구 시 허용되는 데이터 손실의 최대 범위(시점 기준) |
| 재해복구(DR) | 주 운영 환경 전체를 사용할 수 없는 상황에서 별도 환경으로 서비스를 복구하는 체계 |
| 백업 세대 | 보관 중인 백업본의 개수. 세대 수만큼 과거 시점으로 복원할 수 있다. |

## 6. 백업 대상 선정

1. 백업 대상은 양식 02. 정보자산 및 백업 대상 목록에서 자산 단위로 지정하고, 본 항의 기준을 따른다.
2. 아래 표의 유형은 원칙적으로 백업 대상에 포함한다. 제외할 때는 양식 02의 3항에 사유를 기록하고 정보보호 관리자의 확인을 받는다.
3. 신규 자산을 생성하거나 자산 구성을 변경할 때는 변경관리 절차(13항)에서 백업 대상 여부와 백업 방식을 함께 판단하고, {{n}}영업일 이내에 양식 02에 반영한다.

| 유형 | 백업 대상 예시 |
| --- | --- |
| 가상자원 | 가상 서버 이미지·스냅샷, 컨테이너 이미지, 인프라 구성 코드(IaC) |
| 데이터 | 운영 DB, 객체 스토리지·파일 저장소의 서비스 데이터, 이용 기관 데이터 |
| 인프라·보안 설정 | 보안 그룹·방화벽 규칙, IAM 사용자·역할·정책, 네트워크 구성(VPC, 라우팅, DNS), 로드밸런서 설정 |
| 응용·배포 환경 | 소스코드 저장소, 빌드·배포 파이프라인 설정, 환경 변수·응용 설정 파일 |
| 인증정보·암호키 | 인증서, API 키, 비밀정보 저장소(키 자체는 키 관리 서비스의 백업 체계를 따른다) |
| 정보보호시스템 설정 | 백신·EDR 정책, 로그 관리 시스템 설정, 웹 방화벽 규칙, 접근제어 정책 |
| 운영 기록 | 접근기록·감사 로그(보관 기간은 10.1.2 접근기록 관리 기준을 따른다) |

## 8. 백업 수행 및 모니터링

1. 백업은 클라우드 제공자의 백업·스냅샷 기능 또는 백업 도구로 자동 실행하는 것을 원칙으로 하고, 수동 백업은 수행 기록을 남긴다.
2. 백업 작업의 성공·실패를 모니터링하고, 실패 시 백업 관리자에게 자동 통보되도록 알림을 설정한다.
3. 백업 관리자는 백업 결과를 {{일 1회}} 확인하고 실패 건은 당일 원인 분석과 재수행을 완료한다. 재수행이 불가하면 정보보호 관리자에게 보고한다.

| 점검 항목 | 주기 | 담당 | 기록 |
| --- | --- | --- | --- |
| 백업 작업 성공 여부 확인, 실패 건 조치 | {{일 1회}} | 백업 관리자 | {{백업 모니터링 대시보드, 조치 기록}} |
| 백업 저장소 용량·보관 세대 확인 | {{주 1회}} | 백업 관리자 | {{점검 기록}} |

## 10. 복구 절차

1. 장애·재해·침해사고로 시스템·데이터의 복구가 필요하면 양식 04. 복구 시스템 상세 복구절차서에 따라 복구한다.
2. 복구는 9항의 우선순위 순서로 수행하고, 복구 완료 후 양식 04의 복구 후 확인 체크리스트로 서비스 정상 여부를 확인한다.
3. 주 운영 환경 전체를 사용할 수 없는 재해 상황은 정보보호 최고책임자가 재해 복구를 선언하고, {{다른 리전 복구 / DR 서비스(양식 05) 전환}}으로 복구한다.
4. 복구 수행 내역과 결과는 {{장애 보고서 / 침해사고 보고서}}에 기록한다.

## 11. 복원 시험

1. 백업본의 유효성과 복구 절차의 완전성을 검증하기 위해 복원 시험을 {{연 1회}} 이상 수행하고, 결과를 양식 06. 백업 및 복구 시험 결과서에 기록한다.
2. 복원 시험은 운영 환경과 분리된 환경에서 수행하고, 시나리오에 데이터 복원과 시스템(가상자원·설정) 복원을 모두 포함한다. 매 시험마다 대상을 달리하여 {{n}}년 주기로 주요 시스템 전체가 시험되도록 계획한다.
3. 시험에서 발견한 백업 누락, 절차서 오류·누락은 양식 06의 조치 계획에 따라 양식 02, 양식 04와 백업 설정에 반영한다.

## 13. 관련 절차와의 연계

SaaS 환경 운영과 관련된 백업, 비상복구, 변경관리, 침해사고대응 절차는 다음과 같이 연계하여 운영한다.

| 절차 | 연계 내용 |
| --- | --- |
| 비상복구(재해복구) | 재해 선언 시 양식 04와 양식 05(DR 계약 시)에 따라 복구하고, 복구 목표는 9항을 따른다. |
| 변경관리 | 인프라·응용 변경 시 백업 대상·방식의 변경 필요 여부를 검토하고 양식 02, 양식 03, 양식 04를 갱신한다. 변경 작업 전 복구 지점(스냅샷 등)을 확보한다. |
| 침해사고대응 | 랜섬웨어 등으로 데이터가 손상되면 5.1.1 침해사고 대응 절차와 병행하여 오염되지 않은 백업본으로 복구하고, 증거 보전 필요 시 복구 전에 대응 조직과 협의한다. |
| 장애 대응 | 장애 복구에 본 절차와 양식 04를 사용하고, 복구 결과를 6.1.2 장애 보고에 기록한다. |
