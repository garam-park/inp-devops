> [!info] 법령 기준
> 개인정보의 안전성 확보조치 기준 제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행)를 기준으로 작성했다. 제1항은 비밀번호·생체인식정보 등 인증정보의 저장 또는 정보통신망 송·수신 시 암호화(비밀번호 저장은 일방향 암호화), 제2항은 이용자의 주민등록번호·여권번호·운전면허번호·외국인등록번호·신용카드번호·계좌번호·생체인식정보 저장 시 암호화, 제4항은 개인정보를 인터넷망 구간으로 송·수신하는 경우 암호화, 제5항은 개인정보취급자의 컴퓨터·모바일 기기·보조저장매체 저장 시 암호화를 정한다. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인한다.

## 1. 목적

본 지침은 {{회사명}}이 제공하는 {{서비스명}}(하등급 SaaS)의 클라우드 시스템에 저장 또는 전송 중인 데이터를 보호하기 위하여 암호화 대상, 암호 강도(알고리즘·키 길이), 저장·전송 시 암호화 방법, 비밀번호 일방향 암호화, 암호키 관리 절차를 정한다. 전송구간 암호화 채널의 프로토콜별 상세 기준은 11.1.4 네트워크 암호화 산출물을 따르고, 본 지침은 암호 정책 전체의 기준 문서 역할을 한다.

## 5. 암호화 대상

취급하는 정보의 민감도·중요도와 법적 요구사항 유무에 따라 암호화 대상을 다음과 같이 정의한다. 대상별 실제 적용 내역은 양식 03. 암호화 대상 및 적용 현황표로 관리한다.

| 구분 | 대상 | 근거 |
| --- | --- | --- |
| 법적 요구사항 대상 | 인증정보(비밀번호, 생체인식정보 등), 이용자의 주민등록번호·여권번호·운전면허번호·외국인등록번호·신용카드번호·계좌번호·생체인식정보, 인터넷망 구간으로 송·수신하는 개인정보, 개인정보취급자의 컴퓨터·보조저장매체에 저장하는 개인정보 | 안전성 확보조치 기준 제7조제1항·제2항·제4항·제5항 |
| 중요 정보 | 클라우드 시스템 운영 관련 정보(정보자산목록, 네트워크 구성도, 취약점 점검 결과, 위험분석 평가 결과 보고 등), 이용 기관과 협의된 정보, API 인증 정보·소스코드 내 비밀정보, 그 밖에 당사가 중요도를 판단한 정보 | 인증 기준 12.3.1, 정보자산 목록의 기밀성 등급 {{상}} |

- 당사가 개인정보를 처리하지 않는 경우(개인정보 미포함 하등급 인증) 법적 요구사항 대상은 적용 제외할 수 있다. 이 경우 개인정보를 처리하지 않는다는 판단 근거를 양식 03 현황에 기록하고, 중요 정보와 시스템 비밀번호에 대한 암호화는 그대로 적용한다.
- 신규 서비스 기능·시스템을 도입하거나 취급 정보가 변경되면 설계 단계에서 암호화 대상 해당 여부를 검토하고 양식 03 현황에 반영한다.

## 6. 암호 알고리즘·암호 강도 기준

KISA 「암호 알고리즘 및 키 길이 이용 안내서」와 「개인정보의 암호화 조치 안내서」의 권고를 참고하여 다음 기준을 적용한다.

| 암호화 방식 | 허용 알고리즘 | 암호키 길이 | 사용 금지 |
| --- | --- | --- | --- |
| 대칭키 암호화 | SEED, ARIA, AES | 128비트 이상 | DES, 3DES, RC4 |
| 비대칭키 암호화 | RSA, ECDSA | RSA 2048비트 이상, ECDSA P-256 이상 | RSA 1024비트 이하 |
| 일방향 암호화(해시) | SHA-256/384/512, bcrypt, scrypt, Argon2id | - | MD5, SHA-1 |

- 취약한 것으로 알려진 알고리즘(DES, 3DES, MD5, SHA-1 등)은 신규 적용을 금지하고, 운영 중 발견되면 12항의 예외 절차 없이 사용 중인 경우 {{n}}영업일 이내에 교체 계획을 수립한다.
- 양자컴퓨팅에 의해 취약점이 발견된 암호 알고리즘(공개키 기반 일부 취약 알고리즘 등)은 사용을 제한하고, 관계 기관의 양자내성암호 전환 권고를 연 1회 검토 시 반영한다.
- 공공기관 이용 기관에 검증필 암호화 기술을 제공해야 하는 경우 국가정보원 검증필 암호모듈·검증 대상 알고리즘 기준을 함께 적용한다. 상세 요구는 14.3.1 검증필 암호화 기술 제공 산출물을 따른다.

## 7. 전송 시 암호화

중요정보를 전송하는 경우 구간별로 다음 방식을 적용한다. 프로토콜 버전·암호 스위트의 상세 기준과 구간별 현황은 11.1.4 네트워크 암호화 산출물을 따른다.

| 구분 | 암호화 방안 |
| --- | --- |
| 서버와 클라이언트 간 전송(이용자·이용 기관 ↔ 서비스) | SSL/TLS 방식(TLS 1.2 이상, TLS 1.3 권장) 또는 응용프로그램 방식 |
| 개인정보처리시스템 간·시스템 간 전송 | IPsec 방식, SSL/TLS 방식, SSH 방식 |
| 관리자 원격 접근 | VPN, SSH-2, HTTPS |
| 외부 서비스 연계·데이터 이관·백업 전송 | HTTPS(TLS), SFTP 등 암호화 채널, 필요 시 파일 단위 암호화 병행 |

- SSL v3, TLS 1.0, TLS 1.1 등 안전하지 않은 전송구간 암호화 방식은 지원(허용) 상태로도 두지 않는다. 서버·로드밸런서 설정에서 비활성화하고, 양식 05. 암호 정책 검토 및 점검 기록의 점검으로 확인한다.
- 인증정보는 취급 구간과 관계없이 모든 전송에서 암호화한다(안전성 확보조치 기준 제7조제1항).

## 8. 저장 시 암호화

| 구분 | 암호화 방식(택일 또는 병행) | 적용 기준 |
| --- | --- | --- |
| 개인정보처리시스템(DB·스토리지) | 응용프로그램 자체 암호화, DB 서버 암호화, DBMS 자체 암호화, DBMS 암호화 기능 호출, 운영체제 암호화 | 5항의 법적 요구사항 대상 컬럼·필드는 필수. 이용자가 아닌 정보주체의 고유식별정보를 내부망에 저장하는 경우 위험도 분석(또는 개인정보 영향평가) 결과에 따라 적용 여부·범위를 정할 수 있다(제7조제3항). |
| 클라우드 스토리지·백업 | 제공자 저장소 암호화 기능(서버 측 암호화) 활성화, 필요 시 응용 계층 암호화 병행 | 중요정보를 저장하는 버킷·볼륨·백업은 암호화 옵션을 기본 활성화한다. |
| 업무용 컴퓨터·보조저장매체 | 문서 도구 자체 암호화, 암호 유틸리티 이용 암호화, DRM, 디스크 암호화 | 중요정보·개인정보를 저장하는 경우 필수. 보조저장매체 반출은 별도 승인 절차를 따른다. |
| 소스코드·설정 내 비밀정보 | 비밀정보 저장소 보관, 환경변수 주입 | 소스코드·형상관리 저장소·파이프라인 설정에 API 키·비밀번호를 평문으로 저장하지 않는다. |

## 9. 비밀번호 일방향 암호화

1. 이용자(고객 등)와 사용자(임직원 등)의 비밀번호는 안전한 알고리즘(SHA-256/384/512, bcrypt, scrypt, Argon2id 등)으로 일방향 암호화하여 저장한다(안전성 확보조치 기준 제7조제1항).
2. MD5, SHA-1 등 안전하지 않은 알고리즘은 일방향 암호화에 사용하지 않는다. 범용 해시(SHA-2 계열)를 사용하는 경우 솔트(salt)를 적용하고, 신규 구현에는 bcrypt·scrypt·Argon2id 등 키 스트레칭 기반 알고리즘을 권장한다.
3. 법률에 따른 대상 이외의 서비스·시스템 비밀번호(내부 관리 도구, 배치 계정, 장비 계정 등)에도 일방향 암호 알고리즘을 적용한다.
4. 비밀번호 복구는 재설정 방식으로만 제공하고, 원래 비밀번호를 복원·통지하는 기능을 두지 않는다.
5. 비밀번호 생성 규칙·변경 주기 등 운영 기준은 10.3.4 패스워드 관리 산출물을 따른다.

## 10. 암호키 관리

암호키의 생성·이용·보관·배포·교체·폐기 절차를 다음과 같이 정하고, 키별 이력은 양식 04. 암호키 관리대장에 기록한다.

| 단계 | 절차 |
| --- | --- |
| 생성 | 6항의 기준을 충족하는 알고리즘·키 길이로 키 관리 서비스에서 생성한다. 예측 가능한 값이나 수동 생성 키를 사용하지 않는다. |
| 이용·보관 | 키는 키 관리 서비스 또는 비밀정보 저장소에만 보관하고, 소스코드·문서·메신저에 평문으로 저장·전달하지 않는다. 키 암호화 키(KEK)와 데이터 암호화 키(DEK)를 구분하여 관리한다. |
| 배포 | 키 접근 권한은 업무상 필요한 최소 인원에게만 부여하고, 부여·회수 내역을 대장에 기록한다. |
| 교체 | 키 유형별 교체 주기({{예: 데이터 암호화 키 1년, TLS 인증서는 유효기간 만료 30일 전}})를 정하여 교체하고, 유출·유출 의심 시 즉시 교체한다. |
| 백업·복구 | 키 분실 시 암호화된 데이터를 복구할 수 없으므로 키 관리 서비스의 백업·복제 기능으로 보호하고, 복구 절차를 대장에 기록한다. |
| 폐기 | 사용 종료된 키는 관련 데이터의 복호화 필요성이 없음을 확인한 뒤 2인 확인으로 폐기하고 대장에 기록한다. |

- 암호키 관리자는 2.1.2 주요 직무자 목록의 암호키·인증정보 관리 직무(KD-11)로 지정하고, 암호화 대상 데이터의 운영 권한(DBA 등)과 겸하지 않는다.
- 암호키 관리자는 암호화 대상과 대상별 암호화 방식의 구현 여부를 정기 점검(양식 05)에서 확인한다.

## 11. 신규 도입·변경 시 검토

1. 클라우드 시스템·서비스 기능을 새로 도입·개발·변경할 때 설계 단계에서 암호화 대상 해당 여부, 적용 방식, 알고리즘 기준 충족을 검토한다.
2. 검토 결과 암호화가 필요한 대상은 오픈 전에 양식 03. 암호화 대상 및 적용 현황표에 등재하고 적용을 확인한다.
3. 암호화 기능의 동작(암호화 저장, 전송 암호화, 해시 적용)은 시험 결과로 확인하고 기록을 보관한다(13.2.1 시험 계획 및 결과 연계).

## 12. 예외 관리

1. 기술적 제약(레거시 연동, DBMS 미지원 등)으로 본 지침의 기준을 적용할 수 없는 경우 담당 부서장이 예외를 신청하고, 정보보호 관리자 검토를 거쳐 정보보호 최고책임자가 승인한다.
2. 예외 승인 시 보완 통제(접근통제 강화, 망 분리, 모니터링 강화 등)와 적용 기한(최대 {{n}}개월)을 함께 정한다.
3. 예외는 양식 03. 암호화 대상 및 적용 현황표 5항에 기록하고, 기한 도래 시 재검토한다. 법령이 예외를 허용하지 않는 항목(비밀번호 일방향 암호화 등)은 예외로 승인할 수 없다.

## 13. 검토 및 현행화

1. 정보보호 관리자는 본 지침과 사용 중인 알고리즘·프로토콜을 연 1회 이상 검토하여 KISA 안내서 등 최신 권고사항과 법령 개정 사항을 반영한다.
2. 사용 중인 알고리즘·프로토콜의 취약점이 공개되면 수시로 검토하고 필요 시 허용·금지 기준을 개정한다.
3. 검토·점검 결과는 양식 05. 암호 정책 검토 및 점검 기록으로 남기고, 결과에 따라 본 지침과 양식 03 현황을 갱신한다.
