## 2. 권장 작성 순서

1. 01 시스템 개발 보안 지침 인증 및 암호화 조항: 인증·암호화·시큐어 코딩 보안 요구사항과 기준값을 정하고 정보보호 최고책임자 승인을 받아요.
2. 02 보안요구사항 정의 및 반영 절차: 요구사항이 설계부터 배포까지 반영·검증되도록 단계별 절차와 필수 시험 항목을 정해요.
3. 03 시스템 설계서 보안 요구사항 반영표: 운영 중인 시스템(웹 포털, 관리자 콘솔, API 등)별로 현행 설계를 등재하고, 요구사항 ID별 반영 여부를 확인해요. 신규 개발 시에는 설계 단계에서 작성해요.
4. 05 증적 수집 점검표: 반영표의 설계가 실제로 구현되어 있음을 보여주는 화면·설정·점검 결과 증적을 수집해요.
5. 04 시스템 변경 내역서: 이후 변경이 생길 때마다 영향 검토와 반영·시험 확인을 기록하고 반영표·증적을 현행화해요.

## 3. 심사 대비 체크리스트

- [ ] 개발 관련 지침에 사용자 인증 보안 요구사항(인증 시기, 패스워드 잠금 임계치·암호화·길이·조합·변경 주기, 동시 접근·IP 제한, 세션 타임아웃, 추가 인증, API 인증)이 빠짐없이 정의되어 있다.
- [ ] 이용자 웹 포털뿐 아니라 관리서버, 개인정보 수집·과금 기능, API 서버의 인증도 설계에 포함했다.
- [ ] 관리자 기능은 일반 사용자와 분리했고 추가 인증(OTP, 인증서 등)을 요구한다.
- [ ] SaaS 접근 권한 정책을 수립하여 사용 권한과 관리 권한을 구분해 부여하도록 설계했다.
- [ ] API 연동 호출에 안전한 인증을 적용했고 인증키를 비밀정보 저장소 등으로 보호하며 평문 저장이 없다.
- [ ] 중요정보 저장 시 안전성이 입증된 알고리즘·키 길이로 암호화하고(12.3.1 암호 정책과 일치), 비밀번호는 일방향 암호화로 저장한다.
- [ ] 전송 구간에 TLS 1.2 이상을 적용했고, SSL v3·TLS 1.0/1.1 등 취약 프로토콜이 비활성화되어 있음을 스캔으로 확인했다.
- [ ] 접속 시도 횟수 제한과 임계치 초과 시 계정 잠금 등 정의한 요구사항이 실제로 동작함을 시험·화면으로 입증할 수 있다.
- [ ] 입력값 검증과 Prepared Statement 사용을 코드 리뷰·취약점 점검으로 확인했고 SQL Injection 취약점이 없다.
- [ ] 시스템 변경 시 인증·암호화 영향을 검토한 변경 내역서가 있고, 설계 반영표와 증적이 현행화되어 있다.
- [ ] 하이퍼바이저 등 IaaS/PaaS 제공자 책임 영역의 인증은 제공자 인증·계약으로 확인한 근거가 있고, 당사가 사용하는 클라우드 콘솔 계정의 인증 설정은 당사가 관리한다.

## 4. 관련 산출물(다른 항목)

- 10.3.2 사용자 인증: 본 항목은 설계·개발 단계의 요구사항 정의·반영을, 10.3.2는 운영 단계의 인증 통제를 다뤄요. 요구사항 기준값(잠금 임계치, 세션 시간 등)을 서로 일치시켜요.
- 10.3.3 강화된 인증 수단 제공: 추가 인증 수단(OTP 등)의 제공·운영 방식을 따라요.
- 10.3.4 패스워드 관리: 패스워드 길이·조합·변경 주기의 세부 기준을 맞춰요.
- 11.1.4 네트워크 암호화: 전송 구간의 프로토콜·암호 스위트·인증서 기준과 운영 현황 관리를 따라요.
- 12.3.1 암호 정책 수립: 저장·전송 암호화에 사용하는 알고리즘·키 길이·키 관리의 전사 기준이에요.
- 13.2.1 시험 계획 및 결과: 보안 요구사항 반영 여부를 확인하는 시험의 계획·결과 양식을 따라요.
- 14.3.1 검증필 암호화 기술 제공: 공공기관에 제공하는 암호화 기능은 국가정보원 검증필 암호모듈 요구를 따라요.

## 5. 양식 작성 규칙

- `{{ }}`로 표시한 자리표시자는 실제 값으로 바꿔요. 표의 빈 칸은 해당 값을 채워요.
- 01 조항의 잠금 임계치·세션 시간 등 수치는 법령·고시가 정하지 않은 당사 내부 기준이에요. 조직 상황에 맞게 조정하되 부적합 사례가 걸리는 통제(실패 잠금, 세션 타임아웃, 취약 프로토콜 금지, 입력값 검증)는 없애지 않아요.
- 서명이 필요한 문서는 서명본을 스캔해 보관하고, md 원본에는 서명본 보관 위치를 적어요.
- 반영표(03)와 변경 내역서(04)는 버전을 올릴 때 이전 버전을 삭제하지 않고 보관해서 특정 시점의 설계·변경 근거를 확인할 수 있게 해요.
- 문서를 개정하면 문서 정보 표의 버전과 개정 이력을 갱신해요.
- 법령 인용은 개인정보 보호법 제29조(법률 제20897호, 2025. 10. 2. 시행), 개인정보의 안전성 확보조치 기준 제6조·제7조(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 기준이에요. 법령·고시가 개정되면 국가법령정보센터에서 조문을 다시 확인해요.
- 허용·금지 프로토콜과 알고리즘 기준은 KISA 암호이용 안내서의 권고가 바뀌면 01 조항의 표를 함께 개정해요.
